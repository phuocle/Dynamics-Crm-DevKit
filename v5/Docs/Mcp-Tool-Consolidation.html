05

Gọi ít tool hơn, vẫn dùng đúng contract

1 · Chọn operation

Danh sách enum ngắn trong tool chỉ ra các tên cũ: manage_view, manage_form…

→
2 · Đọc contract khi cần

read_instruction(name="contract://manage_view") hoặc resource tương ứng.

→
3 · Gọi handler qua router

Giữ nguyên tên tham số, default, action, lỗi và dữ liệu kết quả.

Trước

manage_view({
  "action": "list",
  "entity_name": "account"
})

Sau — đề xuất

manage_ui({
  "operation": "manage_view",
  "arguments": {
    "action": "list",
    "entity_name": "account"
  }
})

Hai utility giữ cách gọi hiện tại. Tám router có operation và arguments. Object arguments giữ nguyên các field cũ; field nào vốn là JSON string vẫn giữ string. Server lấy schema/default từ descriptor và bind theo đúng handler, không cho gọi method tùy ý.

Contract không biến mất

Input/output schema chi tiết, quy tắc theo action, default, ví dụ và hướng dẫn file/backup được trả cho đúng operation. Giữ 13 resource cũ. Client không hỗ trợ resources vẫn dùng read_instruction.

Payload mặc định giữ nguyên

Đợt gộp catalog chuyển nguyên CallToolResult, gồm text, structuredContent và isError. Tối ưu result bằng tham số hiện có trước; view ngắn mới là hạng mục opt-in riêng. Không tự retry mutation khi gặp timeout.

Đánh đổi thật: compact không còn công bố sẵn typed schema chi tiết cho mỗi operation. Client autocomplete/kiểm tra output tĩnh phải đọc contract hoặc dùng legacy. Đây là thay đổi API khám phá/gọi tool; mục tiêu là giữ chức năng thực thi và payload, không khẳng định API cũ vẫn giống hệt.

07

Những chỗ dễ “gộp xong mà mất tính năng”

01 · Nullable, default và kiểu dữ liệu

Không đồng nhất omitted/null/false/0/chuỗi rỗng. Bảo toàn record_ids dạng array, auto_number_seed nullable Int64 và JSON-string fields. Dùng binder tương đương SDK, kiểm thử parity.

02 · Quyền và category

Category lấy từ attribute ReadOnly. Mixed facade không được quảng bá là read-only. Giữ dry-run, admin gate và impersonation ở server; không thêm tham số để AI override policy.

03 · Backup, file local và publish

Report create/dataset là local-only; download ghi file. View undo cần cặp XML. App/form/chart có publish và validation riêng. Router không “đơn giản hóa” các side effect này.

04 · Discovery và resource references

Host hiện scan assembly; read_instruction scan URI trong descriptions. Rút mô tả hoặc bỏ registration thiếu kiểm soát sẽ làm mất tool/resource mapping. Cần một catalog dùng chung.

05 · Compatibility và tool permissions

Giữ --tool-surface legacy|compact. Tên compact mới có thể cần cấu hình quyền ở client. Không advertise cả hai: 40 cũ + 8 router mới thành 48 tool.

06 · Help và lỗi làm tăng token trở lại

Chỉ tải contract cho operation cần dùng, cache theo instance/build/hash. Đo cả help, lịch sử hội thoại, retry và latency; không chỉ chụp catalog nhỏ rồi coi là thành công.

Handler có state theo invocation phải giữ lifetime phù hợp; không biến registry singleton thành nơi giữ instance mutable. Chạy thử đồng thời để tránh một request dùng nhầm dữ liệu request khác.

09

Reuse test cũ, không sửa test cũ

Ràng buộc theo review: không sửa, xóa, rename, tham số hóa hay bổ sung method vào file test cũ. Không đổi expected values, helper, fixture, snapshot, Ignore/Skip hoặc cấu hình chạy để làm test xanh. Chỉ thêm file test mới.

Test cũ phải chạy lại để phát hiện regression. Tuy nhiên, test cũ pass chỉ chứng minh những tình huống suite đã kiểm tra; router, binder, discovery và client compact cần test mới. Không thể dùng một bên để thay cho bên còn lại.

Yêu cầu này thay đổi cách đăng ký tool

McpServerHostCoverageTests đang assert 18/40. DryRunGatewayContractTests scan assembly trực tiếp và yêu cầu đúng 22 mixed tool. Nếu thêm 8 annotated classes vào cùng scan, test có thể fail dù runtime chỉ quảng bá 10 tool. Vì vậy, lọc runtime chưa đủ.

Nên giảm, nhưng giảm theo nhu cầu

Đợt A · Dùng contract hiện có

  • Query chỉ chọn cột cần, filter đúng; dùng aggregate cho yêu cầu đếm/tổng.
  • Dùng max_records/top và get_all=false khi chỉ cần xem mẫu; không đổi default legacy.
  • Metadata compact/standard khi đủ; dùng full khi clone cột/formula.
  • List trước, detail theo ID; giới hạn thời gian/status khi đọc log.
  • Giữ XML/RDL và backup đầy đủ cho sửa/undo; không cắt dữ liệu cần cho hành động.

Đợt B · View ngắn opt-in, nếu cần

  • Thêm presentation riêng; full/default và helper legacy giữ nguyên.
  • Summary/page có schema công bố đúng; báo rõ phần nào chưa đầy đủ.
  • Giữ ID/status/warnings/errors/partial counts/backupPath và kết quả publish.
  • Mọi phần không inline phải lấy lại được bằng detail/paging/resource hoặc đường đọc đã kiểm thử.
  • Đọc lại snapshot của mutation không được chạy lại mutation.

Chỉ trả đường dẫn file chưa đủ. Client ở máy khác có thể không đọc được; client không hỗ trợ resources cần đường đọc phù hợp. Chưa chứng minh lấy lại đủ dữ liệu thì giữ full result. Thiết kế view mới là hạng mục cần review riêng, chưa chốt thêm tham số vào tám router hiện tại.

Giảm duplication tốt nhất tại lớp presentation/host đã biết client cần kênh nào: cho model đọc một bản cần thiết, giữ fallback/display đúng hợp đồng. Nếu không kiểm soát host, không cam kết mức giảm này. Không đổi key thành a/b/c, bỏ null/false/0 có ý nghĩa hoặc nén/base64 rồi bắt model đọc.

Đo toàn workflow: catalog + result mới + lịch sử + help/retry, cùng output model sinh. Không cộng “tool output token” thêm một lần vào input đã chứa result. Báo cached input riêng. Nếu người dùng cần đọc toàn bộ dữ liệu thì chia trang có thể vẫn tốn tổng token tương đương hoặc hơn; tiết kiệm thật đến từ không nạp phần không cần hoặc xử lý phù hợp phía server.

Chưa benchmark result-size/token của 40 operation. Những điểm về duplication ở đây là truy vết source; mức token phải xác nhận bằng representation/usage thật của từng client.
