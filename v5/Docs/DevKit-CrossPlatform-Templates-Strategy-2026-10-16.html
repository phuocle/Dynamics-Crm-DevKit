Cross-Platform Template Architecture · macOS / Linux / Windows

Nên chọn VS Code Extension, CLI hay CLI MCP để chạy Project & Item Templates?

VSIX hiện tại sở hữu 13 Project Templates và 17 Item Templates cực kỳ mạnh mẽ nhưng bị khóa chặt vào .NET Framework 4.8, EnvDTE, WPF Dialog và dịch vụ STextTemplating của Visual Studio trên Windows. Để chạy trên macOS và Linux, câu trả lời tốt nhất không phải là chọn 1 bỏ 2, mà là đặt toàn bộ Template Engine vào CLI (.NET 10) làm lõi duy nhất, đồng thời mở ra CLI Interactive + CLI MCP Tools ngay trong cùng binary, và dùng VS Code Extension mỏng (thin wrapper) ở giai đoạn sau.

01 / KẾT LUẬN & KHUYẾN NGHỊ CHIẾN LƯỢC

Đừng bắt đầu bằng VS Code Extension đơn lẻ — hãy bắt đầu từ CLI + CLI MCP.

Qua phân tích mã nguồn thực tế tại DynamicsCrm.DevKit.Vsix/Wizard/, DynamicsCrm.DevKit.Shared/ và DynamicsCrm.DevKit.Cli/, bản chất của việc tạo Project/Item Template trong DevKit gồm 3 bước: (1) Kết nối Dataverse & lấy Metadata (Entities, Forms, Messages, CustomApis, Solutions), (2) Render nội dung qua CodeGenService + T4Helper + Replacement, và (3) Ghi file xuống ổ đĩa + cập nhật cấu trúc Solution/Project (.sln / .csproj / devkit.json).

  • Tại sao KHÔNG nên làm VS Code Extension độc lập trước? Viết VS Code Extension bằng TypeScript đòi hỏi phải dựng lại 11 màn hình WPF sang Webview/QuickPick, đồng thời vẫn phải gọi xuống một tiến trình .NET bên dưới để lấy Metadata từ Dataverse và chạy T4/CodeGen. Nếu logic tạo template nằm ở tầng VS Code, người dùng dùng JetBrains Rider trên Mac, dùng Neovim, chạy CI/CD hoặc dùng Claude Code / Cursor CLI sẽ không dùng được.
  • Tại sao CLI + CLI MCP là bước đi chiến lược? Trong kiến trúc hiện tại của v5, DynamicsCrm.DevKit.Cli đã tích hợp sẵn cả 3 chế độ:
    • Normal CLI (devkit ... dùng Spectre.Console.Cli — hỗ trợ cả truyền tham số lẫn menu tương tác đẹp mắt trên Terminal Mac/Linux).
    • MCP Server (devkit mcp — cho phép AI Agent như Claude Desktop, Cursor, VS Code Copilot, Antigravity tự động tra cứu table/message rồi tạo project/item chuẩn xác bằng ngôn ngữ tự nhiên).
    • Tool Invoker (devkit tool call <tool_name> — gọi trực tiếp MCP tool từ dòng lệnh hoặc script với JSON schema tự động).
  • Kết luận: Hãy xây dựng Cross-Platform Template Engine ngay trong DynamicsCrm.DevKit.Shared + DynamicsCrm.DevKit.Cli. Khi có CLI (`devkit new ...`) và MCP Tools (`scaffold_project`, `scaffold_item`), bạn lập tức hỗ trợ được Mac/Linux trên mọi IDE (VS Code, Rider, Cursor, Antigravity, Terminal). Sau đó, nếu cần trải nghiệm chuột phải trên VS Code, chỉ mất 15% công sức để bọc một VS Code Extension siêu mỏng gọi `devkit` CLI bên dưới.
02 / GIẢI PHẪU VSIX HIỆN TẠI

Điều gì làm cho Project & Item Templates của VSIX "quá hay" — và điều gì đang giữ chân nó trên Windows?

Không giống như các template tĩnh thông thường (chỉ đổi tên file và namespace), các template trong DynamicsCrm.DevKit.Vsix là Metadata-Driven Interactive Wizards (Wizard thông minh kết nối trực tiếp vào Dataverse):

Điểm mạnh cốt lõi của VSIX Templates

  • Kết nối sống tới Dataverse: Tự động tải danh sách Entities, Messages, Stages, Execution Modes, Solutions, Forms, Custom APIs, Virtual Entity Data Sources ngay lúc tạo file.
  • T4 Template tùy biến được: T4Helper.cs nạp file .tt từ DynamicsCrm.DevKit.Shared/Resources/tt/ (hoặc Custom Template nén trong cấu hình) và truyền T4Context để sinh code C# chuẩn chỉnh kèm [CrmPluginRegistration].
  • Sinh bộ file kép thông minh: Ví dụ JsForm sinh cùng lúc Account.js, Account.form.js, Account.d.ts (kiểm tra xem Account.webapi.js đã tồn tại chưa để gộp Intellisense). LateBound sinh Account.cs và Account.generated.cs.
  • Tự động hóa NuGet & Signing: Replacement.cs tự tra phiên bản NuGet mới nhất, điền $CliConnectionArgs$ vào các file script, và SigningHelper tự tạo khóa .snk.

Các thành phần đang khóa chặt vào VS 2026 / Windows

  • UI Layer (WPF): FormProject, FormPlugin, FormItem, FormConnection2 dùng PresentationFramework (chỉ chạy trên Windows).
  • IDE Automation (EnvDTE & VS.Shell): IWizard, VsixHelper.SelectedItem, TrySetDependentUpon, FixProjectFolder phụ thuộc COM API của Visual Studio.
  • Visual Studio T4 Host: T4Helper.ProcessTemplateAsync gọi VS.GetServiceAsync<STextTemplating, ITextTemplating>() của Visual Studio thay vì engine T4 độc lập.
  • Cấu trúc Project cũ: Template Shared tạo .shproj (Shared Project của VS) và các script tự động sinh ra đều là file .bat (Windows Batch) thay vì đa nền tảng.
03 / PHÂN TÍCH CHI TIẾT 3 PHƯƠNG ÁN

Đặt lên bàn cân: VS Code Extension vs CLI vs CLI MCP

Phương án 1

VS Code Extension

Xây dựng extension TypeScript trên VS Code Marketplace, cung cấp menu chuột phải trong Explorer ("DevKit: New Project / New Item") và giao diện QuickPick / Webview.

Ưu điểm:

  • Trải nghiệm gần giống VSIX nhất cho lập trình viên thích giao diện đồ họa (click chuột phải vào thư mục → chọn Entity → tạo file).
  • Hỗ trợ tốt việc mở file vừa tạo, hiển thị diff và cây thư mục trực quan.

Nhược điểm lớn:

  • Không thể tự chạy một mình: Node.js của VS Code không có sẵn ServiceClient của Dataverse, không có bộ sinh code C# trong DynamicsCrm.DevKit.Shared và không chạy được T4 C#. Bạn vẫn bắt buộc phải viết CLI backend bên dưới để VS Code gọi sang!
  • Tốn nhiều công sức duy trì 2 codebase (TypeScript UI + C# Backend).
  • Bị khóa vào VS Code (không hỗ trợ JetBrains Rider trên Mac/Linux hay chạy tự động qua CI/CD).
Phương án 2

DevKit CLI (devkit new)

Mở rộng DynamicsCrm.DevKit.Cli (.NET 10) với lệnh devkit new project và devkit new item, hỗ trợ cả 2 chế độ: Interactive Wizard trên Terminal (dùng Spectre.Console) và Non-interactive Flags.

Ưu điểm:

  • 100% cùng ngôn ngữ & chia sẻ code trực tiếp: Gọi thẳng MetadataService, CodeGenService, CSharpLateBound, JsForm, TsForm trong DynamicsCrm.DevKit.Shared mà không cần viết lại.
  • Spectre.Console Wizard cực mạnh: Có sẵn trong CLI! Hỗ trợ chọn Entity có tìm kiếm/lọc, chọn Message/Stage bằng phím mũi tên trên Terminal của macOS/Linux/Windows.
  • Chạy ở mọi nơi: VS Code Terminal, JetBrains Rider, iTerm2 (Mac), bash/zsh (Linux), GitHub Actions / Azure DevOps.

Nhược điểm:

  • Người dùng phải gõ lệnh hoặc thao tác trên Terminal thay vì bấm chuột phải trên cây thư mục (trừ khi kết hợp VS Code Tasks hoặc Extension mỏng).
Phương án 3

DevKit CLI MCP (devkit mcp)

Bổ sung nhóm MCP Tools (ví dụ: list_templates, scaffold_project, scaffold_item) vào MCP Server sẵn có trong DynamicsCrm.DevKit.Cli/Mcp/.

Ưu điểm:

  • Trải nghiệm hiện đại nhất (AI-Native): Developer trên Mac/Linux chỉ cần gõ trong Claude Code / Cursor / VS Code Copilot / Antigravity: "Tạo cho tôi plugin PreValidationUpdate cho bảng account kiểm tra hạn mức tín dụng và kèm unit test".
  • Không cần dựng UI phức tạp: AI Agent đóng vai trò là "Wizard thông minh" — tự gọi get_tables, get_messages để tra cứu metadata rồi gọi scaffold_item để tạo đúng file từ T4 template và viết luôn logic nghiệp vụ bên trong!
  • Mua 1 được 2 nhờ devkit tool: Mọi MCP Tool trong DevKit đều tự động chạy được như lệnh CLI qua devkit tool call <tool> (kèm describe, example, validate).

Nhược điểm:

  • Khi không dùng AI (hoặc muốn tạo nhanh 1 file offline/deterministic mà không tốn token), người dùng vẫn cần một lệnh CLI ngắn gọn.

05 / KIẾN TRÚC ĐỀ XUẤT

Kiến trúc 3 tầng "One Engine, Three Surfaces" (Một Lõi, Ba Giao Diện)

Điểm đặc biệt của repository DynamicsCrm.DevKit ở phiên bản v5 là CLI và MCP đã nằm chung trong một project DynamicsCrm.DevKit.Cli, và đã có sẵn lớp Tool/ (devkit tool list|describe|example|call) biến mọi MCP Tool thành lệnh CLI chuẩn JSON. Vì vậy, bạn không phải chọn giữa CLI hay CLI MCP — chỉ cần viết một TemplateEngineService trong DynamicsCrm.DevKit.Shared và mở nó ra cả 2 đường trong vòng vài chục dòng code!

Tại sao kiến trúc này thắng tuyệt đối?
  • Khi bạn code xong Lõi (Shared) + MCP Tool: Người dùng dùng AI (Claude, Copilot, Cursor, Antigravity) dùng được ngay lập tức qua devkit mcp; script tự động hóa hoặc VS Code Extension dùng được ngay qua devkit tool call scaffold_item --input @params.json.

07 / RÀO CẢN KỸ THUẬT TRÊN MACOS & LINUX VÀ CÁCH XỬ LÝ

5 điểm trong source code cần xử lý để chạy mượt trên Mac & Linux

Khi kiểm tra mã nguồn hiện tại của DynamicsCrm.DevKit.Vsix, Shared và Cli, có 5 điểm phụ thuộc Windows cần được thay thế bằng giải pháp chuẩn .NET 10 đa nền tảng:

  • Thêm project vào .sln / .slnx: Gọi dotnet sln add <project.csproj> hoặc sửa trực tiếp XML/SLN.

  • Với .projitems (Shared Project): Dùng XDocument thêm thẻ <Compile Include="$(MSBuildThisFileDirectory)..." />.
5 Mã hóa mật khẩu & Token Cache bằng Windows DPAPI
ProtectedData.Protect chỉ hỗ trợ Windows		 Shared/Helper.cs

08 / THIẾT KẾ GIAO DIỆN CLI & CLI MCP ĐỀ XUẤT

Trải nghiệm thực tế trên macOS / Linux sẽ trông như thế nào?

1. Trải nghiệm qua DevKit CLI (devkit template / devkit new)

Hỗ trợ cả Interactive Mode (khi chỉ gõ devkit new) lẫn Command-line Flags (cho script/VS Code):

# 1. Chế độ Interactive Wizard (Spectre.Console trên Mac/Linux):
$ devkit new
? Chọn loại muốn tạo:
  > Item Template (Plugin, JsForm, TsForm, LateBound, CustomApi...)
    Project Template (Server, WebResourceTs, Shared, ConsoleCore...)
? Chọn Item Template: [Plugin]
? Chọn Bảng (Entity): [account (Account)]
? Chọn Message: [Update]
? Chọn Stage: [PreOperation (20)]
? Chọn Execution Mode: [Synchronous]
✔ Đã sinh file: PreOperationAccountUpdateSynchronous.cs (T4: Default)

# 2. Chế độ Non-Interactive (nhanh, dùng trong script / VS Code):
$ devkit new project --type WebResourceTs --name Contoso.WebResource
$ devkit new project --type Server --name Contoso.Plugin

$ devkit new item --type TsForm --entity account --out ./src/entities
$ devkit new item --type Plugin --entity contact --message Create \
  --stage PreOperation --execution Synchronous --out ./Contact

2. Trải nghiệm qua DevKit CLI MCP (devkit mcp & devkit tool)

Chỉ cần thêm 3 MCP Tools vào DynamicsCrm.DevKit.Cli/Mcp/Tools/:

  • list_devkit_templates (ReadOnly = true): Trả về danh sách 13 Project Templates & 17 Item Templates cùng schema tham số cần thiết và danh sách Custom T4 templates trong DynamicsCrm.DevKit.Cli.json.
  • scaffold_devkit_project (ReadOnly = false): Tạo Project Template (Server, WebResourceTs, ConsoleCore, Shared...), tạo key .snk, cập nhật .sln và DynamicsCrm.DevKit.Cli.json.
  • scaffold_devkit_item (ReadOnly = false): Kết nối Dataverse lấy Metadata của Entity/Message/CustomApi/DataSource, chạy Mono.TextTemplating hoặc CodeGenService để sinh các file Item Template (Plugin, TsForm, JsForm, LateBound, CustomApi, Workflow, Test...).
# Gọi qua AI Agent (Claude / Cursor / Copilot / Antigravity):
"Tạo project WebResourceTs tên Contoso.WebResource và tạo luôn
item TsForm + TsWebApi cho 2 bảng account và contact"
→ AI tự gọi:
  1. scaffold_devkit_project(type="WebResourceTs", name="Contoso.WebResource")
  2. scaffold_devkit_item(type="TsForm", entity="account", ...)
  3. scaffold_devkit_item(type="TsForm", entity="contact", ...)

# Hoặc gọi trực tiếp qua CLI Tool:
$ devkit tool call scaffold_devkit_item \
  --input '{"type":"Plugin","entity":"account","message":"Update","stage":"PreOperation"}'
09 / LỘ TRÌNH TRIỂN KHAI (PHASED ROADMAP)

Làm theo thứ tự nào để có kết quả nhanh nhất và ít rủi ro nhất?

Giai đoạn Hạng mục công việc Giá trị mang lại trên Mac / Linux Ước lượng công sức
Phase 1: Core Template Engine & T4 độc lập
(Nền tảng trong Shared + Cli)
  • Tách logic của Replacement.cs và T4Helper.cs từ VSIX sang DynamicsCrm.DevKit.Shared (hoặc Cli/Services/) không phụ thuộc EnvDTE.
  • Dùng Mono.TextTemplating để chạy toàn bộ 11 file Resources/tt/*.tt với T4Context.
  • Nhúng các file khung .csproj.template vào Shared/CLI resources.
 Chạy được toàn bộ logic sinh code Item & Project trên .NET 10 (Windows, macOS, Linux) mà không cần Visual Studio. 3 – 5 ngày
Phase 2: Mở giao diện CLI MCP + CLI Command
(Dùng được ngay trên Mac/Linux)
  • Thêm 3 MCP Tools: list_devkit_templates, scaffold_devkit_project, scaffold_devkit_item.
  • Thêm lệnh CLI devkit template (hoặc devkit new) với chế độ Interactive Spectre.Console + Flags.
  • Hỗ trợ sinh script đa nền tảng (.sh / npm scripts) bên cạnh .bat.
 Developer trên Mac/Linux tạo được mọi Project & Item Templates bằng cả Terminal Interactive, CLI Flags và AI Agents (MCP). 3 – 4 ngày
Phase 3: Thin VS Code Extension (Tùy chọn)
(Dành cho người thích bấm chuột GUI)
  • Tạo một VS Code Extension siêu nhẹ (TypeScript).
  • Menu chuột phải "DevKit: Add New Item..." / "DevKit: New Project...".
  • Sử dụng VS Code QuickPick để hỏi tham số và gọi xuống devkit tool call scaffold_devkit_item.
 Mang lại trải nghiệm click chuột phải trên cây thư mục VS Code giống hệt VSIX, nhưng tốn chỉ 1/5 công sức nhờ toàn bộ logic nằm ở CLI. 3 – 5 ngày
Tóm tắt câu trả lời cho bài toán của bạn:
  1. Bước 1 (Quan trọng nhất — Làm ngay): Đưa bộ tạo Item/Project Templates vào DevKit CLI + CLI MCP (vì cả hai nằm chung trong project DynamicsCrm.DevKit.Cli chạy .NET 10). Nhờ đó Mac và Linux có thể dùng ngay qua cả dòng lệnh tương tác (devkit new), lệnh tự động (devkit tool call) và AI Agent (devkit mcp).
  2. Bước 2 (Bổ sung khi cần GUI): Viết một VS Code Extension mỏng chỉ làm nhiệm vụ hiển thị QuickPick/Menu chuột phải và gọi xuống CLI ở Bước 1. Không bao giờ viết lại logic template bằng TypeScript.
