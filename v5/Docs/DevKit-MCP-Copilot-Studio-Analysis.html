Có thể port. DevKit hiện đã có phần nghiệp vụ MCP để tái sử dụng; cần bổ sung server HTTP và thiết kế lại vòng đời connection nếu phục vụ nhiều người dùng.

Trả lời trực tiếp: Hiểu “phải có HTTP endpoint” là đúng. Nhưng endpoint phải nói MCP Streamable HTTP, chứ một API REST nhận JSON bất kỳ hoặc một bước HTTP request trong flow chưa đủ. Với một Dataverse environment và application user cố định, việc làm bản thử nghiệm tương đối thuận lợi. Nếu mỗi người phải dùng đúng quyền Dataverse của mình, OAuth/OBO, DI scope và token isolation là phần việc chính.

1. “Setup MCP là một HTTP request” có đúng không?

Copilot Studio là MCP client. Nó cần một URL HTTPS có thể truy cập từ hạ tầng chạy connector. MCP server vẫn chạy ở backend do mình host; Copilot Studio không tải executable devkit trên máy developer rồi chạy process local.

Tài liệu Microsoft hiện ghi nhận Streamable HTTP; transport HTTP+SSE cũ đã ngừng được hỗ trợ sau tháng 08/2025. Đăng ký server qua wizard hoặc custom connector, với API key hoặc OAuth 2.0. [S1]

Hiện tại:
IDE / MCP client local ── stdin/stdout ── devkit mcp ── ServiceClient ── Dataverse

Khi đưa vào Copilot Studio:
Người chat ── Copilot Studio ── Power Platform MCP connector
                                     │ HTTPS / MCP
                                     ▼
                               DevKit HTTP host
                                     │ SDK / Web API
                                     ▼
                                 Dataverse

MCP mang JSON-RPC với quy trình khởi tạo, khám phá tool và gọi tool: ví dụ initialize, tools/list, tools/call. Một URL thường dùng là https://devkit.example.com/mcp. Streamable HTTP có thể trả JSON hoặc dùng SSE cho một response stream; điều này khác transport SSE cũ với endpoint tách riêng. Các chi tiết header, session, GET/POST và version negotiation nên để SDK xử lý. [S3]

Hai cách tích hợp khác nhau: nếu chọn MCP tool của Copilot Studio, ta cung cấp endpoint MCP và giữ khả năng khám phá tool. Nếu chọn REST API/custom action/HTTP trong flow, ta phải thiết kế API action riêng, và tự quản lý inputs, outputs, auth, lỗi. Cách REST có thể phù hợp cho vài thao tác nghiệp vụ cố định nhưng không phải port nguyên MCP hiện tại.

MCP trong Copilot Studio cần generative orchestration. Microsoft hiện mô tả hỗ trợ tools và resources; không nên mặc định prompts, roots, sampling hoặc mọi capability của desktop client đều dùng được. [S2]

4. Connection lưu ở đâu? Tách hai chặng xác thực

Connection A: Copilot Studio / connector → DevKit HTTP endpoint
  API key hoặc OAuth token cho DevKit API

Connection B: DevKit HTTP host → Dataverse
  Application user hoặc delegated token của người dùng

Hai connection này không tự trở thành một. Đăng nhập được vào agent hoặc DevKit endpoint chưa chứng minh SDK đã kết nối Dataverse dưới đúng identity.

Copilot Studio có Connection Settings để chọn/tạo connection và xem Connected, Expired, Stale. Nên mô tả chính xác rằng connection được quản lý qua Power Platform, không khẳng định “Copilot Studio tự lưu password”. Microsoft nêu Copilot Studio không lưu credentials trực tiếp. [S10] [S11]

Không lấy cách mã hóa legacy trong source làm vault cloud: Shared/Helper.cs dùng AES-CBC với passphrase và IV cố định trong code, auto-fallback về nguyên input khi decrypt lỗi. Đây là cơ chế tương thích hiện hữu, không cung cấp ranh giới bảo vệ secrets độc lập khỏi ứng dụng. 5. Phương án A: một application user cho một environment

Khuyến nghị cho PoC nội bộ: một host, một Dataverse environment, một application user chỉ có các quyền cần thử. Inbound có thể API key qua header để làm demo nhanh; production nên cân nhắc Entra OAuth để kiểm soát người truy cập endpoint. Dù inbound là per-user OAuth, downstream vẫn là application user nếu chọn kiến trúc A.

Copilot Studio ── X-DevKit-Key hoặc OAuth ── DevKit HTTP host
                                               │
                                URL + AppId + secret từ Key Vault
                                               ▼
                                Dataverse application user

Source ClientSecretConnectionBuilder đã tạo ServiceClient từ URL, ClientId, ClientSecret và TenantId khi có. Host mới phải resolve config/vault rồi tạo client qua factory; devkit mcp hiện không tự đọc những giá trị này từ environment.

Cần tạo application user trong Dataverse environment và gán security role. Microsoft cho phép chọn app registration hoặc Azure Managed Identity Application ID khi tạo application user. [S8]

Hệ quả: mọi người gọi tool đều nhận dữ liệu/quyền của application user. Backend biết người gọi MCP để audit/authorize, nhưng Dataverse không tự áp dụng quyền row-level của người chat. Đây là lựa chọn hợp lý cho tác vụ nội bộ có phạm vi dữ liệu được xác định; không phù hợp nếu yêu cầu “user A chỉ thấy records của A” mà chưa xây dựng lớp authorization tương ứng.

Có thể giữ client singleton trong một host identity cố định nếu không thay đổi CallerId/config giữa request và đã xác minh concurrency/lifecycle của SDK. Nếu cần nhiều environment, chọn process/deployment riêng hoặc pool được khóa theo profile + identity; không cho model cung cấp arbitrary URL + client secret.

Config minh họa cho HTTP host mới, không phải config CLI đã hỗ trợ

{
  "Dataverse": {
    "Url": "https://example.crm.dynamics.com",
    "TenantId": "<tenant-id>",
    "ClientId": "<application-id>",
    "ClientSecretReference": "<Key Vault secret reference>"
  },
  "McpPolicy": {
    "Category": "readonly",
    "MutationsBlocked": true
  }
}

Các key trong ví dụ là đề xuất mới. Registry phải validate HTTPS, exact allowed host, tenant và principal. API key không phải Dataverse client secret; ưu tiên header thay query để giảm lộ qua URL/access logs.

Managed identity có dùng được không?

Hai việc riêng: managed identity để đọc Key Vault, và managed identity/application identity để lấy Dataverse token. Việc đầu không làm việc sau tự hoạt động. DevKit connection registry hiện không có auth type ManagedIdentity; muốn dùng cần adapter lấy token cho Dataverse resource và application user/roles tương ứng. ServiceClient có constructor nhận token provider do caller quản lý. [S7]

6. Phương án B: dùng đúng quyền Dataverse của từng người

Khuyến nghị khi phát hành cho người dùng nghiệp vụ: user authentication tới DevKit API, sau đó DevKit backend dùng OBO lấy delegated token cho Dataverse.

User → Copilot Studio → connector → token A [audience = DevKit API]
                                            │ validate JWT + scope
                                            ▼
                                       DevKit backend
                                            │ OBO exchange tại Entra
                                            ▼
                                token B [audience = Dataverse]
                                            │ ServiceClient(token provider)
                                            ▼
                                  Dataverse quyền của user

Cần phân biệt connector OBO/SSO tới API và backend OBO tới Dataverse. Bật OBO trong connector không tự viết đoạn đổi token downstream trong DevKit. Token có audience DevKit không dùng trực tiếp để gọi Dataverse; API chỉ được đổi token dành cho chính mình trong OBO flow. [S6]

Thiết kế app registration: một service app đại diện DevKit API với delegated scope; connector app được cấp scope đó và callback URL; DevKit service app có delegated permission Dataverse phù hợp, consent và credential cho confidential client. Backend dùng MSAL/Microsoft.Identity.Web để acquire token cho https://<org>.crm.dynamics.com/.default với user assertion, sau đó cung cấp token callback cho ServiceClient. Scope .default không có nghĩa cấp mọi quyền; dựa trên permissions đã cấu hình và consent.

Tài liệu connector OBO yêu cầu cấu hình Entra, Resource URL, scope, Enable on-behalf-of login, redirect và chia sẻ connector cho end users. Có thể vẫn có consent “Allow”; không cam kết mọi kênh đều đăng nhập im lặng. [S5]

Thay đổi connection lifetime bắt buộc

  • Validate signature, issuer, audience, expiry và scopes trước tool execution. Claims đã validate quyết định identity; không dùng email/GUID do model truyền làm bằng chứng đăng nhập.
  • ServiceClient, MetadataService, connection info, Web API executor và execution context phải cùng một identity/environment scope. Không dùng singleton client của user A cho user B.
  • Thiết kế request/invocation scope theo cách SDK HTTP resolve services thực tế; nếu stateful session thì phải bind với identity. Transport session ID không phải credential.
  • Token cache dùng thư viện chuẩn, phân vùng tenant/account/resource, xử lý expiry/revocation; nếu cache phân tán phải bảo vệ cả dữ liệu và quyền truy cập. Không chỉ lưu token trong biến global hoặc bảng plaintext.
  • Không mutate CallerId trên singleton. Nếu dùng impersonation thay delegated token, clone/client riêng, mapping principal được verify và không fallback sang application identity khi thất bại.
  • Kiểm tra Web API code đọc CurrentAccessToken và worker Clone() trong create_records. Không mặc định token-provider client có hành vi clone giống ClientSecret client.

ServiceClient constructor nhận Func<string, Task<string>> được Microsoft khuyến nghị cho web applications/OBO; callback cần acquire/refresh on demand, không trả mãi một token đã hết hạn. [S7]

Giới hạn kênh cần kiểm tra sớm: user auth cho tools hỗ trợ Teams/custom website theo tài liệu, Demo Website không hỗ trợ; Teams có yêu cầu SSO riêng. Test thành công trong Studio chưa đủ cho kênh đã publish. [S11]

Vì sao --as-user, FromPac, DeviceCode không thay được mô hình này?

--as-user là server-side impersonation, cần quyền kết nối và mapping đáng tin cậy; không chứng minh user đã sign in. FromPac dựa vào profile/token local của PAC. Interactive/DeviceCode phù hợp người vận hành local nhưng không tạo connection per-user tự động ở cloud. Không dùng password OAuth legacy hoặc AD credentials như thiết kế mặc định cho agent cloud.

7. File local, schema và vận hành: các điểm dễ bỏ sót

7.1. Files không đi theo người chat

CreateRecordsTool đọc CSV/JSON path; ManageRecordFileTool đọc local path/URL/base64 và download ghi .devkit/manage_record_file, trả savedPath. Các tool form/view/chart/app/ribbon/role/webresource/report có nhánh backup/restore hoặc đọc file. GenerateDemoDataTool ghi .devkit/generate_demo_data. Một E:\... của laptop không tồn tại trên HTTP server.

Đề xuất PoC bắt đầu bằng tools dùng inline JSON/query, chưa mở local-file tools. Giai đoạn sau có artifact store và download endpoint có authorization/expiry, sandbox đường dẫn theo tenant/principal, chống traversal, giới hạn size và retention. URL upload cần kiểm soát SSRF và egress. Disk container tạm không nên là backup duy nhất.

Không âm thầm biến savedPath thành URL hoặc đổi temp-file convention của tool hiện tại. Tạo cloud adapter/resource riêng hoặc thay contract có chủ đích sau khi được yêu cầu; giữ stdio behavior. Nếu cloud cần field bổ sung, phải kiểm tra tương thích client/schema.

7.2. Tool schema và resources

Microsoft ghi nhận vấn đề với reference types, array of multiple types, enums và exclusiveMinimum. Lấy tools/list thực tế để kiểm tra input/output schema, nested DTO, $ref, nullable union và enum trước khi cho rằng cả 38 tools được discovery. Trang troubleshooting còn nhắc SSE dù trang onboarding đã ngừng hỗ trợ transport cũ; áp dụng hướng dẫn transport mới, dùng mục schema làm danh sách kiểm thử. [S9]

Không bỏ resources chỉ vì ví dụ HTTP đơn giản chỉ dùng tools. DevKit có hướng dẫn/schema hữu ích; kiểm tra resources/list/resources/read và cách orchestrator thực sự sử dụng. Metadata/resource không được tiết lộ environment của user khác.

7.3. HTTP session và scaling

SDK C# chính thức tách package ASP.NET Core để hỗ trợ HTTP transport. Nên bắt đầu stateless nếu không cần server-to-client requests/subscriptions, nhưng cần kiểm tra API/default của đúng version được chọn thay vì copy ví dụ main branch. Stateless transport không có nghĩa backend được bỏ phân quyền hay bỏ token cache. [S4]

Stateful mode cần lifecycle, session binding và phương án routing/storage khi nhiều replicas. Reverse proxy cần giữ Content-Type/Accept/MCP headers và streaming, không redirect sang trang HTML sign-in. Backend trả challenge/lỗi HTTP phù hợp thay vì form đăng nhập.

7.4. Thao tác dài và quyền ghi

Source connection có timeout tới một giờ, một số transfer có HttpClient timeout năm phút; những giá trị này không bảo đảm Copilot Studio chờ được lâu tương ứng. Đo timeout của đúng đường connector/channel. Query nên lấy trang nhỏ; bulk/publish dài có thể cần job + status nếu vượt budget thực tế.

Không retry mù khi create/update timeout: lệnh có thể đã thực hiện nhưng response bị mất. Cần idempotency/correlation và cách kiểm tra kết quả. ReadOnly/Destructive annotations giúp client hiểu tool, không thay Dataverse security hoặc backend authorization. Với agent rộng người dùng, chia deployment/profile và policy server-side; không chỉ dựa prompt “đừng xóa”.

8. Thiết kế port đề xuất cho repository này

Hướng ưu tiên: bổ sung entry HTTP bên cạnh stdio, giữ tools/resources và contracts. Có thể dùng nhánh HTTP trong CLI hoặc web host project riêng. PoC một identity có thể làm nhánh CLI nhanh; production nhiều identity hợp lý hơn với web host riêng và thư viện nghiệp vụ dùng chung. Việc tách thư viện cần cân nhắc Shared Project, internal access và assembly scanning.

  1. Tách “đăng ký MCP tool/resource + filter” khỏi “khởi động stdio process” với phạm vi nhỏ; giữ readonly/all, DisabledToolSet, ToolResourceMap và nameof.
  2. Thêm ModelContextProtocol.AspNetCore cùng phiên bản release compatible với ModelContextProtocol; Web SDK/framework reference phù hợp. Không đổi SDK/version chỉ để khớp ví dụ Internet.
  3. HTTP path dùng WebApplication, WithHttpTransport, MapMcp("/mcp"), authentication và authorization. Health/readiness không lộ secret hoặc dữ liệu organization.
  4. Connection factory cho HTTP lấy config/vault ở backend hoặc OBO identity. Không thay quy tắc explicit arguments của stdio khi chưa được yêu cầu.
  5. Nếu tools vẫn ở CLI assembly thì scan đúng assembly chứa tools; WithToolsFromAssembly() trên web assembly mới có thể bỏ sót. Filter hiện dùng Assembly.GetExecutingAssembly(), cần rà lại khi move code.
  6. ServerInstructions hiện chứa organization/environment cố định lúc startup. Với per-user/multi-environment cần xây context thích hợp hoặc dùng instructions chung và whoami để lấy context; không nhúng thông tin tenant khác.
  7. Không public mọi file/mutation tools trong lần thử đầu. Chỉ mở sau khi có storage isolation, schema compatibility và identity tests.

Khung minh họa, không phải patch có thể build ngay

// ASP.NET Core host mới; auth, factory, policy và filtering phải được implement.
var builder = WebApplication.CreateBuilder(args);

// Register HTTP authentication/authorization.
// Resolve Dataverse client per fixed application identity or per invocation user.
// Register all adapters, resources, policy and tool filters from DevKit.

builder.Services.AddMcpServer()
    .WithHttpTransport()
    .WithToolsFromAssembly(typeof(WhoAmITool).Assembly)
    .WithResourcesFromAssembly(typeof(WhoAmITool).Assembly);

var app = builder.Build();
app.UseAuthentication();
app.UseAuthorization();
app.MapMcp("/mcp").RequireAuthorization();
app.Run();

Ví dụ chỉ mô tả cấu trúc. Cần đối chiếu overload/session options với package 2.2.0 và DI thực tế, thêm factory/policy/filter. RequireAuthorization() không tự triển khai API key validation. Trong application-user PoC có thể reuse registration singleton hiện hữu; trong OBO không gọi nguyên RegisterSharedServices để bind client mọi người.

9. Cấu hình phía Copilot Studio

Sau khi endpoint hoạt động, dùng Tools → Add a tool → New tool → Model Context Protocol; nhập URL HTTPS, tên/mô tả, chọn authentication và tạo/chọn connection. Với OAuth manual, lấy callback URL để đăng ký. Custom connector có extension x-ms-agentic-protocol: mcp-streamable-1.0. DLP của Power Platform áp dụng cho connector/MCP. [S1]

Không mặc định Entra hỗ trợ DCR cho app này; manual OAuth/custom connector là hướng kiểm soát được khi chưa triển khai dynamic registration/discovery. Kết nối riêng cho DEV/UAT/PROD, tránh profile tự do do AI chọn. Connection reference trong solution được bind lại ở environment đích, không export credentials vào HTML/source.

Phải chọn rõ user authentication hay maker/agent-author credentials ở chặng connector. Dùng maker credentials có thể làm người chat truy cập với quyền của maker; admin có thể hạn chế chế độ này. [S13]

Ngay cả khi connector dùng user auth, kiến trúc A vẫn gọi Dataverse dưới application user. Kiến trúc B mới truyền quyền user xuống Dataverse qua delegated token. Ghi rõ lựa chọn này trong deployment và audit.

10. Lộ trình và ước lượng công sức

Đây là ước lượng kỹ thuật từ source, chưa phải cam kết tiến độ. Giả định một engineer quen .NET/Entra/Dataverse, có sẵn tenant, quyền cấu hình và hosting; không tính chờ admin, procurement hoặc chính sách tổ chức.

Đề xuất quyết định: nếu mục tiêu là agent kỹ thuật nội bộ, chọn A để xác minh khả năng tích hợp trước. Nếu mục tiêu phục vụ nhiều business users có quyền khác nhau, chọn B ngay ở thiết kế pilot; không dùng shared app identity rồi hứa sẽ tự có per-user permissions.

12. Có cần port nếu Microsoft đã có Dataverse MCP?

Microsoft có Dataverse MCP tích hợp vào Copilot Studio, cần environment cho phép client tương ứng và một Dataverse connection. Đây là lựa chọn nên thử nếu nhu cầu chủ yếu hỏi/tra cứu dữ liệu. [S15]

Reference hiện gắn nhãn preview, liệt kê query/search/fetch, CRUD record và table/schema tools. Không có đủ bằng chứng để kết luận thay thế mọi DevKit tool; danh sách reference không liệt kê toàn bộ form/ribbon/webresource/report/role và runtime diagnostics mà DevKit cung cấp. Tool names/parameters preview có thể thay đổi. [S14]
