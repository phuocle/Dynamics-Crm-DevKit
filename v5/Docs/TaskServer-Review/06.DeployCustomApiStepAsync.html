DeployCustomApiStepAsync · Bind/unbind handler của Custom API có sẵn

Giữ chức năng hiện có: gắn hoặc gỡ plug-in handler. Không thay đổi định nghĩa hay contract của API.

Snapshot: 6cc55c1d9f2913fed470c6f6f646356ab895cb2b · Source version 4.44.44.44 · Bắt đầu từ file 00 · Báo cáo gốc giữ nguyên

1. Phạm vi của một lượt làm việc

Hàm tìm customapi theo unique name trong cache. Activate gắn handler hoặc no-op; Deactivate chỉ gỡ khi API đang trỏ đúng type đang triển khai. Nếu đang trỏ type khác, hàm ghi DEACTIVATED nhưng không thay binding.

Trạng thái bằng chứng

Khi không tìm đúng một API, hàm log “deployment stopped” rồi return; caller vẫn có thể sang attribute/type tiếp theo. Tên test có chữ “Stops” chưa chứng minh toàn pipeline đã dừng. Cần seed ít nhất một type tiếp theo và kiểm tra request trace. Log DEACTIVATED khi không gỡ gì cũng cần xem có gây hiểu sai, nhưng không sửa binding theo log.

Chủ sở hữu: CLI. Shared/helpers, tests và wrapper được đọc để hiểu ảnh hưởng; việc đọc không có nghĩa phải sửa chúng. Đây là hồ sơ chuẩn bị cho lượt AI tiếp theo, không phải bản sửa đã áp dụng.

2. Những hành vi phải giữ nguyên

  • Không tạo API, request parameter hay response property; prerequisite API giữ nguyên.
  • Deactivate handler không có nghĩa vô hiệu hóa API; không hứa API ngừng callable.
  • Không tháo handler khác trong nhánh Deactivate.
  • Giữ no-op khi Activate cùng type.

Thay đổi hành vi chỉ chấp nhận trong case lỗi đã được xác định. Một điểm chưa hoàn chỉnh không tự động là lý do thay đổi contract đang dùng.

3. Cách phân tích và sửa nhỏ nhất

  1. Tạo fixture API missing/duplicate cùng một type hợp lệ phía sau để thấy chính xác continuation.
  2. Phối hợp file 05 cho failure propagation; tránh hai patch cùng đổi contract hàm theo hai cách.
  3. Nếu sửa log, mô tả “không có binding của type này để gỡ” mà không thay dữ liệu. Chỉ đổi message cần thiết và rà test liên quan.
Điều kiện hoàn thành

Binding của type khác được bảo toàn ở Deactivate, log và failure phản ánh đúng điều đã xảy ra; API contract giữ nguyên.

5. Điểm dễ làm hỏng phần đang chạy

Nhầm “Deactivate” của API handler với state của step dễ dẫn đến sửa sai cả semantics. File 12 có đường unregister khác và chưa kiểm tra ownership tương tự; đừng cho rằng hai hàm đã an toàn như nhau.

Liên quan: 05.RunAsync.html · 12.UnregisterPluginTypeAsync.html

Một patch nên có một root cause. Hồ sơ liên quan giúp kiểm tra ảnh hưởng, không phải yêu cầu kéo tất cả vào cùng lần sửa. Quyền triển khai hoặc thay đổi scope đến từ yêu cầu mới của người dùng.
