DeployPackageAsync · Existing package Id và các nhánh no-op

Tách lỗi Id của package khỏi bài toán versioning/signing. Chỉ sửa lỗi đã tái hiện trên nhánh hiện có.

BUG CÓ ĐIỀU KIỆN · B04 / F04CHƯA CHẠY TEST / CHƯA SỬA CODE
Snapshot: 6cc55c1d9f2913fed470c6f6f646356ab895cb2b · Source version 4.44.44.44 · Bắt đầu từ file 00 · Báo cáo gốc giữ nguyên

1. Phạm vi của một lượt làm việc

Hàm đọc nupkg, so content, create/update pluginpackage rồi bind managed identity nếu có. Biến PluginPackageId khởi tạo Guid.Empty; được gán ở create hoặc content-update, không được gán ở nhánh existing content bằng nhau.

Trạng thái bằng chứng

Nếu package đã tồn tại, content không đổi nhưng managed identity cần bind/rebind, request dùng PluginPackageId vẫn Empty. Đây là đường logic rõ; mức xảy ra qua entry point thật phụ thuộc signing có làm content đổi hay không. Cần test cả hàm và đường gọi phù hợp.

Chủ sở hữu: CLI. Shared/helpers, tests và wrapper được đọc để hiểu ảnh hưởng; việc đọc không có nghĩa phải sửa chúng. Đây là hồ sơ chuẩn bị cho lượt AI tiếp theo, không phải bản sửa đã áp dụng.

2. Những hành vi phải giữ nguyên

  • Giữ cách đặt package name, publisher prefix, content comparison và solution association.
  • Giữ no-op content: không upload lại toàn bộ package chỉ để tránh lỗi Id.
  • Giữ workflow package rejection và cách signing được gọi.
  • Không gộp thay đổi package version policy vào bản sửa existing Id.

Thay đổi hành vi chỉ chấp nhận trong case lỗi đã được xác định. Một điểm chưa hoàn chỉnh không tự động là lý do thay đổi contract đang dùng.

3. Cách phân tích và sửa nhỏ nhất

  1. Tái hiện existing package P, cùng content, identity cũ khác identity đích; mock kiểm tra Id của request bind.
  2. Xác định existing record Id ngay ở nhánh đã tìm được record; mọi request update/bind phải dùng đúng Id đó.
  3. Tách thành issue riêng nếu nhiều record trùng, package version đổi, DLL selection hoặc dependency resolution có lỗi.
Điều kiện hoàn thành

Nhánh no-op + rebind dùng existing Id, các nhánh còn lại giữ request semantics. Vấn đề version được ghi nhận riêng nếu chưa đủ bằng chứng.

5. Điểm dễ làm hỏng phần đang chạy

Tài liệu Microsoft nêu không đổi name/version của package sau khi tạo, trong khi code gửi version ở update. Không tự xóa/tạo lại package, ghim version hay đổi cách đặt tên để “sửa luôn”: các lựa chọn đó có thể ảnh hưởng type/step/solution dependencies.

Liên quan: 07.GetTypes.html · 09.DeployManagedIdentityAsync.html · 05.RunAsync.html

Một patch nên có một root cause. Hồ sơ liên quan giúp kiểm tra ảnh hưởng, không phải yêu cầu kéo tất cả vào cùng lần sửa. Quyền triển khai hoặc thay đổi scope đến từ yêu cầu mới của người dùng.
