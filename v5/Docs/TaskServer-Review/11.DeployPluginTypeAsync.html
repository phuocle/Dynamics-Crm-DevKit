DeployPluginTypeAsync · Type metadata và workflow activity

Tách xử lý type khỏi step để không sửa lỗi plug-in rồi làm hỏng workflow activity.

REVIEW · GIỮ HỢP ĐỒNG HIỆN TẠICHƯA CHẠY TEST / CHƯA SỬA CODE
Snapshot: 6cc55c1d9f2913fed470c6f6f646356ab895cb2b · Source version 4.44.44.44 · Bắt đầu từ file 00 · Báo cáo gốc giữ nguyên

1. Phạm vi của một lượt làm việc

Type lookup theo full name; DLL create/update metadata name, friendly name, description, workflow group. Với NuGet và type đã có, hàm no-op. DeployFileAsync bỏ qua step khi IsWorkflowType trả true.

Trạng thái bằng chứng

Cần kiểm chứng duplicate full type name giữa assembly, null/default metadata và no-op update. NuGet type no-op có thể liên quan ownership của package trên server; không đổi thành update giống DLL mà chưa hiểu quy tắc. Đây chủ yếu là vùng regression cần bảo vệ, không danh sách bug đã xác nhận.

Chủ sở hữu: CLI. Shared/helpers, tests và wrapper được đọc để hiểu ảnh hưởng; việc đọc không có nghĩa phải sửa chúng. Đây là hồ sơ chuẩn bị cho lượt AI tiếp theo, không phải bản sửa đã áp dụng.

2. Những hành vi phải giữ nguyên

  • Workflow vẫn đăng ký type mà không tạo sdkmessageprocessingstep thông thường.
  • Giữ FriendlyName/Description/GroupName và giá trị mặc định hiện có.
  • Giữ validation registered type bị bỏ khỏi assembly.
  • Không đổi signature input/output của CodeActivity hoặc hỗ trợ workflow trong NuGet.

Thay đổi hành vi chỉ chấp nhận trong case lỗi đã được xác định. Một điểm chưa hoàn chỉnh không tự động là lý do thay đổi contract đang dùng.

3. Cách phân tích và sửa nhỏ nhất

  1. Lập request snapshots có chọn lọc cho DLL plug-in, workflow type và NuGet existing type.
  2. Tái hiện case identity cùng file 08/13; nếu chung root cause thì sửa một nơi, không nhiều patch chồng nhau.
  3. Null/default metadata chỉ sửa khi có input thực được hỗ trợ dẫn đến lỗi; không chuẩn hóa toàn model Shared theo cảm tính.
Điều kiện hoàn thành

Chỉ bug type metadata/lookup đã chứng minh được sửa; workflow và NuGet behavior được giữ bằng regression liên quan.

5. Điểm dễ làm hỏng phần đang chạy

Workflow definitions có thể phụ thuộc type và activity arguments. Đổi tên/type identity hoặc tự xóa type có thể làm hỏng process đang dùng. Nếu phải động vào Shared model, phạm vi regression sẽ vượt CLI.

Liên quan: 07.GetTypes.html · 08.DeployAssemblyAsync.html · 12.UnregisterPluginTypeAsync.html · 13.LoadAllPluginTypesAsync.html

Một patch nên có một root cause. Hồ sơ liên quan giúp kiểm tra ảnh hưởng, không phải yêu cầu kéo tất cả vào cùng lần sửa. Quyền triển khai hoặc thay đổi scope đến từ yêu cầu mới của người dùng.
