# ✅ TOOL DESCRIPTION

```text
Manage Dataverse Power Fx functions — Custom APIs linked to an FxExpression. Actions: 'list', 'detail', 'validate' (read-only) | 'invoke' (executes the function; may change data; never retried automatically after timeout). Authoring actions ('create', 'update', 'delete') are gated: the public API cannot yet bind input parameters to the formula (the fxexpression.parameters serialization format is not a published contract), and deleting the Custom API orphans the expression — use the maker portal Functions area or solution ALM for authoring. 'invoke' passes arguments converted per the declared signature; unknown names, missing required inputs, and non-scalar types are rejected.

WHEN TO USE:
- Discover Power Fx functions and inspect formula, signature, binding, and compile state
- Invoke a resolved function with typed arguments and read the real outputs

RELATED TOOLS:
- get_custom_apis → every Custom API, with or without an expression
- get_solution_components → verify a function's solution membership
```

# PARAMETERS

```text
action          : string : 'list', 'detail', 'validate', 'invoke'. 'create'/'update'/'delete' are gated.
function_name   : string : Display name, unique name, or GUID (customapiid) of the Custom API. Required: detail/validate/invoke.
solution_name   : string : Unique/display name. 'list': filter by solution membership.
definition_json : string : 'validate' only: DevKit definition JSON to cross-check against metadata.
arguments_json  : string : 'invoke' only: JSON object of {"inputName": value} per the declared signature.
record_id       : string : 'invoke' only: record GUID for entity-bound functions (bindingtype=Entity).
max_records     : int    : 'list' only. ≤0 → 50, >500 → 500.
include_managed : bool   : 'list' only. Include managed (solution-imported) functions.
```

# RESULTS

- Test 1: list discovers the one org function — the Custom API row linked to an FxExpression.
- Test 2: solution filter is membership-based (solutioncomponent componenttype 10036) and finds the same function in `all_in_one`.
- Test 3: detail returns the full graph — formula, `compiledPresent`, raw `context` symbol table, declared output, and both graph IDs.
- Test 4: validate reports `status: "valid"` with `serverValidated: true` (platform-generated compiledexpression present) and zero issues.
- Test 5: an unknown key in definition_json makes validate return `status: "invalid"` with the issue listed — still a success result (`IsError: false`).
- Test 6: invoke executes the compiled formula and returns the declared output (`Total: 2`); `durationMs` is reported.
- Test 7-9: missing function_name, unknown GUID, and invalid action all return `IsError: true` with a `[Hint]` telling the caller what to pass.
- Test 10-12: create/update/delete are gated — each returns a specific reason (private parameters format, binding consistency, RemoveLink orphan) and points at the maker portal.
- Test 13: invoke rejects unknown argument names with the declared inputs listed.
- Test 14: invoke rejects malformed arguments_json with the parser diagnostic.
- Test 15: dry-run invoke returns the `[DryRun]` preview with `status: "not_executed"` and `invoked: false` — no Dataverse call is made.
