# ✅ TOOL DESCRIPTION

```text
Classic workflows (background async + realtime sync) for a Dataverse entity. workflow_id empty = list; set = detail. Classic only.

WHEN TO USE:
- Check if a field triggers any workflow (trigger_field + entity_name)
- Find synchronous workflows (mode='realtime'; Pre-op can cancel/rollback)
- Inspect workflow triggers and execution metadata before refactoring/disabling

For workflow and related server-logic inspection modes, read docs://server_logic_guide.

RELATED TOOLS:
- get_business_process_flows → BPF definitions + stages
- get_business_rules → client-side business rules
- get_flows → Power Automate cloud flows + run history
- get_system_jobs → workflow execution results (asyncoperation)
```

# PARAMETERS

```text
workflow_id  : string : GUID → detail. Empty = list.
entity_name  : string : Entity Display Name or logical name (e.g. 'Account' or 'account'). Empty = all.
mode         : string : 'background' / 'realtime'. Empty = both.
status       : string : 'active' / 'draft' / 'all'. Default: active.
trigger_field: string : Update trigger field Display Name or logical name when entity_name is set; otherwise contains filter.
name_filter  : string : Name contains. 1 match → auto-detail.
max_records  : int    : Max 250. Default 50.
```

# RESULTS

- Test 1: List all classic workflows on account returns 4 workflows (3 Activated + 1 Draft) with the counts block summarizing mode/onDemand/subprocess/state counts.
- Test 2: Detail mode by workflow_id returns the full entry plus the decompiled DSL: category, xamlParseStatus, workflowText, steps with assignment ASTs, dependencies, and parseIssues; the summary line ends with the XAML parse status.
- Test 3: trigger_field=statecode matches the 3 workflows whose triggerOnUpdateFields contains statecode; triggerField is echoed in structured output.
- Test 4: name_filter matching exactly one workflow auto-resolves to detail mode with the same DSL output shape as Test 2.
- Test 5: Invalid mode 'sync' returns an error listing the valid values background and realtime.
- Test 6: Nonexistent workflow_id returns a not-found error with a hint that only category=0 classic workflows and category=3 custom actions are visible.
- Test 7: Invalid status 'not-found' returns an error listing the valid values active, draft, all.
- Test 8: Non-GUID workflow_id returns an error with a hint to take an ID from list mode.
- Test 9: Nonexistent entity_name returns a not-found error with a hint to use get_tables.
- Test 10: Ambiguous entity_name Product returns a one-line error, a retry hint, and the 3 matching entities in the [Detail] JSON as entityMatches.
- Test 11: Nonexistent trigger_field on account returns a not-found error with a hint to list attributes via get_tables.
