# ✅ TOOL DESCRIPTION

```text
Publish Dataverse customizations. Pass at least one target (entities/optionset_names/dashboards/webresources/appmodules/include_ribbons/include_sitemap/include_global_optionset) for targeted PublishXml; pass nothing for PublishAll (async, org-wide lock).

WHEN TO USE:
- After metadata mutations with auto_publish=false, or when changes are not showing up
- Batch many changes then publish once at the end

RELATED TOOLS:
- get_system_jobs → track PublishAll async operation status
- get_tables / manage_app / manage_webresource → discover valid target identifiers
```

# PARAMETERS

```text
entities                 : string : Comma-separated entity Display Names or logical names (e.g. 'Account,contact'). Empty with no other targets = PublishAll.
optionset_names          : string : Comma-separated global option set unique names (e.g. 'new_priority,new_status'). Use instead of include_global_optionset for targeted publish.
include_ribbons          : bool   : Publish the application (global) ribbon. Entity-level ribbons are covered by 'entities'. Default false.
dashboards               : string : Comma-separated system-form (dashboard) GUIDs to publish.
webresources             : string : Comma-separated web resource GUIDs or logical names to publish.
include_global_optionset : bool   : Publish ALL global option sets at once. Prefer optionset_names for targeted publish. Default false.
include_sitemap          : bool   : Also publish sitemap. Default false.
appmodules               : string : Comma-separated appmodule GUIDs, Display Names, or unique names for model-driven apps.
```

# RESULTS

- Test 1: targeted publish of entity `all_testfile` succeeds in 25.4s with `mode: specific` and `entityCount: 1`.
- Test 2: no parameters triggers PublishAll — returns `all_async`/`in_progress` with an AsyncOperationId; get_system_jobs shows the PublishAllXml job In Progress/Locked, then Succeeded in 1m 15s.
- Test 3: web resource + sitemap targeted publish succeeds after the lock is released (23.9s).
- Test 4: application ribbon publish via `include_ribbons: true` succeeds in 48.5s.
- Test 5: nonexistent entity name fails with a friendly resolver message plus a single `[Hint]` pointing at `get_tables`.
- Test 6: invalid dashboard GUID fails validation with a friendly `[Hint]` showing the expected GUID format and where to find valid dashboard IDs.
- Test 7: targeted publish while the PublishAll org-wide lock is held is rejected by Dataverse and returned as `[Error]` with `status: failed` — correct server behavior, retry succeeds once the lock is released.
- Test 8: nonexistent web resource logical name fails with a friendly `[Hint]` pointing at `manage_webresource(action='list')`.
- Test 9: dry-run preview of PublishAll (no targets) returns `mode: all_async`, `status: not_executed`, `durationSeconds: 0` and a `[DryRun] Would PUBLISH ALL customizations.` summary; nothing is sent to Dataverse.
- Test 10: dry-run preview of a targeted entity publish returns `mode: specific`, `entityCount: 1`, `status: not_executed` and a `[DryRun] Would PUBLISH 1 entity: all_testfile.` summary; nothing is sent to Dataverse.
