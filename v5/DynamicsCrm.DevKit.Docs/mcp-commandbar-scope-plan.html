DevKit MCP Command Bar (manage_command / appaction) — Nghiên cứu & Kế hoạch mở rộng tầm vực Entity / App / Global

Ngày: 2026-11-23 · Thành phần: DynamicsCrm.DevKit.Cli/Mcp/Tools/ManageCommandTool.cs & Tools/Command/* · Đối tượng: Modern Command Bar (appaction) — không phải Classic Ribbon (RibbonDiffXml) · Trạng thái: Bản nghiên cứu & Kế hoạch thiết kế (Plan)

TL;DR — Kết quả nghiên cứu & Đề xuất:

1. Xác nhận từ tài liệu Microsoft Dataverse: Bảng appaction (Modern Command Bar) hỗ trợ đầy đủ 4 tầm vực (Command Scopes) thông qua tổ hợp 2 cột context (0 = All, 1 = Entity) và appmoduleid (Guid của Model-Driven App hoặc null):
  • App + Entity Scope (context=1, appmoduleid!=null): Nút chỉ hiện trên 1 bảng trong 1 App cụ thể. (Hiện tại manage_command chỉ mới hỗ trợ tầm vực này).
  • App-Level Scope (context=0, appmoduleid!=null): Nút gắn với 1 App nhưng không gắn bảng (contextentity=null, contextvalue=null) — dùng cho global_header, dashboard của App đó, hoặc hiện trên mọi bảng trong App đó.
  • Entity / Table Scope (All Apps) (context=1, appmoduleid=null): Nút gắn với 1 bảng cụ thể nhưng không gắn App — tự động xuất hiện trên bảng đó ở tất cả các Model-Driven Apps trong toàn Environment.
  • Global Scope (All Apps & All Entities) (context=0, appmoduleid=null): Nút không gắn bảng và không gắn App — xuất hiện ở location chỉ định (vd: global_header, dashboard, form, main_grid...) trên mọi bảng và mọi App trong toàn Environment.
2. Nguyên nhân manage_command hiện tại bị giới hạn: Code trong CommandCreateUpdate.cs, CommandFlyout.cs, CommandHideShow.cs đang bắt buộc cả entity_name lẫn app_id/app_name, hardcode context = OptionSetValue(1), suy diễn publisherPrefix từ entity_name, và gọi PublishHelper.PublishEntity(contextvalue) (sẽ gây NullReferenceException nếu contextvalue == null).

3. Giải pháp đề xuất: Không cần tách tool mới; giữ nguyên tool manage_command và mở rộng linh hoạt theo sự hiện diện của entity_name và app_id/app_name (hoặc tham số tùy chọn scope), đồng thời bổ sung thông tin scope / context vào kết quả trả về của list & detail.

1. Nghiên cứu tài liệu Microsoft Dataverse: Bảng appaction & Command Scopes

1.1 Kiến trúc lưu trữ Modern Command Bar (appaction)

Khác với Classic Ribbon (lưu dưới dạng XML nén trong RibbonDiffXml của từng Entity hoặc Application Ribbon), Modern Commanding lưu từng nút lệnh (Standard Button, Dropdown Flyout, Split Button, Group) thành một bản ghi độc lập trong bảng hệ thống appaction (và các rule classic liên kết qua bảng appactionrule).

Theo tài liệu chính thức của Microsoft Learn (Modern commanding overview — Command scope và appaction EntityType reference), phạm vi hiển thị (Scope) của một bản ghi appaction được quyết định bởi các cột sau:

Cột trên bảng appaction Kiểu dữ liệu Giá trị & Ý nghĩa trong Dataverse
context OptionSetValue (Choice)
  • 0 = All: Không gắn với một bảng cụ thể (áp dụng cho mọi bảng hoặc cho các vùng không thuộc bảng như GlobalHeader, Dashboard).
  • 1 = Entity: Gắn trực tiếp với một bảng Dataverse cụ thể.
contextentity EntityReference("entity", Guid)
  • Khi context = 1: Trỏ tới MetadataId (entityid) của bảng đích.
  • Khi context = 0: Phải để null.
contextvalue string
  • Khi context = 1: Tên logical của bảng đích (ví dụ: "account", "all_testform").
  • Khi context = 0: Phải để null (hoặc không set).
appmoduleid EntityReference("appmodule", Guid)
  • Khi có giá trị (!= null): Command chỉ có hiệu lực bên trong Model-Driven App được trỏ tới.
  • Khi để null: Command có hiệu lực trên tất cả các Model-Driven Apps trong toàn Environment.
location OptionSetValue (Choice) Vị trí hiển thị trên giao diện (bắt buộc ở mọi Scope):
  • 0 = Form (Main Form command bar)
  • 1 = MainGrid (Main Grid / HomepageGrid command bar)
  • 2 = SubGrid (Subgrid view command bar)
  • 3 = AssociatedGrid (Associated view command bar)
  • 4 = QuickForm (Quick Form command bar)
  • 5 = GlobalHeader (Thanh Header toàn cục góc trên ứng dụng)
  • 6 = Dashboard (Thanh command bar trên trang Dashboard)
uniquename string Định danh duy nhất dùng khi đóng gói Solution (không được trùng trong cùng org, lỗi 0x80072013 nếu trùng).

1.2 Tại sao Power Apps Command Designer UI bị hạn chế nhưng Dataverse SDK làm được trực tiếp?

Điểm mạnh vượt trội khi hỗ trợ qua DevKit MCP:
Trong giao diện kéo thả của Microsoft (Power Apps Modern Command Designer), khi người dùng bấm "Edit command bar", giao diện của Microsoft chỉ cho phép tạo nút ở tầm vực hẹp nhất là App + Entity Scope (context = 1 + appmoduleid != null). Để tạo nút ở tầm vực Table Scope (mọi App), App Scope (mọi Table / Global Header) hoặc Global Scope (mọi App & mọi Table), tài liệu Microsoft hướng dẫn developer phải export unmanaged solution ra file zip, giải nén, mở appaction.xml bằng tay để xóa node <appmoduleid> và sửa <context>0</context> rồi zip lại import vào!

Tuy nhiên, ở tầng Dataverse OrganizationService SDK (IOrganizationService.Create / Update), bảng appaction cho phép tạo và cập nhật trực tiếp bản ghi với context = 0 và/hoặc appmoduleid = null ngay lập tức mà không cần tháo lắp solution XML!

1.3 Lưu ý quan trọng từ Microsoft về Power Fx vs JavaScript ở tầm vực Global / Table

Ràng buộc của Power Fx Component Library:
  • Các command dùng JavaScript (onclick_type = "javascript") hoặc None (onclick_type = "none", vd: container Flyout Dropdown, Group) hoạt động hoàn hảo ở cả 4 tầm vực (App+Entity, App-Global, Entity-AllApps, Global).
  • Các command dùng Power Fx Formula (onclick_type = "formula") trong kiến trúc của Microsoft thực chất lưu công thức trong một Command Component Library gắn với một App cụ thể. Do đó Microsoft khuyến nghị các nút ở tầm vực Entity (All Apps) và Global (All Apps) nên sử dụng javascript hoặc none.

3. Ma trận 4 Tầm vực (Scopes) & Quy tắc location / uniquename / publish

3.1 Ma trận 4 Tầm vực (Command Scopes)

Ta định nghĩa rõ 4 tầm vực chuẩn dựa trên sự kết hợp của entity_name và app_id / app_name:

Tên Scope (scope) Điều kiện tham số đầu vào context contextentity & contextvalue appmoduleid Ý nghĩa & Trường hợp sử dụng thực tế
1. app_entity
Đã có		 Có entity_name
+ Có app_id/app_name		 1 (Entity) Có (trỏ tới Entity) Có (trỏ tới App) Nút chỉ xuất hiện trên bảng X bên trong ứng dụng Y (mặc định của Power Apps Command Designer).
2. app
Mới — App Level		 Không có entity_name
+ Có app_id/app_name		 0 (All) null Có (trỏ tới App)
  • Nút trên global_header hoặc dashboard của riêng ứng dụng Y.
  • Hoặc nút trên form / main_grid / sub_grid áp dụng cho tất cả các bảng bên trong ứng dụng Y.
3. entity
Mới — Table Level		 Có entity_name
+ Không có app_id/app_name		 1 (Entity) Có (trỏ tới Entity) null Nút gắn với bảng X và tự động xuất hiện trên bảng X ở tất cả mọi Model-Driven Apps trong toàn Environment.
4. global
Mới — Global Level		 Không có entity_name
+ Không có app_id/app_name		 0 (All) null null
  • Nút trên global_header hoặc dashboard của toàn bộ các ứng dụng trong Environment.
  • Hoặc nút chung trên form / main_grid... xuất hiện trên mọi bảng của mọi ứng dụng trong Environment.

3.2 Quy tắc sinh name và uniquename theo Scope

Để đảm bảo tính nhất quán 100% với các test hiện hành khi ở tầm vực app_entity và không bao giờ xung đột uniquename ở các tầm vực mới:

Scope {entitySegment} {appSegment} Mẫu name Mẫu uniquename
app_entity (giữ nguyên) {entityLogical} {appUniqueName} {prefix}.{entityLogical}.{safeLabel}.{locPrefix}.{Kind} {prefix}__{name}!{appUniqueName}!{entityLogical}!{locationValue}
app (App-Level) all {appUniqueName} {prefix}.all.{safeLabel}.{locPrefix}.{Kind} {prefix}__{name}!{appUniqueName}!all!{locationValue}
entity (Entity / All Apps) {entityLogical} global {prefix}.{entityLogical}.{safeLabel}.{locPrefix}.{Kind} {prefix}__{name}!global!{entityLogical}!{locationValue}
global (Environment Global) all global {prefix}.all.{safeLabel}.{locPrefix}.{Kind} {prefix}__{name}!global!all!{locationValue}

Trong đó {Kind} là Button, Dropdown, Split, hoặc Group (và {flyoutSafeLabel}.{locPrefix}.{safeItemLabel}.Button cho flyout item).

3.3 Quy tắc tìm {prefix} (Publisher Prefix) khi không có entity_name

private string ResolvePublisherPrefix(string entityLogicalName, string appUniqueName = null)
{
    // 1. Ưu tiên lấy prefix từ entityLogicalName nếu có (vd: "all_testform" → "all")
    if (!string.IsNullOrWhiteSpace(entityLogicalName))
    {
        var idx = entityLogicalName.IndexOf('_');
        if (idx > 0) return entityLogicalName.Substring(0, idx);
    }
    // 2. Nếu không có entity (hoặc entity OOB như "account"), lấy từ appUniqueName nếu có (vd: "all_ALLINONE" → "all")
    if (!string.IsNullOrWhiteSpace(appUniqueName))
    {
        var idx = appUniqueName.IndexOf('_');
        if (idx > 0) return appUniqueName.Substring(0, idx);
    }
    // 3. Fallback chuẩn
    return "devkit";
}

3.4 Chiến lược Auto-Publish theo Scope (Tránh NullReferenceException & Đảm bảo hiệu lực ngay)

Tạo một helper dùng chung PublishCommandScope(string entityLogicalName, Guid? appModuleId) trong CommandHelpers.cs:

Scope của Command Có entityLogicalName? Có appModuleId? Hành động Publish được gọi
app_entity Có Có PublishHelper.PublishEntity(_context, _orgService, entityLogicalName) (giữ nguyên hành vi hiện tại, nhanh ~2–5s).
entity Có Không (null) PublishHelper.PublishEntity(_context, _orgService, entityLogicalName).
app Không (null) Có PublishHelper.PublishAppModule(_context, _orgService, appModuleId.Value) (publish trực tiếp AppModule đó qua <appmodules>).
global Không (null) Không (null) PublishHelper.PublishRibbon(_context, _orgService) (publish application ribbons / global command bar mà không tốn thời gian PublishAll toàn bộ org).

4. Thiết kế thay đổi trên MCP Tool manage_command

4.1 Phương án tham số: Bổ sung tham số scope hay tự suy luận từ entity_name & app_id/app_name?

Khuyến nghị thiết kế (An toàn + Tường minh cho cả AI lẫn Developer):

Hỗ trợ tham số tùy chọn scope ("" | "app_entity" | "app" | "entity" | "global") dùng cho cả Create / Add Flyout / Add Split Button và dùng làm bộ lọc trong List:
  • Khi scope để trống (mặc định) hoặc "app_entity": Giữ nguyên validation bắt buộc cả entity_name và app_id/app_name như hiện tại → 100% backward-compatible với toàn bộ unit tests và tránh trường hợp AI quên truyền app_name hoặc entity_name rồi vô tình tạo nhầm nút Global!
  • Khi scope = "app": Bắt buộc app_id hoặc app_name; không dùng entity_name (nếu truyền entity_name thì báo lỗi hướng dẫn dùng scope='app_entity'). Tạo command với context = 0 (All) và appmoduleid = resolvedAppId.
  • Khi scope = "entity": Bắt buộc entity_name; không dùng app_id/app_name. Tạo command với context = 1 (Entity), contextentity, contextvalue, và appmoduleid = null (áp dụng cho bảng đó trên mọi App).
  • Khi scope = "global": Không cần entity_name và không cần app_id/app_name. Tạo command với context = 0 (All) và appmoduleid = null (áp dụng toàn bộ Environment).
  • Trong action = "list": Nếu truyền scope ("app_entity", "app", "entity", "global"), filter FetchXML sẽ lọc đúng các bản ghi thuộc tầm vực đó (ví dụ scope="global" lọc context = 0 và appmoduleid null).

5. Chi tiết kỹ thuật theo từng file trong DynamicsCrm.DevKit.Cli

File Thay đổi chi tiết
Mcp/Tools/Models/CommandEntry.cs
  • Thêm property Context ([JsonPropertyName("context")]: "Entity" hoặc "All").
  • Thêm property Scope ([JsonPropertyName("scope")]: "AppEntity", "App", "Entity", "Global").

  • Thêm dictionary ContextMap (0 → "All", 1 → "Entity") và ScopeFilterMap ("app_entity", "app", "entity", "global").
  • Thêm tham số tùy chọn string scope = "" vào InvokeAsync và manage_command, cập nhật Description của tool & các tham số entity_name, app_id, scope.

  • Thêm helper ResolveCommandScope(...): kiểm tra tính hợp lệ của scope, entity_name, app_id/app_name và trả về bộ giá trị đã chuẩn hóa: (int ContextValue, string EntityLogical, Guid? EntityId, Guid? AppModuleId, string AppUniqueName, string PublisherPrefix, string ScopeLabel, string ErrorMessage, string ErrorHint).
  • Thêm helper PublishCommandTarget(string entityLogical, Guid? appModuleId): tự động chọn PublishEntity, PublishAppModule, hoặc PublishRibbon tùy theo entityLogical và appModuleId.
  • Cập nhật CreateFlyoutItem để nhận int contextType, Guid? appModuleId (nullable) và string entityLogical (nullable).
  • Cập nhật MapCommandEntry để đọc context vàappmoduleid, gán entry.Context và entry.Scope.
Mcp/Tools/Command/CommandCreateUpdate.cs
  • HandleCreate: Dùng ResolveCommandScope để hỗ trợ tạo command ở cả 4 tầm vực (app_entity, app, entity, global); gọi PublishCommandTarget.
  • HandleUpdate: Truy vấn thêm cột appmoduleid bên cạnh contextvalue; gọi PublishCommandTarget thay vì gọi cứng PublishEntity(contextvalue.Trim()) để không bị lỗi khi update command ở tầm vực app hoặc global.
Mcp/Tools/Command/CommandFlyout.cs
  • HandleAddFlyout & HandleAddSplitButton: Dùng ResolveCommandScope để cho phép tạo Dropdown Flyout và Split Button ở cả 4 tầm vực.
  • HandleAddFlyoutItem: Không còn báo lỗi khi appModuleRef == null (tầm vực entity hoặc global) hoặc khi contextvalue rỗng (tầm vực app hoặc global); kế thừa chính xác context, contextvalue, contextentity, appmoduleid từ Flyout/Split cha xuống Group và Item con.
Mcp/Tools/Command/CommandHideShow.cs
  • Khi truyền command_id: Truy vấn thêm appmoduleid và dùng PublishCommandTarget để có thể hide/show các command ở tầm vực app và global mà không bị NullReferenceException.
  • Mở rộng ResolvePublisherPrefix(string entityLogicalName, string appUniqueName = null).
Mcp/Tools/Command/CommandListDetail.cs
  • Bổ sung <attribute name='context'/> vào FetchXML của GetList.
  • Hỗ trợ lọc theo scope trong HandleList / GetList:
    • scope = "app_entity" → context = 1 AND appmoduleid not-null
    • scope = "app" → context = 0 AND appmoduleid not-null
    • scope = "entity" → context = 1 AND appmoduleid null
    • scope = "global" → context = 0 AND appmoduleid null

7. Câu hỏi thiết kế cần chốt trước khi triển khai code

3 điểm cần anh xác nhận để bắt đầu code:
  1. Cơ chế chọn tầm vực (scope parameter): Anh đồng ý thêm tham số tùy chọn scope (app_entity | app | entity | global, mặc định khi bỏ trống là app_entity cho create/add_flyout/add_split_button để không phá vỡ backward-compatibility), hay anh muốn tool tự động suy luận (auto-infer) luôn từ việc có/không có entity_name và app_id/app_name mà không bắt truyền scope? (Hoặc kết hợp: có thể truyền scope tường minh HOẶC tự suy luận nếu bỏ trống?)
  2. Phạm vi các action áp dụng tầm vực App / Global: Ngoài create, update, list, detail, hide, show, anh có muốn mở rộng luôn cho cả bộ add_flyout, add_split_button, add_flyout_item ở tầm vực app, entity, global trong cùng đợt này không? (Khuyến nghị: Có, vì logic dùng chung ResolveCommandScope rất gọn).
  3. Xử lý onclick_type = "formula" ở tầm vực global / entity (không gắn App): Khi không có app_id/app_name, anh muốn cho phép tạo bình thường hay chặn/cảnh báo nếu onclick_type = "formula"?
