DevKit MCP — Quy ước ghi/đọc file trong .devkit/

Trang này mô tả toàn bộ cách các MCP tool của DynamicsCrm.DevKit ghi file xuống đĩa và đọc lại file đó. Ví dụ dùng workspace_folder = D:\github\Dynamics-Crm-DevKit\v5 (folder A — workspace đang mở trong editor, KHÔNG phải folder cài devkit CLI).

Quy ước chung (v5.5):
  • Backup tools: {workspace_folder}\.devkit\{tool_name}\{entity}\ — file backup nằm trực tiếp trong folder entity, KHÔNG có level backups\. manage_app dùng {appName} thay {entity}.
  • Output tools (flat): .devkit\search_records\, .devkit\generate_demo_data\{entity}\.
  • manage_record_file: .devkit\manage_record_file\{entity}\{record}\ (output chính của download, không phải backup).
  • Backup LUÔN chạy trước mutate (không còn param backup); dry-run KHÔNG ghi backup (không đổi gì thì không cần backup).
  • workspace_folder bắt buộc cho mọi action ghi file; không có CWD fallback.
  • Đường dẫn file chỉ nằm trong DTO (structured content) — text summary chỉ nói "Backup saved." / "(see filePath)".
  • Extension theo nội dung: XML thuần → .xml; envelope có metadata → .json.
  • Timestamp chuẩn mọi tool: yyyyMMddHHmmss.

manage_form — systemform

Chi tiết
GHIBackup FormXML hiện tại trước khi update/rename (sau DryRun check). File JSON envelope: {entity, formId, formName, timestamp, formxml}
FolderD:\github\Dynamics-Crm-DevKit\v5\.devkit\manage_form\{entity}\
Tên file{entity}_{formId:N}_{yyyyMMddHHmmss}.formxml.json
ĐỌCaction='undo' — truyền path backup vào param formxml (auto-detect file .formxml.json, lấy field formxml). Undo KHÔNG backup (restore thuần).

Ghi chú bổ sung

  • Dry-run KHÔNG ghi backup: dry-run không thay đổi gì nên không cần backup — backup chỉ chạy ngay trước bước mutate thật (DTO dry-run trả status='not_executed', không có path).
  • Timestamp chuẩn: mọi tool dùng yyyyMMddHHmmss (không milliseconds).
  • Extension = loại nội dung: file chứa XML thuần → .xml (view: .fetchxml.xml/.layoutxml.xml — editor highlight ngay); file envelope có metadata → .json (form/chart/app/ribbon, payload XML nằm trong field bên trong).
  • workspace_folder = folder A (folder đang mở trong VS Code), KHÔNG phải folder cài devkit CLI (folder B). Truyền sai → backup rơi vào folder B.
  • Không còn CWD fallback: thiếu workspace_folder → tool trả Error + Hint, không silently ghi vào current directory.
  • Không tool nào tự dọn backup cũ — folder entity lớn dần theo thời gian, dọn tay khi cần.
