# MCP Tool: get_audit_histories

## Tool #9 — Security & Audit

## Status: IMPLEMENTED

## Purpose

Retrieve audit history for Dataverse records. Two modes: browse mode (entity-wide/cross-entity summary) and detail mode (field-level old/new values for a single record).

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| entity_name | string | No | `""` | Entity logical name. Required in detail mode. Optional in browse mode. |
| record_id | string | No | `""` | Record GUID. Empty = browse mode. Provided = detail mode. |
| minutes_ago | int | No | `1440` | Return entries from last N minutes (max 43200 = 30 days). Ignored when from_date is set. |
| from_date | string | No | `""` | ISO 8601 start date (e.g., `2026-03-01`). Overrides minutes_ago. |
| to_date | string | No | `""` | ISO 8601 end date. Used with from_date. Defaults to now. |
| user_filter | string | No | `""` | Filter by user display name (contains) or email address (auto-resolved). |
| operation | string | No | `""` | Filter by: Create, Update, Delete, Activate, Deactivate, Assign, Merge, Cascade, SetState |
| attribute_name | string | No | `""` | Detail mode only. Show changes for a specific field. |
| max_records | int | No | `50` | Maximum entries to return (max 500). |

## Returns

- Detail mode (record_id provided): audit entries with timestamp, user, action, field, old value, new value
- Browse mode (record_id empty): summary table with timestamp, user, entity, record, action, operation

## When to Use

- When a user asks "who changed this field?" or "when was this record modified?"
- To debug unexpected data changes (e.g., integration overwriting values)
- For compliance auditing (GDPR, SOX data change trails)
- To find all changes to an entity ("what changed on any account today?")
- To audit deleted records ("show all deleted accounts this week")
- To track user activity across entities

## Tips

- Audit must be enabled at organization level AND entity level — use `whoami` to check org-level
- Use `from_date`/`to_date` for specific date ranges instead of `minutes_ago`
- User filter supports email addresses — auto-resolves to display name via systemuser lookup
- Browse mode with both entity_name and record_id empty = full system audit
- Real data: "Phước Lê Văn" has recent audit entries on "Fourth Coffee 4" account
