# MCP Tool: upsert_attribute

## Tool — Schema Management

## Status: IMPLEMENTED

## Purpose

Create a new column or update an existing column (attribute) on a Dataverse entity. Automatically detects whether the attribute exists: creates if new, updates if existing.

**Create mode**: Supports all common types: string, memo, integer, bigint, decimal, money, float, boolean, datetime, lookup, customer, picklist, multipicklist, image, file.

**Update mode**: Supports modifying display properties (name, description, required level), type-specific properties (max length, value ranges, precision, format, boolean labels), and picklist option management (add/rename/remove).

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| entity_name | string | Yes | — | Entity logical name (e.g., `account`) |
| attribute_name | string | Yes | — | Logical name with publisher prefix (e.g., `v4_priority`) |
| attribute_type | string | Create only | — | Type: `string`, `memo`, `integer`, `bigint`, `decimal`, `money`, `float` (or `double`), `boolean`, `datetime`, `lookup`, `customer`, `picklist`, `multipicklist`, `image`, `file`. Ignored on update. |
| display_name | string | Create only | `""` | Display name shown in forms. Required for create. |
| description | string | No | `""` | Column description |
| required_level | string | No | `""` | `None`, `Recommended`, or `Required`. Omit to keep current value on update. |
| max_length | int | No | `0` | For string: max chars (1-4000). For memo: (1-1048576). For file: max KB. |
| min_value | number | No | — | For numeric types: minimum value |
| max_value | number | No | — | For numeric types: maximum value |
| precision | int | No | `-1` | For decimal/money/float: decimal places (0-10, default 2 on create). Omit to keep current value on update. |
| format | string | No | — | For string: `Text`, `Email`, `Url`, `Phone`, `TextArea`, `RichText`. For datetime: `DateOnly`, `DateAndTime`. |
| options | string | No | — | For picklist (create): JSON array `[{"label":"Low","value":100000000}]` |
| global_optionset_name | string | No | — | For picklist (create): reuse existing global option set |
| lookup_target | string | No | — | For lookup (create): target entity (e.g., `contact`) |
| lookup_relationship_name | string | No | auto | For lookup (create): relationship schema name |
| true_label | string | No | `""` | For boolean: true label (default `Yes` on create). Omit to keep current value on update. |
| false_label | string | No | `""` | For boolean: false label (default `No` on create). Omit to keep current value on update. |
| add_options | string | No | `""` | For picklist (update): JSON array of options to add |
| update_options | string | No | `""` | For picklist (update): JSON array of options to rename |
| delete_options | string | No | `""` | For picklist (update): JSON array of integer values to remove |
| is_audit_enabled | bool | No | `null` | Enable/disable auditing (update only) |
| is_valid_for_advanced_find | bool | No | `null` | Show/hide in Advanced Find (update only) |
| solution_name | string | No | `""` | Add column to this solution |
| auto_publish | bool | No | `true` | Publish after operation |

## Returns

**Create mode:**
- Created attribute details: name, type, MetadataId
- Options (for picklist), target (for lookup)
- Solution and publish status

**Update mode:**
- Updated attribute details with before/after values for changed properties
- Picklist option changes (added/renamed/deleted)
- Publish status

## When to Use

- To add a new field to an entity (create)
- After creating a new entity with `upsert_entity` (create)
- To rename a column's display name (update)
- To change required level (update)
- To expand a string field's max length (update)
- To add/rename/remove picklist options (update)
- To change boolean Yes/No labels (update)

## Tips

- Attribute name MUST include publisher prefix (e.g., `v4_`, `new_`)
- Use `get_metadata_entities` to check if attribute exists
- For lookups, the 1:N relationship is created automatically (create mode)
- For picklist with existing choices, use `global_optionset_name` instead of `options`
- After creation, use `build_formxml` to add the new field to a form
- Cannot change attribute type after creation — Dataverse limitation
- Only provide parameters you want to change (update mode) — omitted params keep current values

## Adversarial Review

> Tested against live environment `DEVKITV4` on 2026-04-05. Test data: `v4_test_mcp` entity (29 custom attributes covering all types) and `account` entity (16 custom v4_ attributes).

### Finding 1 — FIXED: required_level default silently resets Required/Recommended fields

| Item | Detail |
|------|--------|
| **Severity** | Critical |
| **Status** | **FIXED** — Changed `required_level` default from `"None"` to `""` (empty sentinel). Update mode now skips required_level when not explicitly provided. |

### Finding 2 — FIXED: precision default silently resets decimal/money/float precision

| Item | Detail |
|------|--------|
| **Severity** | Critical |
| **Status** | **FIXED** — Changed `precision` default from `2` to `-1` (sentinel). Update mode condition `precision >= 0` now correctly skips when not provided. Create mode still defaults to 2 via existing clamp logic. |

### Finding 3 — FIXED: true_label/false_label defaults silently reset custom boolean labels

| Item | Detail |
|------|--------|
| **Severity** | Critical |
| **Status** | **FIXED** — Changed `true_label`/`false_label` defaults from `"Yes"`/`"No"` to `""` (empty sentinels). Create mode defaults to "Yes"/"No" via new guard in `CreateBooleanAttribute`. Update mode skips when empty. |

### Finding 4 — FIXED: Invalid required_level values silently default to None

| Item | Detail |
|------|--------|
| **Severity** | Medium |
| **Status** | **FIXED** — Changed `ParseRequiredLevel` to return `null` for unrecognized values (instead of defaulting to `None`). Both create and update paths now return a clear error: `"Invalid required_level: 'mandatory'. Valid values: 'None', 'Recommended', 'Required'"`. |

### Finding 5 — FIXED: Malformed JSON in option management silently ignored

| Item | Detail |
|------|--------|
| **Severity** | Medium |
| **Status** | **FIXED** — Changed `ParseOptions` and `ParseDeleteValues` to return `(items, error)` tuples. `ManagePicklistOptions` now reports `[Error] add_options: Invalid JSON: ...` instead of silently skipping. Create-mode picklist also reports JSON parse errors. |

### Finding 6 — FIXED: Changes recorded even when old and new values are identical

| Item | Detail |
|------|--------|
| **Severity** | Low |
| **Status** | **FIXED** — Added `oldVal != newVal` checks for `displayName` and `description` in `UpdateExistingAttribute`. No-op updates now correctly report "No changes specified" instead of phantom changes. |

### Finding 7 — FIXED: Doc parameter description missing TextArea format and double alias

| Item | Detail |
|------|--------|
| **Severity** | Low |
| **Status** | **FIXED** — Updated `attribute_type` `[Description]` to include `'double'` as alias for `'float'`. Updated doc parameter table to include `TextArea` in format list. |
