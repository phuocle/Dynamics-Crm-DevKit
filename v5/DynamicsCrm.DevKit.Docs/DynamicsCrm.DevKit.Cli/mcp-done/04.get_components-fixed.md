# MCP Tool: get_components

## Tool #5 — Solution Management

## Status: IMPLEMENTED

## Purpose

List all components inside a Dataverse solution. Accepts either the solution unique name or display name — uses fuzzy (contains) matching to find the correct solution.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| solution_name | string | Yes | — | Solution unique name or display name (supports fuzzy matching) |
| include_active_layers | bool | No | false | When true, queries msdyn_componentlayer for each component and adds ActiveLayer column (Yes/No). Shows which components have unmanaged customizations. |
| active_layers_only | bool | No | false | When true, implies include_active_layers=true and filters output to show ONLY components with active (unmanaged) layers. Useful for cleanup audits. |

## Returns

- Solution info: uniqueName, displayName, version, publisher, isManaged
- Component summary table: count per component type
- Full component detail table: componentType, typeId, objectId, name
- When include_active_layers=true: ActiveLayer column (Yes/No), active layer count in summary
- When active_layers_only=true: filtered to only components with active layers

## When to Use

- Before packaging or deploying a solution, to audit its contents
- To find objectIds of specific components (plugin assemblies, web resources, workflows)
- To count entities, attributes, forms, or other component types in a solution
- As a prerequisite step before operating on specific solution components
- To identify components with unmanaged customizations (include_active_layers=true)
- To audit which components need cleanup before deploying managed solutions (active_layers_only=true)

## Tips

- Fuzzy matching: `"devkit"` matches 3 solutions (devkitv4, devkitv4_devkit, devkitv4_legacy) — use exact uniqueName to disambiguate
- The objectId column is the primary key — pass it to `get_record` for full details
- For entities added with "Include All Components", use `get_metadata_entities` to expand

## Adversarial Review

> Tested against live environment `DEVKITV4` on 2026-04-03. Environment has 15 visible solutions including devkitv4 (3 sub-solutions), TEMP, Default, and managed solutions. devkitv4_legacy has 35 components (entities, web resources, plugin assemblies, SDK steps).

### Finding 1 — FIXED: SQL LIKE wildcards not escaped in solution_name

| Item | Detail |
|------|--------|
| **Severity** | Critical |
| **Status** | **FIXED** — Escape `%`, `_`, `[` in user input via `Replace("[","[[]").Replace("%","[%]").Replace("_","[_]")` before wrapping in LIKE pattern |

### Finding 2 — FIXED: No exact-match priority causes false disambiguation

| Item | Detail |
|------|--------|
| **Severity** | Critical |
| **Status** | **FIXED** — After fuzzy search returns multiple results, check if any has an exact `uniquename` match (case-insensitive) and prefer it, breaking the infinite loop |

### Finding 3 — FIXED: Unmapped component types show as Type_NNN

| Item | Detail |
|------|--------|
| **Severity** | Medium |
| **Status** | **FIXED** — Added 35 missing component type entries to `ComponentTypeNames` dictionary (from 43 to 78 entries), covering Canvas App, Connector, SDK Message, and all official types |

### Finding 4 — FIXED: Name resolution silently fails for unresolvable components

| Item | Detail |
|------|--------|
| **Severity** | Medium |
| **Status** | **FIXED** — Changed empty name fallback from `""` to `"(unresolved)"` so AI can see which components have no name |

### Finding 5 — FIXED: Doc file references wrong source file name

| Item | Detail |
|------|--------|
| **Severity** | Low |
| **Status** | **FIXED** — Updated doc file reference from `GetSolutionComponentsTool.cs` to `GetComponentsTool.cs` |

### Finding 6 — FIXED: Attribute/Relationship resolution silently skipped above 250

| Item | Detail |
|------|--------|
| **Severity** | Medium |
| **Status** | **FIXED** — Replaced hard `<= 250` guard with chunked resolution (250 per chunk, iterates until all resolved), matching the same pattern used by `BatchResolve` |
