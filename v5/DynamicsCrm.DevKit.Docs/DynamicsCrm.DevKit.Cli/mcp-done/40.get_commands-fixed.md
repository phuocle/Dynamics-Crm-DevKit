# MCP Tool: get_commands

## Tool #40 — UI Customization

## Status: PROPOSED

## Purpose

List and inspect modern command bar buttons (the `appaction` entity) that have replaced classic Ribbon XML in Model-Driven Apps. Covers command definitions, associated visibility/enable rules (`appactionrule`), and migration status (`appactionmigration`).

## Background

Modern Commands are the Dataverse-native replacement for classic Ribbon customization. Instead of hand-editing RibbonDiffXml, commands are stored as `appaction` records scoped to a specific Model-Driven App (`appmodule`). Each command can invoke either **JavaScript** or **Power Fx** and can be controlled by Power Fx visibility formulas or classic migrated rules (`appactionrule`). Power Fx formulas are stored in a **Command Component Library**, which is a special `canvasapp` record linked via `onclickeventformulacomponentlibraryid`.

### Three Core Entities

| Entity | EntitySetName | ObjectTypeCode | Purpose |
|--------|---------------|----------------|---------|
| `appaction` | `appactions` | 10326 | Command button definitions (label, icon, action, visibility, location) |
| `appactionrule` | `appactionrules` | 10328 | Classic enable/display rules (JSON definition) linked N:N to `appaction` |
| `appactionmigration` | `appactionmigrations` | 10327 | Tracks migration of classic ribbon commands to modern commands |

### Key Concepts

| Concept | Detail |
|---------|--------|
| **Location** | Where the command appears: Form (0), Main Grid (1), Sub Grid (2), Associated Grid (3), Quick Form (4), Global Header (5), Dashboard (6) |
| **Type** | Button shape: Standard Button (0), Dropdown Button (1), Split Button (2), Group (3) |
| **OnClick Event Type** | None (0), Formula/Power Fx (1), JavaScript (2) |
| **Visibility Type** | None (0), Formula/Power Fx (1), Classic Rules (2) |
| **Origin** | Default (0) = created natively, Migrated (1) = auto-converted from classic ribbon, Enhanced Migrated (2) |
| **App-scoped** | Commands are tied to a specific `appmodule` via `appmoduleid` lookup |
| **Hierarchical** | Self-referential `parentappactionid` enables nested dropdown/split/group structures |
| **Component Library** | Power Fx formulas stored in a `canvasapp` record, referenced by `onclickeventformulacomponentlibraryid` and `visibilityformulacomponentlibraryid` |

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `command_id` | string | No | — | GUID of a specific `appaction` record. Returns full detail including rules and component library info. All other filters ignored. |
| `entity_name` | string | No | — | Filter by `contextvalue` (entity logical name, e.g., `"account"`, `"v4_devkitv4"`). |
| `location` | string | No | — | Filter by location: `"form"`, `"main_grid"`, `"sub_grid"`, `"associated_grid"`, `"quick_form"`. Empty = all. |
| `app_name` | string | No | — | Filter by Model-Driven App name (contains match on `appmodule.name`). |
| `origin` | string | No | — | `"default"` (natively created), `"migrated"` (auto-converted from ribbon), `"all"`. Empty = all. |
| `action_type` | string | No | — | Filter by onclick event type: `"javascript"`, `"formula"` (Power Fx), `"none"`. Empty = all. |
| `name_filter` | string | No | — | Filter by command name (contains match). |
| `include_rules` | bool | No | `false` | When `true`, expand N:N relationship to include associated `appactionrule` records with their JSON definitions. |
| `include_children` | bool | No | `false` | When `true`, include child commands (dropdown/split button items) via `parentappactionid`. |
| `max_records` | int | No | `50` | Max commands to return (1-500). |

## Returns

- Command name, unique name, button label, font icon
- Location (Form / Main Grid / Sub Grid / Associated Grid)
- Type (Standard / Dropdown / Split / Group)
- OnClick event type (JavaScript / Power Fx / None) with function name and web resource
- Visibility type (Formula / Classic Rules / None)
- Origin (Default / Migrated)
- Parent command (for nested structures)
- App module name
- Sequence / order
- Hidden and disabled flags
- Client type (Browser / Mobile / Mail App)
- Associated `appactionrule` records with parsed JSON definitions (when `include_rules=true`)
- Child commands (when `include_children=true`)
- Component library info for Power Fx commands

## When to Use

- List all command bar buttons for an entity (e.g., "what commands are on the account form?")
- Find custom (non-migrated) commands created via the Command Designer
- Debug why a command button is visible/hidden by inspecting its visibility rules
- Audit JavaScript function bindings on command buttons
- Discover Power Fx commands and their component library references
- Compare commands across different Model-Driven Apps
- Inspect migrated ribbon commands to understand the auto-conversion result

## Tips

- Use `origin="default"` to filter out the hundreds of auto-migrated system commands and see only custom commands
- Use `include_rules=true` to see the classic enable/display rules as parsed JSON — useful for debugging visibility
- Use `include_children=true` when inspecting dropdown or split buttons to see their nested items
- The `contextvalue` field contains the entity logical name; for system-migrated commands it may contain the placeholder `{!EntityLogicalName}`
- Commands are app-scoped — the same entity can have different commands in different Model-Driven Apps
- Related tools: `get_forms` (form layout), `get_views` (grid columns), `build_formxml` (form events)
- The `appactionrule.definition` field contains serialized JSON with typed rule parts: `SelectionCountRulePart`, `PrivilegeRulePart`, `JavaScriptRulePart`, `EntityRulePart`, `FormStateRulePart`, etc.
- Use `get_solution_components` to find commands included in a specific solution (component type 10326 = appaction)

## Implementation

- **File**: `DynamicsCrm.DevKit.Cli/Mcp/Tools/GetCommandsTool.cs`
- **ReadOnly**: Yes
- **Destructive**: No
- **Idempotent**: Yes

### Two Modes

**List Mode** (no `command_id`): Returns a compact table of commands filtered by entity, location, app, origin, etc.

**Detail Mode** (`command_id` provided): Returns full command metadata including:
- All attribute values
- Expanded `appactionrule` records via N:N (`appaction_appactionrule_classicrules`)
- Child commands via `parentappactionid`
- Resolved web resource and component library names

### Key Queries

**List commands for an entity + location:**

```xml
<fetch>
  <entity name="appaction">
    <attribute name="name" />
    <attribute name="uniquename" />
    <attribute name="buttonlabeltext" />
    <attribute name="type" />
    <attribute name="location" />
    <attribute name="contextvalue" />
    <attribute name="onclickeventtype" />
    <attribute name="onclickeventjavascriptfunctionname" />
    <attribute name="fonticon" />
    <attribute name="origin" />
    <attribute name="sequence" />
    <attribute name="hidden" />
    <attribute name="isdisabled" />
    <attribute name="visibilitytype" />
    <attribute name="parentappactionid" />
    <attribute name="clienttype" />
    <attribute name="appmoduleid" />
    <filter>
      <condition attribute="statecode" operator="eq" value="0" />
      <condition attribute="contextvalue" operator="eq" value="v4_devkitv4" />
    </filter>
    <order attribute="location" />
    <order attribute="sequence" />
  </entity>
</fetch>
```

**Detail with rules (via Web API expand):**

```
GET /api/data/v9.2/appactions({GUID})?$expand=appaction_appactionrule_classicrules($select=name,type,definition,uniquename)
```
