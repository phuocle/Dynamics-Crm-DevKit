# Proposal: upsert_record MCP Tool

## Priority: 6 (Data Operations -- Very common in data integration)

## Why This Tool Is Needed

Upsert (create-or-update) is essential for data integration and migration scenarios. AI often needs to ensure a record exists with specific values, without knowing if it already exists. Currently AI must: (1) query to check existence, (2) call `create_record` or `update_record` based on result -- 2 calls instead of 1.

## Purpose

Create a new record OR update an existing record in a single operation. Matches records by:
1. **Primary key** (GUID) -- if `record_id` is provided
2. **Alternate keys** -- if `key_attributes` is provided (e.g., `email` for contacts)

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| entity_name | string | Yes | - | Entity logical name (e.g., `"account"`, `"contact"`). |
| fields_json | string | Yes | - | JSON object with field logical names as keys and values. Same format as `create_record`. |
| record_id | string | No | (empty) | GUID of the record. If provided, upsert by primary key. |
| key_attributes | string | No | (empty) | Comma-separated alternate key attributes (e.g., `"emailaddress1"` or `"name,accountnumber"`). Values must be included in `fields_json`. |

## Dataverse API

### Upsert by Primary Key

```
PATCH /accounts({guid})
Body: {"name": "Contoso", "revenue": 50000}
Headers: (none -- default upsert behavior)
```

### Upsert by Alternate Key

```
PATCH /accounts(emailaddress1='info@contoso.com')
Body: {"name": "Contoso", "revenue": 50000}
```

### Prevent Create (update only)

```
PATCH /accounts({guid})
Headers: If-Match: *
```

### Prevent Update (create only)

```
PATCH /accounts({guid})
Headers: If-None-Match: *
```

### SDK Equivalent

```csharp
var entity = new Entity(entityName);
// Set key attributes or primary ID
entity.KeyAttributes.Add("emailaddress1", "info@contoso.com");
// Set field values
entity["name"] = "Contoso";

var request = new UpsertRequest { Target = entity };
var response = (UpsertResponse)_serviceClient.Execute(request);
bool wasCreated = response.RecordCreated;
```

## Response Format (Compact)

### Record created
```
[Upsert] account
Action: Created
RecordId: abc-123-def-456
```

### Record updated
```
[Upsert] account
Action: Updated
RecordId: abc-123-def-456
```


## Tool Description for AI

```
Create or update a Dataverse record in a single operation (upsert).
If the record exists, it is updated; if not, it is created.

PARAMETERS:
- entity_name (required): Entity logical name (e.g., 'account', 'contact').
- fields_json (required): JSON object with field values (same format as create_record).
- record_id: GUID to match by primary key. Leave empty if using alternate keys.
- key_attributes: Comma-separated alternate key attribute names (e.g., 'emailaddress1').
  Values for these attributes must be included in fields_json.

RETURNS:
- Action taken: 'Created' or 'Updated'
- Record GUID

WHEN TO USE:
- Data import/migration: ensure records exist without checking first
- Integration scenarios: sync data from external systems
- When you want to set specific field values regardless of whether the record exists
- To avoid the query-then-create-or-update pattern (saves 1 API call)

TIPS:
- Either record_id OR key_attributes must be provided (not both empty)
- Alternate keys must be defined on the entity (use get_entity_metadata to check)
- Field values in fields_json follow the same format as create_record
- The response tells you whether the record was created or updated
```

## Implementation Notes

- Use `UpsertRequest` from `Microsoft.Xrm.Sdk.Messages`
- If `record_id` provided: set `entity.Id = Guid.Parse(record_id)`
- If `key_attributes` provided: set `entity.KeyAttributes` from `fields_json` values
- Use `EntityParserHelper.ParseFieldsToEntity()` (same as create/update) for field parsing
- Response: `UpsertResponse.RecordCreated` tells if created (true) or updated (false)
- Return `RecordCreated` status + record GUID in structured output
