# MCP Tool: get_entity_metadata

## Tool #2 — Metadata Discovery

## Status: IMPLEMENTED

## Purpose

Retrieve full metadata for a single Dataverse entity/table. Call this BEFORE writing FetchXML to discover correct attribute names and relationships.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| entity_name | string | Yes | — | The logical name of the entity (always lowercase) |
| attribute_prefix | string | No | `""` | Optional prefix filter for attributes and relationships (e.g., `v4_`, `msdyn_`) |

## Returns

- Entity info: logicalName, displayName, entitySetName, primaryIdAttribute, primaryNameAttribute, ownershipType, totalAttributes
- Attributes table: logicalName, type, requiredLevel, isValidForCreate, isValidForUpdate, constraints, displayName
- Relationships: 1:N, N:1, N:N with schema names and join columns
- Alternate Keys: schemaName, displayName, keyAttributes

## When to Use

- Before building any FetchXML query to ensure correct attribute names
- When you need to join entities and need the correct from/to columns
- When you need to know what picklist/choice options are available for filtering
- When you need to find the primary key or primary name field of an entity

## Tips

- Use `attribute_prefix` to filter only custom fields (e.g., `v4_` returns 16 attributes on account instead of 237)
- Picklist options are shown inline — no need to call `get_global_optionsets` for local option sets
- Relationship output shows the correct `from`/`to` columns needed for `<link-entity>` in FetchXML
- Call `get_entities_metadata` first if you're unsure of the entity logical name
