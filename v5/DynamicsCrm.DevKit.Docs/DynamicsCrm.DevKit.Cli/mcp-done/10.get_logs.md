# MCP Tool: get_logs

## Tool #11 — Security & Audit

## Status: IMPLEMENTED

## Purpose

Query plugin execution trace logs from Dataverse for debugging. Returns log entries with trace output, exception details, and execution timing.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| record_id | string | No | `""` | Specific plugin trace log GUID for full detail (ignores all other filters) |
| type_name | string | No | `""` | Filter by plugin type name (contains match, e.g., `AccountPlugin`) |
| minutes_ago | int | No | `60` | Return logs from last N minutes (max 1440) |
| correlation_id | string | No | `""` | Filter by correlation ID (exact GUID match) |
| message_name | string | No | `""` | Filter by SDK message (e.g., `Create`, `Update`, `Delete`) |
| mode | string | No | `""` | Filter by execution mode: `sync` or `async` |
| max_records | int | No | `50` | Maximum log entries (max 200) |

## Returns

- Without record_id: compact list of logs with typename, message, entity, mode, depth, duration, created
- With record_id: FULL detail — complete messageblock (trace output) and exceptiondetails, never truncated

## When to Use

- When debugging a plugin that is failing or producing unexpected results
- After deploying a plugin to verify it executes correctly
- When a user reports "my plugin isn't working" or "I got an error"
- To trace a specific request using correlation ID

## Tips

- Browse first (no record_id) to find the log, then get full detail (with record_id)
- Plugin Trace Log must be enabled in Dataverse (System Settings > Customization)
- Recent logs include: `FormPredictAgentPlugin` (sync) and `Dev.DevKit.Legacy.Package2.Plugins.Account.PostAccountUpdateAsynchronousPackage` (async, 203ms)
- Use `correlation_id` to trace all plugins that executed for a single request
