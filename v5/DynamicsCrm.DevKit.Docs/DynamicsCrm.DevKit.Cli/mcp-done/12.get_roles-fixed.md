# MCP Tool: get_roles

## Tool #13 — Security & Audit

## Status: IMPLEMENTED

## Purpose

List security roles and their privileges for Dataverse entities. Three modes: list all roles, detail for a specific role, or check a user's assigned roles and effective privileges.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| user_id | string | No | `""` | Email or GUID of a user to check their roles |
| role_id | string | No | `""` | GUID of a specific role for privilege details |
| role_name | string | No | `""` | Filter roles by name (contains match). List mode only. |
| business_unit_id | string | No | `""` | Filter by business unit GUID |
| entity_name | string | No | `""` | Show privileges for this entity only |
| max_records | int | No | `50` | Max roles in list mode (max 250) |

## Returns

- User mode: user info + assigned roles + effective entity privileges
- Detail mode: all privileges grouped by entity with access depth (User/BU/Parent:Child/Org)
- List mode: table of roles with ID, name, managed status, customizable flag

## When to Use

- When a user reports "access denied" — check their roles and privileges
- To understand what a specific role grants
- Before creating a new entity (need to set up role permissions)
- To compare security roles or audit security configuration

## Tips

- The environment has 50+ security roles — use `role_name` to filter (e.g., `"Admin"`, `"Sales"`)
- Depth levels: User < BusinessUnit < Parent:ChildBU < Organization
- System Administrator has all privileges at Organization depth
- Pass `entity_name` in user/detail mode to focus on one entity's privileges
- Use `whoami` first to find the current user's security roles
