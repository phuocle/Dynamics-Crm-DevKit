# MCP Tool: get_entities_metadata

## Tool #1 — Metadata Discovery

## Status: IMPLEMENTED

## Purpose

List ALL entities (tables) in a Dataverse environment. Returns each entity's logicalName, displayName, schemaName, ownershipType, isCustom, isActivity, and isAuditEnabled flag.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| filter | string | No | `""` | Optional keyword to filter entities by logical name or display name |
| custom_only | bool | No | `false` | Return only custom entities (non-system) |
| include_intersect | bool | No | `false` | Include intersect (N:N relationship) entities |

## Returns

- Markdown table of all matching entities with: logicalName, displayName, ownershipType, isCustom, isActivity
- Total count header (e.g., `[Entities] 482 total`)

## When to Use

- When you don't know the logical name of an entity the user mentions (e.g., user says "Cases" but the logical name is `incident`)
- When you need to find custom entities (they have prefixes like `v4_`, `msdyn_`, `mspp_`)
- When a FetchXML query fails with "entity not found" error
- To explore what tables are available in the Dataverse environment

## Tips

- Use `filter` to narrow results instead of retrieving all entities (faster, fewer tokens)
- After finding the correct logicalName, call `get_entity_metadata` to get column details before querying
- Custom entities always have a publisher prefix (e.g., `v4_devkit`, `msdyn_aimodel`)
- Set `custom_only=true` to skip system entities when exploring project-specific tables
- Display names are locale-dependent; logical names are always lowercase English
