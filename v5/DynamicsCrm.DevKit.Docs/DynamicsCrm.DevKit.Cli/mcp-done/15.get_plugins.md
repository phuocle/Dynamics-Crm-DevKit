# Proposal: get_plugins MCP Tool

## Priority: 24 (Admin & Governance — Plugin Registration Discovery)

## Phase: 4 — Admin & Governance

## Why This Tool Is Needed

Plugin registrations are the backbone of server-side logic in Dynamics 365 / Dataverse. Understanding what plugins are registered, on which messages/entities, at what stage and mode, with what images and configurations, is critical for debugging, auditing, and planning changes. The DevKit CLI already has `TaskServer` for deploying plugins — `get_plugins` provides the read-only discovery counterpart.

### Existing Tool Coverage

| Tool | Scope | Gap |
|------|-------|-----|
| `get_messages` | SDK messages + Custom Actions for an entity | Only message names — no plugin step details |
| `get_workflows` | Classic workflows (category=0) | Different automation type |
| `get_logs` | Plugin trace logs (execution output) | Debugging after execution, not registration discovery |
| `execute_fetchxml` | Can query all plugin entities | Requires knowledge of 4 joined entities and their relationships |

### Current Pain (execute_fetchxml)

```xml
<!-- Must query 4 separate entities and join them -->
<fetch>
  <entity name="sdkmessageprocessingstep">
    <attribute name="name"/>
    <attribute name="stage"/>
    <attribute name="mode"/>
    <attribute name="filteringattributes"/>
    <attribute name="statecode"/>
    <link-entity name="plugintype" from="plugintypeid" to="plugintypeid" alias="pt">
      <attribute name="typename"/>
      <link-entity name="pluginassembly" from="pluginassemblyid" to="pluginassemblyid" alias="pa">
        <attribute name="name"/>
      </link-entity>
    </link-entity>
    <link-entity name="sdkmessagefilter" from="sdkmessagefilterid" to="sdkmessagefilterid" alias="mf">
      <attribute name="primaryobjecttypecode"/>
    </link-entity>
    <link-entity name="sdkmessage" from="sdkmessageid" to="sdkmessageid" alias="m">
      <attribute name="name"/>
    </link-entity>
  </entity>
</fetch>
```

Must know: (1) `stage` values (10=PreValidation, 20=PreOperation, 40=PostOperation), (2) `mode` values (0=Sync, 1=Async), (3) join structure across 4+ entities, (4) `sdkmessageprocessingstepimage` for images, (5) secure/unsecure config is on separate entities.

### Proposed (get_plugins)

List assemblies:
```
action: list
```

Detail for an assembly:
```
assembly_name: Dev.DevKit.Plugins
```

Steps for an entity:
```
entity_name: account
```

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `assembly_name` | string | No | — | Filter by plugin assembly name (contains match). When provided alone: shows all types + steps for matching assemblies. |
| `entity_name` | string | No | — | Filter steps by entity logical name. Shows all plugin steps registered on this entity across all assemblies. |
| `message_name` | string | No | — | Filter steps by SDK message name (e.g., `"Create"`, `"Update"`, `"Delete"`). |
| `type_name` | string | No | — | Filter by plugin type name (contains match, e.g., `"AccountPlugin"`, `"PreValidate"`). |
| `include_images` | bool | No | `true` | Include pre/post image details for each step. |
| `include_config` | bool | No | `false` | Include unsecure/secure configuration values. Default false to avoid exposing sensitive data. |
| `stage` | string | No | — | Filter by stage: `"prevalidation"`, `"preoperation"`, `"postoperation"`. |
| `mode` | string | No | — | Filter by execution mode: `"sync"`, `"async"`. |
| `active_only` | bool | No | `true` | Only return activated steps. Set false to include disabled steps. |
| `max_records` | int | No | `100` | Max results (1–500). |

## Dataverse API

### List Assemblies

```csharp
var fetchXml = $@"
<fetch>
  <entity name='pluginassembly'>
    <attribute name='pluginassemblyid'/>
    <attribute name='name'/>
    <attribute name='version'/>
    <attribute name='isolationmode'/>
    <attribute name='sourcetype'/>
    <attribute name='ismanaged'/>
    <attribute name='managedidentityid'/>
    <filter type='and'>
      <condition attribute='ishidden' operator='eq' value='false'/>
      {(!string.IsNullOrEmpty(assembly_name) ? $""<condition attribute='name' operator='like' value='%{assembly_name}%'/>"" : """")}
    </filter>
    <order attribute='name'/>
  </entity>
</fetch>";
// Then count types per assembly with a second query
```

### Steps by Entity (using ObjectTypeCode from sdkmessagefilter)

```csharp
var fetchXml = $@"
<fetch top='{max_records}'>
  <entity name='sdkmessageprocessingstep'>
    <attribute name='sdkmessageprocessingstepid'/>
    <attribute name='name'/>
    <attribute name='stage'/>
    <attribute name='mode'/>
    <attribute name='rank'/>
    <attribute name='filteringattributes'/>
    <attribute name='configuration'/>
    <attribute name='statecode'/>
    <attribute name='asyncautodelete'/>
    <attribute name='impersonatinguserid'/>
    <attribute name='supporteddeployment'/>
    <attribute name='description'/>
    <link-entity name='plugintype' from='plugintypeid' to='plugintypeid' alias='pt'>
      <attribute name='typename'/>
      <attribute name='name'/>
      <link-entity name='pluginassembly' from='pluginassemblyid' to='pluginassemblyid' alias='pa'>
        <attribute name='name'/>
      </link-entity>
    </link-entity>
    <link-entity name='sdkmessage' from='sdkmessageid' to='sdkmessageid' alias='m'>
      <attribute name='name'/>
    </link-entity>
    <link-entity name='sdkmessagefilter' from='sdkmessagefilterid' to='sdkmessagefilterid' link-type='outer' alias='mf'>
      <attribute name='primaryobjecttypecode'/>
      {(!string.IsNullOrEmpty(entity_name) ? $""<filter><condition attribute='primaryobjecttypecode' operator='eq' value='{objectTypeCode}'/></filter>"" : """")}
    </link-entity>
    <filter type='and'>
      {(active_only ? ""<condition attribute='statecode' operator='eq' value='0'/>"" : """")}
      {(!string.IsNullOrEmpty(message_name) ? $""<condition attribute='sdkmessageid' operator='eq' value='{sdkMessageId}'/>"" : """")}
      {(!string.IsNullOrEmpty(stage) ? $""<condition attribute='stage' operator='eq' value='{stageValue}'/>"" : """")}
      {(!string.IsNullOrEmpty(mode) ? $""<condition attribute='mode' operator='eq' value='{modeValue}'/>"" : """")}
    </filter>
    <order attribute='name'/>
  </entity>
</fetch>";
```

## Relationship to Existing Code

### TaskServer.cs — Deploy Logic (Write Side)

The DevKit CLI's `TaskServer` is the **write** counterpart to this tool's **read** operations:

| TaskServer Cache | get_plugins Query | Purpose |
|-----------------|-------------------|---------|
| `_AttributesCache` | — | Parsed from assembly reflection (deploy-time only) |
| `LoadAllPluginTypesAsync()` | List plugin types per assembly | `plugintype` entity |
| `LoadAllPluginStepsAsync()` | List steps per entity/assembly | `sdkmessageprocessingstep` entity |
| `LoadAllPluginImagesAsync()` | List images per step | `sdkmessageprocessingstepimage` entity |
| `LoadAllSecureEntitiesAsync()` | Show secure config (when `include_config=true`) | `sdkmessageprocessingstepsecureconfig` join |
| `LoadAll_SdkMessages_SdkMessageFilters_Async()` | Resolve message names + entity from filters | `sdkmessage` + `sdkmessagefilter` entities |
| `LoadAllCustomApisAsync()` | Included in step output (Custom API type) | `customapi` entity |
| `DeployCustomApiStepAsync()` | Show Custom API plugin bindings | `customapi.plugintypeid` |

### Batching Pattern

Follow `TaskServer`'s batching pattern (PACK=50) for queries that reference step IDs → images, to avoid FetchXML condition limits:

```csharp
const int PACK = 50;
var batches = (int)Math.Ceiling((double)stepIds.Count / PACK);
for (int i = 0; i < batches; i++)
{
    var batch = stepIds.Skip(i * PACK).Take(PACK).ToList();
    // build condition per batch
}
```

## Stage & Mode Reference

| Stage Value | Name | Description |
|-------------|------|-------------|
| 10 | PreValidation | Before validation — can cancel operation |
| 20 | PreOperation | After validation, before DB write — can modify target |
| 40 | PostOperation | After DB write — read committed data |
| 30 | MainOperation | Reserved for Custom API / DataProvider plugins |

| Mode Value | Name | Description |
|------------|------|-------------|
| 0 | Synchronous | Runs in-pipeline, blocks the operation |
| 1 | Asynchronous | Runs in background queue, does not block |

## Implementation Notes

1. **DI**: Constructor injects `ServiceClient` (same pattern as `GetWorkflowsTool`)
2. **Reuse TaskServer patterns**: Batched queries (PACK=50), objectTypeCode resolution, message/filter cache — mirror the proven patterns from `TaskServer.cs`
3. **Security**: `include_config` defaults to `false` — secure config values should not be casually exposed
4. **Custom API steps**: Steps with `stage=30` (MainOperation) are Custom API plugin bindings — display distinctly
5. **Workflow types**: Plugin types that are workflow activities (inherit from `CodeActivity`) should be marked with `isWorkflow=true`
6. **ishidden filter**: Always filter `pluginassembly.ishidden=false` to exclude system assemblies
7. **Output**: Compact format via TSV for tables, Key-Value for detail sections
