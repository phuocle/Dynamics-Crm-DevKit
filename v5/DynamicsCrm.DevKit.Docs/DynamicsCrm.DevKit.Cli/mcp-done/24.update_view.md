# MCP Tool: update_view

## Tool #24 — UI Customization

## Status: IMPLEMENTED

## Purpose

Update, create, rename, or undo a Dataverse view (saved query) with automatic backup, FetchXML↔LayoutXML sync validation, and publishing. This is the safe write companion to `get_views` (read).

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| action | string | No | `"update"` | `update` (modify existing), `create` (new view), `rename` (change name), or `undo` (restore from backup) |
| entity_name | string | Yes | — | Entity logical name (e.g., `account`) |
| view_id | string | Cond. | `""` | GUID of the view. Required for `update`, `rename`, `undo`. Ignored for `create`. |
| view_name | string | Cond. | `""` | View name. Required for `create` and `rename`. |
| layoutxml | string | Cond. | `""` | LayoutXML content. Required for `update` and `create`. For `undo`: layout backup file path. |
| fetchxml | string | No | `""` | FetchXML content. Empty = keep existing (update) or auto-generate (create). For `undo`: fetch backup file path. |
| validate | bool | No | `true` | Validate XMLs and check FetchXML↔LayoutXML sync |
| backup | bool | No | `true` | Save current XMLs to local backup before overwriting |
| auto_publish | bool | No | `true` | Publish the entity after changes |

## Returns

- Update status (success/blocked/error)
- Sync validation results (FetchXML ↔ LayoutXML match check)
- Backup file paths (for rollback)
- Publish status

## When to Use

- After reading a view with `get_views` and making modifications
- To add/remove/reorder columns in a view
- To change view filters or sorting
- To create a new public view
- To undo/rollback a previous view change

## Tips

- Critical sync rule: every `<attribute>` in FetchXML MUST have a matching `<cell>` in LayoutXML (and vice versa) — tool validates automatically
- Workflow: `get_views` (read) → modify XMLs → `update_view` (write)
- Read `docs://instructions_for_views` for sync rules and best practices
- Standard column widths: 100 (narrow), 150 (medium), 200 (wide), 300 (extra wide)
- Real data: account has 9 public views including "My Active Accounts" (default), "Active Accounts", "All Accounts"
- Set `auto_publish=false` when batching multiple changes
