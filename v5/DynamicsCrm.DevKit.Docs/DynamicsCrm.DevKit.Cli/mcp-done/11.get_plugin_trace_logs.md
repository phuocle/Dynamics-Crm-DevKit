# Proposal: get_plugin_trace_logs MCP Tool

## Priority: 2 (Developer Troubleshooting -- #1 most requested debugging tool)

## Why This Tool Is Needed

Plugin trace logs are the **primary debugging mechanism** for Dynamics 365 plugin/workflow development. When a plugin fails or behaves unexpectedly, developers MUST check trace logs to understand what happened. Currently, AI has no way to read these logs -- it must instruct the user to manually check the Plugin Trace Log view in Dynamics.

2 of 15 competitor MCP servers already include this tool (Cliveo/Power-Platform-MCP, vignaesh01/DataverseDevToolsMcpServer).

## Competitor Analysis

- **Cliveo/Power-Platform-MCP**: Has plugin trace log tools
- **vignaesh01/DataverseDevToolsMcpServer**: Has plugin trace log tools
- **AppMaker**: Does NOT have this (UI-focused only)
- **mwhesse**: Does NOT have this (schema-focused only)

## Purpose

Query plugin execution trace logs from Dataverse. Supports filtering by:
- Plugin type name (e.g., "AccountPlugin", "PreValidateContact")
- Time range (last N minutes/hours)
- Correlation ID (trace a specific request across multiple plugins)
- Message name (e.g., "Create", "Update")
- Execution mode (synchronous/asynchronous)

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| record_id | string | No | (empty) | Specific plugin trace log GUID to retrieve in full detail. When provided, ALL other filters are ignored and the tool returns the FULL trace output + exception for that one record. Use `parse_record_url` to extract this from a Dynamics 365 URL. |
| type_name | string | No | (empty) | Filter by plugin type name (contains match). E.g., `"AccountPlugin"`, `"PreValidate"`. Leave empty for all plugins. |
| minutes_ago | int | No | 60 | Return logs from the last N minutes. Default: 60 (last hour). Max: 1440 (24 hours). |
| correlation_id | string | No | (empty) | Filter by specific correlation ID (exact match GUID). Useful for tracing a single request. |
| message_name | string | No | (empty) | Filter by SDK message name. E.g., `"Create"`, `"Update"`, `"Delete"`, `"Retrieve"`. |
| mode | string | No | (empty) | Filter by execution mode: `"sync"` or `"async"`. Leave empty for both. |
| max_records | int | No | 50 | Maximum number of log entries to return. Default: 50. Max: 200. |

## Dataverse Table

**Entity:** `plugintracelog` | **Entity Set:** `/plugintracelogs`

### Key Columns

| Column | Type | Description |
|--------|------|-------------|
| `plugintracelogid` | Guid | Primary key |
| `typename` | String | Full type name of the plugin (e.g., "MyNamespace.Plugins.AccountPlugin") |
| `messagename` | String | SDK message (Create, Update, Delete, etc.) |
| `primaryentity` | String | Entity logical name the plugin ran against |
| `operationtype` | Picklist | 0 = Unknown, 1 = Plug-in |
| `mode` | Picklist | 0 = Synchronous, 1 = Asynchronous |
| `depth` | Int | Execution depth (1 = first level, >1 = triggered by another plugin) |
| `messageblock` | Memo | The actual trace log output (what the plugin wrote via ITracingService) |
| `exceptiondetails` | Memo | Exception message and stack trace (if plugin threw an exception) |
| `performanceexecutionstarttime` | DateTime | When execution started |
| `performanceexecutionduration` | Int | Execution duration in milliseconds |
| `correlationid` | Guid | Correlation ID for request tracing |
| `requestid` | Guid | Request ID |
| `createdon` | DateTime | When the log was created |
| `issystemcreated` | Boolean | Whether the log was system-generated |
| `configuration` | String | Plugin step unsecure configuration |
| `secureconfiguration` | String | Plugin step secure configuration |
| `persistencekey` | String | Persistence key for durable plugins |

### FetchXML Query Pattern

```xml
<fetch>
  <entity name="plugintracelog">
    <attribute name="typename" />
    <attribute name="messagename" />
    <attribute name="primaryentity" />
    <attribute name="mode" />
    <attribute name="depth" />
    <attribute name="messageblock" />
    <attribute name="exceptiondetails" />
    <attribute name="performanceexecutionstarttime" />
    <attribute name="performanceexecutionduration" />
    <attribute name="correlationid" />
    <attribute name="createdon" />
    <filter type="and">
      <condition attribute="createdon" operator="last-x-minutes" value="60" />
      <!-- Add typename filter if provided -->
      <!-- Add correlationid filter if provided -->
      <!-- Add messagename filter if provided -->
      <!-- Add mode filter if provided (0=Sync, 1=Async) -->
    </filter>
    <order attribute="createdon" descending="true" />
  </entity>
</fetch>
```

## Response Format (Compact)

### Mode 1: Detail mode (when `record_id` is provided)

Returns FULL detail for that one specific log record. `messageblock` and `exceptiondetails` are NEVER truncated.

```
[PluginTraceLog] MyPlugin.AccountPlugin
Message: Update
Entity: account
Mode: Synchronous
Depth: 1
Duration: 45ms
CorrelationId: abc-123-def
Created: 2026-03-29 18:30:15

[Trace Output]
Entering ExecutePlugin...
Target entity: account (id: xxx-yyy)
Old value: "Contoso"
New value: "Contoso Ltd"
Exiting ExecutePlugin.

[Exception]
(none)
```

### Mode 2: List mode (when `record_id` is NOT provided — browsing/filtering)

Returns compact TSV table **WITHOUT messageblock and exceptiondetails** to save tokens. Only metadata columns.

```
[PluginTraceLogs] 12 logs (last 60 min)

typename	message	entity	mode	depth	duration	created
MyPlugin.AccountPlugin	Update	account	Sync	1	45ms	2026-03-29 18:30:15
MyPlugin.ContactPlugin	Create	contact	Async	1	120ms	2026-03-29 18:28:02
...
```

> **IMPORTANT:** List mode intentionally omits `messageblock` and `exceptiondetails` to save tokens (~44% savings). To see full trace output for a specific log, call the tool again with `record_id` set to the log's GUID.

### Error -- No logs found
```
[PluginTraceLogs] 0 logs found
Filters: typename contains "AccountPlugin", last 60 minutes
Tip: Check if Plugin Trace Log is enabled in System Settings > Customization
```

## Tool Description for AI

```
Query plugin execution trace logs from Dataverse for debugging.
Returns log entries with trace output, exception details, and execution timing.

PARAMETERS:
- record_id: Specific plugin trace log GUID for full detail (ignores all other filters when set)
- type_name: Filter by plugin type name (contains match, e.g., 'AccountPlugin')
- minutes_ago: Return logs from last N minutes (default: 60, max: 1440)
- correlation_id: Filter by correlation ID (exact GUID match) to trace a single request
- message_name: Filter by SDK message (e.g., 'Create', 'Update', 'Delete')
- mode: Filter by execution mode: 'sync' or 'async'
- max_records: Maximum log entries (default: 50, max: 200)

RETURNS:
- With record_id: FULL detail for one log — complete messageblock (trace output) and exceptiondetails, NEVER truncated
- Without record_id: Compact list of logs with metadata ONLY (typename, message, entity, mode, depth, duration, created) — NO messageblock/exceptiondetails to save tokens
- To see full trace output, first browse with filters, then call again with record_id for the specific log

WHEN TO USE:
- When debugging a plugin that is failing or producing unexpected results
- After deploying a plugin to verify it executes correctly
- When a user reports "my plugin isn't working" or "I got an error"
- To trace a specific request using correlation ID
- When a user pastes a plugin trace log URL — use parse_record_url first to extract the GUID, then call with record_id

TIPS:
- Plugin Trace Log must be enabled in Dataverse (System Settings > Customization)
- Use correlation_id to trace all plugins that executed for a single request
- Logs are retained for 24 hours by default
- If no logs found, suggest enabling plugin trace logging
- Use parse_record_url to extract record_id from Dynamics 365 URLs
- Browse first (no record_id) to find the log, then get full detail (with record_id)
```

## Implementation Notes

- When `record_id` is provided: use `_serviceClient.Retrieve("plugintracelog", id, new ColumnSet(true))` to get the full record, return detail format with FULL messageblock and exceptiondetails
- When `record_id` is NOT provided: use FetchXML query on `plugintracelog` entity, but do NOT fetch `messageblock` or `exceptiondetails` columns — only metadata columns (typename, messagename, primaryentity, mode, depth, performanceexecutionduration, createdon, correlationid)
- **CRITICAL: List mode MUST NOT fetch messageblock/exceptiondetails** — these fields can be very large and waste tokens when browsing
- **CRITICAL: Detail mode (with record_id) MUST return messageblock and exceptiondetails in FULL — NEVER truncate**
- Mode values: 0 = Synchronous, 1 = Asynchronous
- Sort by `createdon` descending (newest first)
- Use `operator='ge'` with calculated UTC datetime instead of `last-x-minutes` (SDK compatibility)
- Handle the case where Plugin Trace Log is not enabled (no logs exist)
