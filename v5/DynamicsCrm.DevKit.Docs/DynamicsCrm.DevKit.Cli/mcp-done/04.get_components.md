# MCP Tool: get_components

## Tool #5 — Solution Management

## Status: IMPLEMENTED

## Purpose

List all components inside a Dataverse solution. Accepts either the solution unique name or display name — uses fuzzy (contains) matching to find the correct solution.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| solution_name | string | Yes | — | Solution unique name or display name (supports fuzzy matching) |

## Returns

- Solution info: uniqueName, displayName, version, publisher, isManaged
- Component summary table: count per component type
- Full component detail table: componentType, typeId, objectId, name

## When to Use

- Before packaging or deploying a solution, to audit its contents
- To find objectIds of specific components (plugin assemblies, web resources, workflows)
- To count entities, attributes, forms, or other component types in a solution
- As a prerequisite step before operating on specific solution components

## Tips

- Fuzzy matching: `"devkit"` matches 3 solutions (devkitv4, devkitv4_devkit, devkitv4_legacy) — use exact uniqueName to disambiguate
- The objectId column is the primary key — pass it to `get_record` for full details
- For entities added with "Include All Components", use `get_metadata_entities` to expand
