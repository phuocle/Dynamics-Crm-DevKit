# Enhancement Proposal: Rename & Enhance `get_audit_history` → `get_audit_histories`

**Document Type:** Enhancement Analysis
**Current Tool:** `get_audit_history` (rename to `get_audit_histories`)
**Source:** `DynamicsCrm.DevKit.Cli\Mcp\Tools\GetAuditHistoryTool.cs`
**Environment:** DEVKITV4 (`dynamics-crm-devkit-v4.crm.dynamics.com`)
**Tested:** 2026-04-01
**Status:** Pending Review

---

## Design Decision: Rename to `get_audit_histories` + TWO MODES

### Why Rename?

The plural name `get_audit_histories` better reflects the tool's enhanced capability:

| Name | Implies | Scope |
|------|---------|-------|
| `get_audit_history` (old) | Single record's history | 1 record only |
| `get_audit_histories` (new) | Multiple audit entries across records/entities | 1 record OR entity-wide OR cross-entity |

### Existing TWO MODES Pattern in Codebase

| Tool | Optional ID | Empty = | Provided = |
|------|------------|---------|------------|
| `get_forms` | `form_id` | List all forms | Full FormXML detail |
| `get_views` | `view_id` | List all views | Full FetchXML/LayoutXML |
| `get_plugin_trace_logs` | `record_id` | Browse/filter logs | Full trace + exception |
| `get_security_roles` | `role_id` / `user_id` | List all roles | Privileges detail |
| `upsert_record` | `record_id` | Create new | Upsert existing |
| **`get_audit_histories`** | **`record_id`** | **Entity-wide / cross-entity** | **Single record detail** |

### TWO MODES

```
TWO MODES:
- record_id PROVIDED → Single-record detail mode (current behavior)
  API: RetrieveRecordChangeHistoryRequest
  Returns: field-level old/new values
  Requires: entity_name + record_id

- record_id EMPTY → Entity-wide / cross-entity browse mode (NEW)
  API: FetchXML on 'audit' entity
  Returns: summary rows (timestamp, user, record, entity, action)
  Requires: at least entity_name OR user_filter (or both empty = full system audit)
```

| Aspect | record_id provided (detail) | record_id empty (browse) |
|--------|----------------------------|--------------------------|
| **API** | `RetrieveRecordChangeHistoryRequest` | FetchXML on `audit` entity |
| **Scope** | Single record | Entity-wide or cross-entity |
| **Detail** | Field-level: old value → new value | Summary: timestamp, user, record, action |
| **entity_name** | Required | Optional (empty = all entities) |
| **Use case** | "Who changed revenue on this account?" | "What changed on any account today?" |

### Parameter Changes

```csharp
// BEFORE (get_audit_history): entity_name + record_id both REQUIRED
string entity_name,      // Required
string record_id,        // Required

// AFTER (get_audit_histories): both OPTIONAL
string entity_name = "", // Optional. Required when record_id is provided
string record_id = "",   // Optional. Empty = browse mode
```

### Behavior Matrix

| `entity_name` | `record_id` | Mode | Example Prompt |
|:---:|:---:|---|---|
| `"account"` | `"0fb34179..."` | Single record detail | "Who changed revenue on account 0fb34179?" |
| `"account"` | `""` | Entity-wide browse | "Show all account changes in the last 24 hours" |
| `""` | `""` | Cross-entity browse | "What did user X change across all entities today?" |
| `""` | `"0fb34179..."` | Error | "entity_name is required when record_id is provided" |

### Browse Mode FetchXML Template

```xml
<fetch>
  <entity name='audit'>
    <attribute name='createdon'/>
    <attribute name='userid'/>
    <attribute name='objectid'/>
    <attribute name='action'/>
    <attribute name='operation'/>
    <attribute name='objecttypecode'/>
    <filter>
      <!-- entity_name provided → add objecttypecode filter -->
      <!-- user_filter provided → add userid filter (resolve name first) -->
      <!-- operation provided → add action filter -->
      <!-- minutes_ago → add createdon filter -->
    </filter>
    <order attribute='createdon' descending='true'/>
  </entity>
</fetch>
```

## 1. Operation Description Bug (Zero-Code Fix)

> **Failing prompt:** "Who **assigned** this account to a different owner?"
> AI passes `operation=Update` instead of `operation=Assign` because the description only documents 3 of 9 supported values.

### Problem

The `operation` parameter `[Description()]` says:

```
"Values: 'Create', 'Update', 'Delete'."
```

But `FormatAction()` at line 291-303 actually supports **9 values**:

| Action Value | Label | Documented? |
|:---:|---|:---:|
| 1 | Create | Yes |
| 2 | Update | Yes |
| 3 | Delete | Yes |
| 4 | Activate | No |
| 5 | Deactivate | No |
| 11 | Cascade | No |
| 12 | Merge | No |
| 13 | Assign | No |
| 41 | SetState | No |

### Impact

When user asks "who assigned this record?" or "show me when this case was deactivated", AI cannot pass the correct `operation` filter. The entries still appear in unfiltered results, but AI cannot narrow down to just those actions.

### Fix

Update `[Description()]` at line 76-78 in `GetAuditHistoryTool.cs`:

```csharp
// FROM:
"Values: 'Create', 'Update', 'Delete'. "

// TO:
"Values: 'Create', 'Update', 'Delete', 'Activate', 'Deactivate', 'Assign', 'Merge', 'Cascade', 'SetState'. "
```

**Effort:** 1 line change. No logic change. No tests needed.

## 2. User Filter Matches Display Name Only

> **Failing prompt:** "What changes did **john@contoso.com** make to this account?"
> `user_filter=john@contoso.com` does a **contains match on display name** (e.g., "John Smith"), so `"john@contoso.com"` will NOT match `"John Smith"`.

### Problem

The original proposal specified `user_id` (email or GUID). The implementation changed to `user_filter` (display name contains match). This means:

| User Input | Display Name in Audit | Match? |
|---|---|:---:|
| `"John"` | `"John Smith"` | Yes (contains) |
| `"john@contoso.com"` | `"John Smith"` | No |
| `"Phước"` | `"Phước Lê Văn"` | Yes (contains) |
| `"phuoc@devkit.com"` | `"Phước Lê Văn"` | No |

### Verified with Real Data

```
Input:  user_filter="Phước"      → 3 entries (matched "Phước Lê Văn")
Input:  user_filter="phuoc@"     → 0 entries (email not in display name)
```

### Fix Options

| Option | Description | Effort |
|--------|-------------|--------|
| A. Resolve email → display name | Before filtering, query `systemuser` by `internalemailaddress` to get display name, then match | Medium |
| B. Match against both fields | Retrieve `userid` GUID from audit, query `systemuser` for both `fullname` and `internalemailaddress`, match either | Medium |
| C. Keep as-is, update description | Make it explicit: "Matches display name only, NOT email" | Low (description only) |

### Recommendation

**Option A** — resolve email to display name first. If `user_filter` contains `@`, do a quick FetchXML on `systemuser` where `internalemailaddress` contains the filter, get the `fullname`, then use that for the contains match. This handles the most common user expectation ("filter by email") without changing the core logic.

## 3. Entity-Wide Audit Query (Browse Mode)

> **Failing prompt:** "Show me all changes to **any** account in the last 24 hours"
> Current tool requires a specific `record_id` — cannot query audit across all records of an entity.

### Problem

`RetrieveRecordChangeHistoryRequest` requires an `EntityReference(entityName, recordId)`. There is no way to pass "all records" to this API.

### Real-World Scenarios That Fail Today

| # | Prompt | Why |
|---|--------|-----|
| 1 | "Show me all account changes in the last 24 hours" | No record_id = no query |
| 2 | "List all contacts modified by the sync service today" | Entity-wide + user filter |
| 3 | "How many records were updated on the lead entity this week?" | Entity-wide aggregation |

### Fix: Browse mode with `record_id=""` + `entity_name="account"`

```
get_audit_histories(entity_name="account", minutes_ago=1440)
```

Internally queries the `audit` entity via FetchXML with `objecttypecode` filter.

**Effort:** Covered by the TWO MODES enhancement.

## 4. Deleted Record Audit Not Accessible

> **Failing prompt:** "Show me all record **deletions** on the account entity in the last 30 days"
> Deleted records no longer exist, so `record_id` is invalid. Tool returns error or empty result.

### Problem

When a record is deleted:
- The record's GUID is no longer valid for `RetrieveRecordChangeHistoryRequest`
- The audit entries still exist in the `audit` entity, but the tool cannot reach them
- Even if user has the GUID of a deleted record, the API call may fail

### Real-World Scenarios That Fail Today

| # | Prompt | Why |
|---|--------|-----|
| 1 | "Show all deleted accounts in the last week" | Entity-wide scope + deleted records |
| 2 | "Who deleted contact abc-123?" | Specific GUID but record no longer exists |
| 3 | "Restore the data from the deleted opportunity" | Need old values from delete audit |

### Fix: Browse mode with `operation="Delete"`

```
get_audit_histories(entity_name="account", operation="Delete", minutes_ago=43200)
```

Adds `action=3` filter in the FetchXML.

**Effort:** Covered by the TWO MODES enhancement.

## 5. Cross-Entity Audit Query Not Supported

> **Failing prompt:** "Show me all changes made by the **nightly sync integration** across all entities"
> Current tool scopes to one entity + one record. Cannot query across entities.

### Problem

Common scenarios in enterprise D365:
- Integration accounts that write to multiple entities
- Admin wanting to see "everything user X did today"
- Security audit: "what did this service principal change?"

### Real-World Scenarios That Fail Today

| # | Prompt | Why |
|---|--------|-----|
| 1 | "What did the integration service change across all entities last night?" | Cross-entity + user filter |
| 2 | "Show me everything that happened in the system in the last hour" | Full system audit |
| 3 | "List all entities that user X modified today" | Cross-entity user activity |

### Fix: Browse mode with both `entity_name=""` and `record_id=""`

```
get_audit_histories(user_filter="sync service", minutes_ago=1440)
```

Omits `objecttypecode` filter when `entity_name` is empty.

**Effort:** Covered by the TWO MODES enhancement.

## 6. No Date Range Support (From-To)

> **Failing prompt:** "Show changes from **March 1 to March 15** specifically"
> `minutes_ago` only supports "last N minutes from now" — no way to exclude recent entries.

### Problem

| What User Wants | What Tool Supports |
|---|---|
| March 1 → March 15 | Last N minutes from now only |
| Last Monday → Last Friday | Last N minutes from now only |
| Q1 2026 (Jan 1 → Mar 31) | Max 43200 min = 30 days |

The `minutes_ago` parameter cannot express:
- A **start date** that is NOT "now"
- A **specific end date** in the past
- A range **longer than 30 days**

### Fix Options

| Option | Description | Effort |
|--------|-------------|--------|
| A. Add `from_date` / `to_date` params | ISO date strings, filter client-side on `createdon` | Low |
| B. Keep `minutes_ago` as-is | AI converts date ranges to approximate `minutes_ago` (lossy) | None |

### Recommendation

**Option A** — add optional `from_date` and `to_date` parameters (ISO 8601 strings). When provided, they override `minutes_ago`. Filter client-side on `createdon` same as current implementation.

```csharp
// New optional parameters (applies to BOTH modes)
string from_date = "",  // "2026-03-01" or "2026-03-01T00:00:00"
string to_date = "",    // "2026-03-15" or "2026-03-15T23:59:59"
```

**Effort:** Low. Add 2 parameters + adjust the `sinceUtc` / add `untilUtc` filter in `FormatAuditEntries()`.

## 7. Access/Read Audit Logs Skipped

> **Failing prompt:** "Who **viewed** this account record? Show me access logs"
> Tool skips all non-`AttributeAuditDetail` entries at line 160.

### Problem

Line 159-160 in `GetAuditHistoryTool.cs`:

```csharp
if (auditDetail is not AttributeAuditDetail attrAudit)
    continue;  // <-- skips read/access audit, relationship audit, share audit
```

Dataverse audit detail types:

| Type | What It Contains | Handled? |
|------|-----------------|:---:|
| `AttributeAuditDetail` | Field-level old/new values | Yes |
| `RelationshipAuditDetail` | N:N associate/disassociate | No (skipped) |
| `ShareAuditDetail` | Share/unshare with user/team | No (skipped) |
| `RolePrivilegeAuditDetail` | Security role changes | No (skipped) |
| Base `AuditDetail` | Access/read log (no field data) | No (skipped) |

### Real-World Scenarios That Fail

| # | Prompt | Audit Detail Type |
|---|--------|-------------------|
| 1 | "Who viewed this account record?" | Base `AuditDetail` (access log) |
| 2 | "Show N:N relationship changes for this record" | `RelationshipAuditDetail` |
| 3 | "Who was this record shared with?" | `ShareAuditDetail` |

### Fix Options

| Option | Description | Effort |
|--------|-------------|--------|
| A. Handle all audit detail types | Add branches for `RelationshipAuditDetail`, `ShareAuditDetail`, etc. | Medium |
| B. Handle base `AuditDetail` minimally | For non-`AttributeAuditDetail`, show timestamp + user + action (no field details) | Low |

### Recommendation

**Option B** — for non-`AttributeAuditDetail` entries, still emit a row with timestamp/user/action but field/oldValue/newValue as `-`. This way users at least see the activity happened, even without field-level details.

## 8. No Aggregation / Statistics

> **Failing prompt:** "How many times was the revenue field changed on this account?"
> Tool returns raw entries only. AI must count manually.

### Problem

This is a **minor gap**. AI can count the rows returned, but:
- Token-inefficient for records with 500+ audit entries
- Cannot answer "which field changed the most?" without downloading all data
- Cannot aggregate by user ("who made the most changes?")

### Recommendation

**No tool change needed.** AI can process the TSV output. If needed in the future, add optional `summary=true` parameter that returns counts instead of raw entries.
