# MCP Tool: upsert_record

## Tool #25 — Data Operations

## Status: IMPLEMENTED

## Purpose

Create a new record or update an existing record in a single Dataverse operation (upsert). If the record exists (by primary key), it is updated; if not, it is created.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| entity_name | string | Yes | — | Entity logical name (e.g., `account`, `contact`) |
| fields_json | string | Yes | — | JSON object with field logical names as keys and values matching Dataverse types |
| record_id | string | No | `""` | GUID of the record. Omit for create, provide for upsert/update. |

## Returns

- Action taken: Created or Updated
- Record GUID

## When to Use

- Data import/migration: ensure records exist without checking first
- Integration scenarios: sync data from external systems
- When you want to set specific field values regardless of whether the record exists
- To avoid the query-then-create-or-update pattern (saves 1 API call)

## Tips

- Omit `record_id` = pure CREATE (auto-generated ID); provide `record_id` = UPSERT (create-or-update)
- Field value types: String `"hello"`, Integer `42`, Decimal `99.50`, Boolean `true`, DateTime `"2025-01-15"`, Lookup `"guid"`, Picklist `100000001`, null to clear
- For polymorphic lookups (Customer/Owner): use `"fieldname@targetentity"` as key (e.g., `"customerid@account": "guid"`)
- Use `get_metadata_entities` to discover field names and types before writing
- Real data: accounts like "Fourth Coffee 4" (0fb34179-3ca5-f011-bbd3-6045bd053599), "Litware, Inc. (sample)"
