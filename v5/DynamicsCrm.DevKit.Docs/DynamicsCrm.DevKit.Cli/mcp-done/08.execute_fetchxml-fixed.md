# MCP Tool: execute_fetchxml

## Tool #8 — Query & Read

## Status: IMPLEMENTED

## Purpose

Execute a FetchXML query against Dataverse and return results as a compact table. Supports auto-paging to retrieve large datasets. Max 5000 records per call.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| fetchxml | string | Yes | — | The FetchXML query string (valid XML starting with `<fetch>`) |
| max_records | int | No | `5000` | Maximum records to return (capped at 5000) |
| get_all | bool | No | `false` | Automatically page through all results until max_records is reached |

## Returns

- Record count header with pagination info
- TSV table of matching records with requested columns

## When to Use

- For querying data with complex filters, joins, or aggregations
- When you need more control than what `search` provides
- For reporting and analytics queries
- When you need precise filtering by date range, status, numeric values

## Tips

- Do NOT use `top='N'` in FetchXML — use the `max_records` parameter instead
- Always use entity/attribute logical names (lowercase)
- Call `get_entity_metadata` first to discover correct attribute and relationship names
- Use `max_records=10` for quick sampling before running large queries
- Real data: accounts include "Fourth Coffee 4", "Litware, Inc. (sample)", "Adventure Works (sample)", "Fabrikam, Inc. (sample)"
