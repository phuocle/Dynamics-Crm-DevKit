# MCP Tool: manage_sitemap

## Tool #23 — UI Customization

## Status: IMPLEMENTED

## Purpose

Update a Model-Driven App's SiteMap XML with automatic backup, XSD validation, and publishing. Completes the UI customization trilogy: Forms (`update_form`) → Views (`update_view`) → SiteMap (`manage_sitemap`).

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| action | string | No | `"update"` | `update` (modify SiteMap XML), `create` (new SiteMap for app without one), or `undo` (restore from backup) |
| app_module_id | string | Yes | — | GUID of the Model-Driven App. Query `appmodule` table to find IDs. |
| sitemapxml | string | Yes | — | For `update`: new SiteMap XML. For `undo`: backup file path. |
| validate | bool | No | `true` | Validate SiteMap XML against XSD before writing |
| backup | bool | No | `true` | Save current SiteMap XML to backup before overwriting |
| auto_publish | bool | No | `true` | Publish the app module after changes |

## Returns

- Update status (success/blocked/error)
- Validation results
- Backup file path (for rollback)
- Publish status

## When to Use

- To add/remove/rearrange navigation areas, groups, and sub-areas in a Model-Driven App
- To add a new entity to app navigation
- To customize app navigation structure
- After creating a new entity that needs to appear in the app
- To undo/rollback a previous SiteMap change

## Tips

- SiteMap structure: `SiteMap > Area > Group > SubArea` — SubArea `Entity` attribute links to a Dataverse entity
- Read `schema://sitemapxml` for SiteMap XML structure and rules
- Follows the same safety pattern as `update_form` and `update_view`: auto-backup → validate → update → publish
- If backup=true and backup fails, update is BLOCKED (fail-safe)
- Set `auto_publish=false` when batching multiple changes
- Use `execute_fetchxml` on `appmodule` to find app IDs
