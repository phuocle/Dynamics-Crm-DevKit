# MCP Tool: get_views

## Tool #14 — UI Customization

## Status: IMPLEMENTED

## Purpose

Retrieve view (saved query) definitions for a Dataverse entity. List mode shows all views; detail mode returns full FetchXML and LayoutXML for a specific view.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| entity_name | string | Yes | — | Entity logical name (e.g., `account`) |
| view_id | string | No | `""` | GUID of a specific view for full details. Leave empty to list all. |
| query_type | int | No | `-1` | Filter by type: 0=Public, 1=Lookup, 2=AdvancedSearch, 4=QuickFind, 64=SubGrid |
| include_fetchxml | bool | No | `false` | In list mode, also include FetchXML/LayoutXML (default false) |
| include_personal | bool | No | `false` | Include personal views (userquery) owned by current user |

## Returns

- List mode: table of views with ID, name, type, default status, activation state
- Detail mode: full view metadata + FetchXML query + LayoutXML column layout

## When to Use

- To understand how data is displayed in an entity's grid/list
- To find which columns are shown in the default view
- To get the FetchXML query behind a view for analysis or modification
- Before modifying a view via `update_view`

## Tips

- Account entity has 9 public views including "My Active Accounts" (default), "Active Accounts", "All Accounts"
- Use `query_type=0` for public views (what users see in the view selector)
- Use `query_type=4` for QuickFind (defines what columns are searched)
- To update a view, use `update_view` — do NOT use `execute_webapi`
