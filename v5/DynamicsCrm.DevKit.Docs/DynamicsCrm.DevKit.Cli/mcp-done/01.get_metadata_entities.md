# MCP Tool: get_metadata_entities

## Tool #1 — Metadata Discovery

## Status: IMPLEMENTED

## Purpose

Retrieve Dataverse entity/table metadata. Unified tool that replaces the old `get_entities_metadata` (list all) and `get_entity_metadata` (detail one).

**TWO MODES** based on `entity_name`:

- **List all** (entity_name empty): Returns a markdown table of ALL entities with logicalName, displayName, schemaName, ownershipType, isCustom, isActivity, isAuditEnabled.
- **Detail one** (entity_name provided): Returns full metadata for a single entity including attributes, relationships, and alternate keys.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| entity_name | string | No | `""` | When provided: detail mode for that entity. When empty: list all entities |
| filter | string | No | `""` | List mode: keyword filter. Detail mode: attribute prefix filter |
| custom_only | bool | No | `false` | List mode only: return only custom entities |
| include_intersect | bool | No | `false` | List mode only: include N:N intersect entities |

## Returns

### List Mode (entity_name empty)

- Markdown table of all matching entities with: logicalName, displayName, ownershipType, isCustom, isActivity
- Total count header (e.g., `[Entities] 482 total`)

### Detail Mode (entity_name provided)

- Entity info: logicalName, displayName, displayCollectionName, entitySetName, primaryIdAttribute, primaryNameAttribute, ownershipType, totalAttributes
- Attributes table: logicalName, type, requiredLevel, isValidForCreate, isValidForUpdate, constraints, displayName
- Relationships: 1:N, N:1, N:N with schema names and join columns
- Alternate Keys: schemaName, displayName, keyAttributes

## When to Use

- When you don't know the logical name of an entity (leave entity_name empty, use filter)
- Before building any FetchXML query to ensure correct attribute names
- When you need to join entities and need the correct from/to columns
- When you need to know what picklist/choice options are available for filtering
- When you need to find the primary key or primary name field of an entity
- When you need to know which fields are required vs optional for create/update

## Tips

- Use `filter` to narrow results in list mode (faster, fewer tokens)
- In detail mode, use `filter` as attribute prefix (e.g., `v4_`) to see only custom fields
- Picklist options are shown inline in detail mode
- Relationship output shows the correct `from`/`to` columns for `<link-entity>` in FetchXML
