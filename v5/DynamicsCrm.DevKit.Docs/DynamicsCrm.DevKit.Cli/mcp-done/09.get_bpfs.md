# Proposal: get_bpfs MCP Tool

## Priority: 25 (Admin & Governance — Business Process Flows)

## Phase: 4 — Admin & Governance

## Why This Tool Is Needed

Business Process Flows (BPFs) guide users through multi-stage business processes in Dynamics 365. They are stored in the `workflow` entity with `category = 4` and each BPF auto-creates its own Dataverse entity to track instances. Understanding what BPFs exist, which entities they span, what stages they define, and their activation status is critical for customization planning, form design, and automation auditing.

### Existing Tool Coverage

| Tool | Scope | Gap |
|------|-------|-----|
| `get_workflows` | Classic workflows only (category=0) | Explicitly excludes BPFs |
| `get_rules` | Business rules (category=2) | No BPF coverage |
| `get_flows` | Cloud flows (category=5) | Different automation type |
| `execute_fetchxml` | Can query workflow + processstage | Requires knowledge of category=4, processstage join, stagecategory values |

### Current Pain (execute_fetchxml)

```xml
<!-- List BPFs -->
<fetch>
  <entity name="workflow">
    <attribute name="name"/>
    <attribute name="uniquename"/>
    <attribute name="primaryentity"/>
    <attribute name="statecode"/>
    <filter>
      <condition attribute="category" operator="eq" value="4"/>
      <condition attribute="type" operator="eq" value="1"/>
    </filter>
  </entity>
</fetch>

<!-- Get stages for a BPF - separate query, must know processid -->
<fetch>
  <entity name="processstage">
    <attribute name="stagename"/>
    <attribute name="stagecategory"/>
    <attribute name="primaryentitytypecode"/>
    <filter>
      <condition attribute="processid" operator="eq" value="{bpf-workflow-id}"/>
    </filter>
  </entity>
</fetch>
```

Must know: (1) category=4 for BPFs, (2) type=1 for definitions, (3) `processstage` entity for stages, (4) `processid` links stages to the BPF workflow, (5) `stagecategory` values (0=Qualify, 1=Develop, 2=Propose, 3=Close, etc.), (6) each BPF creates its own entity.

### Proposed (get_bpfs)

List mode:
```
status: active
```

Detail mode:
```
bpf_name: Lead to Opportunity Sales Process
```

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `bpf_id` | string | No | — | GUID of a specific BPF workflow. When provided: shows full detail including stages. |
| `bpf_name` | string | No | — | Filter by BPF name (contains match). If exactly 1 match: returns detail automatically. |
| `entity_name` | string | No | — | Filter BPFs by primary entity logical name (e.g., `"lead"`, `"opportunity"`). |
| `status` | string | No | `"active"` | `"active"`, `"draft"`, `"all"`. |
| `include_stages` | bool | No | `false` | In list mode: also include stages for each BPF (more queries, richer output). In detail mode: always included. |
| `max_records` | int | No | `50` | Max BPFs to return (1–250). |

## Dataverse Entities

### workflow (BPF Definition, category=4)

| Attribute | Type | Description |
|-----------|------|-------------|
| `workflowid` | Guid | Primary key |
| `name` | String | BPF display name |
| `uniquename` | String | Unique name (also the name of auto-created BPF entity) |
| `description` | String | Description |
| `category` | OptionSet | Must be `4` (Business Process Flow) |
| `type` | OptionSet | `1`=Definition |
| `primaryentity` | String | Primary entity logical name the BPF starts on |
| `statecode` | OptionSet | `0`=Draft, `1`=Activated |
| `statuscode` | OptionSet | Status reason |
| `ownerid` | Lookup | Owner |
| `ismanaged` | Boolean | Managed solution |
| `businessprocesstype` | OptionSet | `0`=Business Flow, `1`=Task Flow |
| `clientdata` | String | JSON of the BPF definition |
| `createdon` | DateTime | Created date |
| `modifiedon` | DateTime | Last modified date |
| `modifiedby` | Lookup | Last modified by |

### processstage (BPF Stages)

| Attribute | Type | Description |
|-----------|------|-------------|
| `processstageid` | Guid | Primary key |
| `processid` | Lookup | Parent BPF workflow |
| `stagename` | String | Stage display name |
| `stagecategory` | OptionSet | Stage category (see below) |
| `primaryentitytypecode` | EntityName | Entity this stage operates on |
| `clientdata` | Memo | Stage step metadata (JSON) |
| `parentprocessstageid` | Lookup | Parent stage (for branching) |
| `ownerid` | Owner | Owner |

### stagecategory Values

| Value | Label | Typical Use |
|-------|-------|-------------|
| 0 | Qualify | Lead qualification |
| 1 | Develop | Opportunity development |
| 2 | Propose | Proposal/quote stage |
| 3 | Close | Deal close |
| 4 | Identify | Issue identification |
| 5 | Research | Research phase |
| 6 | Resolve | Resolution phase |
| 7 | Approval | Approval stage |

## Dataverse API

### List Mode

```csharp
var fetchXml = $@"
<fetch top='{max_records}'>
  <entity name='workflow'>
    <attribute name='workflowid'/>
    <attribute name='name'/>
    <attribute name='uniquename'/>
    <attribute name='description'/>
    <attribute name='primaryentity'/>
    <attribute name='statecode'/>
    <attribute name='statuscode'/>
    <attribute name='ownerid'/>
    <attribute name='ismanaged'/>
    <attribute name='businessprocesstype'/>
    <attribute name='createdon'/>
    <attribute name='modifiedon'/>
    <attribute name='modifiedby'/>
    <filter type='and'>
      <condition attribute='category' operator='eq' value='4'/>
      <condition attribute='type' operator='eq' value='1'/>
      {(status == ""active"" ? ""<condition attribute='statecode' operator='eq' value='1'/>"" :
        status == ""draft"" ? ""<condition attribute='statecode' operator='eq' value='0'/>"" : """")}
      {(!string.IsNullOrEmpty(entity_name) ? $""<condition attribute='primaryentity' operator='eq' value='{entity_name}'/>"" : """")}
      {(!string.IsNullOrEmpty(bpf_name) ? $""<condition attribute='name' operator='like' value='%{bpf_name}%'/>"" : """")}
    </filter>
    <order attribute='name'/>
  </entity>
</fetch>";
```

### Stages for a BPF

```csharp
var fetchStages = $@"
<fetch>
  <entity name='processstage'>
    <attribute name='processstageid'/>
    <attribute name='stagename'/>
    <attribute name='stagecategory'/>
    <attribute name='primaryentitytypecode'/>
    <attribute name='clientdata'/>
    <attribute name='parentprocessstageid'/>
    <filter>
      <condition attribute='processid' operator='eq' value='{bpfWorkflowId}'/>
    </filter>
    <order attribute='stagecategory'/>
  </entity>
</fetch>";
```

### Stage Count per BPF (for list mode with include_stages=false)

```csharp
// Aggregate query to get stage count per BPF
var fetchStageCounts = $@"
<fetch aggregate='true'>
  <entity name='processstage'>
    <attribute name='processid' alias='processId' groupby='true'/>
    <attribute name='processstageid' alias='stageCount' aggregate='count'/>
    <filter type='or'>
      {bpfIdConditions}
    </filter>
  </entity>
</fetch>";
```

## Cross-Entity BPF Detection

A key insight for BPFs is that they can **span multiple entities** (e.g., Lead → Opportunity). Each stage has its own `primaryentitytypecode`. The detail mode output should clearly show which entity each stage operates on, making cross-entity flows easy to spot:

```
[Stages] 4 stages (ordered)

#	stageName	stageCategory	primaryEntity
1	Qualify	Qualify	lead          ← starts on lead
2	Develop	Develop	opportunity   ← crosses to opportunity
3	Propose	Propose	opportunity
4	Close	Close	opportunity
```

## Implementation Notes

1. **DI**: Constructor injects `ServiceClient` (same pattern as `GetWorkflowsTool`)
2. **Two entities**: `workflow` (category=4) for BPF definitions, `processstage` for stages
3. **Stage ordering**: Stages should be ordered by `stagecategory` value (0→7) as this represents the intended progression. For BPFs with custom stage categories, fall back to the order returned by Dataverse.
4. **Auto-created entity**: Each BPF creates a Dataverse entity with the same logical name as `uniquename`. Can mention this in the output for reference.
5. **businessprocesstype**: `0`=Business Flow (standard), `1`=Task Flow (mobile task flows). Filter or label accordingly.
6. **Stage count optimization**: In list mode with `include_stages=false`, use an aggregate FetchXML query to get stage counts without fetching all stage records.
7. **bpf_name auto-detail**: If `bpf_name` matches exactly 1 BPF, automatically switch to detail mode (include stages) for convenience — same pattern as `get_forms` with `form_name`.
