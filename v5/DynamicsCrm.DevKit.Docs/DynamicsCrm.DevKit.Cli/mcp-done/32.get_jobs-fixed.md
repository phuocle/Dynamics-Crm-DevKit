# Proposal: get_jobs MCP Tool

## Priority: 26 (Admin & Governance — System Jobs / Async Operations)

## Phase: 4 — Admin & Governance

## Why This Tool Is Needed

System Jobs (`asyncoperation`) are the **primary debugging target** for Dynamics 365 developers. Every async plugin failure, classic workflow failure, bulk operation, import job, and solution operation writes its result here. While `get_logs` shows plugin trace output, the actual **error message and stack trace** for async failures live in `asyncoperation.message` and `asyncoperation.friendlymessage`. These are two complementary but distinct data sources.

### Existing Tool Coverage

| Tool | Scope | Gap |
|------|-------|-----|
| `get_logs` | Plugin trace logs (trace output from `ITracingService`) | Only execution traces — not job status, not error messages for async failures |
| `get_workflows` | Classic workflow definitions (category=0) | Definitions only — not execution results |
| `get_flows` | Cloud flow runs via `flowsession` | Cloud flows only — not classic workflows, not plugins, not bulk ops |
| `execute_fetchxml` | Can query `asyncoperation` | Requires knowledge of operationtype values (98 codes), statuscode mappings, complex filters |

### Current Pain (execute_fetchxml)

```xml
<!-- Find failed async plugin jobs -->
<fetch top="10">
  <entity name="asyncoperation">
    <attribute name="name"/>
    <attribute name="friendlymessage"/>
    <attribute name="message"/>
    <attribute name="operationtype"/>
    <attribute name="statuscode"/>
    <attribute name="startedon"/>
    <attribute name="completedon"/>
    <attribute name="primaryentitytype"/>
    <attribute name="ownerid"/>
    <filter type="and">
      <condition attribute="statuscode" operator="eq" value="31"/>
      <condition attribute="startedon" operator="last-x-hours" value="24"/>
    </filter>
    <order attribute="startedon" descending="true"/>
  </entity>
</fetch>
```

Must know: (1) `statuscode=31` means Failed, (2) `operationtype` values (10=Workflow, 1=SystemEvent, 13=BulkDelete, etc.), (3) `message` contains the stack trace (can be huge), (4) `friendlymessage` is the user-facing error, (5) `owningextensionid` links to the plugin step, (6) `workflowactivationid` links to the workflow.

### Proposed (get_jobs)

Failed jobs last 24h:
```
status: failed
```

Detail for a specific job:
```
job_id: d9e875bf-1c9b-ea11-a811-000d3a122b89
```

Jobs for a specific entity:
```
entity_name: account
status: failed
```

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `job_id` | string | No | — | GUID of a specific system job. When provided: shows full detail including error message and stack trace. |
| `entity_name` | string | No | — | Filter by primary entity type (e.g., `"account"`, `"contact"`). |
| `status` | string | No | `"failed"` | `"failed"`, `"succeeded"`, `"waiting"`, `"in_progress"`, `"canceled"`, `"all"`. Default is `"failed"` because the primary use case is debugging failures. |
| `operation_type` | string | No | — | Filter by operation type: `"plugin"` (operationtype=1), `"workflow"` (operationtype=10), `"bulk_delete"` (operationtype=13), `"import"` (operationtype=5), `"goal_rollup"` (operationtype=40), `"all"`. Maps to operationtype values. |
| `name_filter` | string | No | — | Filter by job name (contains match). |
| `correlation_id` | string | No | — | Filter by correlation ID (exact GUID match) to trace all jobs from a single request. |
| `minutes_ago` | int | No | `1440` | Return jobs from last N minutes. Default: 1440 (24 hours). Max: 43200 (30 days). |
| `max_records` | int | No | `50` | Max jobs to return (1–500). |

## Dataverse Entity

### asyncoperation (System Job)

| Attribute | Type | Description |
|-----------|------|-------------|
| `asyncoperationid` | Guid | Primary key |
| `name` | String | Job name (typically plugin type name or workflow name) |
| `operationtype` | OptionSet | Type of operation (see below) |
| `primaryentitytype` | EntityName | Entity the job operates on |
| `statecode` | State | State (0=Ready, 1=Suspended, 2=Locked, 3=Completed) |
| `statuscode` | Status | Status reason (see below) |
| `startedon` | DateTime | When the job started |
| `completedon` | DateTime | When the job completed |
| `createdon` | DateTime | When the job was created |
| `message` | Memo | Full error message + stack trace (up to 100K chars) |
| `friendlymessage` | Memo | User-friendly error message (up to 100K chars) |
| `messagename` | String | SDK message that triggered this job (e.g., "Update") |
| `errorcode` | Integer | Error code (read-only) |
| `executiontimespan` | Double | Execution duration in seconds |
| `retrycount` | Integer | Number of retries (read-only) |
| `depth` | Integer | SDK call depth |
| `correlationid` | Guid | Correlation ID for tracing |
| `ownerid` | Owner | Owner (user or team) |
| `owningextensionid` | Lookup | Plugin step that owns this job (`sdkmessageprocessingstep`) |
| `workflowactivationid` | Lookup | Workflow activation related to this job (`workflow`) |
| `regardingobjectid` | Lookup | Related record |
| `data` | Memo | Unstructured data (can be very large — skip in list mode) |
| `postponeuntil` | DateTime | Scheduled execution time (for waiting jobs) |

### statecode Values

| Value | Label | Description |
|-------|-------|-------------|
| 0 | Ready | Job is queued and waiting to execute |
| 1 | Suspended | Job is suspended (waiting) |
| 2 | Locked | Job is currently executing |
| 3 | Completed | Job has finished (check statuscode for result) |

### statuscode Values

| Value | Label | State | Description |
|-------|-------|-------|-------------|
| 0 | WaitingForResources | Ready (0) | Queued, waiting for server resources |
| 10 | Waiting | Suspended (1) | Waiting (e.g., postponed, recurring) |
| 20 | InProgress | Locked (2) | Currently executing |
| 21 | Pausing | Locked (2) | Being paused |
| 22 | Canceling | Locked (2) | Being canceled |
| 30 | Succeeded | Completed (3) | Completed successfully |
| 31 | Failed | Completed (3) | Completed with error |
| 32 | Canceled | Completed (3) | Canceled by user or system |

### operationtype Values (Developer-Relevant Subset)

| Value | Label | Tool Alias | Description |
|-------|-------|------------|-------------|
| 1 | System Event | `plugin` | Async plugin execution |
| 2 | Bulk Email | `bulk_email` | Mass email operation |
| 5 | Import | `import` | Data import |
| 10 | Workflow | `workflow` | Classic workflow execution |
| 13 | Bulk Delete | `bulk_delete` | Bulk delete operation |
| 17 | Import Subprocess | `import` | Child import job |
| 23 | Bulk Delete Subprocess | `bulk_delete` | Child bulk delete job |
| 35 | Recurring Series Expansion | — | Appointment recurrence |
| 40 | Goal Roll Up | `goal_rollup` | Goal metric recalculation |
| 54 | Execute Async Request | `plugin` | Custom Action async execution |
| 57 | Calculate Rollup Field | — | Rollup field recalculation |

| 202 | Export Solution | `solution` | Solution export |

Full reference: 98 total values. Remaining values are system-internal (index management, DB maintenance, provisioning, etc.) — rarely relevant for developer debugging.

## Dataverse API

### List Mode FetchXML

```csharp
var fromDate = DateTime.UtcNow.AddMinutes(-minutes_ago).ToString("o");
var fetchXml = $@"
<fetch top='{max_records}'>
  <entity name='asyncoperation'>
    <attribute name='asyncoperationid'/>
    <attribute name='name'/>
    <attribute name='operationtype'/>
    <attribute name='primaryentitytype'/>
    <attribute name='statecode'/>
    <attribute name='statuscode'/>
    <attribute name='startedon'/>
    <attribute name='completedon'/>
    <attribute name='executiontimespan'/>
    <attribute name='friendlymessage'/>
    <attribute name='messagename'/>
    <attribute name='errorcode'/>
    <attribute name='ownerid'/>
    <attribute name='correlationid'/>
    <filter type='and'>
      {BuildStatusFilter(status)}
      {BuildOperationTypeFilter(operation_type)}
      <condition attribute='startedon' operator='ge' value='{fromDate}'/>
      {(!string.IsNullOrEmpty(entity_name) ? $""<condition attribute='primaryentitytype' operator='eq' value='{entity_name}'/>"" : """")}
      {(!string.IsNullOrEmpty(name_filter) ? $""<condition attribute='name' operator='like' value='%{name_filter}%'/>"" : """")}
      {(!string.IsNullOrEmpty(correlation_id) ? $""<condition attribute='correlationid' operator='eq' value='{correlation_id}'/>"" : """")}
    </filter>
    <order attribute='startedon' descending='true'/>
  </entity>
</fetch>";
```

### Complete Debugging Flow

```
Plugin fails SYNC   → get_logs (trace output in ITracingService)
Plugin fails ASYNC  → get_jobs (error in asyncoperation) + get_logs (trace output)
Workflow fails      → get_jobs (error in asyncoperation)
Cloud flow fails    → get_flows runs mode (error in flowsession)
Bulk delete fails   → get_jobs (error in asyncoperation)
Import fails        → get_jobs (error in asyncoperation)
Solution import     → get_jobs (status in asyncoperation)
```

## Status Filter Mapping

```csharp
private static string BuildStatusFilter(string status)
{
    return status.Trim().ToLowerInvariant() switch
    {
        "failed" => "<condition attribute='statuscode' operator='eq' value='31'/>",
        "succeeded" => "<condition attribute='statuscode' operator='eq' value='30'/>",
        "waiting" => "<filter type='or'>" +
                     "<condition attribute='statuscode' operator='eq' value='0'/>" +
                     "<condition attribute='statuscode' operator='eq' value='10'/>" +
                     "</filter>",
        "in_progress" => "<condition attribute='statuscode' operator='eq' value='20'/>",
        "canceled" => "<condition attribute='statuscode' operator='eq' value='32'/>",
        "all" => "",
        _ => "<condition attribute='statuscode' operator='eq' value='31'/>"
    };
}
```

## Implementation Notes

1. **DI**: Constructor injects `ServiceClient` (same pattern as `GetWorkflowsTool`)
2. **Default to failed**: Unlike other tools that default to "active" or "all", this tool defaults to `status=failed` because the primary use case is debugging failures
3. **message field**: Only include in detail mode — can be 100K chars and would blow up list mode output
4. **friendlymessage truncation**: In list mode, truncate to ~100 chars for the table preview
5. **operationtype mapping**: Map integer values to human-readable labels. Only the developer-relevant subset needs labels; the rest can show "System ({value})"
6. **executiontimespan**: Format as human-readable (e.g., "1.2s", "2m 15s", "1h 3m")
7. **owningextensionid**: Resolve to plugin step name for the `pluginStep` field in detail mode
8. **workflowactivationid**: Resolve to workflow name for the `workflowName` field in detail mode
9. **Pagination**: `asyncoperation` can have millions of records — always enforce `max_records` and time filter
10. **No data field**: Never return the `data` field — it can be enormous and is rarely useful for debugging

## Adversarial Review

> Tested against live environment `DEVKITV4` on 2026-04-05. Used real failed plugin jobs (PostAccountUpdateAsynchronous), succeeded rollup field jobs, waiting system jobs, and bulk delete jobs across 30-day window.

### Finding 1 — FIXED: entity_name filter crashes on all inputs

| Item | Detail |
|------|--------|
| **Severity** | Critical |
| **Status** | **FIXED** — Resolved entity logical name to ObjectTypeCode (int) via `RetrieveEntityRequest` before building FetchXML filter; returns clear error if entity not found. |

### Finding 2 — FIXED: Invalid operation_type silently returns unfiltered results

| Item | Detail |
|------|--------|
| **Severity** | Medium |
| **Status** | **FIXED** — Added `ValidOperationTypes` HashSet; invalid values now return error listing valid options before query executes. |

### Finding 3 — FIXED: Invalid status silently defaults to "failed"

| Item | Detail |
|------|--------|
| **Severity** | Medium |
| **Status** | **FIXED** — Added `ValidStatuses` HashSet; invalid values now return error listing valid options before query executes. |

### Finding 4 — FIXED: "all" status produces ungrammatical header text

| Item | Detail |
|------|--------|
| **Severity** | Low |
| **Status** | **FIXED** — When status is "all", the status word is omitted from the header (e.g., "3 jobs" instead of "3 all jobs"). |
