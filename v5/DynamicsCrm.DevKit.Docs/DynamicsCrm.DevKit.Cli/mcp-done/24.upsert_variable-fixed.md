# MCP Tool: upsert_variable

## Tool #24 — Configuration Management

## Status: IMPLEMENTED

## Purpose

Create or update a Dataverse environment variable (definition + current value) in a single call. Automatically detects whether the variable exists, coordinates writes across both `environmentvariabledefinition` and `environmentvariablevalue` tables, and optionally adds the definition to a solution.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `variable_name` | string | Yes | — | Schema name with publisher prefix (e.g., `new_ApiEndpoint`). Used to find or create the definition. |
| `display_name` | string | Cond. | `""` | Display name. Required when creating a new variable. On update, only applied if provided. |
| `type` | string | Cond. | `""` | Variable type: `string`, `number`, `boolean`, `json`, `datasource`, `secret`. Required on create, ignored on update (type cannot change). |
| `default_value` | string | No | `""` | Default value for the definition. |
| `value` | string | No | `""` | Current value override. Creates or updates the `environmentvariablevalue` record. If empty, leaves current value unchanged. Mutually exclusive with `clear_value`. |
| `clear_value` | bool | No | false | Delete the current value record, reverting to default. Mutually exclusive with `value`. |
| `description` | string | No | `""` | Variable description. |
| `solution_name` | string | No | `""` | Solution to add the definition to (create only). |
| `auto_publish` | bool | No | false | Publish after changes. Environment variables typically do not require publishing. |

## Returns

- Action performed: `created` or `updated`
- Variable name, display name, and type
- Default value and current value (after the operation)
- Whether the value was cleared (`valueCleared: true`)
- Solution and publish status

## When to Use

- When creating a new environment variable with a specific type and value
- When updating the current value of an existing environment variable
- When changing the default value of an environment variable
- When clearing the current value to revert to the default
- When setting up environment-specific configuration (API endpoints, feature flags, secrets)
- When adding a new environment variable to a specific solution

## Tips

- Use `get_variables` first to check if a variable already exists and see its current/default values
- `value` and `clear_value` are mutually exclusive — provide one or neither, not both
- Type cannot be changed after creation — only `display_name`, `default_value`, `description`, and `value` can be updated
- Environment variables rarely need publishing (`auto_publish` defaults to false)
- For secret type variables, Dataverse stores the value reference — not the actual secret
- Use `get_components` to check which solution a variable belongs to

## Adversarial Review

> Tested against live environment `DEVKITV4` on 2026-04-03. Created 4 test variables (`new_AdvTest1` string, `new_AdvTest2` number, `new_AdvTestSolution` string, `NEW_ADVTESTCASE` boolean) with various adversarial inputs, then cleaned up all test data.

### Finding 1 — FIXED: Invalid solution_name silently succeeds in structured output

| Item | Detail |
|------|--------|
| **Severity** | Critical |
| **Status** | **FIXED** — Added `solutionWarning` field to `UpsertVariableResult` model; populated with failure message when `AddSolutionComponentRequest` throws. AI agents now see `"solutionWarning": "Failed to add to solution..."` in structured JSON. |

### Finding 2 — Publish uses PublishAllXmlRequest instead of targeted publish

| Item | Detail |
|------|--------|
| **Severity** | Low |
| **Status** | **DEFERRED** — Dataverse `PublishXmlRequest` is entity-based and does not support targeted publish for environment variable components. `PublishAllXmlRequest` is the only available option. Mitigated by `auto_publish` defaulting to `false`. |
