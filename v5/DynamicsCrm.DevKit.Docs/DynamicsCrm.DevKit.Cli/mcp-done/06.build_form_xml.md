# MCP Tool: build_form_xml

## Tool #7 -- UI Customization

## Status: IMPLEMENTED

## Purpose

Build modified FormXML by adding fields, sections, tabs, libraries, or event handlers to an existing Dataverse form. Automatically resolves classid GUIDs, generates proper XML structure, creates unique IDs, and handles event/handler/library registration.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| entity_name | string | Yes | - | Entity logical name (e.g., `account`) |
| form_id | string | Yes | - | GUID of the form to modify |
| operations | string | Yes | - | JSON array of operations: `add_fields`, `add_section`, `add_tab`, `add_library`, `add_event` |

## Returns

- Complete modified FormXML string ready to pass to `update_form`
- Validated field metadata with resolved classid GUIDs

## Operations

### Layout Operations

| Operation | Purpose | Required Params |
|-----------|---------|-----------------|
| `add_fields` | Add fields to an existing section | `tab`, `section`, `fields` |
| `add_section` | Add a new section (with fields) to an existing tab | `tab`, `label` |
| `add_tab` | Add a new tab (with sections and fields) to the form | `label` |

### Event Operations

| Operation | Purpose | Required Params |
|-----------|---------|-----------------|
| `add_library` | Add a web resource library reference to `<formLibraries>` | `library_name` |
| `add_event` | Add an event handler with auto library registration | `event_name`, `function_name`, `library_name` |

## add_library Parameters

| Parameter | Required | Default | Description |
|-----------|----------|---------|-------------|
| `library_name` | Yes | - | Web resource name (e.g., `new_/js/account.js`) |

## add_event Parameters

| Parameter | Required | Default | Description |
|-----------|----------|---------|-------------|
| `event_name` | Yes | - | Event name: `onload`, `onsave`, `onchange`, `ontabstatechange`, `onrecordselect` |
| `function_name` | Yes | - | JavaScript function name to call |
| `library_name` | Yes | - | Web resource containing the function |
| `pass_execution_context` | No | `false` | Pass execution context to handler |
| `parameters` | No | `""` | Additional parameters string |
| `enabled` | No | `true` | Whether handler is enabled |
| `target` | No | `"form"` | Where to attach: `"form"`, `"tab:{tab_name}"`, `"field:{field_name}"` |

## Event Type Resolution

| Event | eventType | target | attribute |
|-------|-----------|--------|-----------|
| `onload` | `ControlEvent` | form or tab | - |
| `onsave` | `ControlEvent` | form | - |
| `onchange` | `DataEvent` | form (with attribute) | field logical name |
| `ontabstatechange` | `ControlEvent` | tab | - |

## When to Use

- When adding fields to an existing section on a form
- When adding a new section (with fields) to an existing tab
- When adding a new tab (with sections and fields) to a form
- When adding form event handlers (onload, onsave, onchange)
- When registering web resource libraries on a form
- Instead of manually editing FormXML (error-prone classid resolution and event structure)

## Tips

- Always call `get_forms` first to find the form_id
- Use `get_metadata_entities` to verify field names exist before adding them
- Fields can be strings (`"createdon"`) or objects (`{"field":"createdon","label":"Date Created","disabled":true}`)
- section_columns: 1 (one field per row), 2 (two per row), 3 (three per row)
- After building, pass the returned FormXML to `update_form` to write it
- `add_event` auto-adds the library to `<formLibraries>` if not already present
- Duplicate libraries and handlers are detected and skipped automatically
- For field onchange events, use `target: "field:fieldname"` to set the correct `attribute` and `eventType`

## Example Operations JSON

### Add library
```json
[{"action": "add_library", "library_name": "new_/js/account.js"}]
```

### Add form onload
```json
[{"action": "add_event", "event_name": "onload", "function_name": "accOnload",
  "library_name": "new_/js/account.js", "pass_execution_context": true}]
```

### Add field onchange
```json
[{"action": "add_event", "event_name": "onchange", "function_name": "onNameChange",
  "library_name": "new_/js/account.js", "target": "field:name"}]
```

### Combined: library + multiple events
```json
[
  {"action": "add_library", "library_name": "new_/js/account.js"},
  {"action": "add_event", "event_name": "onload", "function_name": "accOnload",
   "library_name": "new_/js/account.js", "pass_execution_context": true},
  {"action": "add_event", "event_name": "onsave", "function_name": "accOnSave",
   "library_name": "new_/js/account.js"},
  {"action": "add_event", "event_name": "onchange", "function_name": "onNameChange",
   "library_name": "new_/js/account.js", "target": "field:name"}
]
```

## Generated XML Structure

### formLibraries
```xml
<formLibraries>
  <Library name="new_/js/account.js" libraryUniqueId="{guid}" />
</formLibraries>
```

### Form-level event (onload/onsave)
```xml
<events>
  <event name="onload" application="false" active="true" eventType="ControlEvent">
    <Handlers>
      <Handler functionName="accOnload" libraryName="new_/js/account.js"
               handlerUniqueId="{guid}" enabled="true" passExecutionContext="true">
        <dependencies>
          <dependency id="{library-guid}" />
        </dependencies>
      </Handler>
    </Handlers>
  </event>
</events>
```

### Field-level event (onchange)
```xml
<event name="onchange" application="false" active="true"
       eventType="DataEvent" attribute="name">
  <Handlers>
    <Handler functionName="onNameChange" libraryName="new_/js/account.js"
             handlerUniqueId="{guid}" enabled="true" passExecutionContext="false">
      <dependencies>
        <dependency id="{library-guid}" />
      </dependencies>
    </Handler>
  </Handlers>
</event>
```
