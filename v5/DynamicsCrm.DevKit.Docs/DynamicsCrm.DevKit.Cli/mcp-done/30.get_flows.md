# Proposal: get_flows MCP Tool

## Priority: 23 (Admin & Governance — Power Automate Cloud Flows)

## Phase: 4 — Admin & Governance

## Why This Tool Is Needed

Power Automate cloud flows (category=5 in the `workflow` table) are the modern automation backbone of Dynamics 365 / Power Platform. Understanding what flows exist, their trigger types, owners, status, and recent run history is critical for debugging failures, auditing automation, and planning schema changes that could break flows.

### Existing Tool Coverage

| Tool | Scope | Gap |
|------|-------|-----|
| `get_workflows` | Classic workflows only (category=0) | Explicitly excludes cloud flows |
| `get_rules` | Business rules only (category=2) | No flow coverage |
| `execute_fetchxml` | Can query `workflow` and `flowsession` | Requires knowledge of category values, flowsession join, status mappings |

### Current Pain (execute_fetchxml)

```xml
<!-- List cloud flows -->
<fetch>
  <entity name="workflow">
    <attribute name="name"/>
    <attribute name="statecode"/>
    <attribute name="ownerid"/>
    <attribute name="modifiedon"/>
    <filter>
      <condition attribute="category" operator="eq" value="5"/>
      <condition attribute="type" operator="eq" value="1"/>
      <condition attribute="statecode" operator="eq" value="1"/>
    </filter>
  </entity>
</fetch>

<!-- Get run history - requires separate query + knowing flowsession entity -->
<fetch>
  <entity name="flowsession">
    <attribute name="startedon"/>
    <attribute name="completedon"/>
    <attribute name="statuscode"/>
    <attribute name="errorcode"/>
    <attribute name="errormessage"/>
    <filter>
      <condition attribute="regardingobjectid" operator="eq" value="{flow-guid}"/>
    </filter>
    <order attribute="startedon" descending="true"/>
  </entity>
</fetch>
```

Must know: (1) category=5 for cloud flows, (2) type=1 for definitions (not activations/templates), (3) `flowsession` entity for run history, (4) `regardingobjectid` links flow runs to the flow, (5) `statuscode` mappings for flow sessions.

### Proposed (get_flows)

List mode:
```
status: active
```

Detail mode:
```
flow_id: d9e875bf-1c9b-ea11-a811-000d3a122b89
```

Runs mode:
```
flow_id: d9e875bf-1c9b-ea11-a811-000d3a122b89
action: runs
```

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `flow_id` | string | No | — | GUID of a specific cloud flow. When provided: shows detail + recent runs. When empty: list mode. |
| `action` | string | No | `"list"` | `"list"` (list/detail flows) or `"runs"` (show run history for a specific flow). `"runs"` requires `flow_id`. |
| `name_filter` | string | No | — | Filter flows by name (contains match). Only used in list mode. |
| `owner_filter` | string | No | — | Filter by owner display name or email (contains match). Only used in list mode. |
| `status` | string | No | `"active"` | `"active"` (on), `"draft"` (off), `"suspended"`, `"all"`. |
| `status_filter` | string | No | — | For runs mode: `"succeeded"`, `"failed"`, `"running"`, `"cancelled"`. Empty = all. |
| `minutes_ago` | int | No | `1440` | For runs mode: return runs from last N minutes. Default: 1440 (24 hours). Max: 43200 (30 days). |
| `max_records` | int | No | `50` | Max results (1–250). |

## Dataverse Tables

### workflow (Cloud Flows)

Cloud flows are stored in the `workflow` entity with `category = 5`.

| Attribute | Type | Description |
|-----------|------|-------------|
| `workflowid` | Guid | Primary key |
| `name` | String | Flow display name |
| `description` | String | User-provided description |
| `category` | OptionSet | Must be `5` (Modern Flow) |
| `type` | OptionSet | `1`=Definition, `2`=Activation, `3`=Template |
| `statecode` | OptionSet | `0`=Draft (Off), `1`=Activated (On), `2`=Suspended |
| `statuscode` | OptionSet | Status reason |
| `ownerid` | Lookup | Owner (user or team) |
| `ismanaged` | Boolean | Whether installed via managed solution |
| `clientdata` | String | JSON of flow definition + connectionReferences |
| `createdon` | DateTime | Created date |
| `modifiedon` | DateTime | Last modified date |
| `modifiedby` | Lookup | Last modified by |
| `solutionid` | Guid | Solution context |
| `uniquename` | String | Unique name for solution-aware flows |

### flowsession (Flow Run History)

Run history is stored in the `flowsession` entity.

| Attribute | Type | Description |
|-----------|------|-------------|
| `flowsessionid` | Guid | Primary key (run ID) |
| `name` | String | Run name |
| `regardingobjectid` | Lookup | Links to the parent `workflow` record |
| `startedon` | DateTime | When the run started |
| `completedon` | DateTime | When the run completed |
| `statecode` | OptionSet | `0`=Active, `1`=Inactive |
| `statuscode` | OptionSet | Status reason (see below) |
| `errorcode` | String | Error code (if failed) |
| `errormessage` | String | Error message (if failed) |
| `errordetails` | String | Detailed error info |
| `runduration` | Integer | Total run duration |
| `runexecutionduration` | Integer | Execution duration |
| `runwaitduration` | Integer | Wait duration |
| `ownerid` | Lookup | Owner |
| `triggertype` | String | What triggered this run |
| `context` | String | Run context data |

### flowsession statuscode Values

| Value | Label | Description |
|-------|-------|-------------|
| 0 | NotSpecified | Status not set |
| 1 | Paused | Run is paused |
| 2 | Running | Currently executing |
| 3 | Waiting | Waiting for input/approval |
| 4 | Succeeded | Completed successfully |
| 5 | Skipped | Skipped (trigger condition not met) |
| 6 | Suspended | Suspended |
| 7 | Cancelled | Cancelled by user |
| 8 | Failed | Failed with error |

## Dataverse API

### List Mode FetchXML

```csharp
var fetchXml = $@"
<fetch top='{max_records}'>
  <entity name='workflow'>
    <attribute name='workflowid'/>
    <attribute name='name'/>
    <attribute name='description'/>
    <attribute name='statecode'/>
    <attribute name='statuscode'/>
    <attribute name='ownerid'/>
    <attribute name='ismanaged'/>
    <attribute name='createdon'/>
    <attribute name='modifiedon'/>
    <attribute name='modifiedby'/>
    <attribute name='uniquename'/>
    <filter type='and'>
      <condition attribute='category' operator='eq' value='5'/>
      <condition attribute='type' operator='eq' value='1'/>
      {(status == ""active"" ? ""<condition attribute='statecode' operator='eq' value='1'/>"" :
        status == ""draft"" ? ""<condition attribute='statecode' operator='eq' value='0'/>"" :
        status == ""suspended"" ? ""<condition attribute='statecode' operator='eq' value='2'/>"" : """")}
      {(!string.IsNullOrEmpty(name_filter) ? $""<condition attribute='name' operator='like' value='%{name_filter}%'/>"" : """")}
    </filter>
    <order attribute='name'/>
  </entity>
</fetch>";
```

### Detail Mode — Flow Record

```csharp
var fetchApi = $@"
<fetch>
  <entity name='workflow'>
    <all-attributes/>
    <filter>
      <condition attribute='workflowid' operator='eq' value='{flow_id}'/>
      <condition attribute='category' operator='eq' value='5'/>
    </filter>
  </entity>
</fetch>";
```

### Runs Mode — Flow Sessions

```csharp
var fromDate = DateTime.UtcNow.AddMinutes(-minutes_ago).ToString("o");
var fetchRuns = $@"
<fetch top='{max_records}'>
  <entity name='flowsession'>
    <attribute name='flowsessionid'/>
    <attribute name='name'/>
    <attribute name='startedon'/>
    <attribute name='completedon'/>
    <attribute name='statuscode'/>
    <attribute name='errorcode'/>
    <attribute name='errormessage'/>
    <attribute name='runduration'/>
    <attribute name='triggertype'/>
    <filter type='and'>
      <condition attribute='regardingobjectid' operator='eq' value='{flow_id}'/>
      <condition attribute='startedon' operator='ge' value='{fromDate}'/>
      {(!string.IsNullOrEmpty(status_filter) ? BuildStatusFilter(status_filter) : """")}
    </filter>
    <order attribute='startedon' descending='true'/>
  </entity>
</fetch>";
```

## Status Filter Mapping (Runs Mode)

```csharp
private static string BuildStatusFilter(string statusFilter)
{
    return statusFilter.Trim().ToLowerInvariant() switch
    {
        "succeeded" => "<condition attribute='statuscode' operator='eq' value='4'/>",
        "failed" => "<condition attribute='statuscode' operator='eq' value='8'/>",
        "running" => "<condition attribute='statuscode' operator='eq' value='2'/>",
        "cancelled" => "<condition attribute='statuscode' operator='eq' value='7'/>",
        "waiting" => "<condition attribute='statuscode' operator='eq' value='3'/>",
        "paused" => "<condition attribute='statuscode' operator='eq' value='1'/>",
        "skipped" => "<condition attribute='statuscode' operator='eq' value='5'/>",
        "suspended" => "<condition attribute='statuscode' operator='eq' value='6'/>",
        _ => ""
    };
}
```

## Implementation Notes

1. **DI**: Constructor injects `ServiceClient` (same pattern as `GetWorkflowsTool`)
2. **No DevKit CLI task**: Unlike `get_workflows` which mirrors classic workflow logic, there is no existing CLI task for Power Automate flows. All Dataverse queries are new.
3. **Two entities**: `workflow` (category=5) for flow definitions, `flowsession` for run history
4. **Owner filter**: Uses `ownerid` lookup — may need a sub-query to resolve email to systemuser ID
5. **Run duration**: `flowsession.runduration` is in milliseconds — format as human-readable (e.g., "45s", "2m 15s")
6. **Detail mode auto-includes runs**: When `flow_id` is provided in list action, automatically include last 5 runs for quick overview
7. **Supersedes**: This tool supersedes the earlier `11.get_flow_runs.md` proposal by providing a more complete and structured implementation with proper separation of list/detail/runs modes

## Note on Existing Proposal

File `11.get_flow_runs.md` in this folder contains an earlier, simpler proposal that combined flow listing and run history into a single `get_flow_runs` tool. This `get_flows` proposal is the refined version with:
- Proper three-mode design (list/detail/runs) matching `get_workflows` pattern
- Detailed `flowsession` attribute reference from Microsoft docs
- Structured output model
- Status code mappings for both `workflow.statecode` and `flowsession.statuscode`
- Owner filtering support
