# Proposal: get_flow_runs MCP Tool

## Priority: 12 (Operations — Power Automate flow inspection)

## Phase: 3 — ALM & Operations (Long Term)

## Analysis Reference

- **Gap #9** in MCP-Analysis-2026.md
- **Impact**: 🟡 Medium
- **Effort**: Medium

## Why This Tool Is Needed

Power Automate cloud flows are integral to D365 solutions. When flows fail, developers need to inspect run history. Currently, they must navigate the Power Automate portal. An MCP tool would provide quick flow status checks from the AI workspace.

## Purpose

List cloud flows and their recent run history with status and error details.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| action | string | No | `"list"` | `"list"` (list flows) or `"runs"` (show run history). |
| flow_id | string | No | `""` | For runs: GUID of the flow. |
| name_filter | string | No | `""` | Filter flows by name (contains match). |
| solution_name | string | No | `""` | Filter by solution. |
| status_filter | string | No | `""` | For runs: `"Succeeded"`, `"Failed"`, `"Running"`. |
| minutes_ago | int | No | 1440 | For runs: last N minutes. Default: 24 hours. |
| max_records | int | No | 50 | Max results. |

## Dataverse Tables

| Table | Purpose |
|-------|---------|
| `workflow` | Cloud flows (category = 5) |
| `flowsession` | Flow run history |

## Response Format (Compact)

### List flows
```
[CloudFlows] 8 total

flowId	name	status	trigger	lastRun
abc-123	Notify on Case Create	Active	When record created	2026-03-31 09:15
def-456	Sync Accounts to ERP	Active	Scheduled (daily)	2026-03-31 06:00
```

### Run history
```
[FlowRuns] Sync Accounts to ERP (last 24h, 3 runs)

runId	startedOn	status	duration	error
run-001	2026-03-31 06:00	Succeeded	45s	-
run-002	2026-03-30 06:00	Failed	12s	Timeout connecting to ERP endpoint
run-003	2026-03-29 06:00	Succeeded	38s	-
```

## Tool Description for AI

```
List Power Automate cloud flows and their recent run history.

PARAMETERS:
- action: 'list' (list flows) or 'runs' (show run history).
- flow_id: For runs: flow GUID.
- name_filter: Filter flows by name.
- solution_name: Filter by solution.
- status_filter: For runs: 'Succeeded', 'Failed', 'Running'.
- minutes_ago: For runs: time window (default: 1440 = 24h).

WHEN TO USE:
- Debugging flow failures ("my flow stopped working")
- Checking flow run history and error messages
- Auditing which flows are active in a solution
- Investigating automation issues

TIPS:
- Cloud flows are workflow records with category=5
- Use flowsession table for run history
- Failed runs include error details in the output
```
