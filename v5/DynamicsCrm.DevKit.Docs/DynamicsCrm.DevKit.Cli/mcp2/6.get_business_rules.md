## Why This Tool Is Needed

Business Rules are client-side logic that runs in the CRM form without code. They show/hide fields, set values, set required levels, and show error messages. Developers need to understand them when debugging form behavior, avoiding conflicts with JS scripts, or auditing entity logic.

## Purpose

List business rules for a Dataverse entity with their scope, conditions, and actions.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| entity_name | string | Yes | - | Entity logical name. |
| rule_id | string | No | `""` | GUID for full detail. Leave empty to list all. |
| status | string | No | `""` | `"active"`, `"draft"`, or empty for all. |
| max_records | int | No | 50 | Max rules to return. |

## Dataverse Tables

Business rules are `workflow` records with `category = 2`.

### FetchXML Query

```xml
<fetch>
  <entity name="workflow">
    <attribute name="workflowid" />
    <attribute name="name" />
    <attribute name="primaryentity" />
    <attribute name="scope" />
    <attribute name="statecode" />
    <attribute name="clientdata" />
    <filter type="and">
      <condition attribute="category" operator="eq" value="2" />
      <condition attribute="primaryentity" operator="eq" value="{entity_name}" />
    </filter>
    <order attribute="name" />
  </entity>
</fetch>
```

### Scope Values

| Value | Scope |
|-------|-------|
| 1 | Entity (all forms) |
| 2 | All Forms |
| 3 | Specific Form |

## Response Format (Compact)

### List mode
```
[BusinessRules] account (3 rules)

ruleId	name	scope	status	modifiedOn
abc-123	Set Required on Revenue	Entity	Active	2026-03-15
def-456	Hide Credit Limit	All Forms	Active	2026-03-10
```

### Detail mode
```
[BusinessRule] Set Required on Revenue
RuleId: abc-123
Entity: account
Scope: Entity
Status: Active

[Conditions]
IF industrycode = "Banking" (value: 6)

[Actions]
THEN Set Required: revenue = Required
AND Set Value: creditlimit = 1000000
```

## Tool Description for AI

```
List business rules (client-side logic) for a Dataverse entity.

PARAMETERS:
- entity_name (required): Entity logical name (e.g., 'account').
- rule_id: GUID for full detail (conditions + actions). Leave empty to list all.
- status: Filter by 'active' or 'draft'.
- max_records: Maximum rules (default: 50).

RETURNS:
- List mode: Table of rules with name, scope, status
- Detail mode: Conditions and actions parsed from clientdata

WHEN TO USE:
- Debugging form behavior (fields hiding/showing unexpectedly)
- Understanding existing logic before adding JavaScript
- Auditing what logic runs on an entity

TIPS:
- Business rules run client-side, not server-side
- They execute BEFORE JavaScript form events
- Scope 'Entity' means the rule runs on ALL forms
```

## Implementation Notes

- Query `workflow` with `category = 2`
- Parse `clientdata` JSON for conditions and actions in detail mode
- Handle both active (statecode=1) and draft (statecode=0) states
