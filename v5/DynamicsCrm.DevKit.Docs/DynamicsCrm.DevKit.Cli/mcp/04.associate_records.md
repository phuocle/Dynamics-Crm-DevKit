# Proposal: associate_records MCP Tool

## Priority: 10 (Data Operations -- N:N relationship management)

## Why This Tool Is Needed

Many-to-many (N:N) relationships are managed through Associate/Disassociate operations, which are different from standard CRUD. Currently AI must use `execute_webapi` with manually constructed `$ref` URLs, which is complex and error-prone.

Common scenarios: adding contacts to a marketing list, assigning security roles to users, linking products to price lists.

## Purpose

Associate or disassociate records through N:N relationships.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| action | string | Yes | - | `"associate"` or `"disassociate"`. |
| entity_name | string | Yes | - | Entity logical name of the primary record (e.g., `"account"`). |
| record_id | string | Yes | - | GUID of the primary record. |
| relationship_name | string | Yes | - | Schema name of the N:N relationship (e.g., `"contactleads_association"`). Use `get_entity_metadata` to find relationship names. |
| related_entity | string | Yes | - | Entity logical name of the related record(s) (e.g., `"contact"`). |
| related_ids | string | Yes | - | Comma-separated GUIDs of related records to associate/disassociate. |

## Dataverse API

### Associate (Web API)

```
POST /accounts({record_id})/contact_customer_accounts/$ref
Body: {
  "@odata.id": "contacts({related_id})"
}
```

### Disassociate (Web API)

```
DELETE /accounts({record_id})/contact_customer_accounts({related_id})/$ref
```

### SDK Equivalent

```csharp
// Associate
var request = new AssociateRequest
{
    Target = new EntityReference(entityName, recordId),
    RelatedEntities = new EntityReferenceCollection(
        relatedIds.Select(id => new EntityReference(relatedEntity, id)).ToList()
    ),
    Relationship = new Relationship(relationshipName)
};
_serviceClient.Execute(request);

// Disassociate
var request = new DisassociateRequest
{
    Target = new EntityReference(entityName, recordId),
    RelatedEntities = new EntityReferenceCollection(
        relatedIds.Select(id => new EntityReference(relatedEntity, id)).ToList()
    ),
    Relationship = new Relationship(relationshipName)
};
_serviceClient.Execute(request);
```

## Response Format (Compact)

### Associate success
```
[Associate] account (abc-123)
Relationship: contact_customer_accounts
Related: contact (3 records)
- def-456
- ghi-789
- jkl-012
Status: Associated successfully
```

### Disassociate success
```
[Disassociate] account (abc-123)
Relationship: contact_customer_accounts
Related: contact (1 record)
- def-456
Status: Disassociated successfully
```

### Error
```
[Error] Association failed
Relationship: invalid_relationship_name
Message: Relationship 'invalid_relationship_name' does not exist for entity 'account'
Tip: Use get_entity_metadata to find correct N:N relationship schema names
```

## Tool Description for AI

```
Associate or disassociate records through N:N (many-to-many) relationships.
Use this to link/unlink records like adding contacts to a marketing list,
assigning roles to users, or connecting products to price lists.

PARAMETERS:
- action (required): 'associate' or 'disassociate'.
- entity_name (required): Primary entity logical name (e.g., 'account').
- record_id (required): GUID of the primary record.
- relationship_name (required): Schema name of the N:N relationship.
  Use get_entity_metadata to find N:N relationship names.
- related_entity (required): Related entity logical name (e.g., 'contact').
- related_ids (required): Comma-separated GUIDs of related records.

RETURNS:
- Action performed (Associated/Disassociated)
- Record count and IDs

WHEN TO USE:
- To add records to a many-to-many relationship
- Adding contacts to marketing lists
- Assigning security roles to users/teams
- Linking products to price lists
- Any N:N relationship management

TIPS:
- Use get_entity_metadata to find N:N relationship schema names (look for intersectEntity)
- You can associate/disassociate multiple records in a single call (comma-separated IDs)
- 1:N relationships are managed through lookup fields (use update_record instead)
- If relationship_name is wrong, the error will tell you it doesn't exist
```

## Implementation Notes

- Use `AssociateRequest` / `DisassociateRequest` from `Microsoft.Xrm.Sdk.Messages`
- Parse `related_ids` into list of GUIDs
- Both requests accept `EntityReferenceCollection` for batch associate/disassociate
- Validate all GUIDs before executing
- Handle common errors: relationship not found, records already associated, record not found
