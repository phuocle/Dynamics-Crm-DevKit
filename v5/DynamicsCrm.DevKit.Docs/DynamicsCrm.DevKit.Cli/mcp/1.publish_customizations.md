# Proposal: publish_customizations MCP Tool

## Priority: 1 (BLOCKER -- required for any metadata modification workflow)

## Why This Tool Is Needed

Without `publish_customizations`, AI cannot complete **any** metadata modification workflow end-to-end. After creating/updating entities, attributes, forms, views, option sets, or relationships, changes are NOT visible to users until published. This is the easiest quick win -- simple implementation, massive impact.

Currently, AI must use `execute_webapi` with manually constructed `PublishXml` requests, which is error-prone and requires knowledge of the XML format.

## Competitor Analysis

- **No competitor** has a dedicated publish tool (all rely on raw API calls)
- AppMaker (Greg.Xrm.Mcp) uses `IPublishXmlBuilder` service internally but doesn't expose it as a standalone tool

## Purpose

Publish Dataverse customizations (specific entities or all). This makes metadata changes (entity definitions, form layouts, view definitions, option sets, relationships, ribbons, sitemaps, web resources) visible to end users.

Two modes:
1. **Publish specific entities** -- publish only named entities (faster, targeted)
2. **Publish all** -- publish everything (slower, but guaranteed complete)

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| entities | string | No | (empty) | Comma-separated entity logical names to publish. E.g., `"account,contact,lead"`. Leave empty to publish ALL customizations. |
| include_global_optionset | bool | No | false | Also publish global option sets. Only applies when `entities` is specified. |
| include_sitemap | bool | No | false | Also publish the sitemap. Only applies when `entities` is specified. |

## Dataverse API

### Publish Specific Entities

```
POST /PublishXml
Body: {
  "ParameterXml": "<importexportxml>
    <entities>
      <entity>account</entity>
      <entity>contact</entity>
    </entities>
    <optionsets />
    <sitemaps />
  </importexportxml>"
}
```

### Publish All

```
POST /PublishAllXml
Body: {}
```

### SDK Equivalent

```csharp
// Publish specific
var request = new PublishXmlRequest {
    ParameterXml = "<importexportxml><entities><entity>account</entity></entities></importexportxml>"
};
_serviceClient.Execute(request);

// Publish all
_serviceClient.Execute(new PublishAllXmlRequest());
```

## Response Format (Compact)

### Success -- Specific entities
```
[Publish] 3 entities
Entities: account, contact, lead
GlobalOptionSets: no
SiteMap: no
Status: Published successfully
Duration: 4.2s
```

### Success -- All
```
[Publish] All customizations
Status: Published successfully
Duration: 12.8s
```

### Error
```
[Error] Publish failed
Message: {error message from Dataverse}
```

## McpServerTool Attribute

```csharp
[McpServerTool(
    Name = "publish_customizations",
    ReadOnly = false,
    Destructive = false)]
```

Note: `ReadOnly = false` because publishing changes the runtime state (makes unpublished changes visible). `Destructive = false` because it doesn't delete data.

## Tool Description for AI

```
Publish Dataverse customizations to make metadata changes visible to users.
After creating/updating entities, attributes, forms, views, option sets, or
relationships, changes are NOT visible until published.

PARAMETERS:
- entities: Comma-separated entity logical names (e.g., 'account,contact').
  Leave empty to publish ALL customizations.
- include_global_optionset: Also publish global option sets (default: false)
- include_sitemap: Also publish the sitemap (default: false)

RETURNS:
- Published entity count and names
- Duration of publish operation
- Status (success/error)

WHEN TO USE:
- After ANY metadata change (create/update entity, attribute, form, view,
  option set, relationship, web resource, sitemap)
- When user reports "I made changes but they're not showing up"
- As the final step in any customization workflow

TIPS:
- Publish specific entities when possible (faster than publish all)
- PublishAll can take 30+ seconds on large environments
- This is REQUIRED after using execute_webapi to modify metadata
```

## Implementation Notes

- Use `PublishXmlRequest` for specific entities (faster, targeted)
- Use `PublishAllXmlRequest` for "publish all" mode
- Build the `ParameterXml` string from the comma-separated `entities` parameter
- Measure and report duration using `Stopwatch`
- Timeout: PublishAll can take 60+ seconds on large environments -- use extended timeout
- This tool is idempotent -- publishing already-published changes is harmless
