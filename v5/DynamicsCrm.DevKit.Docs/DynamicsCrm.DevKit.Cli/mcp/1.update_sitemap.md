## Why This Tool Is Needed

The SiteMap defines the **navigation structure** of a Model-Driven App — what areas, groups, and sub-areas (entity links, dashboards, web resources, URLs) appear in the left-hand nav. DevKit already:

1. Has the SiteMap XSD resource (`schema://sitemapxml`) with `SiteMap.xsd` + `SiteMapType.xsd`
2. **Blocks** SiteMap writes via `execute_webapi` (deliberate safety guardrail)
3. References `update_sitemap (coming soon)` in the codebase

But the actual tool doesn't exist — leaving a dead-end where AI can read the SiteMap schema but cannot modify it safely.

### Current Pain Point

Without this tool, developers must:
1. Export the solution manually
2. Edit `SiteMap.xml` in a text editor
3. Re-import the solution
4. Or use `execute_webapi` which is **blocked** by DevKit's safety layer

### Competitor Analysis

**No competitor** has a SiteMap management tool — this would be a **first-in-ecosystem** feature.

## Purpose

Read, update, and undo SiteMap XML with automatic backup, XSD validation, and publishing. Follows the exact same safety pattern as `update_form` and `update_view`.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| action | string | No | `"update"` | `"update"` (modify SiteMap XML), `"undo"` (restore from backup). |
| app_module_id | string | Yes | - | GUID of the Model-Driven App (appmodule) whose SiteMap to modify. Use `execute_fetchxml` on `appmodule` to find app IDs. |
| sitemapxml | string | Yes* | - | For `update`: the new SiteMap XML content. For `undo`: the file path to the backup `.json` file. |
| validate | bool | No | true | Validate SiteMap XML against XSD schema before writing. |
| backup | bool | No | true | Save current SiteMap XML to local backup before overwriting. |
| auto_publish | bool | No | true | Publish the app module after changes. |

## Execution Flow

```
┌─────────────────────────────────────────────────────────────────┐
│ 1. RETRIEVE current SiteMap for the app module                  │
│    └─ Query appmodule → sitemapid → sitemap entity              │
│    └─ If app not found → error with tip                         │
├─────────────────────────────────────────────────────────────────┤
│ 2. BACKUP current SiteMap XML to local file (if backup=true)    │
│    └─ Path: .devkit/backups/sitemaps/{appname}_{id}_{ts}.json   │
│    └─ Include app name, SiteMap ID in backup metadata           │
├─────────────────────────────────────────────────────────────────┤
│ 3. VALIDATE new SiteMap XML against XSD (if validate=true)      │
│    └─ Load SiteMap.xsd + SiteMapType.xsd from embedded resources│
│    └─ If invalid → error with validation details + DO NOT write │
├─────────────────────────────────────────────────────────────────┤
│ 4. UPDATE SiteMap record in Dataverse                           │
│    └─ Set sitemap.sitemapxml = new SiteMap XML                  │
│    └─ serviceClient.Update(sitemap)                             │
├─────────────────────────────────────────────────────────────────┤
│ 5. PUBLISH app module (if auto_publish=true)                    │
│    └─ PublishXmlRequest for the sitemap/app                     │
├─────────────────────────────────────────────────────────────────┤
│ 6. RETURN result with backup file path for rollback reference   │
└─────────────────────────────────────────────────────────────────┘
```

## Dataverse Tables

| Table | Entity Set | Purpose |
|-------|-----------|---------|
| `appmodule` | `/appmodules` | Model-Driven App definitions |
| `sitemap` | `/sitemaps` | SiteMap XML storage |
| `appmodulesitemap` | N:N intersect | App-to-SiteMap mapping |

### Retrieve Current SiteMap

```csharp
// Option 1: Direct from appmodule's sitemap
var app = serviceClient.Retrieve("appmodule", appModuleId,
    new ColumnSet("uniquename", "name"));

// Get sitemap via relationship
var query = new QueryExpression("sitemap")
{
    ColumnSet = new ColumnSet("sitemapxml", "sitemapname", "sitemapid"),
    LinkEntities =
    {
        new LinkEntity("sitemap", "appmodulesitemap", "sitemapid", "sitemapid", JoinOperator.Inner)
        {
            LinkEntities =
            {
                new LinkEntity("appmodulesitemap", "appmodule", "appmoduleid", "appmoduleid", JoinOperator.Inner)
                {
                    LinkCriteria = new FilterExpression
                    {
                        Conditions = { new ConditionExpression("appmoduleid", ConditionOperator.Equal, appModuleId) }
                    }
                }
            }
        }
    }
};
var sitemap = serviceClient.RetrieveMultiple(query).Entities.FirstOrDefault();
```

### Update SiteMap

```csharp
var update = new Entity("sitemap", sitemapId);
update["sitemapxml"] = newSiteMapXml;
serviceClient.Update(update);
```

### Publish App Module

```csharp
var publishRequest = new PublishXmlRequest
{
    ParameterXml = $"<importexportxml><sitemaps><sitemap></sitemap></sitemaps></importexportxml>"
};
serviceClient.Execute(publishRequest);
```

## Tool Description for AI

```
Update a Model-Driven App's SiteMap XML with automatic backup, XSD validation, and publishing.
This completes the UI customization trilogy: Forms (update_form) → Views (update_view) → SiteMap (update_sitemap).

PARAMETERS:
- action: 'update' (default) or 'undo' (restore from backup).
- app_module_id (required): GUID of the Model-Driven App. Query appmodule table to find IDs.
- sitemapxml: For 'update': the new SiteMap XML. For 'undo': backup file path.
- validate: Validate against XSD before writing (default: true).
- backup: Save current SiteMap XML to backup before overwriting (default: true).
- auto_publish: Publish the app after changes (default: true).

RETURNS:
- Update status (success/blocked/error)
- Validation results
- Backup file path (for rollback)

WORKFLOW:
1. Query appmodule to find the app and its SiteMap
2. Read current SiteMap XML
3. Modify as needed (refer to schema://sitemapxml for structure)
4. Call update_sitemap with the modified XML
5. Tool auto-handles: backup → validate → update → publish

WHEN TO USE:
- To add/remove/rearrange navigation areas, groups, and sub-areas
- To add a new entity to app navigation
- To customize app navigation structure
- After creating a new entity that needs to appear in the app

SAFETY:
- Auto-backup before ANY modification
- XSD validation blocks invalid XML
- Undo action restores from backup
- If backup fails, update is BLOCKED (fail-safe)

TIPS:
- Read schema://sitemapxml for SiteMap XML structure and rules
- SiteMap structure: SiteMap > Area > Group > SubArea
- SubArea Entity attribute links to a Dataverse entity
- Set auto_publish=false when making multiple changes
- Backup files at: .devkit/backups/sitemaps/{appname}_{id}_{timestamp}.sitemap.json
```

## Implementation Notes

- Follow the **exact same safety pattern** as `update_form` and `update_view`
- SiteMap XSD validation requires **both** `SiteMap.xsd` and `SiteMapType.xsd` (already embedded)
- The `execute_webapi` blocked endpoint for sitemaps should reference this tool
- Backup format: JSON with `{ sitemapxml, appname, sitemapid, timestamp }`
- Strip XML declaration before writing
- Modern model-driven apps may use the new app designer — this tool handles classic SiteMap XML

## Pre-requisite
