# Proposal: get_apis MCP Tool

## Priority: 22 (Admin & Governance — Custom API Management)

## Phase: 4 — Admin & Governance

## Why This Tool Is Needed

Custom APIs are the modern replacement for Custom Actions in Dataverse. They are registered via `customapi` + `customapirequestparameter` + `customapiresponseproperty` entities and support richer metadata than legacy Actions (bound/unbound, private/public, plugin binding, request/response parameters with type info). Understanding what Custom APIs exist, their parameters, and their plugin bindings is critical for plugin developers, integration builders, and AI agents orchestrating Dataverse operations.

### Current Pain (get_messages + execute_fetchxml)

`get_messages` only returns Custom API **names** — no parameters, no response properties, no binding type, no plugin association, no owner info. To get full details, you must write complex FetchXML joining 3 entities:

```xml
<fetch>
  <entity name="customapi">
    <attribute name="uniquename"/>
    <attribute name="name"/>
    <attribute name="bindingtype"/>
    <attribute name="boundentitylogicalname"/>
    <attribute name="isfunction"/>
    <attribute name="isprivate"/>
    <attribute name="allowedcustomprocessingsteptype"/>
    <attribute name="plugintypeid"/>
    <attribute name="description"/>
    <attribute name="statuscode"/>
    <filter>
      <condition attribute="uniquename" operator="eq" value="v4_AccountCustomApi"/>
    </filter>
    <link-entity name="customapirequestparameter" from="customapiid" to="customapiid" link-type="outer" alias="req">
      <attribute name="uniquename"/>
      <attribute name="type"/>
      <attribute name="isoptional"/>
      <attribute name="logicalentityname"/>
      <attribute name="description"/>
    </link-entity>
    <link-entity name="customapiresponseproperty" from="customapiid" to="customapiid" link-type="outer" alias="res">
      <attribute name="uniquename"/>
      <attribute name="type"/>
      <attribute name="logicalentityname"/>
      <attribute name="description"/>
    </link-entity>
  </entity>
</fetch>
```

Must know: (1) `bindingtype` values (0=Global, 1=Entity, 2=EntityCollection), (2) `type` values for parameters (0=Boolean, 1=DateTime, ..., 10=Entity, etc.), (3) `allowedcustomprocessingsteptype` values (0=None, 1=Async, 2=Sync), (4) join structure across 3 entities.

### Proposed (get_apis)

```
api_name: v4_AccountCustomApi
```

Or list mode:

```
entity_name: account
```

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `api_name` | string | No | — | Unique name of a specific Custom API to get full detail (parameters + response properties + plugin binding). |
| `entity_name` | string | No | — | Filter by bound entity logical name. Empty + no api_name = list all Custom APIs. |
| `include_microsoft` | bool | No | `false` | Include Microsoft-provided APIs (prefixed `msdyn_`, `mspp_`, etc.). Default false to reduce noise. |
| `status` | string | No | `active` | `active`, `inactive`, `all`. |
| `max_records` | int | No | 100 | Max results (1–500). Only used in list mode. |

## Dataverse API

### List Mode

```csharp
var fetchXml = $@"
<fetch count='{max_records}'>
  <entity name='customapi'>
    <attribute name='customapiid'/>
    <attribute name='uniquename'/>
    <attribute name='name'/>
    <attribute name='displayname'/>
    <attribute name='bindingtype'/>
    <attribute name='boundentitylogicalname'/>
    <attribute name='isfunction'/>
    <attribute name='isprivate'/>
    <attribute name='allowedcustomprocessingsteptype'/>
    <attribute name='plugintypeid'/>
    <attribute name='statuscode'/>
    <attribute name='modifiedon'/>
    <filter type='and'>
      {(entity_name != null ? $""<condition attribute='boundentitylogicalname' operator='eq' value='{entity_name}'/>"" : """")}
      {(status == ""active"" ? ""<condition attribute='statuscode' operator='eq' value='1'/>"" : status == ""inactive"" ? ""<condition attribute='statuscode' operator='eq' value='2'/>"" : """")}
    </filter>
    <order attribute='uniquename'/>
  </entity>
</fetch>";
```

### Detail Mode

```csharp
// Query 1: Custom API record
var fetchApi = $@"
<fetch>
  <entity name='customapi'>
    <all-attributes/>
    <filter>
      <condition attribute='uniquename' operator='eq' value='{api_name}'/>
    </filter>
  </entity>

// Query 2: Request parameters
var fetchParams = $@"
<fetch>
  <entity name='customapirequestparameter'>
    <attribute name='uniquename'/>

      <condition attribute='customapiid' operator='eq' value='{customApiId}'/>
    </filter>
    <order attribute='uniquename'/>
  </entity>

// Query 3: Response properties
var fetchResponse = $@"
<fetch>
  <entity name='customapiresponseproperty'>
    <attribute name='uniquename'/>
    <attribute name='name'/>
    <attribute name='type'/>
    <attribute name='logicalentityname'/>

    <filter>
      <condition attribute='customapiid' operator='eq' value='{customApiId}'/>
    </filter>
    <order attribute='uniquename'/>
  </entity>
</fetch>";
```

## Type Reference

### Custom API Parameter/Response Types

| Value | Type | Description |
|-------|------|-------------|
| 0 | Boolean | True/False |
| 1 | DateTime | Date and time |
| 2 | Decimal | Decimal number |
| 3 | Entity | Full entity record |
| 4 | EntityCollection | Collection of entity records |
| 5 | EntityReference | Reference to a record (table + GUID) |
| 6 | Float | Floating point number |
| 7 | Integer | Whole number |
| 8 | Money | Currency value |
| 9 | Picklist | Option set value |
| 10 | String | Text |
| 11 | StringArray | Array of strings |
| 12 | Guid | Unique identifier |

### Binding Type

| Value | Type | Description |
|-------|------|-------------|
| 0 | Global | Not bound to any entity (unbound action/function) |
| 1 | Entity | Bound to a single entity record |
| 2 | EntityCollection | Bound to an entity collection |

### Allowed Processing Step Type

| Value | Type | Description |
|-------|------|-------------|
| 0 | None | No plugin allowed |
| 1 | Async Only | Only async plugin execution |
| 2 | Sync and Async | Both sync and async plugin execution |

## Relationship to Existing Tools

| Tool | What it does | Gap filled by get_apis |
|------|-------------|----------------------|
| `get_messages` | Lists SDK messages, Custom Actions, Custom API **names** | Only returns names — no parameters, no response properties, no binding info |
| `execute_fetchxml` | Can query `customapi` entity directly | Requires knowledge of 3 joined entities and type value mappings |
| `get_metadata_entities` | Shows entity attributes and relationships | Does not show Custom APIs registered on an entity |

## Filter Logic for Microsoft-provided APIs

When `include_microsoft` is `false` (default), exclude APIs whose `uniquename` starts with common Microsoft prefixes:

```csharp
var msftPrefixes = new[] { "msdyn_", "mspp_", "msdynce_", "msdyncrm_", "Microsoft." };
```

This dramatically reduces noise — production environments can have 200+ Microsoft-provided Custom APIs that are rarely relevant to developer queries.

## Implementation Notes

1. **DI**: Constructor injects `MetadataService` (same pattern as `GetMessagesTool`)
2. **Helper class**: Create `CustomApiDiscoveryHelper.cs` in `Mcp\Tools\Helper\` for query + format logic
3. **Output**: Compact format via `CompactFormatter` — TSV for list, Key-Value for detail
4. **Reuse**: `MetadataService.GetCustomApisAsync()` already queries `customapi` — extend it or add new methods for parameter/response queries
5. **TaskServer integration**: The CLI's `TaskServer` already queries `customapi` for deployment (see `LoadAllCustomApisAsync` and `DeployCustomApiStepAsync`) — the MCP tool provides read-only discovery of the same data
