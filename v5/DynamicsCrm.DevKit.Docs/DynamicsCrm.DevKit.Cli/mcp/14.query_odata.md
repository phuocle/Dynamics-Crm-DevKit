# Proposal: query_odata MCP Tool

## Priority: 1 (Core Query — Most requested missing capability)

## Phase: 1 — Core Operations

## Why This Tool Is Needed (vs execute_webapi)

`execute_webapi` is a **raw HTTP tool** — the AI must manually construct OData URLs, handle pagination cookies, add Prefer headers, and parse raw JSON. A dedicated `query_odata` tool provides a **guided, validated, high-level interface** that handles all OData complexity automatically.

### Gap Comparison

| Aspect | `execute_webapi` (raw) | `query_odata` (guided) |
|--------|----------------------|----------------------|
| **URL** | Manual: `accounts?$select=name&$filter=revenue gt 1000&$top=50` | Auto: separate `entity_name`, `select`, `filter`, `top` params |
| **Pagination** | Manual: parse `@odata.nextLink`, re-call tool | Auto: `get_all=true` auto-pages (up to 50K records) |
| **Formatted values** | Manual: add `Prefer: odata.include-annotations="*"` header | Auto: `formatted_values=true` param |
| **$count** | Manual: append `$count=true` to URL string | Auto: `count=true` param |
| **$expand** | Manual: construct full expand syntax | Auto: `expand` param |
| **$apply (aggregation)** | Manual: construct `$apply=groupby((...),aggregate(...))` | Auto: `apply` param |
| **Response** | Raw OData envelope + `@odata.context` + metadata (truncated at 200 lines) | Clean records array + count + paging info |
| **Token cost** | ~500-2000 tokens per response (includes OData metadata noise) | ~200-500 tokens (clean data only) |
| **Query guardrails** | None — AI can accidentally pull 100K records | Auto-warns: missing `$select`, missing `$filter`, `$top > 5000` |
| **Error handling** | Raw HTTP status text | Typed: `SCHEMA_MISMATCH` (404), `PERMISSIONS` (401/403) |
| **Entity name** | Must know `entitySetName` (plural OData name, e.g., `accounts`) | Uses `entity_name` (logical name, e.g., `account`) — auto-resolves |
| **Learning curve** | AI must know OData URL syntax | AI uses simple params — no URL knowledge needed |

### Real Example: "Get top 10 active accounts with revenue > $1M"

**With `execute_webapi` (current — 5 pain points):**
```
method: GET
url: accounts?$select=name,revenue,primarycontactid&$filter=statecode eq 0 and revenue gt 1000000&$top=10&$orderby=revenue desc
headers: {"Prefer": "odata.include-annotations=\"OData.Community.Display.V1.FormattedValue\""}
```
AI must: (1) know `accounts` not `account`, (2) construct URL manually, (3) add Prefer header for formatted values, (4) parse raw OData envelope, (5) handle pagination if needed.

**With `query_odata` (proposed — zero pain points):**
```
entity_name: account
select: ["name", "revenue", "primarycontactid"]
filter: statecode eq 0 and revenue gt 1000000
top: 10
orderby: revenue desc
formatted_values: true
```
Tool auto-resolves entity set name, adds headers, returns clean records.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `entity_name` | string | Yes | — | Entity logical name (e.g., `account`). Tool auto-resolves to OData `entitySetName`. |
| `select` | string | No | — | Comma-separated columns to return (e.g., `name,revenue`). **Strongly recommended** to minimize payload. |
| `filter` | string | No | — | OData `$filter` expression (e.g., `statecode eq 0 and revenue gt 1000000`). |
| `orderby` | string | No | — | OData `$orderby` expression (e.g., `revenue desc,name asc`). |
| `top` | int | No | 50 | Max records to return (1–5000). Default 50. |
| `expand` | string | No | — | OData `$expand` for related entities (e.g., `primarycontactid($select=fullname)`). |
| `count` | bool | No | false | Include `@odata.count` total in response. |
| `apply` | string | No | — | OData `$apply` for server-side aggregation (e.g., `groupby((statuscode),aggregate($count as total))`). |
| `formatted_values` | bool | No | false | Include formatted labels for picklist/status fields (e.g., `Active` instead of `0`). |
| `get_all` | bool | No | false | Auto-paginate through all pages (up to 100 pages / 50,000 records). Default: first page only. |
| `max_records` | int | No | 5000 | When `get_all=true`, cap total records. Default 5000, max 50000. |

## Dataverse API

### Basic Query

```csharp
// Resolve entity logical name → entitySetName
var entitySetName = ResolveEntitySetName(entity_name); // account → accounts

// Build OData query string
var queryParts = new List<string>();
if (!string.IsNullOrEmpty(select)) queryParts.Add($"$select={select}");
if (!string.IsNullOrEmpty(filter)) queryParts.Add($"$filter={filter}");
if (!string.IsNullOrEmpty(orderby)) queryParts.Add($"$orderby={orderby}");
if (top > 0) queryParts.Add($"$top={top}");
if (!string.IsNullOrEmpty(expand)) queryParts.Add($"$expand={expand}");
if (count) queryParts.Add("$count=true");
if (!string.IsNullOrEmpty(apply)) queryParts.Add($"$apply={apply}");

var url = $"{entitySetName}?{string.Join("&", queryParts)}";

// Add formatted values header if requested
var headers = new Dictionary<string, string>();
if (formatted_values)
    headers["Prefer"] = "odata.include-annotations=\"OData.Community.Display.V1.FormattedValue\"";

// Execute via ServiceClient
var response = _serviceClient.ExecuteWebRequest(HttpMethod.Get, url, null, headers);
```

### Auto-Pagination (get_all = true)

```csharp
var allRecords = new List<JsonElement>();
var nextLink = initialUrl;
int pageCount = 0;

while (nextLink != null && pageCount < 100 && allRecords.Count < max_records)
{
    var response = ExecuteGet(nextLink, headers);
    var page = ParseODataResponse(response);
    allRecords.AddRange(page.Records);
    nextLink = page.NextLink; // @odata.nextLink
    pageCount++;
}
```

```
|------|---------|------------------------|
| Contoso Ltd | 5000000 | a1b2c3d4-... |
| Fabrikam Inc | 3200000 | e5f6g7h8-... |
| ... | | |

Total: 10 records (page 1)
```

### Success — With Formatted Values

```
[QueryResult] account: 10 records returned

| name | revenue | statecode |
|------|---------|-----------|
| Contoso Ltd | $5,000,000.00 | Active |
| Fabrikam Inc | $3,200,000.00 | Active |
```

### Success — Aggregation ($apply)

```
[QueryResult] account: 3 groups returned
Apply: groupby((statuscode),aggregate($count as total))

| statuscode | total |
|-----------|-------|
| 0 | 1250 |
| 1 | 340 |
| 2 | 85 |
```

### Success — Auto-Paged (get_all)

```
[QueryResult] account: 12,500 records retrieved across 3 pages
Filter: statecode eq 0
Pages: 3 (5000 + 5000 + 2500)
```

### Warning — Missing $select

```
[QueryResult] account: 50 records returned
[WARNING] NO_SELECT: No $select specified — all columns returned. Specify select to reduce payload.
```

### Error — Entity Not Found

```
[Error] Entity 'acounts' not found (HTTP 404)
Tip: Use get_entities_metadata to find the correct entity logical name. Did you mean 'account'?
```

## Structured Output Model

```csharp
internal sealed class QueryODataResult
{
    [JsonPropertyName("entityName")]
    public string EntityName { get; set; }

    [JsonPropertyName("recordCount")]
    public int RecordCount { get; set; }

    [JsonPropertyName("totalCount")]
    [JsonIgnore(Condition = JsonIgnoreCondition.WhenWritingNull)]
    public int? TotalCount { get; set; } // from @odata.count

    [JsonPropertyName("pageCount")]
    public int PageCount { get; set; }

    [JsonPropertyName("hasMorePages")]
    public bool HasMorePages { get; set; }

    [JsonPropertyName("warnings")]
    [JsonIgnore(Condition = JsonIgnoreCondition.WhenWritingNull)]
    public List<string> Warnings { get; set; }
}
```

## Query Guardrails

| Condition | Warning Code | Message |
|-----------|-------------|---------|
| No `select` specified | `NO_SELECT` | All columns will be returned. Specify `select` to reduce payload. |
| No `filter` specified | `NO_FILTER` | No filter — consider adding one to reduce results. |
| `top` > 5000 | `LARGE_TOP` | Large result set requested. Consider reducing `top` or using `get_all`. |
| `get_all` with no `select` | `PAGING_NO_SELECT` | Auto-paging without `select` will retrieve all columns for every page — very expensive. |

## Implementation Notes

- Entity name resolution: maintain a cache (logical name → entitySetName), lazy-load from `EntityDefinitions` metadata
- The `select` parameter should accept both comma-separated string and validate column names
- `filter` is passed through as-is (OData syntax) — do NOT attempt to parse or transform
- For `get_all`, respect `@odata.nextLink` for pagination (do NOT use `$skip`)
- Formatted values use the `Prefer: odata.include-annotations="OData.Community.Display.V1.FormattedValue"` header
- Response should strip `@odata.context`, `@odata.etag`, and annotation keys to reduce token cost
- Truncate large result sets with a clear message about remaining records
