# MCP Tool: get_webresources

## Tool #35 — Query & Read

## Status: IMPLEMENTED

## Purpose

List and inspect web resources (JavaScript, CSS, HTML, images, RESX) in Dataverse. Essential for mapping local files to their Dataverse web resource names/GUIDs before adding form event handlers or library references.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| name_filter | string | No | `""` | Filter by name (contains match). E.g., `"account"`, `"v4_/entities"`. |
| type_filter | string | No | `""` | Filter by type: `"js"`, `"html"`, `"css"`, `"xml"`, `"png"`, `"jpg"`, `"gif"`, `"svg"`, `"ico"`, `"resx"`. |
| solution_name | string | No | `""` | Filter by solution unique name. |
| web_resource_id | string | No | `""` | GUID for single web resource detail. Empty = list mode. |
| max_records | int | No | 50 | Max results for list mode (1-500). |

## Returns

- List mode: web resource name, display name, type (JS/CSS/HTML/etc.), GUID, modified date (TSV format)
- Detail mode (web_resource_id provided): full metadata including description, language code, customizability, created/modified info
- Type codes mapped to human-readable labels (e.g., 3 = JS, 2 = CSS)

## When to Use

- Find a web resource by name before adding a form event handler with `build_formxml` `add_event`/`add_library`
- List all JavaScript web resources in a solution to understand what's deployed
- Get full detail of a specific web resource by its GUID

## Tips

- Call this tool first to find the exact `library_name` needed for `build_formxml` `add_event` and `add_library` operations
- Names follow convention: `{prefix}_/path/filename.ext` (e.g., `v4_/entities/Account.form.js`)
- Related tools: `build_formxml` (add events/libraries to forms), `get_forms` (inspect form structure)
