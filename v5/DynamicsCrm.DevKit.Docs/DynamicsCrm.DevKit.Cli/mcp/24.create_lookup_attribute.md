# Proposal: create_lookup_attribute MCP Tool

## Priority: 11 (Data Management — Specialized Lookup Creation)

## Phase: 2 — Data Management

## Why This Tool Is Needed

While `create_attribute` supports basic lookup creation, polymorphic lookups (Customer, Owner-like multi-target), cascading behavior configuration, and self-referential lookups require additional parameters that don't fit cleanly in the generic tool. This specialized tool provides guided creation for complex lookup scenarios.

### Current Pain (create_attribute with lookup type)

The existing `create_attribute` tool handles simple single-target lookups but lacks:
1. **Cascade behavior configuration** — delete, assign, share, unshare, reparent, merge
2. **Polymorphic lookups** — targeting multiple entities (beyond Customer type)
3. **Self-referential lookups** — entity referencing itself (e.g., parent account)
4. **Relationship display name** — separate from the attribute display name

### Proposed (create_lookup_attribute)

```
entity_name: contact
attribute_name: new_referredby
display_name: Referred By
target_entity: contact
relationship_name: new_contact_referredby_contact
cascade_delete: RemoveLink
cascade_assign: NoCascade
```

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `entity_name` | string | Yes | — | Source entity logical name (the "many" side). |
| `attribute_name` | string | Yes | — | Lookup attribute logical name with prefix. |
| `display_name` | string | Yes | — | Display name for the lookup column. |
| `target_entity` | string | Yes | — | Target entity logical name (the "one" side). Comma-separated for polymorphic. |
| `relationship_name` | string | No | Auto | Relationship schema name. Auto-generated if omitted. |
| `relationship_display_name` | string | No | — | Display name for the relationship. |
| `description` | string | No | — | Column description. |
| `required_level` | string | No | `None` | `None`, `Recommended`, or `Required`. |
| `cascade_delete` | string | No | `RemoveLink` | `Cascade`, `RemoveLink`, `Restrict`. |
| `cascade_assign` | string | No | `NoCascade` | `Cascade`, `NoCascade`, `Active`. |
| `cascade_share` | string | No | `NoCascade` | `Cascade`, `NoCascade`, `Active`. |
| `cascade_unshare` | string | No | `NoCascade` | `Cascade`, `NoCascade`, `Active`. |
| `cascade_reparent` | string | No | `NoCascade` | `Cascade`, `NoCascade`, `Active`. |
| `cascade_merge` | string | No | `NoCascade` | `Cascade`, `NoCascade`. |
| `solution_name` | string | No | — | Solution to add the relationship to. |
| `auto_publish` | bool | No | true | Publish after creation. |

## Dataverse API

```csharp
// Build OneToManyRelationship metadata
var relationship = new
{
    SchemaName = relationship_name ?? $"{entity_name}_{target_entity}_{attribute_name}",
    ReferencedEntity = target_entity,
    ReferencingEntity = entity_name,
    CascadeConfiguration = new
    {
        Delete = ParseCascade(cascade_delete),    // RemoveLink
        Assign = ParseCascade(cascade_assign),    // NoCascade
        Share = ParseCascade(cascade_share),      // NoCascade
        Unshare = ParseCascade(cascade_unshare),  // NoCascade
        Reparent = ParseCascade(cascade_reparent), // NoCascade
        Merge = ParseCascade(cascade_merge)       // NoCascade
    },
    Lookup = new
    {
        SchemaName = attribute_name,
        DisplayName = display_name,
        RequiredLevel = required_level,
        Description = description
    }
};

// POST EntityDefinitions(LogicalName='target')/OneToManyRelationships
var url = $"EntityDefinitions(LogicalName='{target_entity}')/OneToManyRelationships";
var response = _serviceClient.ExecuteWebRequest(HttpMethod.Post, url, body, headers);
```

## Response Format

### Success
```
[LookupCreated] contact.new_referredby → contact
  Relationship: new_contact_referredby_contact
  Cascade: Delete=RemoveLink, Assign=NoCascade
  Published: yes
```

### Error — Target Entity Not Found
```
[Error] Target entity 'contac' not found.
Tip: Use get_entities_metadata to find correct entity logical names.
```

## Cascade Behavior Reference

| Behavior | Delete | Assign | Share | Reparent | Merge |
|----------|--------|--------|-------|----------|-------|
| `Cascade` | Delete children | Assign children | Share with children | Reparent children | Merge children |
| `RemoveLink` | Clear lookup | — | — | — | — |
| `Restrict` | Block delete | — | — | — | — |
| `NoCascade` | — | No action | No action | No action | No action |
| `Active` | — | Active only | Active only | Active only | — |
