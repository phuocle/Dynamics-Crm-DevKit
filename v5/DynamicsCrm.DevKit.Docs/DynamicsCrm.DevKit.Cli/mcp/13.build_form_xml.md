# Proposal: build_form_xml MCP Tool

## Priority: 13 (FormXML Builder -- server-side XML generation for accurate form manipulation)

## Why This Tool Is Needed

When AI receives a natural language request like _"Add createdon to the Account main form"_ or _"Add a new tab with 2 sections and 5 fields"_, the current flow requires AI to:

1. Call `get_forms` to read FormXML (often 2000+ lines)
2. Call `get_entity_metadata` to learn field types
3. **Manually construct the correct XML snippet** -- classid GUIDs, unique cell IDs, section column layout, tab column widths
4. Splice it into the existing FormXML at the right position
5. Pass the entire modified XML to `update_form`

**Step 3-4 is where AI fails 40-60% of the time** because:

| Problem | Example |
|---------|---------|
| Wrong `classid` for attribute type | Using Text classid for a DateTime field |
| Missing `classid` entirely | `<control id="name" datafieldname="name" />` -- no classid = form crash |
| Duplicate or invalid GUIDs | Reusing an existing cell `id` |
| Incorrect section column layout | 2-column section but only 1 cell per row |
| Wrong XML hierarchy | Putting `<rows>` directly inside `<tab>` |
| Forgetting `<labels>` element | Tab/Section renders with no title |

### Competitor Analysis (AppMaker / Greg.Xrm.Mcp)

AppMaker has **NO builder tool** -- they rely entirely on the LLM generating correct XML. This is the shared weakness of all current Dataverse MCP implementations.

**DevKit advantage:** Server-side XML generation eliminates the entire class of classid/structure errors.

### Architecture Decision: Read-Only Builder, NOT Writer

This tool **generates** the modified FormXML and **returns** it. It does NOT write to Dataverse.

```
build_form_xml (READ-ONLY)  ──→  returns modified FormXML string
                                         │
                                         ▼
                                  update_form (WRITE)
                                  backup → validate → update → publish
```

**Rationale:** `update_form` already handles backup, XSD validation, and publishing correctly. Duplicating that logic would create maintenance burden and double the bug surface.

---

## Purpose

Server-side FormXML builder that takes natural-language-friendly parameters (field names, tab/section descriptions) and generates the correct FormXML with accurate classid GUIDs, unique IDs, and proper XML structure. Returns the modified FormXML string for the AI to pass to `update_form`.

---

## The 3 Levels: Tab → Section → Field

FormXML has a strict hierarchy (from `FormXml.xsd`):

```
form
 └── tabs
      └── tab                    ← Level 1: TAB (1-3 columns)
           └── columns
                └── column       ← width="100%" or "50%"/"50%" or "33%"/"34%"/"33%"
                     └── sections
                          └── section         ← Level 2: SECTION (1-3 columns via `columns` attr)
                               └── rows
                                    └── row
                                         └── cell          ← Level 3: FIELD (control)
                                              └── control   ← classid + datafieldname
```

### XSD Constraints (from FormXml.xsd)

| Element | Parent | Min | Max | Key Attributes |
|---------|--------|-----|-----|----------------|
| `tab` | `tabs` | 1 | 100 | `name`, `id` (GUID), `showlabel`, `expanded`, `visible`, `locklevel` |
| `column` | `columns` | 1 | **3** | `width` (percentage, e.g., `"100%"`, `"50%"`) |
| `section` | `sections` | 0 | unbounded | `name`, `id` (GUID), `showlabel`, `columns` (1-3), `labelwidth`, `celllabelposition` |
| `row` | `rows` | 0 | unbounded | `height` |
| `cell` | `row` | 0 | unbounded | `id` (GUID), `showlabel`, `colspan`, `rowspan`, `visible` |
| `control` | `cell` | 0 | 1 | `id`, `classid` (GUID), `datafieldname`, `disabled` |

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `entity_name` | string | Yes | - | Entity logical name (e.g., `"account"`). Used to resolve field metadata. |
| `form_id` | string | Yes | - | GUID of the form to modify. Tool reads current FormXML from Dataverse. |
| `operations` | string (JSON) | Yes | - | JSON array of operations to perform. See [Operations Format](#operations-format). |

### Operations Format

The `operations` parameter is a JSON array. Each operation is an object with an `action` field:

#### Action: `add_tab`

Add a new tab to the form.

```json
{
  "action": "add_tab",
  "name": "tab_audit",
  "label": "Audit Information",
  "tab_columns": 1,
  "position": "last",
  "expanded": true,
  "sections": [
    {
      "name": "audit_sec_dates",
      "label": "Date Fields",
      "section_columns": 2,
      "fields": ["createdon", "modifiedon", "overriddencreatedon"]
    },
    {
      "name": "audit_sec_users",
      "label": "User Fields",
      "section_columns": 2,
      "fields": ["createdby", "modifiedby", "ownerid"]
    }
  ]
}
```

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| `name` | string | No | auto (`tab_$label`) | Tab name attribute. Auto-generated from label if omitted. |
| `label` | string | Yes | - | Tab display label (languagecode=1033). |
| `tab_columns` | int | No | 1 | Number of columns in the tab layout (1, 2, or 3). Maps to `<column>` elements with width percentages. |
| `position` | string | No | `"last"` | `"last"` = append as last tab. `"first"` = prepend. `"after:tab_name"` = insert after specific tab. |
| `expanded` | bool | No | true | Whether tab is expanded by default. |
| `sections` | array | Yes | - | Array of section definitions (see below). |

**Tab column width mapping:**

| `tab_columns` | Generated `<column>` elements |
|---|---|
| 1 | `<column width="100%">` |
| 2 | `<column width="50%">` + `<column width="50%">` |
| 3 | `<column width="33%">` + `<column width="34%">` + `<column width="33%">` |

#### Action: `add_section`

Add a new section to an existing tab.

```json
{
  "action": "add_section",
  "tab": "tab_general",
  "name": "general_sec_social",
  "label": "Social Media",
  "section_columns": 2,
  "position": "last",
  "fields": ["websiteurl", "ftpsiteurl"]
}
```

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| `tab` | string | Yes | - | Name of the target tab (must exist in form or be created in a prior operation). |
| `tab_column` | int | No | 1 | Which column of the tab to add to (1-based). For single-column tabs, always 1. |
| `name` | string | No | auto (`$tab_sec_$label`) | Section name attribute. |
| `label` | string | Yes | - | Section display label. |
| `section_columns` | int | No | 1 | Number of columns in the section grid (1, 2, or 3). Controls how many `<cell>` elements per `<row>`. |
| `position` | string | No | `"last"` | `"last"` = append. `"first"` = prepend. `"after:section_name"` = insert after specific section. |
| `fields` | array | No | `[]` | Array of field names or field objects to add (see [Field Specification](#field-specification)). |

#### Action: `add_fields`

Add fields to an existing section.

```json
{
  "action": "add_fields",
  "tab": "tab_general",
  "section": "general_sec_info",
  "fields": [
    "createdon",
    { "field": "modifiedon", "label": "Last Modified", "disabled": true },
    { "field": "statuscode", "colspan": 2 }
  ]
}
```

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| `tab` | string | Yes | - | Name of the target tab. |
| `section` | string | Yes | - | Name of the target section. |
| `position` | string | No | `"last"` | `"last"` = append after last row. `"first"` = prepend before first row. |
| `fields` | array | Yes | - | Array of field names or field objects. |

### Field Specification

Each entry in the `fields` array can be:

**Simple form** (string): Just the attribute logical name. Tool resolves everything automatically.
```json
"createdon"
```

**Detailed form** (object): Override label, visibility, etc.
```json
{
  "field": "createdon",
  "label": "Date Created",
  "disabled": true,
  "visible": true,
  "colspan": 2,
  "rowspan": 1,
  "showlabel": true
}
```

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| `field` | string | Yes | - | Attribute logical name (e.g., `"createdon"`). |
| `label` | string | No | (from metadata DisplayName) | Override the display label. |
| `disabled` | bool | No | false | Read-only control. |
| `visible` | bool | No | true | Control visibility. |
| `colspan` | int | No | 1 | How many section columns this cell spans. |
| `rowspan` | int | No | 1 | How many rows this cell spans. |
| `showlabel` | bool | No | true | Show/hide the field label. |

## Execution Flow

```
┌─────────────────────────────────────────────────────────────────┐
│ 1. VALIDATE parameters                                          │
│    └─ entity_name, form_id, operations JSON parsing             │
├─────────────────────────────────────────────────────────────────┤
│ 2. RETRIEVE current FormXML from Dataverse                      │
│    └─ serviceClient.Retrieve("systemform", formId, ...)         │
├─────────────────────────────────────────────────────────────────┤
│ 3. RETRIEVE entity metadata for all referenced fields           │
│    └─ RetrieveEntityRequest with EntityFilters.Attributes       │
│    └─ Build map: attributeName → (AttributeType, Format, etc.)  │
├─────────────────────────────────────────────────────────────────┤
│ 4. RESOLVE classid for each field                               │
│    └─ AttributeType + Format → ControlClassId (see mapping)     │
│    └─ Error if field not found in entity metadata               │
├─────────────────────────────────────────────────────────────────┤
│ 5. PARSE current FormXML into XDocument                         │
├─────────────────────────────────────────────────────────────────┤
│ 6. EXECUTE operations in order                                  │
│    └─ add_tab: create tab XML element, inject into <tabs>       │
│    └─ add_section: locate tab, inject section into column       │
│    └─ add_fields: locate section, generate rows/cells/controls  │
│    └─ Generate unique GUIDs: Guid.NewGuid() for each id attr    │
├─────────────────────────────────────────────────────────────────┤
│ 7. SERIALIZE modified XDocument back to string                  │
├─────────────────────────────────────────────────────────────────┤
│ 8. RETURN the modified FormXML + summary of changes             │
│    └─ AI passes this to update_form for write                   │
└─────────────────────────────────────────────────────────────────┘
```

### Resolution Logic (Pseudocode)

```csharp
string ResolveClassId(AttributeMetadata attr)
{
    return attr switch
    {
        // String with format subtypes
        StringAttributeMetadata s => s.FormatName?.Value switch
        {
            "Email"        => ControlClassId.SINGLE_LINE_OF_TEXT_EMAIL,
            "Url"          => ControlClassId.SINGLE_LINE_OF_TEXT_URL,
            "TickerSymbol" => ControlClassId.SINGLE_LINE_OF_TEXT_TICKER_SYMBOL,
            "Phone"        => ControlClassId.SINGLE_LINE_OF_TEXT_PHONE,
            _              => ControlClassId.SINGLE_LINE_OF_TEXT
        },

        // Integer with format subtypes
        IntegerAttributeMetadata i => i.Format switch
        {
            IntegerFormat.Duration => ControlClassId.WHOLE_NUMBER_DURATION,
            IntegerFormat.Language => ControlClassId.WHOLE_NUMBER_LANGUAGE,
            IntegerFormat.TimeZone => ControlClassId.WHOLE_NUMBER_TIMEZONE,
            _                     => ControlClassId.WHOLE_NUMBER
        },

        // Simple type mappings
        MemoAttributeMetadata          => ControlClassId.MULTI_LINES_OF_TEXT,
        DateTimeAttributeMetadata      => ControlClassId.DATE_TIME,
        BooleanAttributeMetadata       => ControlClassId.TWO_OPTIONS_2,
        PicklistAttributeMetadata      => ControlClassId.STATE_CODE,    // generic OptionSet
        StateAttributeMetadata         => ControlClassId.STATE_CODE,
        StatusAttributeMetadata        => ControlClassId.STATUS_CODE,
        DoubleAttributeMetadata        => ControlClassId.FLOATING_POINT_NUMBER,
        DecimalAttributeMetadata       => ControlClassId.DECIMAL_NUMBER,
        MoneyAttributeMetadata         => ControlClassId.CURRENCY,
        LookupAttributeMetadata        => ControlClassId.LOOKUP,
        MultiSelectPicklistAttributeMetadata => ControlClassId.MULTI_OPTIONSET,
        ImageAttributeMetadata         => ControlClassId.IMAGE,
        FileAttributeMetadata          => ControlClassId.FILE,
        EntityNameAttributeMetadata    => ControlClassId.ENTITY_NAME,
        UniqueIdentifierAttributeMetadata => ControlClassId.SINGLE_LINE_OF_TEXT,
        BigIntAttributeMetadata        => ControlClassId.WHOLE_NUMBER,

        _ => throw new NotSupportedException($"Unsupported attribute type: {attr.AttributeType}")
    };
}
```

## XML Generation Examples

### Example 1: Add a single field to an existing section

**Prompt:** _"Add createdon to the General tab, Info section on Account form"_

**AI calls:**
```json
{
  "entity_name": "account",
  "form_id": "abc-123",
  "operations": [
    {
      "action": "add_fields",
      "tab": "tab_general",
      "section": "general_sec_info",
      "fields": ["createdon"]
    }
  ]
}
```

**Tool generates and injects into existing section:**
```xml
<row>
  <cell id="{a1b2c3d4-e5f6-7890-abcd-000000000001}" showlabel="true" locklevel="0">
    <labels>
      <label description="Created On" languagecode="1033" />
    </labels>
    <control id="createdon" classid="{5B773807-9FB2-42DB-97C3-7A91EFF8ADFF}" datafieldname="createdon" />
  </cell>
</row>
```

Note: `classid="{5B773807-...}"` is `DATE_TIME`, resolved from `AttributeTypeCode.DateTime` metadata.

## Section Column Layout Logic

When a section has `columns="N"`, each `<row>` must have exactly N `<cell>` elements to fill the grid.

### N=1 (single column section)
```xml
<section columns="1">
  <rows>
    <row><cell>fieldA</cell></row>
    <row><cell>fieldB</cell></row>
    <row><cell>fieldC</cell></row>
  </rows>
</section>
```

### N=2 (two column section)
Fields fill left-to-right, top-to-bottom. Odd count gets a spacer cell.
```xml
<section columns="2">
  <rows>
    <row><cell>fieldA</cell><cell>fieldB</cell></row>
    <row><cell>fieldC</cell><cell /></row>  <!-- spacer -->
  </rows>
</section>
```

### N=3 (three column section)
```xml
<section columns="3">
  <rows>
    <row><cell>fieldA</cell><cell>fieldB</cell><cell>fieldC</cell></row>
    <row><cell>fieldD</cell><cell /><cell /></row>  <!-- 2 spacers -->
  </rows>
</section>
```

### Spacer Cell Generation

```csharp
// Empty cell acts as spacer in multi-column sections
<cell id="{NEW-GUID}" />
```

A spacer cell has an `id` but no `<control>` child. This is the standard Dataverse pattern.

## Natural Language → Operations Translation Guide

This section helps AI understand how to translate natural language prompts into `operations` JSON.

| Natural Language | `action` | Key Parameters |
|---|---|---|
| _"Add createdon to the form"_ | `add_fields` | Find first/main section, add field |
| _"Add createdon to General tab"_ | `add_fields` | `tab: "tab_general"`, find first section |
| _"Add createdon to the Info section"_ | `add_fields` | Match section by label or name |
| _"Add a new section called X with fields A, B, C"_ | `add_section` | New section with fields |
| _"Add a new tab called X"_ | `add_tab` | New tab with default single section |
| _"Add tab with 2 columns, left has X, right has Y"_ | `add_tab` | `tab_columns: 2`, sections with `tab_column: 1` and `tab_column: 2` |
| _"Add a 2-column section with 4 fields"_ | `add_section` | `section_columns: 2`, fields fill 2 per row |
| _"Put these 3 fields side by side"_ | `add_section` | `section_columns: 3` |

### Ambiguity Resolution

When the user does not specify a target:

| Missing | Default |
|---------|---------|
| Tab not specified | Use the **first non-header tab** (usually `tab_general` or the first Main tab) |
| Section not specified | Use the **last section** in the target tab |
| Section columns not specified | Default to `1` |
| Tab columns not specified | Default to `1` |
| Field label not specified | Use `DisplayName` from entity metadata |
| Position not specified | `"last"` (append at end) |

## Tool Description for AI

```
Build modified FormXML by adding fields, sections, or tabs to an existing Dataverse form.
This is a READ-ONLY builder — it returns the modified FormXML string. Use update_form to write it.

THREE LEVELS OF OPERATIONS:
- add_fields: Add fields to an existing section (resolves classid automatically)
- add_section: Add a new section (with fields) to an existing tab
- add_tab: Add a new tab (with sections and fields) to the form

PARAMETERS:
- entity_name (required): Entity logical name (e.g., 'account'). Used to resolve field metadata.
- form_id (required): GUID of the form. Tool reads current FormXML from Dataverse.
- operations (required): JSON array of operations. Each has 'action' + parameters.

HOW IT WORKS:
1. Reads current FormXML from Dataverse
2. Fetches entity metadata for all referenced fields
3. Resolves the correct classid GUID for each field based on its AttributeType
4. Generates correct XML structure (tabs/columns/sections/rows/cells/controls)
5. Generates unique GUIDs for all id attributes
6. Returns the complete modified FormXML string

WORKFLOW:
1. (Optional) Call get_entity_metadata to understand available fields
2. (Optional) Call get_forms to see current form structure
3. Call build_form_xml with desired operations
4. Pass the returned FormXML to update_form to write it to Dataverse

WHY USE THIS INSTEAD OF EDITING FORMXML MANUALLY:
- Automatically resolves classid GUIDs (most common source of errors)
- Generates proper section column layout (fills rows, adds spacer cells)
- Creates unique GUIDs for all elements
- Validates field names against entity metadata
- Follows Dataverse naming conventions (tab_$label, $tab_sec_$label)

SECTION COLUMNS:
- section_columns=1: One field per row (default)
- section_columns=2: Two fields per row, spacer if odd count
- section_columns=3: Three fields per row, spacers to fill

TAB COLUMNS:
- tab_columns=1: Single column tab with width="100%" (default)
- tab_columns=2: Two columns, width="50%"/"50%"
- tab_columns=3: Three columns, width="33%"/"34%"/"33%"
  Sections specify which tab_column (1-based) they belong to.

TIPS:
- Fields can be simple strings ("createdon") or objects with overrides (label, disabled, colspan)
- Positions: "last" (default), "first", "after:element_name"
- This tool does NOT modify Dataverse — it only returns XML. Use update_form to apply changes.
- Combine multiple operations in one call (add tab + sections + fields in a single request)
```

### Auto-Naming Convention

```csharp
string AutoTabName(string label)
    => $"tab_{Sanitize(label)}";
    // "Audit Information" → "tab_audit_information"

string AutoSectionName(string tabName, string label)
    => $"{tabName.Replace("tab_", "")}_sec_{Sanitize(label)}";
    // tab="tab_audit", label="Date Fields" → "audit_sec_date_fields"

string Sanitize(string s)
    => Regex.Replace(s.ToLowerInvariant(), @"[^a-z0-9]+", "_").Trim('_');
```

### Row Filling Logic

```csharp
void FillRows(XElement rowsElement, List<XElement> cells, int sectionColumns)
{
    var chunks = cells.Chunk(sectionColumns);
    foreach (var chunk in chunks)
    {
        var row = new XElement("row");
        foreach (var cell in chunk)
            row.Add(cell);
        // Pad with spacer cells if needed
        while (row.Elements("cell").Count() < sectionColumns)
            row.Add(CreateSpacerCell());
        rowsElement.Add(row);
    }
}
```
