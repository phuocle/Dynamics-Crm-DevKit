## Why This Tool Is Needed

After creating an entity and adding columns, the next step is **always** defining relationships. Currently, developers must use `execute_webapi` to POST to `RelationshipDefinitions` — which requires understanding the exact JSON schema for `OneToManyRelationshipMetadata` or `ManyToManyRelationshipMetadata`.

This is especially painful because:
1. Relationship metadata JSON is complex (~15 properties per relationship)
2. Cascade configuration has 6 separate cascade behaviors to set
3. N:N relationships require an intersect entity name
4. Error messages from Dataverse for invalid relationships are cryptic

## Purpose

Create 1:N (one-to-many) or N:N (many-to-many) relationships between Dataverse entities with guided parameters, automatic cascade configuration, and solution awareness.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| relationship_type | string | Yes | - | `"one_to_many"` or `"many_to_many"`. |
| parent_entity | string | Yes | - | Referenced/parent entity logical name (e.g., `"account"`). For 1:N: the "one" side. |
| child_entity | string | Yes | - | Referencing/child entity logical name (e.g., `"contact"`). For 1:N: the "many" side. |
| relationship_name | string | No | auto | Schema name for the relationship. Auto-generated if omitted: `{parent}_{child}_{lookup}`. |
| lookup_name | string | Cond. | - | For 1:N only: logical name of the lookup attribute on the child entity (e.g., `"new_accountid"`). Required for 1:N. |
| lookup_display_name | string | No | `"{ParentDisplayName}"` | For 1:N: display name of the lookup field. |
| lookup_required_level | string | No | `"None"` | For 1:N: `"None"`, `"Recommended"`, or `"Required"`. |
| intersect_entity_name | string | No | auto | For N:N only: logical name of the intersect entity. Auto-generated: `{parent}_{child}`. |
| cascade_assign | string | No | `"NoCascade"` | 1:N cascade on assign: `"Cascade"`, `"Active"`, `"NoCascade"`, `"UserOwned"`. |
| cascade_delete | string | No | `"RemoveLink"` | 1:N cascade on delete: `"Cascade"`, `"RemoveLink"`, `"Restrict"`, `"NoCascade"`. |
| cascade_merge | string | No | `"NoCascade"` | 1:N cascade on merge. |
| cascade_reparent | string | No | `"NoCascade"` | 1:N cascade on reparent. |
| cascade_share | string | No | `"NoCascade"` | 1:N cascade on share. |
| cascade_unshare | string | No | `"NoCascade"` | 1:N cascade on unshare. |
| solution_name | string | No | `""` | Add relationship to this solution. |
| auto_publish | bool | No | true | Publish both entities after creation. |

## Dataverse API

### Create 1:N Relationship

```csharp
var request = new CreateOneToManyRequest
{
    OneToManyRelationship = new OneToManyRelationshipMetadata
    {
        SchemaName = relationshipName,
        ReferencedEntity = parentEntity,           // "one" side
        ReferencingEntity = childEntity,           // "many" side
        AssociatedMenuConfiguration = new AssociatedMenuConfiguration
        {
            Behavior = AssociatedMenuBehavior.UseCollectionName,
            Group = AssociatedMenuGroup.Details,
            Order = 10000
        },
        CascadeConfiguration = new CascadeConfiguration
        {
            Assign = cascadeAssign,
            Delete = cascadeDelete,
            Merge = cascadeMerge,
            Reparent = cascadeReparent,
            Share = cascadeShare,
            Unshare = cascadeUnshare
        }
    },
    Lookup = new LookupAttributeMetadata
    {
        SchemaName = lookupSchemaName,
        LogicalName = lookupName,
        DisplayName = new Label(lookupDisplayName, 1033),
        RequiredLevel = new AttributeRequiredLevelManagedProperty(requiredLevel)
    },
    SolutionUniqueName = solutionName
};

var response = (CreateOneToManyResponse)serviceClient.Execute(request);
```

### Create N:N Relationship

```csharp
var request = new CreateManyToManyRequest
{
    IntersectEntitySchemaName = intersectEntityName,
    ManyToManyRelationship = new ManyToManyRelationshipMetadata
    {
        SchemaName = relationshipName,
        Entity1LogicalName = parentEntity,
        Entity2LogicalName = childEntity,
        Entity1AssociatedMenuConfiguration = new AssociatedMenuConfiguration
        {
            Behavior = AssociatedMenuBehavior.UseCollectionName,
            Group = AssociatedMenuGroup.Details,
            Order = 10000
        },
        Entity2AssociatedMenuConfiguration = new AssociatedMenuConfiguration
        {
            Behavior = AssociatedMenuBehavior.UseCollectionName,
            Group = AssociatedMenuGroup.Details,
            Order = 10000
        }
    },
    SolutionUniqueName = solutionName
};

var response = (CreateManyToManyResponse)serviceClient.Execute(request);
```

## Tool Description for AI

```
Create 1:N (one-to-many) or N:N (many-to-many) relationships between Dataverse entities.
For 1:N: also creates the lookup attribute on the child entity.

PARAMETERS:
- relationship_type (required): 'one_to_many' or 'many_to_many'.
- parent_entity (required): Referenced entity (the "one" side for 1:N).
- child_entity (required): Referencing entity (the "many" side for 1:N).
- relationship_name: Schema name. Auto-generated if omitted.
- lookup_name: For 1:N: lookup attribute logical name on child entity. Required for 1:N.
- lookup_display_name: Display name for the lookup field.
- lookup_required_level: 'None' (default), 'Recommended', or 'Required'.
- intersect_entity_name: For N:N: intersect entity name. Auto-generated if omitted.
- cascade_assign/delete/merge/reparent/share/unshare: Cascade behavior for 1:N.
  Values: 'Cascade', 'Active', 'NoCascade', 'RemoveLink', 'Restrict', 'UserOwned'.
- solution_name: Add relationship to this solution.
- auto_publish: Publish both entities after creation (default: true).

RETURNS:
- Relationship details (type, name, MetadataId)
- Lookup field details (for 1:N)
- Cascade configuration
- Solution and publish status

WHEN TO USE:
- After creating entities with create_entity
- To link two entities (e.g., Account → Projects)
- When building the data model relationships

TIPS:
- 1:N creates a lookup on the child entity automatically
- N:N creates an intersect entity for the relationship
- cascade_delete='Cascade' means child records are deleted when parent is deleted
- cascade_delete='Restrict' prevents parent deletion if children exist
- cascade_delete='RemoveLink' clears the lookup (safest default)
- Use get_entity_metadata to verify relationships don't already exist
- For polymorphic lookups (customer/owner type), use execute_webapi instead
```

## Implementation Notes

- Use SDK `CreateOneToManyRequest` (1:N) or `CreateManyToManyRequest` (N:N)
- Validate both entities exist before creating relationship
- Auto-generate relationship name: `{prefix}_{parent}_{child}_{lookup}`
- Auto-generate intersect entity name for N:N: `{prefix}_{entity1}_{entity2}`
- Map cascade string values to SDK `CascadeType` enum
- Publish both parent and child entities after creation
- Handle `FaultException` for duplicate relationship names

## Pre-requisite

- `get_entity_metadata` must exist ✅ (to verify entities exist)
