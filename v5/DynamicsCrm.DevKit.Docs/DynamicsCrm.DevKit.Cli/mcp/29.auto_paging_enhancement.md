# Proposal: query_odata Enhancement to execute_fetchxml (Auto-Paging)

## Priority: 16 (Advanced Features — Enhanced Pagination)

## Phase: 3 — Advanced Features (Enhancement, not new tool)

## Why This Enhancement Is Needed

The existing `execute_fetchxml` tool has `get_all=true` for auto-paging, but it's limited to 5,000 records and uses FetchXML-style paging cookies. For OData queries (via `query_odata` proposal #1), we need equivalent auto-paging with `@odata.nextLink` support. This proposal enhances both `execute_fetchxml` and the proposed `query_odata` with robust pagination.

### Current Limitations

| Feature | execute_fetchxml | Proposed query_odata |
|---------|-----------------|---------------------|
| Max records | 5,000 | Need similar cap |
| Paging method | FetchXML paging cookie | OData `@odata.nextLink` |
| Auto-page | `get_all=true` | Need `get_all=true` |
| Progress reporting | None | Need MCP progress notifications |

### Proposed Enhancements

1. **MCP Progress Notifications** — Report paging progress (`"Fetching page 3 of ~10..."`)
2. **Configurable max records** — Allow up to 50,000 for reporting scenarios (with warning)
3. **Streaming response** — Return partial results as pages complete
4. **Cancellation support** — Allow AI to cancel mid-page if enough data collected

## Implementation — OData Auto-Paging

```csharp
var allRecords = new List<Dictionary<string, object>>();
var currentUrl = initialUrl;
int pageCount = 0;

while (currentUrl != null && allRecords.Count < max_records)
{
    pageCount++;

    // Send MCP progress notification
    if (progress)
    {
        await server.SendProgressNotification(
            progressToken,
            progress: allRecords.Count,
            total: max_records,
            message: $"Fetching page {pageCount}... ({allRecords.Count} records so far)"
        );
    }

    var response = _serviceClient.ExecuteWebRequest(HttpMethod.Get, currentUrl, null, headers);
    var page = ParseODataResponse(response);
    allRecords.AddRange(page.Records);

    // Check for next page
    currentUrl = page.NextLink; // @odata.nextLink
    if (currentUrl == null)
        break; // No more pages
}
```

## Implementation — FetchXML Auto-Paging (Enhanced)

```csharp
var allRecords = new List<Dictionary<string, object>>();
string pagingCookie = null;
int page = 1;

while (allRecords.Count < max_records)
{
    // Send MCP progress notification
    if (progress)
    {
        await server.SendProgressNotification(
            progressToken,
            progress: allRecords.Count,
            total: max_records,
            message: $"Fetching page {page}... ({allRecords.Count} records so far)"
        );
    }

    var pagedFetchXml = InjectPaging(fetchXml, page, pagingCookie);
    var result = ExecuteFetchXml(pagedFetchXml);

    allRecords.AddRange(result.Records);
    pagingCookie = result.PagingCookie;
    page++;

    if (!result.MoreRecords)
        break;
}
```

## MCP Progress Notification Format

```json
{
    "method": "notifications/progress",
    "params": {
        "progressToken": "fetch_abc123",
        "progress": 2500,
        "total": 5000,
        "message": "Fetching page 5... (2,500 records so far)"
    }
}
```

## Guardrails

| Threshold | Behavior |
|-----------|----------|
| > 5,000 records | Warning: "Large dataset — consider filtering to reduce results" |
| > 10,000 records | Warning: "Very large dataset — this may take several minutes" |
| > 50,000 records | Hard cap — refuse with error |
| > 10 pages | Auto-include progress notifications regardless of `progress` flag |
| No filter + get_all | Refuse: "get_all without a filter is dangerous — add a filter first" |
