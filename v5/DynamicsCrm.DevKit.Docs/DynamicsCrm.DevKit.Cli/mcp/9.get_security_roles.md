# Proposal: get_security_roles MCP Tool

## Priority: 9 (Security -- Frequently needed for troubleshooting permissions)

## Why This Tool Is Needed

Security roles control what users can see and do. When AI is troubleshooting "access denied" errors or setting up new entities, it needs to understand the current security role configuration. Currently AI must write complex FetchXML queries joining `role`, `roleprivilege`, and `privilege` tables.

2 of 15 competitor MCP servers have security tools (mwhesse has ~10 tools, vignaesh01 has 3+).

## Purpose

List security roles and optionally their privileges. Two modes:
1. **List mode** (no `role_id`) -- list all roles with basic info
2. **Detail mode** (with `role_id`) -- show all privileges for a specific role

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| role_id | string | No | (empty) | GUID of a specific role. Leave empty to list all roles. |
| role_name | string | No | (empty) | Filter by role name (contains match, e.g., `"Sales"`). |
| business_unit_id | string | No | (empty) | Filter by business unit GUID. Leave empty for root BU. |
| entity_name | string | No | (empty) | In detail mode: filter privileges to only show those for a specific entity. |
| max_records | int | No | 50 | Maximum roles in list mode. Default: 50. |

## Dataverse Tables

| Table | Purpose |
|-------|---------|
| `role` | Security role definitions |
| `roleprivilege` (N:N intersect) | Role-to-privilege mapping |
| `privilege` | Privilege definitions (prvCreate, prvRead, etc.) |
| `privilegeobjecttypecodes` | Maps privileges to entity object type codes |

### FetchXML -- List Roles

```xml
<fetch>
  <entity name="role">
    <attribute name="roleid" />
    <attribute name="name" />
    <attribute name="businessunitid" />
    <attribute name="ismanaged" />
    <attribute name="iscustomizable" />
    <attribute name="createdon" />
    <filter type="and">
      <!-- Add name filter if role_name provided -->
      <!-- Add businessunitid filter if business_unit_id provided -->
      <condition attribute="parentroleid" operator="null" />
      <!-- Only root roles, not inherited copies -->
    </filter>
    <order attribute="name" />
  </entity>
</fetch>
```

### FetchXML -- Role Privileges (Detail Mode)

```xml
<fetch>
  <entity name="roleprivileges">
    <attribute name="privilegedepthmask" />
    <link-entity name="privilege" from="privilegeid" to="privilegeid" alias="priv">
      <attribute name="name" />
      <attribute name="accessright" />
    </link-entity>
    <filter>
      <condition attribute="roleid" operator="eq" value="{role_id}" />
    </filter>
  </entity>
</fetch>
```

### Privilege Depth Mask Values

| Value | Depth | Description |
|-------|-------|-------------|
| 1 | User | Own records only |
| 2 | Business Unit | Same BU records |
| 4 | Parent: Child BU | Parent + child BU records |
| 8 | Organization | All records |

### Access Right (Privilege Name Prefix)

| Prefix | Right |
|--------|-------|
| `prvCreate` | Create |
| `prvRead` | Read |
| `prvWrite` | Update |
| `prvDelete` | Delete |
| `prvAppend` | Append |
| `prvAppendTo` | Append To |
| `prvAssign` | Assign |
| `prvShare` | Share |

## McpServerTool Attribute

```csharp
    Name = "get_security_roles",
    ReadOnly = true,

```

## Tool Description for AI

```
List security roles and their privileges for Dataverse entities.
Shows what CRUD and other access rights each role has at which depth.

PARAMETERS:
- role_id: GUID of a specific role for privilege details. Leave empty to list all roles.
- role_name: Filter roles by name (contains match, e.g., 'Sales').
- business_unit_id: Filter by business unit. Leave empty for root BU roles.
- entity_name: In detail mode, show only privileges for this entity.
- max_records: Max roles in list mode (default: 50).

RETURNS:
- List mode: Table of roles with name, managed status, customizable flag
- Detail mode: All privileges grouped by entity with access depth

WHEN TO USE:
- When troubleshooting "access denied" or permission errors
- To understand what a user can see/do (check their role's privileges)
- Before creating a new entity (need to set up role permissions)
- To compare security roles (run twice with different role_ids)
- When auditing security configuration

TIPS:
- Depth: User < BusinessUnit < Parent:ChildBU < Organization
- Filter by parentroleid=null to get root roles (not inherited copies per BU)
- Use entity_name filter to focus on one entity's privileges in detail mode
- System Administrator has all privileges at Organization depth
```

## Implementation Notes

- List mode: query `role` table with `parentroleid eq null` filter (root roles only)
- Detail mode: query `roleprivileges` intersect with join to `privilege`
- Group privileges by entity (extract entity name from privilege name prefix pattern)
- Map depth mask (1,2,4,8) to display names
- Parse privilege names: `prvCreateAccount` → entity=`account`, right=`Create`
- If `entity_name` filter provided, only show privileges matching that entity
