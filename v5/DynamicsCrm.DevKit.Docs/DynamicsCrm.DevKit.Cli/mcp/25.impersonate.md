# Proposal: impersonate MCP Tool

## Priority: 12 (Advanced Features — Execute As Another User)

## Phase: 3 — Advanced Features

## Why This Tool Is Needed

Impersonation allows executing Dataverse operations as another user — critical for testing security roles, debugging user-specific issues, and administrative operations. The OData pattern requires setting the `CallerObjectId` or `MSCRMCallerID` header on each request. A dedicated tool manages the impersonation context so subsequent tool calls execute as the impersonated user.

### Current Pain (execute_webapi)

```
method: GET
url: accounts?$top=5
headers: {"MSCRMCallerID":"e5f6g7h8-xxxx-xxxx-xxxx-xxxxxxxxxxxx"}
```

Must repeat the header on EVERY request. Easy to forget, hard to debug when impersonation silently affects results.

### Proposed (impersonate)

```
action: start
user_id: e5f6g7h8-...
```

Sets impersonation context for ALL subsequent MCP tool calls until `action: stop`.

---

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `action` | string | Yes | — | `start` (begin impersonation), `stop` (revert to self), `status` (show current). |
| `user_id` | string | No | — | SystemUser GUID or email. Required for `start`. |

---

## Dataverse API

```csharp
// Start impersonation
if (action == "start")
{
    // Resolve email to GUID if needed
    var userId = IsGuid(user_id) ? user_id : ResolveUserByEmail(user_id);

    // Validate user exists and is enabled
    var user = GetRecord("systemuser", userId, "fullname,isdisabled,internalemailaddress");
    if (user.IsDisabled)
        throw new InvalidOperationException("Cannot impersonate a disabled user.");

    // Set on ServiceClient
    _serviceClient.CallerAADObjectId = Guid.Empty; // Clear AAD
    _serviceClient.CallerId = Guid.Parse(userId);
}
else if (action == "stop")
{
    _serviceClient.CallerId = Guid.Empty;
}
```

## Response Format

### Start
```
[Impersonating] Now executing as: John Smith (john@contoso.com)
  User ID: e5f6g7h8-...
  Business Unit: Sales
  Security Roles: Salesperson, Custom Role
⚠️ All subsequent operations will execute as this user until you call impersonate(action=stop).
```

### Stop
```
[ImpersonationStopped] Reverted to original user: Admin User (admin@contoso.com)
```

### Status
```
[ImpersonationStatus] Currently executing as: John Smith (john@contoso.com)
  Since: 2026-03-15 10:30:00 UTC
```

### Status — Not Impersonating
```
[ImpersonationStatus] Not impersonating — executing as: Admin User (admin@contoso.com)
```

```csharp
internal sealed class ImpersonateResult
{

    public string Action { get; set; }

    [JsonPropertyName("impersonatingUserId")]
    [JsonIgnore(Condition = JsonIgnoreCondition.WhenWritingNull)]
    public string ImpersonatingUserId { get; set; }

    [JsonPropertyName("impersonatingUserName")]
    [JsonIgnore(Condition = JsonIgnoreCondition.WhenWritingNull)]
    public string ImpersonatingUserName { get; set; }

    [JsonPropertyName("originalUserId")]
    public string OriginalUserId { get; set; }

    [JsonPropertyName("originalUserName")]
    public string OriginalUserName { get; set; }

    [JsonPropertyName("isImpersonating")]
    public bool IsImpersonating { get; set; }
}
```

## Safety Considerations

- Only users with `prvActOnBehalfOf` privilege can impersonate
- Impersonation affects ALL tool calls (FetchXML, upsert, delete, etc.)
- Audit logs will show the impersonated user as the actor
- Tool should warn if impersonation has been active for >10 minutes
- `stop` should always work, even if the impersonated user becomes disabled
