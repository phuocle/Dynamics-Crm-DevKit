# Proposal: update_form MCP Tool

## Priority: 11 (UI Customization Write -- Forms are the #1 UI artifact)

## Why This Tool Is Needed

After reading FormXML with `get_forms`, AI currently has NO dedicated tool to update it. The only option is `execute_webapi` with manually constructed PATCH requests, which:

1. **No auto-backup** -- AI must manually save current XML (and often forgets)
2. **No XSD validation** -- Invalid FormXML is written directly, breaking the form
3. **No auto-publish** -- Changes are invisible until a separate `publish_customizations` call
4. **Error-prone** -- AI must construct correct JSON body with escaped XML string

A single mistake in FormXML can **break the entire entity form**, making it unusable for all users. Without backup, the only recovery is environment restoration.

### Competitor Analysis (AppMaker)

AppMaker has 2 write tools for forms:

| Tool | Parameters | Auto-backup | XSD Validation | Auto-publish |
|------|-----------|-------------|----------------|--------------|
| `dataverse_form_update_formxml` | formId, formXml | **NO** | **YES** (via IFormXmlValidator) | **YES** |
| `dataverse_form_validate_formxml` | formXml | N/A | **YES** | N/A |

**AppMaker gaps:** No auto-backup. No rollback mechanism. If update fails after write, data is lost.

**DevKit advantage:** Auto-backup + validation + publish in a single safe tool.

## Purpose

Update a Dataverse form's FormXML with automatic backup, XSD schema validation, and publishing. This is the **safe write companion** to `get_forms` (read).

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| entity_name | string | Yes | - | Entity logical name (e.g., `"account"`). Used for backup naming and publishing. |
| form_id | string | Yes | - | GUID of the form to update. Use `get_forms` to find form IDs. |
| formxml | string | Yes | - | The new FormXML content. Must be valid XML following `schema://formxml` structure. |
| validate | bool | No | true | Validate FormXML against XSD schema before writing. Set false only if you've already validated with a separate call. |
| backup | bool | No | true | Save current FormXML to local backup file before overwriting. **Strongly recommended to keep true.** |
| auto_publish | bool | No | true | Automatically publish the entity after update. Set false if batching multiple changes. |

## Execution Flow

```
┌─────────────────────────────────────────────────────────────────┐
│ 1. RETRIEVE current form (systemform by form_id)                │
│    └─ If form not found → error with tip to use get_forms       │
├─────────────────────────────────────────────────────────────────┤
│ 2. BACKUP current FormXML to local file (if backup=true)        │
│    └─ Path: .devkit/backups/forms/{entity}_{formid}_{ts}.bak    │
│    └─ Include form name + entity in backup metadata              │
├─────────────────────────────────────────────────────────────────┤
│ 3. VALIDATE new FormXML against XSD schema (if validate=true)   │
│    └─ Load FormXml.xsd from embedded resources                   │
│    └─ If invalid → error with validation details + DO NOT write  │
├─────────────────────────────────────────────────────────────────┤
│ 4. UPDATE form record in Dataverse                              │
│    └─ Set systemform.formxml = new FormXML                       │
│    └─ client.Update(form)                                        │
├─────────────────────────────────────────────────────────────────┤
│ 5. PUBLISH entity (if auto_publish=true)                        │
│    └─ PublishXmlRequest for the entity                           │
├─────────────────────────────────────────────────────────────────┤
│ 6. RETURN result with backup file path for rollback reference   │
└─────────────────────────────────────────────────────────────────┘
```

## Dataverse API

### Retrieve Current Form

```csharp
var form = serviceClient.Retrieve("systemform", formId, new ColumnSet("formxml", "name", "objecttypecode"));
var currentFormXml = form.GetAttributeValue<string>("formxml");
```

### Save Backup

```csharp
var backupDir = Path.Combine(workingDirectory, ".devkit", "backups", "forms");
Directory.CreateDirectory(backupDir);
var backupFile = $"{entityName}_{formId:N}_{DateTime.Now:yyyyMMddHHmmss}.formxml.bak";
var backupPath = Path.Combine(backupDir, backupFile);
File.WriteAllText(backupPath, currentFormXml);
```

### Validate Against XSD

```csharp
var assembly = typeof(UpdateFormTool).Assembly;
var xsdStream = assembly.GetManifestResourceStream("...FormXml.xsd");
var schema = XmlSchema.Read(xsdStream, null);
var schemaSet = new XmlSchemaSet();
schemaSet.Add(schema);

var doc = XDocument.Parse(newFormXml);
var errors = new List<string>();
doc.Validate(schemaSet, (sender, e) => errors.Add(e.Message));

if (errors.Any())
    // Return validation errors, DO NOT proceed with update
```

### Update Form

```csharp
var update = new Entity("systemform", formId);
update["formxml"] = newFormXml;
serviceClient.Update(update);
```

### Publish

```csharp
var publishRequest = new PublishXmlRequest
{
    ParameterXml = $"<importexportxml><entities><entity>{entityName}</entity></entities></importexportxml>"
};
serviceClient.Execute(publishRequest);
```

## Response Format (Compact)

### Success
```
[FormUpdate] account — Account (Main)
FormId: abc-123-def
Status: Updated successfully
Validated: yes (0 errors)
Backup: .devkit/backups/forms/account_abc123_20260329180000.formxml.bak
Published: yes
```

### Validation Failed (form NOT updated)
```
[FormUpdate] BLOCKED — Validation failed
FormId: abc-123-def
Errors: 2
- Line 15: Element 'tab' has invalid child element 'rows'. Expected: 'labels', 'columns'.
- Line 28: The 'classid' attribute is missing on element 'control'.
Backup: not needed (no changes made)
Tip: Fix the FormXML errors above and retry. Refer to schema://formxml for valid structure.
```

### Error
```
[Error] Form update failed
FormId: abc-123-def
Message: Form with ID 'abc-123-def' not found
Tip: Use get_forms with entity_name to find valid form IDs
```

### Rollback Info (always included on success)
```
To rollback this change:
1. Read backup: .devkit/backups/forms/account_abc123_20260329180000.formxml.bak
2. Call update_form with the backup content as formxml
3. Or use execute_webapi: PATCH /systemforms(abc-123-def) with original formxml
```

## Tool Description for AI

```
Update a Dataverse form's FormXML with automatic backup, schema validation, and publishing.
This is the safe write companion to get_forms (read).

PARAMETERS:
- entity_name (required): Entity logical name (e.g., 'account'). Needed for backup naming and publishing.
- form_id (required): GUID of the form. Use get_forms to find form IDs first.
- formxml (required): The new FormXML content. Must follow the structure from schema://formxml.
- validate: Validate against XSD before writing (default: true). Blocks update if invalid.
- backup: Save current FormXML to local backup before overwriting (default: true).
- auto_publish: Publish the entity after update (default: true).

RETURNS:
- Update status (success/blocked/error)
- Validation results (if validate=true)
- Backup file path (for rollback)
- Publish status

WORKFLOW (MUST follow this order):
1. Call get_forms with form_id to READ the current FormXML
2. Modify the FormXML as needed (follow docs://instructions_for_formxml rules)
3. Call update_form with the modified FormXML
4. Tool auto-handles: backup → validate → update → publish
5. If something breaks: use the backup file path from the response to rollback

WHEN TO USE:
- After reading a form with get_forms and making modifications to the FormXML
- To add/remove/rearrange tabs, sections, or fields on a form
- To change form layout structure

WHEN NOT TO USE:
- To read forms (use get_forms instead)
- For non-FormXML form properties (use execute_webapi for metadata-only updates)

SAFETY:
- Auto-backup saves current FormXML before ANY modification
- XSD validation blocks invalid XML from being written
- Rollback instructions are included in every success response
- If backup=true and backup fails, the update is BLOCKED (fail-safe)

TIPS:
- Always read the current form first with get_forms to understand the structure
- Read schema://formxml for the XSD schema reference
- Read docs://instructions_for_formxml for naming conventions and best practices
- Set auto_publish=false when making multiple changes, then call publish_customizations once
- Backup files are at: .devkit/backups/forms/{entity}_{formid}_{timestamp}.formxml.bak
```

## Implementation Notes

- Use `serviceClient.Retrieve("systemform", ...)` to get current form
- XSD validation uses `System.Xml.Schema.XmlSchemaSet` with embedded `FormXml.xsd`
- Backup directory: `{workingDirectory}/.devkit/backups/forms/`
- **CRITICAL**: If `backup=true` and backup file write fails → ABORT the update (fail-safe)
- Strip XML declaration (`<?xml ...?>`) from input before writing (same as AppMaker)
- Use `PublishXmlRequest` for entity-specific publishing (not PublishAll)
- Return backup file path in response so AI can reference it later for rollback
- Pretty-print FormXML in backup file for human readability

## Pre-requisite

- `get_forms` tool (#3) must exist to read current FormXML
- `schema://formxml` MCP Resource (#2.5) must exist for XSD validation
- `publish_customizations` tool (#1) must exist (or use inline PublishXmlRequest)
- Embedded `FormXml.xsd` in `DynamicsCrm.DevKit.Shared\Resources\xsd\`

## Dependency Chain

```
get_forms (#3) → [AI modifies XML] → update_form (#11)
                                          ├── backup (auto)
                                          ├── validate via FormXml.xsd (#2.5)
                                          └── publish (auto)
```
