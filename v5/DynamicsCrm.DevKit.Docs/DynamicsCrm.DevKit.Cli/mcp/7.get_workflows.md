# Proposal: get_workflows MCP Tool

## Priority: 7 (Business Logic Discovery -- Understand automation on an entity)

## Why This Tool Is Needed

Dynamics 365 entities can have multiple types of automation: classic workflows, real-time workflows, business rules, actions, Business Process Flows, and Power Automate cloud/desktop flows. AI needs to discover what automation exists to avoid conflicts and understand entity behavior.

## Purpose

List workflows, business rules, and processes registered for an entity or across the environment. Covers all workflow categories stored in the `workflow` table.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| entity_name | string | No | (empty) | Filter by entity logical name (e.g., `"account"`). Leave empty for all entities. |
| category | string | No | (empty) | Filter by category: `"workflow"` (0), `"dialog"` (1), `"businessrule"` (2), `"action"` (3), `"bpf"` (4), `"flow"` (5), `"desktopflow"` (6). Leave empty for all. |
| active_only | bool | No | true | Only return active (published) workflows. Default: true. |
| max_records | int | No | 50 | Maximum records. Default: 50. |

## Dataverse Table

**Entity:** `workflow` | **Entity Set:** `/workflows`

### Key Columns

| Column | Type | Description |
|--------|------|-------------|
| `workflowid` | Guid | Primary key |
| `name` | String | Workflow display name |
| `primaryentity` | String | Entity logical name |
| `category` | Picklist | 0=Workflow, 1=Dialog, 2=BusinessRule, 3=Action, 4=BPF, 5=ModernFlow, 6=DesktopFlow |
| `type` | Picklist | 1=Definition, 2=Activation, 3=Template |
| `mode` | Picklist | 0=Background, 1=Realtime |
| `scope` | Picklist | 1=User, 2=BusinessUnit, 3=Parent-Child BU, 4=Organization |
| `statecode` | State | 0=Draft, 1=Activated |
| `statuscode` | Status | 1=Draft, 2=Activated |
| `ondemand` | Boolean | Can be run on-demand |
| `triggeroncreate` | Boolean | Triggers on Create |
| `triggeronupdateattributelist` | String | Comma-separated attributes that trigger on Update |
| `triggerondelete` | Boolean | Triggers on Delete |
| `createdon` | DateTime | Created date |
| `modifiedon` | DateTime | Last modified date |
| `description` | String | Description |
| `runas` | Picklist | 0=Owner, 1=CallingUser |

### FetchXML Query Pattern

```xml
<fetch>
  <entity name="workflow">
    <attribute name="workflowid" />
    <attribute name="name" />
    <attribute name="primaryentity" />
    <attribute name="category" />
    <attribute name="mode" />
    <attribute name="scope" />
    <attribute name="statecode" />
    <attribute name="ondemand" />
    <attribute name="triggeroncreate" />
    <attribute name="triggeronupdateattributelist" />
    <attribute name="triggerondelete" />
    <attribute name="modifiedon" />
    <attribute name="description" />
    <filter type="and">
      <condition attribute="type" operator="eq" value="1" />
      <!-- Only definitions, not activations/templates -->
      <!-- Add entity filter if entity_name provided -->
      <!-- Add category filter if category provided -->
      <!-- Add statecode=1 if active_only=true -->
    </filter>
    <order attribute="category" />
    <order attribute="name" />
  </entity>
</fetch>
```

## Tool Description for AI

```
List workflows, business rules, actions, and processes for a Dataverse entity.
Covers all automation types: classic workflows, business rules, custom actions,
Business Process Flows, and Power Automate flows.

PARAMETERS:
- entity_name: Filter by entity (e.g., 'account'). Leave empty for all.
- category: Filter type: 'workflow', 'businessrule', 'action', 'bpf', 'flow',
  'desktopflow', 'dialog'. Leave empty for all categories.
- active_only: Only return activated workflows (default: true).
- max_records: Maximum records (default: 50).

RETURNS:
- Table: name, category, mode, scope, triggers, status, last modified

WHEN TO USE:
- To understand what automation exists on an entity before making changes
- To check for conflicting workflows when adding a new plugin or workflow
- To audit business rules affecting field behavior
- When troubleshooting unexpected entity behavior (hidden automation)
- Before registering a new plugin (check if a workflow already handles the scenario)

TIPS:
- category=2 (BusinessRule) runs client-side AND server-side
- category=0 (Workflow) with mode=1 (Realtime) behaves like a plugin
- triggeronupdateattributelist shows exactly which attributes trigger the workflow
- Use with get_plugin_registrations to see the full picture of entity automation
```

## Implementation Notes

- Filter by `type eq 1` (Definition only -- exclude Activation records and Templates)
- Build triggers column from `triggeroncreate`, `triggeronupdateattributelist`, `triggerondelete`, `ondemand`
- Map category integers to display names
- Power Automate flows (category=5) may not have `primaryentity` set -- handle null
- BPF (category=4) doesn't have traditional triggers -- show "-"
