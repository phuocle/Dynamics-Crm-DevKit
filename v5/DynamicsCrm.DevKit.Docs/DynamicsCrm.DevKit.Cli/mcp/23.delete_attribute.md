# Proposal: delete_attribute MCP Tool

## Priority: 10 (Data Management — Remove Column)

## Phase: 2 — Data Management

## Why This Tool Is Needed

Deleting a column from a Dataverse entity requires a `DELETE` on the metadata endpoint with the correct `MetadataId` — not the logical name. This means two API calls: (1) resolve logical name → MetadataId, (2) DELETE. A guided tool handles this and adds safety checks (dependency validation, confirmation).

### Current Pain (execute_webapi)

```
# Step 1: Get MetadataId
method: GET
url: EntityDefinitions(LogicalName='account')/Attributes(LogicalName='new_obsoletefield')?$select=MetadataId

# Step 2: Delete
method: DELETE
url: EntityDefinitions(LogicalName='account')/Attributes(xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx)
```

Must know: (1) delete uses MetadataId not logical name, (2) dependent components (forms, views, workflows) may block deletion, (3) must publish after deletion.

### Proposed (delete_attribute)

```
entity_name: account
attribute_name: new_obsoletefield
```

Tool auto-resolves MetadataId, checks dependencies, and publishes.

---

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `entity_name` | string | Yes | — | Entity logical name (e.g., `account`). |
| `attribute_name` | string | Yes | — | Attribute logical name to delete (e.g., `new_obsoletefield`). |
| `force` | bool | No | false | Skip dependency check (dangerous). |
| `auto_publish` | bool | No | true | Publish entity after deletion. |

---

## Dataverse API

```csharp
// Step 1: Resolve MetadataId
var response = _serviceClient.ExecuteWebRequest(
    HttpMethod.Get,
    $"EntityDefinitions(LogicalName='{entity_name}')/Attributes(LogicalName='{attribute_name}')?$select=MetadataId,DisplayName,AttributeType",
    null, null
);
var metadataId = ParseMetadataId(response);

// Step 2: Check dependencies (unless force=true)
if (!force)
{
    var deps = _serviceClient.ExecuteWebRequest(
        HttpMethod.Get,
        $"RetrieveDependenciesForDelete(ObjectId=@id,ComponentType=2)?@id={metadataId}",
        null, null
    );
    if (HasDependencies(deps))
        throw new InvalidOperationException("Attribute has dependent components...");
}

// Step 3: Delete
_serviceClient.ExecuteWebRequest(
    HttpMethod.Delete,
    $"EntityDefinitions(LogicalName='{entity_name}')/Attributes({metadataId})",
    null, null
);

// Step 4: Publish
if (auto_publish)
    PublishEntity(entity_name);
```

---

## Response Format

### Success
```
[AttributeDeleted] account.new_obsoletefield (String)
  MetadataId: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
  Published: yes
```

### Error — Has Dependencies
```
[Error] Cannot delete account.new_obsoletefield — has 3 dependent components:
  - Form: Account Main Form (formid: xxx)
  - View: Active Accounts (viewid: xxx)
  - Workflow: Auto-populate field (workflowid: xxx)
Tip: Remove the attribute from these components first, or use force=true (dangerous).
```

### Error — System Attribute
```
[Error] Cannot delete 'name' — it is a system attribute.
Tip: Only custom attributes (with publisher prefix) can be deleted.
```
