# Proposal: manage_solution_components MCP Tool

## Priority: 8 (ALM -- Solution management is currently read-only)

## Why This Tool Is Needed

The existing `get_solution_components` tool is **read-only**. After AI creates entities, attributes, web resources, or other components, it cannot add them to a solution. This is a critical ALM (Application Lifecycle Management) gap -- components not in a solution cannot be exported/deployed.

## Purpose

Add or remove components to/from an unmanaged Dataverse solution.

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| solution_name | string | Yes | - | Solution unique name (e.g., `"MySolution"`). Must be unmanaged. |
| action | string | Yes | - | `"add"` or `"remove"`. |
| component_type | int | Yes | - | Component type code. Common: `1`=Entity, `2`=Attribute, `3`=Relationship, `9`=OptionSet, `24`=Form, `26`=View, `61`=WebResource, `91`=PluginAssembly, `92`=PluginStep. |
| component_id | string | Yes | - | GUID (MetadataId) of the component to add/remove. |
| add_required_components | bool | No | false | When adding: also add all required dependent components. |
| include_sub_components | bool | No | true | When adding entity (type=1): include all sub-components (attributes, forms, views). Set false to add entity shell only. |

## Dataverse API

### Add Component

```csharp
var request = new AddSolutionComponentRequest
{
    ComponentType = componentType,        // e.g., 1 for Entity
    ComponentId = componentGuid,          // MetadataId of the component
    SolutionUniqueName = solutionName,
    AddRequiredComponents = addRequired,
    DoNotIncludeSubcomponents = !includeSubComponents  // Note: inverted logic!
};
_serviceClient.Execute(request);
```

### Remove Component

```csharp
var request = new RemoveSolutionComponentRequest
{
    ComponentType = componentType,
    ComponentId = componentGuid,
    SolutionUniqueName = solutionName
};
_serviceClient.Execute(request);
```

## Common Component Type Codes

| Code | Type | How to Get ComponentId |
|------|------|----------------------|
| 1 | Entity | `get_entity_metadata` → MetadataId (not entity GUID) |
| 2 | Attribute | `EntityDefinitions(LogicalName='x')/Attributes(LogicalName='y')` → MetadataId |
| 3 | Relationship | `RelationshipDefinitions(SchemaName='x')` → MetadataId |
| 9 | OptionSet | `GlobalOptionSetDefinitions(Name='x')` → MetadataId |
| 24 | SystemForm | `get_forms` → formid |
| 26 | SavedQuery (View) | `get_views` → savedqueryid |
| 61 | WebResource | `execute_fetchxml` on webresource → webresourceid |
| 91 | PluginAssembly | `execute_fetchxml` on pluginassembly → pluginassemblyid |
| 92 | SDKMessageProcessingStep | `get_plugin_registrations` → stepid |

## Response Format (Compact)

### Add success
```
[Solution] MySolution
Action: Added
ComponentType: Entity (1)
ComponentId: abc-123-def
IncludeSubComponents: yes
AddRequiredComponents: no
```

### Remove success
```
[Solution] MySolution
Action: Removed
ComponentType: WebResource (61)
ComponentId: abc-123-def
```

### Error -- Managed solution
```
[Error] Cannot modify managed solution 'ManagedSolution'
Tip: Only unmanaged solutions can have components added/removed
```

### Error -- Dependency blocks removal
```
[Error] Cannot remove Entity 'account' from MySolution
Reason: Other components in the solution depend on this entity
Tip: Use execute_webapi with RetrieveDependenciesForDelete to find dependencies
```

## McpServerTool Attribute

```csharp
[McpServerTool(
    Name = "manage_solution_components",
    ReadOnly = false,
    Destructive = false)]
```

## Tool Description for AI

```
Add or remove components to/from an unmanaged Dataverse solution.
Use this after creating entities, attributes, web resources, or other components
to include them in a solution for export/deployment.

PARAMETERS:
- solution_name (required): Unique name of the unmanaged solution.
- action (required): 'add' or 'remove'.
- component_type (required): Type code: 1=Entity, 2=Attribute, 9=OptionSet,
  24=Form, 26=View, 61=WebResource, 91=PluginAssembly, 92=PluginStep.
- component_id (required): GUID/MetadataId of the component.
- add_required_components: Also add dependencies (default: false).
- include_sub_components: For entities: include all sub-components (default: true).

RETURNS:
- Action performed (Added/Removed)
- Component type and ID

WHEN TO USE:
- After creating a new entity, attribute, or web resource
- To organize components into solutions for deployment
- Before exporting a solution (ensure all needed components are included)
- To clean up a solution by removing unnecessary components

TIPS:
- For entities (type=1), use MetadataId from get_entity_metadata, NOT the entity record GUID
- Use get_solution_components to verify what's already in the solution
- Only unmanaged solutions can be modified
- include_sub_components=true (default) adds entity with ALL its forms, views, attributes
- If removal fails, check dependencies with execute_webapi RetrieveDependenciesForDelete
```

## Implementation Notes

- Use `AddSolutionComponentRequest` / `RemoveSolutionComponentRequest` from `Microsoft.Crm.Sdk.Messages`
- Validate solution exists and is unmanaged before attempting add/remove
- `DoNotIncludeSubcomponents` is the **inverse** of `include_sub_components` parameter
- Component type 1 (Entity) requires MetadataId, not the table's record GUID
- Handle `FaultException` for dependency errors gracefully
