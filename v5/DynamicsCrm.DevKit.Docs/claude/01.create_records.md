# Before optimize

## Block 1 — Tool description (hiện tại)

```text
Create multiple Dataverse records in parallel — optimized for data migration. Partial failures reported per-item; successful records still created.

DEFAULT (shown in output when not provided):
  max_parallelism: from server x-ms-dop-hint (typically 4–8 for cloud). Hard limit: 52.

TIPS:
- records_json: inline JSON array, .json file path (from generate_demo_data), or .csv (headers=Display Name; lookups by Name: 1 match=GUID, 0 or 2+=skipped)
- Polymorphic lookups: use "fieldname@targetentity" syntax
- max_parallelism=1–2 for on-prem/throttled envs; max 5000 records per call
```

## Block 2 — Parameter descriptions (hiện tại)

```text
[entity_name] (string, required)
Entity logical name (e.g., 'account'). Required.

[records_json] (string, required)
JSON array of field objects (inline), OR file path (.json from generate_demo_data), OR CSV file path (.csv with Display Name headers). Max 5000 records.

[max_parallelism] (int, default: 0)
Max concurrent requests. 0 (default) = use server hint (x-ms-dop-hint). Clamped to 1–52.
```

Input: inline JSON array, .json (from generate_demo_data), or .csv with Display Name headers (lookups resolved by Name: 1 match=GUID, 0/2+=skipped). Polymorphic lookup: 'field@targetentity'. Max 5000 records/call.

```text
WHEN TO USE:
- Bulk insert > 1 records of the same entity (data migration, demo seeding)
- Pipe demo data: generate_demo_data → create_records
- For single-record CRUD use manage_record instead

FUZZY/AMBIGUITY:
- CSV lookup-by-name: exactly 1 match becomes GUID; 0 or 2+ is skipped with warning.
```
