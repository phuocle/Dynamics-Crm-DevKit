# Before optimize

## Block 1 — Tool description (hiện tại)

```text
Manage Dataverse views (savedquery/userquery) — list, read, create, update, rename, restore.

ACTIONS:
- action='list': List views with name, type, status. Optional: query_type, include_fetchxml, include_personal
- action='detail': Full FetchXML + LayoutXML + metadata for one view. Requires: view_id
- action='create': New Public view. Requires: view_name + layoutxml
- action='update': Modify LayoutXML/FetchXML. Requires: view_id + (layoutxml and/or cell_updates_json)
- action='rename': Change display name. Requires: view_id + view_name
- action='undo': Restore from backup. Requires: view_id + layoutxml (= backup file path)

WORKFLOW: list → modify XMLs → update. Auto: backup → XSD+sync validate → update → publish.
SYNC RULE: Every FetchXML <attribute> MUST match a LayoutXML <cell>. Tool blocks if out of sync.

TIPS:
- querytype: 0=Public, 4=QuickFind (search bar), 64=SubGrid
- view_name: 1 exact match = auto-returns detail
- Read docs://instructions_for_views for sync rules; schema://layoutxml + schema://fetchxml for XSD
- Set auto_publish=false when batching; call publish_customizations once after
```

## Block 2 — Parameter descriptions (hiện tại)

```text
[action] (string, required)
The action to perform: 'list', 'detail', 'create', 'update', 'rename', or 'undo'.

[entity_name] (string, required)
Entity logical name (e.g., 'account'). Use get_tables if unsure.

[view_id] (string, default: "")
GUID of a view. Required for detail/update/rename/undo. Empty for list/create.

[view_name] (string, default: "")
Filter by name (contains match). 1 match = auto-detail. Ignored if view_id set.

[query_type] (int, default: -1)
Filter by type: 0=Public, 1=Lookup, 4=QuickFind, 64=SubGrid. -1 = all.

[include_fetchxml] (bool, default: false)
Include FetchXML/LayoutXML in list mode (default: false). Detail mode always includes.

[include_personal] (bool, default: false)
Include personal views (userquery) owned by current user. Default: false.

[layoutxml] (string, default: "")
For 'update'/'create': LayoutXML. For 'undo': layout backup path. Ignored for list/detail/rename.

[fetchxml] (string, default: "")
FetchXML. Empty = keep existing (update) or auto-generate (create). For 'undo': fetch backup path.

[validate] (bool, default: true)
Validate XMLs and check FetchXML<>LayoutXML sync (default: true). Blocks if invalid.

[backup] (bool, default: true)
Backup current XMLs before overwriting (default: true). Backup failure blocks update.

[auto_publish] (bool, default: true)
Publish after changes (default: true). Set false when batching.

[cell_updates_json] (string, default: "")
JSON array of cell attribute updates. Each item: {cell_name, set_attributes, remove_attributes}. Patch cell attributes (e.g., imageproviderwebresource, imageproviderfunctionname, ishidden) without rebuilding full LayoutXML. Can be used alone or with layoutxml.
```

# After optimize

## Phân tích

Source: [ManageViewTool.cs](../../DynamicsCrm.DevKit.Cli/Mcp/Tools/ManageViewTool.cs)

- ACTIONS giữ vì required khác nhau — gom 1 dòng/action.
- WORKFLOW + SYNC RULE giữ nguyên (sync rule là nghiệp vụ critical).
- TIPS bullet 4 (auto_publish) đã có trong param.
- Param defaults thừa "default: false/true" lặp.
- Tách FUZZY/AMBIGUITY và SAFETY thành section riêng để AI dễ parse.

## Block 1 — Tool description (optimized)

```text
Dataverse views (savedquery/userquery) — list/detail/create/update/rename/undo. Required: list (none); detail (view_id); create (view_name+layoutxml); update (view_id + layoutxml and/or cell_updates_json); rename (view_id+view_name); undo (view_id+backup path). Auto: backup→XSD+sync validate→update→publish. SYNC RULE: every FetchXML <attribute> MUST have a matching LayoutXML <cell>; mismatch blocks. querytype: 0=Public, 4=QuickFind, 64=SubGrid. See docs://instructions_for_views, schema://layoutxml, schema://fetchxml.

WHEN TO USE:
- Inspect existing views (list, detail) before editing
- Apply layout/fetch changes (action=update)
- Patch cell attributes only via cell_updates_json (no full LayoutXML rebuild)

FUZZY/AMBIGUITY:
- view_name is contains match. Exactly 1 → auto-detail; multiple → tool returns candidates, use view_id to disambiguate.

SAFETY:
- Validation blocks FetchXML/LayoutXML mismatch by default (validate=true).
```
