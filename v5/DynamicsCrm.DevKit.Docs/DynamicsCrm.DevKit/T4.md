# T4 Template Engine Documentation

## Overview

The DynamicsCrm.DevKit VSIX extension uses Microsoft's **T4 (Text Template Transformation Toolkit)** engine to generate C# code for Dynamics 365/Dataverse development. T4 templates enable customizable code generation for plugins, workflows, custom actions, custom APIs, data providers, and unit tests.

## Architecture

### Core Components

| Component | Location | Purpose |
|-----------|----------|---------|
| **T4Helper** | `DynamicsCrm.DevKit\Lib\T4Helper.cs` | Manages template retrieval and processing |
| **T4Callback** | `DynamicsCrm.DevKit\Lib\T4Callback.cs` | Handles T4 compilation errors and output |
| **T4Context** | `DynamicsCrm.DevKit.Shared\Models\T4Context.cs` | Data model passed to templates |
| **Templates** | `DynamicsCrm.DevKit.Shared\Resources\tt\*.tt` | T4 template files |
| **VsixHelper** | `DynamicsCrm.DevKit\Lib\VsixHelper.cs` | Template storage and retrieval |
| **FormPlugin** | `DynamicsCrm.DevKit\Lib\Forms\FormPlugin.xaml.cs` | UI for template selection |
| **FormCustom** | `DynamicsCrm.DevKit\Lib\Forms\FormCustom.xaml.cs` | Template customization editor |

### T4 Workflow

```
User Action → FormPlugin → T4Helper.GetT4CodeAsync() → Load Template
                    ↓
            T4Helper.BuildContextAsync() → Create T4Context
                    ↓
            T4Helper.ProcessTemplateAsync() → Transform Template
                    ↓
            Generated Code → Item Wizard → Create File
```

## T4Helper Class

**Namespace:** `DynamicsCrm.DevKit.Lib`
**Purpose:** Central orchestrator for T4 template operations

### Methods

#### GetT4CodeAsync
```csharp
public static async Task<string> GetT4CodeAsync(ItemType itemType, string templateTitle, string subType = null)
```

**Description:** Retrieves the T4 template code for a specific item type.

**Parameters:**
- `itemType` (ItemType): Type of template (Plugin, Workflow, CustomAction, CustomApi, etc.)
- `templateTitle` (string): Title of custom template or "Default"
- `subType` (string, optional): Sub-type for DataProvider/Test templates

**Returns:** T4 template code as string

**Behavior:**
1. Loads custom templates from `DynamicsCrm.DevKit.Config.json`
2. Returns user's custom template if found
3. Falls back to default embedded template
4. Decompresses template body from storage

---

#### ProcessTemplateAsync
```csharp
public static async Task<string> ProcessTemplateAsync(string t4code, T4Context context)
```

**Description:** Transforms T4 template using Visual Studio's TextTemplating service.

**Parameters:**
- `t4code` (string): T4 template source code
- `context` (T4Context): Data model for template transformation

**Returns:** Generated C# code or error messages

**Process:**
1. Creates `T4Callback` for error handling
2. Retrieves `ITextTemplating` service from Visual Studio
3. Creates session and injects `T4Context` parameter
4. Prepends parameter directive to template
5. Processes template using VS TextTemplating engine
6. Returns generated code or compilation errors

**Important:** Automatically adds this directive to every template:
```
<#@ parameter type="DynamicsCrm.DevKit.Shared.Models.T4Context" name="Context"#>
```

##### IsPluginSupportedPostImage

- assign, create, deliverincoming, deliverpromote, merge, route, send
- setstate, setstatedynamicentity, update, createmultiple, updatemultiple, executeworkflow

**Usage:** Conditionally generates PostImage registration in Plugin.tt

### Wizard Workflow Example (Plugin)

```csharp
public void RunStarted(object automationObject, Dictionary<string, string> replacementsDictionary,
                       WizardRunKind runKind, object[] customParams)
{
    ThreadHelper.JoinableTaskFactory.Run(async () =>
    {
        // 1. Show FormPlugin dialog
        var form = new FormPlugin(ItemType.Plugin, replacementsDictionary["$rootnamespace$"]);
        var ok = form.ShowModal() ?? false;

        if (ok)
        {
            // 2. Get T4 template code
            var t4Code = await T4Helper.GetT4CodeAsync(ItemType.Plugin, form.CustomTemplate);

            // 3. Build T4Context from form selections
            var t4Context = await T4Helper.BuildContextAsync(form);

            // 4. Process template
            var code = await T4Helper.ProcessTemplateAsync(t4Code, t4Context);

            // 5. Add to replacement dictionary
            replacementsDictionary.Add("$plugin$", code);
            replacementsDictionary.Add("$Class$", form.Class);
            replacementsDictionary.Add("$PluginOrder$", form.PluginOrder == 1 ? string.Empty : $"{form.PluginOrder}");
        }
        else
        {
            VsixHelper.ThrowWizardCancelledException();
        }
    });
}
```

### ReplacementsDictionary Parameters

Templates use these placeholders in `.cs` files:

| Placeholder | Source | Description |
|-------------|--------|-------------|
| `$plugin$` | T4 output | Generated plugin code |
| `$Class$` | FormPlugin | Class name |
| `$PluginOrder$` | FormPlugin | Order suffix (empty if 1) |
| `$rootnamespace$` | VS | Project namespace |

## Error Handling

### T4Callback Error Collection

```csharp
if (cb.errorMessages.Count > 0)
    return string.Join("\r\n", cb.errorMessages);
```

**Error Format:**
```
line: 15, column: 23, message: Unexpected character '<'
```

### Common T4 Errors

| Error | Cause | Solution |
|-------|-------|----------|
| Syntax error in template | Malformed `<#` or `#>` tags | Validate T4 syntax |
| Context property missing | Accessing undefined T4Context property | Update T4Context model |
| Type mismatch | Incorrect property type usage | Check T4Context property types |
| Compilation error in output | Generated code has C# errors | Fix template logic |

## Performance Considerations

### Template Caching

- Templates are retrieved from disk on each usage
- Compression/decompression happens for custom templates
- No in-memory caching of parsed templates

### Optimization Opportunities

1. **Cache parsed templates** in memory during VS session
2. **Lazy-load default templates** instead of embedding all in assembly
3. **Parallel template processing** for DataProvider multi-file generation
4. **Incremental template compilation** for live preview

## Comparison with Alternative Approaches

### T4 vs. String Concatenation

| Aspect | T4 Templates | String Concat |
|--------|--------------|---------------|
| **Readability** | High - resembles output | Low - fragmented |
| **Maintainability** | High - in-place editing | Low - string escaping |
| **IDE Support** | Syntax highlighting | None |
| **Performance** | Compilation overhead | Fast |
| **Flexibility** | Full C# logic | Limited |

### T4 vs. Roslyn SyntaxFactory

| Aspect | T4 Templates | Roslyn SyntaxFactory |
|--------|--------------|----------------------|
| **Learning Curve** | Low | High |
| **Type Safety** | Runtime errors | Compile-time |
| **Code Structure** | Text-based | AST-based |
| **Customization** | User-editable | Programmatic only |
| **Dependencies** | VS T4 Engine | Roslyn NuGet |

## Optimization Recommendations

### Current Implementation Analysis

**Strengths:**
- ✅ User-customizable templates
- ✅ Clean separation of logic and output
- ✅ Well-structured data model (T4Context)
- ✅ Compression for storage efficiency
- ✅ Conditional code generation (images, async)

**Weaknesses:**
- ❌ No template validation before save
- ❌ No syntax highlighting in FormCustom editor
- ❌ Template processing on UI thread (blocking)
- ❌ Duplicate template loading logic
- ❌ Missing error recovery in ProcessTemplateAsync

### Suggested Improvements

#### 1. Add Template Validation on Save

**Current:** Templates saved without validation, errors appear during code generation.

**Proposed:**
```csharp
private async Task<bool> ValidateTemplateAsync(string t4Code, T4Context sampleContext)
{
    var result = await T4Helper.ProcessTemplateAsync(t4Code, sampleContext);
    if (result.StartsWith("line:"))
    {
        await VS.MessageBox.ShowErrorAsync($"Template validation failed:\n{result}");
        return false;
    }
    return true;
}
```

**Benefit:** Catch errors before user saves broken templates.

#### 2. Implement Template Preview Cache

**Current:** Every "Review" button click reprocesses template.

**Proposed:**
```csharp
private string _lastT4Code = null;
private string _lastGeneratedCode = null;

private async Task<string> GetCachedOrProcessAsync(string t4Code, T4Context context)
{
    if (t4Code == _lastT4Code && _lastGeneratedCode != null)
        return _lastGeneratedCode;

    _lastT4Code = t4Code;
    _lastGeneratedCode = await T4Helper.ProcessTemplateAsync(t4Code, context);
    return _lastGeneratedCode;
}
```

**Benefit:** Faster preview for iterative editing.

```csharp
public static async Task<Dictionary<string, string>> ProcessMultiContextTemplateAsync(
    string t4code,

    var results = new Dictionary<string, string>();
```

## Best Practices

### Template Design

1. **Keep templates readable** - Use whitespace and comments
2. **Validate Context properties** - Check for null/empty before use
3. **Use conditional blocks wisely** - Don't over-nest `<#if#>` statements
4. **Include helpful comments** - Explain complex logic
5. **Test with edge cases** - Empty entities, special characters

### Custom Template Naming

- Use descriptive names: `PluginWithLogging`, `AsyncWorkflow`
- Avoid generic names: `Template1`, `Test`
- Include purpose: `PluginForComplexLogic`, `WorkflowWithRetry`

### Version Control

- Commit `DynamicsCrm.DevKit.Config.json` to source control
- Document template changes in commit messages
- Use branches for template experiments

## Troubleshooting

### Template Not Found

**Symptom:** Template returns empty string or default.

**Causes:**
- Template title mismatch
- ItemType mismatch
- Config file missing/corrupted

**Solution:** Verify `DynamicsCrm.DevKit.Config.json` structure and reload VS.

---

### Compilation Errors in Generated Code

**Symptom:** VS shows errors in generated .cs file.

**Causes:**
- T4 syntax error
- Invalid C# in template output
- Missing Context property

**Solution:** Use "Review" button in FormCustom to see actual output before saving.

---

### Template Processing Hangs

**Symptom:** UI freezes during template processing.

**Causes:**
- Infinite loop in template logic
- Large template with complex conditionals

**Solution:** Add logging in T4Callback, use VS diagnostic tools.
