# 22. manage_deleted_records

# Tool description AI đọc được

```
Name:        manage_deleted_records
Title:       List/detail/restore/check-status of soft-deleted Dataverse records
Idempotent:  false
Destructive: false
ReadOnly:    false

Description:
List / detail / restore / status for soft-deleted records. Soft-delete = IOrganizationService.Delete
(records recoverable for up to MaxRetentionDays, default 30). Uses FetchXml datasource='bin' for
list/detail (bin exposes only entity attributes — no 'deletedon'/'deletedby', use 'modifiedOn' as
proxy). Restore uses OrganizationRequest('Restore') late-bound. RELATED: manage_record (live CRUD),
execute_webapi (raw), get_audit_history (who deleted).

Parameters:
  action       (string, default: "list")
    Action: 'list' (default) | 'detail' | 'restore' | 'status'.
  entity_name  (string, default: "")
    Entity Display/logical name. list: required. detail: required. restore: required if record_ids
    mix entities. status: not used.
  record_id    (string, default: "")
    Single GUID. detail: required. list: not used. restore: optional if record_ids set.
  record_ids   (string[], default: null)
    Array of GUIDs (preferred for restore). detail/list: not used. restore: alternative to record_id.
  name_filter  (string, default: "")
    Search by primary attribute value (contains, case-insensitive). list only. Empty = all deleted
    records of entity.
  max_records  (int, default: 100)
    Max records. list: default 100, max 5000. detail/restore/status: not used.
  dry_run      (bool, default: true)
    Set false to actually restore. list/detail/status: not used. Default true (safe preview).
```

# Input tool call

```json
{
  "name": "manage_deleted_records",
  "arguments": {
    "action": "list",
    "entity_name": "Account",
    "name_filter": "DEVKIT-MDR",
    "max_records": 20
  }
}
```

> Trên org `🟢DEVKITV4` (DEVKITV4.crm.dynamics.com), list tất cả `Account` đang nằm trong recycle bin (soft-deleted), filter theo `name LIKE '%DEVKIT-MDR%'`. Mục đích: trước khi test `restore`, tìm GUID record test `DEVKIT-MDR-RESTORE-073100` đã xóa ở step trước. `max_records=20` cap để tránh flood (org này có nhiều record test cũ). Tool sẽ build FetchXml `<fetch top='20' datasource='bin'><entity name='account'>...<filter><condition attribute='name' operator='like' value='%DEVKIT-MDR%'/></filter></entity></fetch>` và gọi `RetrieveMultiple`.

# Kết quả AI tổng hợp lại

- **Trạng thái:** Thành công (`[Success]`, `IsError=false`). Trả về **1 record** `account` đang trong recycle bin trên org `🟢DEVKITV4`.
- **Mode = `list`** (default action) → query `FetchExpression` với `datasource="bin"`, filter `name LIKE '%DEVKIT-MDR%'`.
- **Record duy nhất:**
  - `recordId = 4d2869a3-958c-f111-8076-7c1e528d2c9f` — GUID soft-deleted Account.
  - `recordName = "DEVKIT-MDR-RESTORE-073100"` — primary name (cột `name`).
  - `modifiedOn = "2026-07-31 03:49"` — xấp xỉ thời điểm xóa (bin KHÔNG có `deletedon` system field, dùng `modifiedon` làm proxy — verified qua probe §6.8.2 trong plan).
  - `createdOn = "2026-07-31 03:49"` — record được tạo cùng lúc test, sau đó xóa ngay.
  - `modifiedBy = "# DEVKIT"` — user thực hiện delete (= user sửa cuối).
  - `expiresOn = "2026-08-30 03:49"` — `modifiedOn + maxRetentionDays (30)` = ngày tự động purge nếu không restore. Tính từ `recyclebinconfig.cleanupintervalindays` (mặc định 30).
  - `canRestore = true` — luôn `true` nếu record còn trong bin (chưa bị auto-purge).
- **Lưu ý quan trọng về schema bin** (verified §6.8 plan):
  - Bin records là **projection** của live table, KHÔNG có system fields `deletedon` / `deletedby` / `deletionstatecode`.
  - Chỉ có attributes của entity gốc (`name`, `createdon`, `modifiedon`, `modifiedby`, …) + GUID.
  - `statecode` KHÔNG đổi sang 1 (Inactive) khi xóa — vẫn `Active (0)`. Dùng `datasource="bin"` mới biết record đã xóa.
- **Cấu trúc response:**
  - `action = "list"`, `entityName = "account"` (logical, lowercase), `entityDisplayName = "Account"` (user-localized).
  - `totalCount = 1` — số records thực sự trả về (đã áp filter, đã cap theo `max_records`).
  - `records[]` — mỗi entry có 8 trường: `recordId`, `recordName`, `modifiedOn`, `createdOn`, `modifiedBy`, `expiresOn`, `canRestore`. Field null sẽ bị `[JsonIgnore(WhenWritingNull)]` ẩn (ví dụ ở đây `modifiedBy` không null, nên hiện).
  - **`pagingCookie` / `hasMore`** KHÔNG hiển thị ở đây vì null — giấu khỏi JSON theo rule 5.
- **Token tiết kiệm:**
  - Content 1 dòng duy nhất `[Success] account: 1 deleted record(s).` — đủ để AI xác nhận count.
  - DTO null-aware: property null bị `WhenWritingNull` ẩn → JSON gọn.
- **Cách dùng tiếp theo:**
  - Lấy `recordId` ở trên, gọi `action='detail'` để xem full attributes (còn trong bin) — giống `manage_record(action='read')` nhưng đọc từ `datasource="bin"`.
  - Hoặc gọi thẳng `action='restore'` với `record_id=<guid>`, `dry_run=true` để preview, sau đó `dry_run=false` để restore thật.
  - Nếu cần xem config retention của org: `action='status'`.

Nếu `softDeleteSupported=false` → org chưa bật tính năng này (cần admin enable trong Power Platform admin center).
