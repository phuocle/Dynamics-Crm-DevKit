# ✅ TOOL DESCRIPTION

```text
List Business Process Flow definitions or inspect one BPF and its stage definitions.

WHEN TO USE:
- Inspect stage categories and primary entities for a BPF
- Find BPFs bound to an entity (entity_name filter)
- Resolve BPF unique/logical name for the auto-created entity

RELATED TOOLS:
- get_workflows → classic workflow definitions (background async + realtime sync)
- get_business_rules → client-side business rules
- get_flows → Power Automate cloud flows
```

# PARAMETERS

```text
bpf_id          : string : GUID -> detail. Empty = list.
bpf_name        : string : Name contains. 1 match -> auto-detail. Omit or pass null to list all.
entity_name     : string : Primary entity filter, Display Name or logical name (e.g. 'Lead' or 'lead').
status          : string : Filter by state: 'active' (Draft hidden), 'draft' (only Draft), or 'all' (no filter). Default 'all' returns every BPF regardless of state.
include_stages  : bool   : List only. Detail always includes.
max_records     : int    : 1-250.
```

# RESULTS

- Test 1: list mode returns all 5 BPFs (AccountBPF for `account`; Expired/New/Translation Process for `knowledgearticle`; Update Contact for `contact`).
- Test 2: `entity_name='contact'` filter returns 1 BPF, with `entityName` echoed in structured output.
- Test 3: `bpf_name='AccountBPF'` (1 match) auto-switches to detail mode and returns `stages[]` in correct sequence (Stage 1 → Stage 2, Qualify → Develop).
- Test 4: `bpf_id` detail mode returns the identical payload to Test 3.
- Test 5: invalid `status` returns an error with a hint listing the accepted values.
- Test 6: non-GUID `bpf_id` returns an error with a hint showing the expected GUID format.
- Test 7: `bpf_name` with no match is an error (not an empty success) with a hint to list available BPFs.
- Test 8: well-formed but nonexistent `bpf_id` returns a not-found error with a hint to list available BPFs.
- Test 9: unresolvable `entity_name` returns the resolver not-found error with a `[Hint]` pointing to `get_tables` (first line of the resolver error becomes the message — the CreateRecordsTool/GetTablesTool convention).
