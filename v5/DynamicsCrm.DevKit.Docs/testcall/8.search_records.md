# 8. search_records

# Tool description AI đọc được

```
Name:        search_records
Title:       Search records by keyword or check Relevance Search status
Idempotent:  true
Destructive: false
ReadOnly:    true

Description:
Dataverse Relevance Search. Requires Relevance Search enabled.

Parameters:
  action       (string, default: "search")
    'search' (default) or 'status'.
  search_term  (string, default: "")
    Required for search. 1-100 chars. Operators: + (AND), | (OR), - (NOT), * (wildcard), "phrase", () (group).
  entities     (string, default: "")
    Comma-separated Display Names or logical names (e.g. 'Account,contact'). Empty = all searchable.
  top          (int, default: 50)
    Max results to return. 1-100 (default 50).
  filter       (string, default: "")
    OData filter applied after search. e.g. 'statecode eq 0'.
```

# Input tool call

```json
{
  "name": "search_records",
  "arguments": {
    "action": "search",
    "search_term": "Boyle",
    "top": 10
  }
}
```

> Trên org `🟢DEVKITV4` (DEVKITV4.crm.dynamics.com), người dùng tìm keyword **`Boyle`** qua Dataverse Relevance Search. Để ngỏ `entities` → search tất cả indexable entities; `filter` cũng trống → không áp OData filter. `top=10` chỉ là cap, kết quả thực tế nhỏ hơn nhiều.

# Kết quả AI tổng hợp lại

- **Trạng thái:** Thành công (`[Success]`, `IsError=false`). Trả về đúng **1 record** match với keyword `Boyle` trên org `🟢DEVKITV4` Dataverse 9.2.
- **Record khớp:** `account.name = "Boyle Inc"` (account `71f939f8-4e40-f111-bec6-70a8a59a451e`, owner `# DEVKIT`).
- **Score:** `14.692136` — Relevance Search BM25 score (cao = match mạnh hơn). Nếu `top=10` và match nhiều, client có thể sort-desc theo field này để lấy top-K chất lượng nhất.
- **Highlight:** `name` được mark bằng `{crmhit}Boyle{/crmhit} Inc` — Relevance Search nhấn đúng từ khoá tại field `account.name` (field đã được index, xem `get_tables(account)` confirm `isSearchable=true`).
- **Thời gian:** `~200ms` — endpoint `/api/search/v1.0/searchquery` trả về trong 1 round-trip; rất nhanh so với pattern `select * from account where contains(name,'Boyle')`.
- **Cấu trúc response:**
  - `action` = `search`, `searchTerm` echo lại input (đã trim).
  - `returnedCount=1`, `totalCount=1` → `count=true` trong request body được Dataverse trả về giống nhau vì kết quả chỉ có 1.
  - `queryContext.originalQuery = "boyle"` (lowercased) — Dataverse normalize query trước khi search; nếu keyword bị rewrite nặng (vd stemming, alias) thì `alteredQuery` + `reason` + `spellSuggestions` sẽ populate thêm.
  - `attributes` chứa flattened view của indexed columns + `@search.*` annotation: `objecttypecode`, `ownerid` (+ `owneridname` + logical-name hint), `name`, `createdon`, `modifiedon`. Client-side formatted values như `1/30/2026 10:09 AM` đi kèm nhưng key có hậu tố `@OData.Community.Display.V1.FormattedValue` (Dataverse OData convention).
  - **`objectTypeCode` trong record luôn = 0** — quirk của Dataverse `/searchquery`: top-level `objectTypeCode` không populate. Lấy OTC thật từ `attributes["@search.objecttypecode"]` (ở đây = `1` = account). Nếu cần resolve Display Name thì dùng `entityName` (đã được Dataverse set sẵn = `"account"`).
  - `highlights.name` mảng 1 phần tử — nếu keyword xuất hiện ở nhiều field sẽ có nhiều key (vd `name`, `description`).
- **Token tiết kiệm:**
  - Property `null` bị `[JsonIgnore(WhenWritingNull)]` ẩn — `errorCode` / `errorMessage` / `rawResponse` / `status` / `statistics` đều không xuất hiện trong happy-path payload.
  - `records[i]` chỉ include những field Dataverse trả về trong projection mặc định, không phải toàn bộ schema `account`.
- **Cách dùng tiếp theo:** Lấy `id` của record trên để đi tiếp, ví dụ `manage_record(action='read', entity_name='account', record_id='71f939f8-4e40-f111-bec6-70a8a59a451e')`, hoặc dùng `execute_fetchxml` nếu cần filter kỹ hơn (kiểu `statecode eq 0`).
- **Path tương đương FetchXML** nếu Relevance Search tắt: `execute_fetchxml(fetchxml='<fetch><entity name="account"><filter><condition attribute="name" operator="like" value="%Boyle%"/></filter></entity></fetch>')`.

## Ví dụ phụ 1: lọc theo `entities` (account + contact) → chỉ account match

**Input:**

```json
{
  "name": "search_records",
  "arguments": {
    "action": "search",
    "search_term": "Boyle",
    "entities": "account,contact",
    "top": 20
  }
}
```

**Content:**

```
[Success] Found 1 result (1 total) for "Boyle" in 200ms.
```

**Structured content (rút gọn):**

```json
{
  "action": "search",
  "searchTerm": "Boyle",
  "returnedCount": 1,
  "totalCount": 1,
  "records": [
    {
      "id": "71f939f8-4e40-f111-bec6-70a8a59a451e",
      "entityName": "account",
      "attributes": { "name": "Boyle Inc", "owneridname": "# DEVKIT", ... },
      "highlights": { "name": ["{crmhit}Boyle{/crmhit} Inc"] }
    }
  ]
}
```

> `entities` đi qua `DisplayNameFirstResolver` nên `"account"` và `"contact"` (logical name, không phải Display Name) vẫn map được, không ném lỗi. Khi tìm keyword chung, Dataverse chỉ quét các table có trong danh sách — ở đây cả 2 đều indexable nên `account` xuất hiện.
