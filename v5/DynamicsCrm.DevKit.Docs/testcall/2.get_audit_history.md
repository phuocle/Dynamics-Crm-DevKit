# TOOL DESCRIPTION

```text
Browse audit events or inspect field-level changes for one Dataverse record.

WHEN TO USE:
- Identify who changed a record, when, and which logical fields changed
- Browse recent audited create/update/delete/state events

RELATED TOOLS:
- get_plugin_trace_logs → plugin execution traces
- get_system_jobs → asynchronous failures
- get_tables → verify entity and attribute logical names
```

# PARAMETERS

```text
entity_name    : string : Entity Display/logical name. Required with record_id. Optional in browse mode.
record_id      : string : GUID → detail mode. Empty = browse list.
minutes_ago    : int    : Last N min. Default 1440 (24h). Max 43200. Ignored if from_date set.
user_filter    : string : User name (contains) or email. Empty = all users.
operation      : string : Create, Update, Delete, Activate, Deactivate, Assign, Merge, Cascade, SetState. Empty = all.
attribute_name : string : Detail mode only. Filter one field. Error if set without record_id.
max_records    : int    : Default 50. Max 500.
from_date      : string : ISO 8601. Overrides minutes_ago.
to_date        : string : ISO 8601. With from_date. Default = now.
```

# RESULTS

- Test 1: browse mode returns 5 account audit events in the last 30 days.
- Test 2: user_filter by email resolves to systemuserid and filters server-side — same 5 entries as Test 1 because all events belong to that user; no client-side name filter, no false-zero.
- Test 3: detail mode returns `changes[]` with `logicalName`/`displayName`/`oldValue`/`newValue`; `attribute_name='name'` filters to only the name field changes.
- Test 4-6: three validation errors all return `IsError: true` with a clear message and hint where applicable.
- Test 7: browse with zero results is a success with a dedicated `[AuditBrowse]` message — not an error, matching the contract.
