# 4. get_tables

# Tool description AI đọc được

```
Name:        get_tables
Title:       Inspect table metadata, columns, and relationships
Idempotent:  true
Destructive: false
ReadOnly:    true

Description:
Dataverse entity metadata. entity_name empty = list; set = detail (attributes, relationships, alternate keys).

WHEN TO USE:
- Discover entity/attribute names before building FetchXML or calling other tools
- Find join columns, picklist options, required fields, primary key, lookup targets
- Clone or copy a column (detail_level='full' required — compact/standard lack clone metadata)
- AI MUST use get_tables for entity/attribute metadata — do NOT use execute_webapi with EntityDefinitions

RELATED TOOLS:
- upsert_column → create/update columns (pass formula_definition unchanged from full mode)
- upsert_table → create/update tables
- upsert_relationship → create/update relationships
- execute_fetchxml → query data once you know attribute names

Parameters:
  entity_name (string, default: "")
    Logical name → detail mode. Empty = list mode.
  filter (string, default: "")
    LIST: keyword filter on entity. DETAIL: single value = prefix match on logical names; comma/pipe/semicolon-separated = word-boundary match on logical name + exact match on display name.
  custom_only (boolean, default: false)
    LIST: only custom entities.
  include_intersect (boolean, default: false)
    LIST: include N:N intersect entities.
  names (string, default: "")
    LIST: comma-separated logical names. Overrides filter/custom_only.
  detail_level (string, default: "compact")
    DETAIL: 'compact' (default, Display Name, Schema Name, Logical Name, Type, required, isValidForCreate/Update), 'standard' (+ requiredLevel, constraints, lookup targets, picklist options), 'full' (all metadata including audit, formula, security, default values, option colors, description, min/max/precision/behavior).
```

# Input tool call

```json
{
  "name": "get_tables",
  "arguments": {
    "entity_name": "account",
    "filter": "accountid,name",
    "detail_level": "compact"
  }
}
```

> Detail mode với `entity_name=account`, `filter=accountid,name` (multi-value, word-boundary match), `detail_level=compact`. Trả về chỉ các attribute khớp filter, tối thiểu metadata để biết field nào set được khi create/update.

# Kết quả AI tổng hợp lại

- **Trạng thái:** Thành công (`[Success]`, `IsError=false`).
- **Mode:** `detail` — trả metadata cho 1 entity (`account`).
- **Filter:** `accountid,name` — multi-value, word-boundary match. Khớp 4 attributes: `accountid` (exact), `address1_name` + `address2_name` (chứa `name` ở word boundary), `name` (exact).
- **Detail level:** `compact` — chỉ trả `logicalName`, `schemaName`, `type`, `required`, `isValidForCreate`, `isValidForUpdate`, `displayName`. Không có `description`, `options`, `lookupTargets`, `minValue`/`maxValue`, v.v. Các relationship và alternate keys bị ẩn (null).
- **Attribute `accountid`:** `required=true` (SystemRequired), `isValidForUpdate=false` (không set khi update), `type=Uniqueidentifier` — đây là primary key.
- **Attribute `name`:** `required=false`, `type=String` — đây là primary name attribute.
- **Token tiết kiệm:** Compact mode ~2KB cho 4 attrs. Standard mode sẽ ~8KB, full mode ~40KB. Chọn compact khi chỉ cần biết field name + type + required. Null properties bị `WhenWritingNull` ẩn — `entitySetName`, `objectTypeCode`, `oneToManyRelationships`, `manyToOneRelationships`, `manyToManyRelationships`, `alternateKeys` không xuất hiện.
- **Cách dùng tiếp theo:** Dùng `accountid` làm join column trong FetchXML. Dùng `name` làm primary display field khi tạo record mới.

- Relationships và alternate keys bị ẩn khi filter không match (null → `WhenWritingNull` ẩn).

## Ví dụ phụ 3 — Entity not found (validation error)

```json
{
  "name": "get_tables",
  "arguments": {
    "entity_name": "nonexistententity123"
  }
}
```

> Entity name không tồn tại trong org. Đây là validation error (expected), không phải unhandled exception.

**Content:**

```
[NotFoundEntity] 'nonexistententity123' was not found by Display Name or Logical/Unique/Schema Name.
Tip: Use get_tables with no entity_name to list available tables.
```

**IsError:** `true`

- Error message từ `DisplayNameFirstResolver` — resolve failed, trả `[NotFoundEntity]` tag.
- `IsError=true` nhưng không có structured content (validation error, không cần DTO).
- Hint dẫn user gọi list mode để xem available entities.

## Ví dụ phụ 5 — Filter no match (success với hint)

```json
{
  "name": "get_tables",
  "arguments": {
    "entity_name": "account",
    "filter": "zzz_nomatch"
  }
}
```

> Filter không khớp attribute nào. Tool vẫn thành công (IsError=false) nhưng `attributes` bị ẩn (null), kèm `hint` trong structured content.

**Content:**

```
[Success] account (detail=compact): 0 attributes matched filter 'zzz_nomatch'.
```

**Structured content (JSON):**

```json
{
  "mode": "detail",
  "count": 1,
  "entityName": "account",
  "filter": "zzz_nomatch",
  "detailLevel": "compact",
  "table": {
    "logicalName": "account",
    "schemaName": "Account",
    "displayName": "Account",
    "ownershipType": "UserOwned",
    "isCustom": false,
    "isActivity": false,
    "isAuditEnabled": true,
    "primaryIdAttribute": "accountid",
    "primaryNameAttribute": "name"
  },
  "hint": "filter 'zzz_nomatch' matched no attributes. Try a broader filter or omit filter to list all attributes."
}
```

**IsError:** `false`

- `table` object vẫn trả về (entity tồn tại) nhưng `attributes` bị ẩn (null → `WhenWritingNull`).
- `hint` xuất hiện trong structured content, không trong Content text (rule 6: Content 1 dòng).
- Nếu filter gần đúng (ví dụ `acountid` thay `accountid`), `hint` sẽ suggest: `Did you mean: accountid?` dựa trên word-boundary matching score.
