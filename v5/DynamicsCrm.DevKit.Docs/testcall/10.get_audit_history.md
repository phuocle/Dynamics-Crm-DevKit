# get_audit_history

# Tool description

```text
Browse audit events or inspect field-level changes for one Dataverse record.

WHEN TO USE:
- Identify who changed a record, when, and which logical fields changed
- Browse recent audited create/update/delete/state events

RELATED TOOLS:
- get_plugin_trace_logs → plugin execution traces
- get_system_jobs → asynchronous failures
- get_tables → verify entity and attribute logical names
```

# Kết quả

- **Regression phase 4 (user_filter email):** Test 2 chứng minh email resolve thành `systemuserid` và filter server-side — kết quả khớp Test 1 vì mọi event đều của user đó; không còn client-filter theo tên (tránh trùng tên) và không false-zero.
- Detail mode (Test 3) trả `changes[]` với `logicalName`/`displayName`/`oldValue`/`newValue`; `attribute_name='name'` lọc đúng chỉ thay đổi của field name.
- Browse 0 kết quả (Test 7) là Success với message `[AuditBrowse]` riêng, không phải error — đúng contract.
- 3 validation errors (Test 4-6) đều `IsError: true`, message rõ + hint khi có.
- Không có output nào bị rút gọn; description khớp source hiện tại (`GetAuditHistoryTool.cs`).
