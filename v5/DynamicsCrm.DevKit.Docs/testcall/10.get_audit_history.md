# 10. get_audit_history

# Tool description AI đọc được

```
Name:        get_audit_history
Title:       Get record audit history
Idempotent:  true
Destructive: false
ReadOnly:    true

Description:
Audit history (who/what/when/old/new). record_id set = detail (entity_name REQUIRED, returns
event-grouped changes: one entry per save, with a changes[] array of field-level oldValue/newValue).
Each change carries the attribute logicalName + user-localized displayName. Local picklist/boolean/
state/status values are resolved to their labels (e.g. industrycode 2 -> "Agriculture and Non-petrol
Natural Resource Extraction"); global option-set labels are read from the audit record's
FormattedValues. Lookups are returned as the referenced record's primary name. Empty = browse list
(one row per audit record). Audit must be enabled at org AND entity. from_date/to_date override
minutes_ago. attribute_name requires record_id and filters the changes[]. Empty result usually means
auditing not enabled. For plugin traces → get_plugin_trace_logs. For async failures →
get_system_jobs.

Parameters:
  entity_name    (string, default: "")
    Entity Display/logical name. Required with record_id. Optional in browse mode.
  record_id      (string, default: "")
    GUID → detail mode. Empty = browse list.
  minutes_ago    (int, default: 1440)
    Last N min. Default 1440 (24h). Max 43200. Ignored if from_date set.
  user_filter    (string, default: "")
    User name (contains) or email. Empty = all users.
  operation      (string, default: "")
    Create, Update, Delete, Activate, Deactivate, Assign, Merge, Cascade, SetState. Empty = all.
  attribute_name (string, default: "")
    Detail mode only. Keep only events that touched this field. Ignored in browse mode.
  max_records    (int, default: 50)
    Default 50. Max 500.
  from_date      (string, default: "")
    ISO 8601. Overrides minutes_ago.
  to_date        (string, default: "")
    ISO 8601. With from_date. Default = now.
```

```json

    "entity_name": "Account",
    "record_id": "71f939f8-4e40-f111-bec6-70a8a59a451e",
    "minutes_ago": 60,

}
```

> Trên org `🟢DEVKITV4` (DEVKITV4.crm.dynamics.com), truy vấn audit **detail** mode cho account `Boyle Inc` (`71f939f8-4e40-f111-bec6-70a8a59a451e`) trong 60 phút qua. `entity_name="Account"` → `DisplayNameFirstResolver` → logical name `account`, gọi `RetrieveRecordChangeHistoryRequest`. Tool đồng thời fetch `RetrieveEntityRequest` (1 lần, cache trong request) để lấy `AttributeMetadata` (display name + option-set labels cho local picklist). Account này vừa được update 5 lần (gồm picklist `industrycode`, lookup `primarycontactid`, free-text `name`/`description`/`website`/`telephone1`/`creditlimit`), nên ta kỳ vọng 5 entries — mỗi entry = 1 save event, có `changes[]` với `logicalName` + `displayName` + `oldValue`/`newValue` đã được resolve (lookup → primary name, picklist → label).

# Kết quả AI tổng hợp lại

- **Trạng thái:** Thành công (`[Success]`, `IsError=false`). Trả về **5 audit events** cho account `Boyle Inc` trong 60 phút qua.
- **Mode = `detail`** vì có `record_id`; truy vấn qua `RetrieveRecordChangeHistoryRequest` → `AuditDetailCollection`.
- **Quan trọng — 1 entry = 1 event/save** (không phải 1 field). Mỗi entry có:
  - `timestamp` + `user` + `action` (metadata của lần save).
  - `changes[]` — array các field thay đổi trong event đó. 1 save có thể đổi nhiều field cùng lúc → 1 entry có nhiều changes.
  - Mỗi `change` mang 4 thuộc tính: `logicalName` (logical name, vd `industrycode`), `displayName` (user-localized label, vd `Industry`), `oldValue`/`newValue` (ẩn nếu null).
- **Tổng kết 5 events (sắp xếp desc theo `createdon`):**
  1. **2026-07-30 12:55:47** · `Phước Lê Văn` · **1 change** — `Primary Contact` (lookup `primarycontactid`): `"Wendell Ortiz"` → `"Test Audit"`. Lookup được format thành primary name của record được tham chiếu, không phải GUID.
  2. **2026-07-30 12:48:22** · `# DEVKIT` · **2 changes** — `Industry` (picklist): `"Brokers"` → `"Agriculture and Non-petrol Natural Resource Extraction"`; `Account Name`: `"Boyle Inc B"` → `"Boyle Inc - audit test #DEVKIT"`.
  3. **2026-07-30 12:42:04** · `Phước Lê Văn` · **1 change** — `Industry` (picklist): `"Equipment Rental and Leasing"` → `"Brokers"`.
  4. **2026-07-30 12:19:50** · `# DEVKIT` · **1 change** — `Website` (`websiteurl`): `"https://boyle.example.com"` → `"https://boyle.example.org"`.
  5. **2026-07-30 12:19:01** · `# DEVKIT` · **3 changes** — `Description` (text), `Credit Limit` (`16,239,131,948,091.00` → `50,000.00`), `Credit Limit (Base)` (Dataverse mirror base-currency cho `Money`).
- **2 user khác nhau** tham gia: `# DEVKIT` thực hiện 3 saves, `Phước Lê Văn` thực hiện 2 saves (đổi industry + đổi primary contact).
- **Audit hoạt động OK:** org `🟢DEVKITV4` có `isauditenabled=true` (xem `whoami`), entity `account` đang audit ở cả org + entity level.
- **Cấu trúc response (đã cải tiến):**
  - **`logicalName`** (đổi từ `field` ở version trước) — luôn có, vd `industrycode`, `primarycontactid`. Thống nhất convention với các tool khác (vd `get_tables` cũng dùng `logicalName`).
  - **`displayName`** — user-localized label, vd `Industry` ← `industrycode`, `Primary Contact` ← `primarycontactid`. Cache fetch 1 lần đầu `ExecuteDetailMode`.
  - **Local picklist** (`industrycode`): value int → resolve qua metadata cache (`PicklistAttributeMetadata.OptionSet.Options`) → trả label. Ví dụ int `2` → `"Agriculture and Non-petrol Natural Resource Extraction"`.
  - **Global option set**: Dataverse audit record's `OldValue`/`NewValue` đã có `FormattedValues` chứa label → `FormatAttributeValue` ưu tiên dùng (case 1), không cần cache.
  - **Money** (`creditlimit`): format `N2` → `"50,000.00"`. `creditlimit_base` là mirror base-currency do Dataverse tự sinh, có `displayName` riêng = `"Credit Limit (Base)"`.
  - **Lookup** (`primarycontactid`): trả `Name` của record được tham chiếu (`"Wendell Ortiz"`, `"Test Audit"`), fallback GUID nếu Name rỗng.
  - **DateTime**: `"yyyy-MM-dd HH:mm:ss"`.
  - **Boolean** (Two-Option): Dataverse cũng đẩy label vào `FormattedValues` → tool hiển thị label (`"Yes"`/`"No"` hoặc custom `"Allow"`/`"Do Not Allow"`), không phải `true`/`false`.
  - **Field set mới** (chỉ `newValue`): null `oldValue` → bị `[JsonIgnore(WhenWritingNull)]` ẩn. Field bị clear (chỉ `oldValue`): null `newValue` → ẩn.
  - **`event`** (non-attribute audit) xuất hiện ở entry level khi audit là `RelationshipAuditDetail`/`ShareAuditDetail`/`RolePrivilegeAuditDetail` thay vì `AttributeAuditDetail`. Browse mode dùng `entity`/`recordName`/`recordId`/`operation` (cũng null-aware).
- **Performance:**
  - Tool fetch **1 lần** `RetrieveEntityRequest` với `EntityFilters.Attributes` ngay đầu `ExecuteDetailMode` → build `AttributeMetadataCache` (logicalName → displayName + logicalName → value/label map cho local picklist/state/status/boolean).
  - Cache là per-request (không cache xuyên suốt process vì entity có thể thay đổi schema).
  - Fetch này KHÔNG ảnh hưởng browse mode (browse không trả `changes[]`).
  - Nếu metadata fetch fail (lỗi mạng, entity không tồn tại, …) → cache rỗng → `displayName` null (ẩn) + picklist vẫn resolve được qua `FormattedValues` của audit record (global option set) hoặc fallback int. Tool vẫn hoạt động bình thường.
- **Token tiết kiệm:**
  - Content 1 dòng duy nhất `[Success] account 71f939f8-…: 5 entries (last 60 min).` — đủ để AI xác nhận số event + scope.
  - `null` trong `changes[]` (`oldValue`/`newValue`/`displayName`) bị `[JsonIgnore(WhenWritingNull)]` ẩn → JSON payload không phình khi field bị clear, set mới, hoặc metadata không tìm thấy displayName.
  - `null` ở entry level (`event`, `entity`, `recordName`, `recordId`, `operation`) cũng ẩn.
  - User hỏi "Credit Limit được changed bởi ai?" — AI đọc thẳng `changes[]` trong entry tại 12:19:01, thấy `displayName="Credit Limit"` + `user="# DEVKIT"` → trả lời ngay, **không cần gọi thêm `get_tables(account)`** để tra displayName.
- **Cách dùng tiếp theo:**
  - Lọc theo field cụ thể: `attribute_name="industrycode"` (Display Name `Industry` hoặc logical name đều được) → chỉ giữ event có change trên field đó.
  - Lọc theo user: `user_filter="Phước"` (contains match) hoặc email đầy đủ (exact match qua `internalemailaddress`).
  - Lọc theo action: `operation="Update"` → chỉ các lần sửa.
  - Lấy audit browse (1 row = 1 audit record, không expand field-level): bỏ `record_id` → sang browse mode.
  - Audit bị tắt → empty `entries[]` + `totalCount=0`; gợi ý: bật trong **System Settings → Auditing tab** + check entity-level audit.
