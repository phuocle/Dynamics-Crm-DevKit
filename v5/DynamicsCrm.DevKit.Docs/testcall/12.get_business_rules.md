# 12. get_business_rules

# Tool description AI đọc được

```
Name:        get_business_rules
Title:       List business rules for an entity
Idempotent:  true
Destructive: false
ReadOnly:    true

Description:
Business rules (client-side logic) for an entity. rule_id empty = list; set = detail (conditions+actions from XAML).
Rules run BEFORE form JS. Scope 'Entity' = all forms.

WHEN TO USE:
- Inspect a business rule's conditions and actions before refactoring or disabling it
- Find business rules bound to an entity (entity_name filter)
- Check if a field is referenced in any client-side rule logic

RELATED TOOLS:
- get_workflows → classic workflow definitions (background async + realtime sync)
- get_messages → legacy workflow Custom Actions (category=3) + SDK messages
- get_custom_apis → modern Custom API definitions
- get_business_process_flows → BPF definitions + stages
- manage_record(action='read', columns='xaml') → raw XAML when parse is incomplete

Parameters:
  entity_name  (string, required)
    Entity Display Name or logical name. Ignored in detail mode.
  rule_id      (string, default: "")
    GUID → detail mode. Empty = list mode.
  status       (string, default: "")
    'active' or 'draft'. Empty = all. Ignored in detail mode.
  max_records  (int, default: 50)
    1-200. Default 50. Ignored in detail mode.
```

# Test calls

## 1. List mode — entity_name=Analysis Result (default: all statuses)

```
get_business_rules(entity_name="Analysis Result")
```

> Trên org `🟢DEVKITV4`, truy vấn business rules cho entity `Analysis Result` (Display Name). `DisplayNameFirstResolver` → logical name `msdyn_analysisresult`, gọi `RetrieveEntityRequest` lấy `ObjectTypeCode`, rồi FetchXML trên `workflow` với `category=2` (business rule). Entity này có 2 business rules active.

**Content (1 dòng):**

```
[Success] business rules for 'msdyn_analysisresult': 2 found.
```

**Structured content:**

```json
{
  "mode": "list",
  "entityName": "msdyn_analysisresult",
  "count": 2,
  "rules": [
    {
      "ruleId": "11a502ff-3fed-4121-9908-c647af4b12ae",
      "name": "Analysis Result Message Display",
      "scope": "Organization",
      "status": "Activated",
      "modifiedOn": "2025-10-09"
    },
    {
      "ruleId": "51512f78-7504-e911-816a-000d3af752b6",
      "name": "Hide Fields When OrganizationHealth",
      "scope": "Organization",
      "status": "Activated",
      "modifiedOn": "2025-10-09"
    }
  ]
}
```

**IsError:** false

### Kết quả AI tổng hợp lại

- **Trạng thái:** Thành công. Entity `msdyn_analysisresult` có 2 business rules, cả hai đều active (Activated) và scope Organization.
- **mode:** `"list"` — danh sách business rules.
- **entityName:** `"msdyn_analysisresult"` — logical name đã resolve từ Display Name `Analysis Result`.
- **count:** 2 — tổng số rules trả về.
- **rules[]:** mỗi entry chứa metadata tối thiểu cho list mode:
  - `ruleId` — GUID của business rule (workflow record).
  - `name` — tên hiển thị của rule.
  - `scope` — `Organization` / `AllEntities` / specific entity (ẩn khi null).
  - `status` — `Activated` / `Draft` (ẩn khi null).
  - `modifiedOn` — ngày sửa đổi cuối (yyyy-MM-dd, ẩn khi null).
- **Token tiết kiệm:** `scope`, `status`, `modifiedOn` ẩn khi null; `rules` ẩn khi count=0; không trả description/conditions/actions trong list mode → tiết kiệm đáng kể.
- **Cách dùng tiếp theo:** Truyền `rule_id` = một `ruleId` từ list để xem detail đầy đủ (conditions, actions, XAML parse).

## 2. Detail mode — rule_id=11a502ff-… (Analysis Result Message Display)

```
get_business_rules(entity_name="Analysis Result", rule_id="11a502ff-3fed-4121-9908-c647af4b12ae")
```

> Truyền `rule_id` GUID → detail mode: Retrieve workflow record với đầy đủ columns (name, primaryentity, scope, statuscode, xaml, modifiedon, modifiedby, createdon, createdby, description, category). Tool parse XAML để trích xuất conditions và actions tự nhiên. Rule này ẩn field `msdyn_message` khi nó null và hiện `msdyn_solutionhealthmessage`.

**Content (1 dòng):**

```
[Success] Business rule 'Analysis Result Message Display': 1 conditions, 2 actions.
```

**Structured content:**

```json
{
  "mode": "detail",
  "entityName": "msdyn_analysisresult",
  "count": 1,
  "rule": {
    "ruleId": "11a502ff-3fed-4121-9908-c647af4b12ae",
    "name": "Analysis Result Message Display",
    "entityName": "msdyn_analysisresult",
    "scope": "Organization",
    "status": "Activated",
    "description": "Analysis Result Message Display",
    "createdOn": "2025-10-09 14:10:38",
    "createdBy": "SYSTEM",
    "modifiedOn": "2025-10-09 14:11:20",
    "modifiedBy": "SYSTEM",
    "xamlParseStatus": "parsed",
    "conditions": ["IF msdyn_message Null"],
    "actions": [
      "SetVisibility: msdyn_solutionhealthmessage = True",
      "SetVisibility: msdyn_message = False"
    ]
  }
}
```

**IsError:** false

### Kết quả AI tổng hợp lại

- **Trạng thái:** Thành công. Business rule `Analysis Result Message Display` có 1 condition và 2 actions.
- **Trường detail thêm so với list:**
  - `entityName` — logical name của primary entity.
  - `description` — mô tả rule (ẩn khi null hoặc "Click to add description").
  - `createdOn` / `createdBy` — ngày tạo và user tạo (ẩn khi null).
  - `modifiedOn` / `modifiedBy` — ngày sửa và user sửa (ẩn khi null).
  - `xamlParseStatus` — `"parsed"` / `"no conditions or actions extracted"` / `"no xaml"` (ẩn khi null).
  - `conditions[]` — danh sách condition dạng natural language, parse từ XAML (ẩn khi rỗng).
  - `actions[]` — danh sách action dạng natural language (SetVisibility, SetRequired, SetValue, ShowError, LockField, UnlockField, SetDefaultValue) (ẩn khi rỗng).
- **XAML parse logic:**
  - Conditions: trích `GetEntityProperty Attribute="..."` → field name, `ConditionOperator` → operator, `WorkflowPropertyType` → constant value.
  - Actions: regex match cho 7 action types (SetVisibility, SetRequired, SetAttributeValue, ShowError, LockField, UnlockField, SetDefaultValue).
- **Token tiết kiệm:** `description`, `createdOn`, `createdBy`, `modifiedOn`, `modifiedBy`, `xamlParseStatus`, `conditions`, `actions` ẩn khi null/rỗng; raw XAML không trả về (dùng `manage_record` nếu cần).
- **Cách dùng tiếp theo:** Dùng `conditions` và `actions` để hiểu logic rule; nếu parse không đủ, dùng `manage_record(action='read', entity_name='workflow', record_id=ruleId, columns='xaml')` để xem raw XAML.
