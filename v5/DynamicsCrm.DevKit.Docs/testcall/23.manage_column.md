# 23. manage_column

# Tool description AI đọc được

```
Dataverse column (attribute) — auto-detect create vs update. Types: string, memo, integer, bigint, decimal, money, float, boolean, datetime, lookup, customer, picklist, multipicklist, image, file.

MODES:
- CREATE (no logical_name match): need attribute_type + display_name (+ solution_name or prefixed schema_name/logical_name).
- UPDATE (logical_name matches existing attribute): update mutable metadata, format, required_level, picklist options, labels, flags.
- Clone PowerFx/Calculated/Rollup column read by get_tables (CREATE only): pass formula_definition = `source_table:source_column`.
- 5 create flags (single create call, no follow-up update): required_level, is_audit_enabled, is_valid_for_advanced_find, is_secured, is_sortable. On UPDATE, omit=null to keep current.
STATUSCODE (statuscode / StatusType): pass logical_name='statuscode' and use add_options/update_options/delete_options.

FUZZY/AMBIGUITY:
- entity_name resolves Display Name contains first, then logical/schema name contains. Ambiguity returns IsError=true with candidates.
- logical_name (UPDATE) follows the same Display Name first rule. lookup_target, global_optionset_name, solution_name use their shared resolvers.

WHEN TO USE:
- Create a new attribute on an existing table (need attribute_type + display_name)
- Clone a PowerFx, Calculated, or Rollup column read by get_tables (CREATE only)
- Update mutable metadata, format, required_level, and picklist options
- Add/rename/remove options on an existing picklist via add_options/update_options/delete_options
RELATED TOOLS: get_tables, manage_table, manage_relationship, manage_choice, manage_record_file, execute_webapi.
```

Input schema params: `entity_name`, `logical_name`, `attribute_type`, `display_name`, `solution_name`, `confirmed_prefix`, `description`, `required_level`, `max_length`, `min_value` (double?), `max_value` (double?), `precision`, `format`, `behavior`, `precision_source`, `options` (JSON), `global_optionset_name`, `lookup_target`, `lookup_relationship_name`, `true_label`, `false_label`, `add_options` (JSON), `update_options` (JSON), `delete_options` (JSON), `is_audit_enabled` (bool?), `is_valid_for_advanced_find` (bool?), `is_secured` (bool?), `is_sortable` (bool?), `default_value`, `schema_name`, `formula_definition`, `formula_source_type`, `can_store_full_image` (bool?).

# Kết quả AI tổng hợp
- **Refactor refactor3**: manage_column migrate theo rules — 1 try-catch entry, factory methods trực tiếp (Success/Error/ThrowException/DryRun), DTO null-aware rule 4, Content 1 dòng `[Success]`/`[Error]`, Hint: label chuẩn rule 18. Tool auto-detect create vs update qua logical_name match.
- **Bug MCP 2.x quan trọng (root cause của fail invocation)**: sau upgrade `ModelContextProtocol` 1.2.0 → 2.2.0 (commit `dee7fa88c`), mọi MCP tool có param string **không có default value** (vd `string entity_name,` thay vì `string entity_name = ""`) fail với generic `An error occurred invoking '<tool>'` — method body không reach, không exception, log không ghi. MCP 2.x mark param no-default là `required` trong JSON schema, connector invoke không bind được ở host layer. Fix: thêm `= ""` cho `entity_name` + `logical_name` (2 required params đầu). Validation required vẫn trong code (`if (string.IsNullOrWhiteSpace(entity_name)) return Error(...)`). Các tool khác có required param no-default (CreateRecordsTool, ExecuteFetchXmlTool, GenerateDemoDataTool, GetBusinessRulesTool, ManageChartTool, ManageChoiceTool, ManageCommandTool, ManageFormTool, ManageRecordFileTool...) cần check ở session khác — một số (manage_choice `action`) vẫn works, bug có thể phụ thuộc combo param.
- **Debug method rút ra**: khi MCP tool fail "An error occurred invoking" mà không có exception message, thêm `System.IO.File.AppendAllText(Path.GetTempPath()+"_mcp_err.log", ...)` ở đầu method — nếu log rỗng sau invoke = fail ở binding/DI layer, không phải code. Binary search params (giảm dần số param trong tool clone) để cô lập culprit.
- **Coverage test**: 12 test — 2 error path (Test 1 entity_name only, Test 9 update nonexistent, Test 10 invalid type), CREATE happy cho 6 type (string, picklist, boolean, lookup, memo, money, image), UPDATE happy (rename, picklist add/rename/delete atomic). Đủ happy + alternate mode + error paths theo rule quy trình #7.
- **Không touch rule 8 (execute_webapi)**: execute_webapi đã redirect/block metadata endpoint từ trước — không cần đổi.
- **Cleanup**: các column test (all_refactorstrtest, all_refactorpicktest, all_refactorbooltest, all_refactorlooktest, all_refactormemotest, all_refactormoneytest, all_refactorimagetest) vẫn còn trong org DEVKITV4 — có thể delete qua manage_column update hoặc solution remove nếu cần dọn.
