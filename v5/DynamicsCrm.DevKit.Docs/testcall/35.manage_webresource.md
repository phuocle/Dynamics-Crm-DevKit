# TOOL DESCRIPTION

```text
Manage Dataverse web resources — list / detail / create / update / delete.
detail/update/delete need web_resource_id (GUID, Display Name, or unique name); create needs name + file_path + type + solution_name.
On create the prefix in name must match the solution's publisher prefix; on mismatch the tool errors with the suggested name — re-call with it. Create adds the web resource to the solution and publishes; update also publishes; delete is irreversible.
Types: js, html, css, xml, png, jpg, gif, svg, ico, resx, xsl, xap. Naming: {prefix}_/path/filename.ext (e.g. 'v4_/entities/Account.form.js').

WHEN TO USE:
- Upload/update/inspect a web resource
- Find library_name for build_form_xml add_event/add_library (run list first)
- Combine with build_form_xml + manage_form to wire JS into a form

RELATED TOOLS:
- get_solution_components → find solution names for create
- manage_form → wire the JS library into a form
- publish_customizations → publish other components (create/update auto-publish)
```

# PARAMETERS

```text
action           : string : list / detail / create / update / delete. Required.
web_resource_id  : string : GUID, Display Name, or unique name. Required: detail/update/delete.
name             : string : Unique name (e.g. 'v4_/entities/Account.form.js'). Required: create. list: contains filter across Display Name and unique name.
display_name     : string : Display Name. Optional: create/update.
description      : string : Description. Optional: create/update.
file_path        : string : Absolute or relative file path. Required: create. Tool reads file and converts to base64 internally.
type             : string : Required: create. See description for values. Ignored on other actions.
solution_name    : string : list: filter. create: REQUIRED — used to resolve publisher prefix and add WR to solution.
type_filter      : string : list only. See type values.
max_records      : int    : 1-500. Default 50.
```

# RESULTS

- Test 1: list with a name contains-filter matches both name and displayname and returns 3 web resources.
- Test 2: list scoped by solution_name + type_filter joins through solutioncomponent and returns only JS web resources in `all_in_one`.
- Test 3: detail resolves by unique name (not GUID) and returns the extended field set; null fields (languageCode, dependencyXml) are omitted.
- Test 4: create uploads the file as base64, adds the web resource to solution `all_in_one` via AddSolutionComponentRequest, and publishes (`published: true`).
- Test 5: update replaces the content and sets display_name + description (`fieldsUpdated=3`) and publishes.
- Test 6-9: four validation errors (invalid action, detail not found, prefix mismatch with suggested name in the hint, invalid type) all return `IsError: true`.
- Test 10-11: update on a nonexistent GUID and list on a nonexistent solution both fail with a clear message and hint.
- Test 12: create on an existing name is rejected with a redirect to action='update' — the duplicate gate from the resolver.
- Test 13: create with an empty type fails with the valid type list in the hint.
- The created web resource `all_/mcp/test35_manage_webresource.js` is kept in the org (no delete); the delete action was not exercised in this session.
