# TOOL DESCRIPTION

```text
CRUD a single Dataverse record. Actions: 'read' (read-only) | 'create', 'update', 'delete' (IRREVERSIBLE), 'associate', 'disassociate' (mutations). Record changes are live immediately — no publish needed.

WHEN TO USE:
- Create / read / update / delete a single record by GUID
- Partial-update specific fields without rewriting whole record
- Associate/disassociate two records via an N:N relationship
- Verify a record before destructive changes

RELATED TOOLS:
- get_tables → entity/attribute names before building fields_json
- execute_fetchxml → find lookup GUIDs and record_id
- create_records → bulk create multiple records
- execute_webapi → raw OData JSON/annotations
```

# PARAMETERS

```text
action              : string : 'create', 'read', 'update', 'delete', 'associate', 'disassociate'.
entity_name         : string : Entity logical name (e.g., 'account').
record_id           : string : GUID. Required: read/update/delete. Empty: create.
fields_json         : string : JSON object of field values. Required: create/update. Polymorphic lookup: 'fieldname@targetentity' key. Activity party fields (to/from/cc/bcc/requiredattendees/optionalattendees): JSON array of {"id":"<guid>","type":"<entity>"}. Single party auto-wrapped: {"id":"<guid>","type":"<entity>"}. Optional: "addressused":"email". Regular lookup: {"fieldname": "guid"}.
columns             : string : Read only. Comma-separated columns. Empty = all.
related_entity_name : string : Related Entity Name for associate/disassociate.
related_record_id   : string : Related Record GUID for associate/disassociate.
relationship_name   : string : N:N Relationship Name for associate/disassociate.
```

# RESULTS

- Test 1: create with a single name field returns the new record GUID with fieldsUpdated=1.
- Test 2: create accepts mixed field types (string, money, integer, composite address) in one call with fieldsUpdated=4.
- Test 3: read with a column list returns formatted values (money as '$50,000.00', integer as '25') plus the auto-resolved transactioncurrencyid; the text header is the bare GUID with no entity tag and no duplicated primary-key line.
- Test 4: update touches only the 2 fields in fields_json, leaving the others unchanged.
- Test 5: the polymorphic Customer lookup syntax 'parentcustomerid@account' resolves the Account target at create time.
- Test 6: a full read returns every attribute with formatted values; parentcustomerid renders as the account's name.
- Test 7: a single-field update reports fieldsUpdated=1.
- Test 8: activity party fields accept a single party object for 'from' (auto-wrapped) and a 2-element array for 'to'.
- Test 9: reading the phonecall back shows both parties rendered as 'Display Name (entity:guid)' and directioncode=true formatted as 'Outgoing'.
- Test 10-13: four validation errors (invalid GUID twice, empty fields_json, missing record_id) all return IsError=true with a clear message and hint; the empty fields_json case is rewritten to a plain validation error with an example field in the hint.
- Test 14: Display Names ('Account Name', 'Annual Revenue', 'Number of Employees') are accepted as fields_json keys and resolved to logical names.
- Test 15: a typo'd field key ambiguously matching 8 attributes fails with the candidate list as attributeMatches JSON in [Detail] — no text table in the error.
- Test 16: updating the read-only createdon field succeeds at the SDK level — Dataverse silently ignores the write.
- Test 17: creating a phonecall without the metadata-Required subject succeeds — the SDK does not enforce Required without a business rule.
- Test 18: delete removes the contact.
- Test 19: delete removes the phonecall.
- Test 20: deleting an already-deleted GUID is rewritten to a friendly form — a readable not-found message in [Error], recovery guidance in [Hint], and entity/id/errorCode/message in [Detail].
