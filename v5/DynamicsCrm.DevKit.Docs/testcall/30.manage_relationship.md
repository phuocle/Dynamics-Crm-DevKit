# 30. manage_relationship

# Tool description AI đọc được

```
Manage Dataverse 1:N, N:N relationships and polymorphic lookup targets.
Actions: create_1n (referenced_entity + referencing_entity + solution_name, auto-creates lookup), create_nn (entity1 + entity2 + solution_name, auto-creates intersect), update (relationship_name — cascade / menu / hierarchy), delete (relationship_name), add_target (entity_name + attribute_name + referenced_entity + solution_name — polymorphic lookup), remove_target (entity_name + attribute_name + referenced_entity — deletes data).
is_hierarchical: self-referential 1:N only (referenced=referencing), max 1/entity. Cascade presets: Parental (all Cascade) | Referential (NoCascade + RemoveLink) | ReferentialRestrictDelete (NoCascade + Restrict). Cascade types: Cascade | NoCascade | RemoveLink | Restrict | Active | UserOwned.
WHEN TO USE: create 1:N (with auto lookup) / N:N (with intersect), adjust cascade/menu/hierarchy, add/remove polymorphic lookup target.
RELATED TOOLS: get_tables (discover relationships), manage_column (lookup columns), publish_customizations (batch publish).
```

DTO `ManageRelationshipResult` nullable property có `[JsonIgnore(WhenWritingNull)]`, list rỗng → null (`changes`/`warnings` count>0?…:null) (rule 4). Content 1 dòng `[Success]`/`[Error]` (rule 5). Literal prefix `[Success]`/`[Error]`/`Hint:` không viết trong source (rule 10). `dry_run` check 6/6 mutation trước khi Execute (rule 11). `Hint:` không `Tip:` (rule 18). Build 0 errors, 0 warnings. - **Friendly error migration**: `ManageRelationshipTool` + `ExecuteFetchXmlTool` là 2 tool duy nhất dùng `ThrowExceptionFriendly(ex)` (qua wrapper base `McpToolBase.ThrowExceptionFriendly` → `McpToolResults.ThrowExceptionFriendly`). Friendly strip StackTrace + rewrite known Dataverse fault sang `[Error] [Kind] concise guidance`:
  - `[RelationshipNotFound]` — "could not find a relationship with name" (0x80040217) — Test 10, 15, 18
  - `[ParentalConflict]` — "cannot create another parental relation" (0x80047007) — Test 7
  - `[MissingCustomLabel]` — "custom label ... must have/should use" (0x80044328) — Test 8
  - `[ManagedProperty]` — "canchangehierarchicalrelationship" (0x8004F026) — Test 12
  - `[InvalidPrefix]` — "is invalid or missing ... must start with a valid customization prefix" (0x80044366) — Test 14
  33 tool khác vẫn dùng `ThrowException(ex)` raw — chưa migrate friendly (gap refactor3 fleet, separate effort).
- **create_1n (Test 1)**: auto-tạo lookup attribute `all_account` trên contact + relationship `all_account_contact` trong 1 request (`CreateOneToManyRequest` với `Lookup = LookupAttributeMetadata`). Add-to-solution qua `SolutionComponentCreateHelper.ApplySolutionUniqueName` (không tự build AddSolutionRequest). Publish qua `PublishHelper.PublishEntity` (không tự build PublishXmlRequest). - **create_nn (Test 5)**: auto-tạo intersect entity `all_account_contact` + N:N relationship trong 1 request (`CreateManyToManyRequest`). Menu default `UseCollectionName`/`Details`/order 10000.
- **Error paths (Test 7–15, 18)**: 10 error path — 5 tool-side validation (no changes, thiếu solution_name, is_hierarchical entity khác nhau, invalid action), 5 DataverseFault (Parental conflict 0x80047007, UseLabel thiếu label 0x80044328, relationship không tồn tại 0x80040217 ×2, managed property hierarchical 0x8004F026, add_target prefix 0x80044366). Not-found → DataverseFault 0x80040217 (ThrowException, không catch helper). OOB `regardingobjectid` không tuân convention prefix → DataverseFault (Test 18, accept — OOB poly lookup không nên remove target qua tool này).
