# ✅ TOOL DESCRIPTION

```text
List SDK messages and legacy workflow Custom Actions, or inspect one message/action in detail.

WHEN TO USE:
- Discover available SDK messages for an entity before writing plugin registration
- Inspect a legacy Custom Action's input/output parameters from XAML
- Check plugin step count registered on a specific message

RELATED TOOLS:
- get_custom_apis → modern Custom API definitions (replaces Custom Actions)
- get_plugins → plugin assemblies/types/steps registered on these messages
- get_workflows → classic workflow definitions (background + realtime)
```

# PARAMETERS

```text
entity_name            : string : Entity Display/logical name. 'none'/empty = global. Ignored in detail mode.
message_name           : string : Message/Action name → detail mode. Empty = list mode.
include_custom_actions : bool   : List: include Custom Actions. false = SDK only. Ignored in detail mode.
max_records            : int    : List: maximum 1-500 names per category. Default 100.
```

# RESULTS

- Test 1: list mode separates sdkMessages from customActions for account — 10 SDK + 1 custom action.
- Test 2: detail of a legacy Custom Action returns isCustomAction, availability, supportedEntities, and pluginStepCount.
- Test 3: global scope returns 20 messages — max_records=10 applies per category (10 SDK + 10 custom actions), matching "maximum names per category".
- Test 4: unknown message_name returns a not-found error with a hint pointing to list mode.
- Test 5: unresolvable entity_name returns the resolver not-found error with a hint pointing to get_tables.
