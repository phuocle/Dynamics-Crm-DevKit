# TOOL DESCRIPTION

```text
Power Automate cloud flows + run history. Modes: no flow_id = list (filtered); flow_id + action='list' = detail + last 5 runs; flow_id + action='runs' = extended run history. For classic (category=0) workflows use get_workflows.

WHEN TO USE:
- List flows by name/owner/status
- Inspect a specific flow + recent runs
- Drill into run history with status_filter (debug failures)

RELATED TOOLS:
- get_workflows → classic workflows (category=0)
- get_business_process_flows → BPF definitions + stages
- get_business_rules → client-side business rules
```

# PARAMETERS

```text
flow_id        : string : GUID. Empty = list. Set: action determines detail vs runs.
action         : string : 'list' or 'runs'. 'runs' needs flow_id.
name_filter    : string : list only. Name contains.
owner_filter   : string : list only. Owner contains.
status         : string : 'active' / 'draft' / 'suspended' / 'all'.
status_filter  : string : runs only: succeeded/failed/running/cancelled/waiting/paused/skipped/suspended.
minutes_ago    : int    : runs only. Max 43200.
max_records    : int    : 1–250.
```

# RESULTS

- Test 1: list mode with status=all returns all 3 flows (default status='active' returns 0 in this org because every flow is Draft).
- Test 2: detail mode returns fuller metadata (createdOn/modifiedBy); a Draft flow has no runs so the runs field is absent.
- Test 3: name_filter "search" matches 2 of 3 flows.
- Test 4: owner_filter "SYSTEM" returns all 3 flows — owner-filter paging drops no records.
- Test 5: runs mode returns a runSummary covering all 9 states even with 0 runs; success, not an error.
- Test 6: action='runs' without flow_id returns a validation error with a hint, IsError true.
- Test 7: non-existent flow_id returns a not-found error with a hint pointing to list mode, IsError true.
