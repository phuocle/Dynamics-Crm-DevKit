# TOOL DESCRIPTION

```text
Manage views (savedquery/userquery). Actions: 'list', 'detail' (read-only) | 'create', 'update', 'rename', 'set_default', 'undo' (mutations).

WHEN TO USE:
- List or inspect views of an entity (system savedquery or personal userquery, scoped by is_personal_view; use detail for XML) — always list/detail BEFORE editing
- Create/update a view from FetchXML — grid columns are auto-generated from it (follow attribute order, width by data type); patch cell attributes, rename, set the default public view. Created views are always Public (querytype=0)
- QuickFind views: searchable fields are <condition> in <filter isquickfindfields="1">; grid columns are display only
- Restore a view from a .fetchxml.bak backup file written by update/rename/undo (undo)

RELATED TOOLS:
- get_tables → column logical names for FetchXML attributes/conditions
- execute_fetchxml → test a FetchXML before putting it into a view
- manage_form → entity forms; publish_customizations → batch publish; execute_webapi → raw savedquery access
```

# PARAMETERS

```text
action            : string : 'list', 'detail', 'create', 'update', 'rename', 'set_default', 'undo'.
entity_name       : string : Entity Display/logical name (Display Name resolved first).
view_id           : string : GUID. Required: detail/update/rename/undo.
view_name         : string : Name contains. 1 match → auto-select; multiple → returns candidates, use view_id.
is_personal_view  : bool   : false = system views (savedquery), true = personal views (userquery) — scopes list and view_name resolution.
fetchxml          : string : create/update: FetchXML — grid columns are auto-generated from it (follow attribute order, width by data type). undo: .fetchxml.bak backup file path from .devkit/backups/views/.
cell_updates_json : string : JSON array of {cell_name, set_attributes, remove_attributes}. Patch cell attrs (imageproviderwebresource, ishidden, …) without changing the FetchXML.
workspace_folder  : string : Required for update/rename/undo — current view XML is backed up to {workspace_folder}/.devkit/backups/views/ before overwrite.
```

# RESULTS

- Test 1: list returns 7 system views with queryType/isDefault/isManaged summary entries and no XML (XML only via detail).
- Test 2: personal-view scope is strict — 0 userquery rows is a success, fully separated from savedquery.
- Test 3: list with a view_name filter matching nothing returns totalCount 0 as a success — used here as the pre-create collision check.
- Test 4: detail by a unique view_name auto-selects the view and returns columns, fetchXml, layoutXml, and layoutJson.
- Test 5: detail of a Quick Find view additionally returns quickFindColumns extracted from the `isquickfindfields="1"` filter.
- Test 6: create builds a Public view from FetchXML with the grid auto-generated (primary name 300, datetime 150), validated client + server, published.
- Test 7: update with cell_updates_json only patches LayoutXML (`updatedParts="LayoutXML (cell patch)"`) and backs up both XML parts first.
- Test 8: update with a new FetchXML regenerates the layout (`updatedParts="LayoutXML (regenerated from FetchXML) + FetchXML"`); its backup file is the undo source for Test 12.
- Test 9: rename backs up the current XML, renames, and publishes.
- Test 10: set_default clears the 1 previous Public default so exactly one default remains (`clearedPreviousDefaults=1`).
- Test 11: setting the original view back as default clears the test view symmetrically — the clear-previous-default logic works both ways.
- Test 12: undo restores from the `.fetchxml.bak` backup, regenerates LayoutXML, backs up the pre-restore state, and reports 1 non-blocking warning for the `savedqueryid` attribute stored in the backup.
- Test 13: detail after undo confirms the restore — `modifiedon` is gone and the grid matches the Test 6 state.
- Test 14: invalid action returns a 2-part error listing the valid values.
- Test 15: unknown entity_name returns a 2-part error with the get_tables hint.
- Test 16: ambiguous entity_name returns the first-line message, the re-call hint, and the 3 candidates as `entityMatches` in [Detail] — no candidate table in the message.
- Test 17: update without workspace_folder is rejected before any mutation.
- Test 18: undo rejects a `.layoutxml.bak` file — only `.fetchxml.bak` is accepted because LayoutXML is always regenerated.
- Test 19: ambiguous view_name returns the disambiguation hint and the 7 matching views as candidates in [Detail] only.
- Test 20: a well-formed but unknown view_id returns a not-found error with a hint pointing to action='list'.
- Test 21: set_default rejects a Quick Find view — only Public views (querytype=0) can be the default.
- Test 22: create with a nonexistent FetchXML field is blocked by Display-Name-first field resolution before any mutation, with per-field errors in [Detail].
- Test 23: create with an existing view_name is rejected with a hint to rename or update via view_id.
