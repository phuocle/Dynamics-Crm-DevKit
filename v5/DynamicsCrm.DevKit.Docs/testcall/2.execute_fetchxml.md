# 2. execute_fetchxml

# Tool description AI đọc được

```
Name:        execute_fetchxml
Title:       Run a FetchXML query
Idempotent:  true
Destructive: false
ReadOnly:    true

Description:
Run FetchXML against Dataverse. Auto-paging via get_all. See schema://fetchxml for syntax.
Rules: lowercase logical names only; no top/count/page in <fetch> (use max_records); use max_records=10-50 for samples.
For keyword search → search_records. For entity metadata → get_tables.

Parameters:
  fetchxml    (string, required)
    FetchXML starting with <fetch>. Lowercase logical names.
  max_records (int, default: 5000)
    1-5000. Default 5000. Use 10-100 for samples.
  get_all     (bool, default: false)
    true = auto-page until max_records. false = first page only.
```

# Input tool call

```json
{
  "name": "execute_fetchxml",
  "arguments": {
    "fetchxml": "<fetch><entity name=\"account\"><attribute name=\"name\"/><attribute name=\"statecode\"/><attribute name=\"statuscode\"/><attribute name=\"primarycontactid\"/><attribute name=\"createdon\"/><attribute name=\"creditlimit\"/><order attribute=\"createdon\" descending=\"true\"/></entity></fetch>",
    "max_records": 3,
    "get_all": false
  }
}
```

> Trên org `🟢DEVKITV4` (DEVKITV4.crm.dynamics.com), truy vấn 3 account gần nhất theo `createdon` desc. FetchXML chỉ định 6 attribute (`name`, `statecode`, `statuscode`, `primarycontactid`, `createdon`, `creditlimit`). `get_all=false` → chỉ lấy 1 page đầu (page 1, count=3). Tool strip `top` nếu có, inject `page=1` + `count=3` qua `FetchXmlPagingHelper.ApplyPaging`. `max_records=3` < 5000 → giữ nguyên. Kỳ vọng 3 records + `hasMore=true` (org có nhiều hơn 3 account).

# Kết quả AI tổng hợp lại

- **Trạng thái:** Thành công (`[Success]`, `IsError=false`). Trả về **3 records** + `hasMore=true` (còn record nữa trên server).
- **Content 1 dòng:** `[Success] 3 records returned (more available).` — prefix `[Success]`, số record + ghi chú "more available" khi `hasMore=true`.
- **Structured content:**
  - `totalReturned` (int): số record thực tế trả về (3).
  - `hasMore` (bool): `true` = server còn record chưa lấy (do `max_records` giới hạn). `false` = đã lấy hết.
  - `entity` (string, null-aware): logical name của entity nếu toàn bộ records cùng 1 entity (`"account"`). `null` (ẩn) nếu multi-entity hoặc aggregate query không có entity rõ ràng.
  - `records` (array): mỗi record là 1 dictionary key-value:
    - `_entity`: logical name (vd `"account"`).
    - `_id`: GUID của record.
    - Các attribute còn lại: key = logical name (vd `name`, `statecode`, `creditlimit`), value = **formatted string** (Dataverse `FormattedValues` ưu tiên → label, không phải raw value).
- **Value formatting (quan trọng):**
  - **Picklist/Status** (`statecode`, `statuscode`): trả **label** (`"Active"`), không phải int `0`.
  - **Money** (`creditlimit`): format currency (`"$50,000.00"`), có symbol tiền tệ.
  - **Lookup** (`primarycontactid`, `transactioncurrencyid`): trả `Name (logicalName:guid)` hoặc chỉ `Name` nếu có formatted value.
  - **DateTime** (`createdon`): format `"M/d/yyyy h:mm AM/PM"` (Dataverse default culture).
  - **Attribute không có value** (vd `primarycontactid` ở record 1, `creditlimit` ở record 3): không xuất hiện trong record → JSON gọn hơn.
- **Token tiết kiệm:**
  - DTO bỏ echo input (`getAll`, `maxRecords`) — client đã biết giá trị truyền vào, không cần server echo lại.
  - `entity` null-aware (`[JsonIgnore(WhenWritingNull)]`) → ẩn khi multi-entity/aggregate.
  - Attribute null/không set không xuất hiện trong record dictionary → JSON payload không phình.
  - Content 1 dòng duy nhất, đủ thông tin (số record + hasMore).
- **Cách dùng tiếp theo:**
  - Lấy thêm record: tăng `max_records` hoặc set `get_all=true` (auto-page đến `max_records`).
  - Lấy hết record: `get_all=true` + `max_records=5000` (max).
  - Tra metadata entity/attribute: dùng `get_tables(entity_name="account")` để biết logical name, type, picklist options trước khi build FetchXML.
  - Keyword search (không biết entity): dùng `search_records` thay vì FetchXML.
  - Drill-down 1 record: lấy `_id` từ record → gọi `manage_record(action="read", entity_name="account", record_id=<guid>)`.

## Ví dụ phụ 2: FetchXML với link-entity (join account → contact)

**Input:**

```json
{
  "name": "execute_fetchxml",
  "arguments": {
    "fetchxml": "<fetch><entity name=\"account\"><attribute name=\"name\"/><link-entity name=\"contact\" from=\"contactid\" to=\"primarycontactid\" link-type=\"inner\" alias=\"c\"><attribute name=\"fullname\" /></link-entity><filter><condition attribute=\"statecode\" operator=\"eq\" value=\"0\"/></filter><order attribute=\"name\" descending=\"false\"/></entity></fetch>",
    "max_records": 2,
    "get_all": false
  }
}
```

**Content:**

```
[Success] 2 records returned (more available).
```

**Structured content:**

```json
{
  "totalReturned": 2,
  "hasMore": true,
  "entity": "account",
  "records": [
    {
      "_entity": "account",
      "_id": "72f939f8-4e40-f111-bec6-70a8a59a451e",
      "accountid": "72f939f8-4e40-f111-bec6-70a8a59a451e",
      "c.fullname": "Geovany Wintheiser",
      "name": "Bergnaum Inc"
    },
    {
      "_entity": "account",
      "_id": "71f939f8-4e40-f111-bec6-70a8a59a451e",
      "accountid": "71f939f8-4e40-f111-bec6-70a8a59a451e",
      "c.fullname": "Wendell Ortiz",
```

> Linked entity (join) trả về attribute với key dạng `{alias}.{attribute}` (vd `c.fullname`). `link-type="inner"` = inner join, chỉ trả account có primary contact. `entity="account"` vì toàn bộ record cùng entity chính. **Use case:** cần data từ 2 entity liên quan (vd account + tên contact) trong 1 query thay vì 2 query riêng.

## Ví dụ phụ 4: validation path — `fetchxml` rỗng

**Input:**

```json
{
  "name": "execute_fetchxml",
  "arguments": {
    "fetchxml": "",
    "max_records": 3
  }
}
```

**Content:**

```
[Error] fetchxml is required.
Hint: Read schema://fetchxml for FetchXML query structure and examples.
```

**Structured content:**

```json
{
  "error": "fetchxml is required.",
  "hint": "Read schema://fetchxml for FetchXML query structure and examples."
}
```

**IsError:** `true`

> Validation dùng `Error(msg, hint)`, không phải `ThrowException`. `hint` dẫn user đọc `schema://fetchxml` resource để biết cấu trúc FetchXML. Error prefix `[Error]` chỉ trong Content 1 dòng; structured `error`/`hint` là message thuần.

## Ví dụ phụ 5: validation path — `max_records` không hợp lệ

**Input:**

```json
{
  "name": "execute_fetchxml",
  "arguments": {
    "fetchxml": "<fetch><entity name=\"account\"><attribute name=\"name\"/></entity></fetch>",
    "max_records": 0
  }
}
```

**Content:**

```
[Error] max_records must be a positive integer (1-5000).
```

**Structured content:**

```json
{
  "error": "max_records must be a positive integer (1-5000)."
}
```

**IsError:** `true`

> `max_records=0` → validation fail. `max_records` phải trong khoảng 1-5000. Nếu `max_records > 5000` thì tool tự clamp về 5000 (không error, chỉ adjust).
