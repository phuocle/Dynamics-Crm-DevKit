# 10. get_solution_components

# Tool description

```text
List components in a Dataverse solution. Returns: solution info + count-per-type summary + detail (componentType, objectId, name). Full Entity components (rootComponentBehavior=0) listed as-is — use get_tables for sub-components.

WHEN TO USE:
- Audit solution contents before packaging/deploying
- Find objectIds for plugins, web resources, workflows
- Identify unmanaged customizations before importing managed solutions

FUZZY/AMBIGUITY:
- solution_name resolves Display Name contains first, then unique name contains. Ambiguity returns IsError=true with candidates.

RELATED TOOLS:
- get_tables → entity/attribute metadata for sub-components
- get_plugins → plugin assembly/type/step detail
- manage_webresource → web resource detail
```

# Kết quả

- **2 bug phát hiện trong quá trình test — ĐÃ SỬA 07.08.2026 (build 19:02:22), verify live sau khi reinstall:**
  1. **Metadata entity query dùng `In` không chunk** ([GetSolutionComponentsTool.cs](DynamicsCrm.DevKit.Cli/Mcp/Tools/GetSolutionComponentsTool.cs#L297-L326)): solution có >300 full entities (ví dụ `Default Solution`) → `DataverseFault 0x80044183: Query on Entity has exceeded the hard limit of conditions in a single filter (300)`. **Fix:** chunk `fullEntityIds` theo 250. Đã verify: `Default Solution` trả kết quả đầy đủ (~5.5MB components).
  2. **`ResolveAttributeMetadataNames` thiếu `Attributes` trong entity `Properties`** ([GetSolutionComponentsTool.cs](DynamicsCrm.DevKit.Cli/Mcp/Tools/GetSolutionComponentsTool.cs#L524-L533)): solution chứa attribute components (ví dụ `ALL-IN-ONE`) → `DataverseFault 0x80072527: Attributes must be part of the requested EntityMetadata properties when an AttributeQuery is specified`. **Fix:** thêm `"Attributes"` vào entity `Properties` (giống pattern relationship resolver đã làm). Đã verify: `ALL-IN-ONE` trả kết quả đầy đủ.
  - Đồng thời fix latent bug cùng dạng: `ResolveEntityMetadataNames` (Step 2 trong `BuildNameMap`) OR Equals từng id không chunk → giờ chunk 250 giống attr/rel resolvers.
- Resolver chỉ tìm trong solutions `isvisible=true` — `Active Solution` (isvisible=false) trả NotFound (Test 6) dù tồn tại trong org. Đây là thiết kế có chủ đích trong code.
- Ambiguity (Test 4) trả `IsError: true` + structured `details.solutionMatches` đúng contract. Lưu ý: input khớp exact 1 display name ("Contextual Help") sẽ auto-resolve thay vì ambiguous (Test 5).
- Full entities (`rootComponentBehavior=0`) được flag `isFullEntity: true` + liệt kê trong `fullEntities` (Test 5) — đúng mô tả "use get_tables for sub-components".
- include_active_layers (Test 2) và active_layers_only (Test 3) hoạt động; summary có `activeLayerCount` khi bật.
- Description khớp source hiện tại.
