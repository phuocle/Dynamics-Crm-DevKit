# TOOL DESCRIPTION

```text
Run a FetchXML query in single-page or bounded auto-paging mode.

WHEN TO USE:
- Query Dataverse records with deterministic columns, filters, joins, or aggregates
- Page through a bounded result after validating logical names

RELATED TOOLS:
- get_tables → discover entity and attribute logical names
- search_records → keyword relevance search
- schema://fetchxml → FetchXML syntax and examples
```

# PARAMETERS

```text
fetchxml    : string : FetchXML starting with <fetch>. Lowercase logical names.
max_records : int    : 1-5000. Default 5000. Use 10-100 for samples.
get_all     : bool   : true = auto-page until max_records. false = first page only.
```

# TEST 2

## INPUT

Malformed XML in the middle of the string — `<broken` is never closed.

```json
{
  "fetchxml": "<fetch><entity name='account'><attribute name='name'><broken</entity></fetch>"
}
```

## OUTPUT

```text
fetchxml is not well-formed XML: The '<' character, hexadecimal value 0x3C, cannot be included in a name. Line 1, position 61.
Hint: Read schema://fetchxml for FetchXML query structure and examples.
```

# TEST 3

## INPUT

Paging attribute `top` on the opening `<fetch>` is rejected — the tool owns paging.

```json
{
  "fetchxml": "<fetch top='5'><entity name='account'><attribute name='name'/></entity></fetch>"
}
```

## OUTPUT

```text
Do not set top, count, page, or paging-cookie in <fetch>.
Hint: Use max_records and get_all; the tool owns paging attributes.
```

```json
{
  "error": "Do not set top, count, page, or paging-cookie in <fetch>.",
  "hint": "Use max_records and get_all; the tool owns paging attributes."
}
```

## RESULT

```json
{ "IsError": true }
```

# RESULTS

- Test 1: single page returns 3 account records, `hasMore=true`, each record carries `_entity`/`_id` metadata plus requested columns.
- Test 2: malformed XML returns a clean validation `Error` with a hint to `schema://fetchxml` — no raw `XmlException` bubbles up.
- Test 3: paging attributes (`top`, `count`, `page`, `paging-cookie`) on `<fetch>` are rejected with a clear message and a hint to use `max_records`/`get_all`.
- Test 4: non-existent entity returns a `DataverseFault` with `errorCode 0x80041102` and `details` (kind, exceptionType, one-line stackTrace).
- Output convention: success content is prefixed `[Success]`; error content is `message` + a `Hint:` line; structured error always has `error` + `hint` (and `details` when it is an exception).
