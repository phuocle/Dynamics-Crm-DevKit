# TOOL DESCRIPTION

```text
Bulk create Dataverse records in parallel (max 5000/call). Partial failures: successes committed, failures reported per-item. Input: inline JSON array, .json path, or .csv path (Display Name headers).

WHEN TO USE:
- Seed many records at once (accounts, contacts, tasks) or import from CSV
- Pipe generate_demo_data output file (.json) into records_json
- High-throughput parallel creates (server hints concurrency when max_parallelism=0)

RELATED TOOLS:
- generate_demo_data → produce JSON to pipe into create_records
- manage_record → single-record create/update/delete/associate/disassociate
- search_records / execute_fetchxml → verify created records

Field syntax: polymorphic lookup 'field@targetentity' (e.g. 'customerid@account'); activity parties (to/from/cc/bcc/requiredattendees/organizer/customers/resources) are a JSON array of {"id":"<guid>","type":"<entity>"} (single object auto-wrapped; do NOT set participationtypemask). For single-record CRUD → manage_record.

BYPASS: bypass_custom_logic=true sets BypassBusinessLogicExecution=CustomSync,CustomAsync so sync+async plugins/workflows do NOT run for this create. Default false. Requires the System Administrator role (prvBypassCustomLogic privilege); rejected early if the calling user lacks it. Use for bulk seed/data-load where custom logic would slow or block creates.

IMPORT_SEQUENCE_NUMBER: Every record in the batch is auto-stamped with the same importsequencenumber value so the entire batch can be queried and bulk-deleted as a unit (e.g. <condition attribute='importsequencenumber' operator='eq' value='999990'/>). The value is computed as max(999990, maxInTable+1) and returned in the result as importSequenceNumber. If a record explicitly provides importsequencenumber, that value wins for that record (no duplicate checking). Set importsequencenumber on every record to override the auto-fill entirely.
```

# PARAMETERS

```text
entity_name          : string : Entity Display Name or logical name (Display Name resolved first).
records_json         : string : Inline JSON array, .json file path, or .csv file path. Max 5000 records.
max_parallelism      : int    : Concurrent requests. 0 = server hint. Clamped 1-52. Use 1-2 for on-prem.
bypass_custom_logic  : bool   : Bypass custom sync+async plugins/workflows (BypassBusinessLogicExecution=CustomSync,CustomAsync). Default false. Requires System Administrator role; rejected early otherwise. Use for bulk data load where plugins would slow/block creates.
```

# RESULTS

- Test 1: inline JSON creates 3/3 accounts; Display Name `Account` resolved to `account`, batch auto-stamped `importSequenceNumber: 999990`.
- Test 2: the JSON file generated by generate_demo_data (Test 4 of file 19) imports cleanly 5/5 via `records_json` file path — the intended generate → pipe → create workflow.
- Test 3: CSV with Display Name headers imports 2/2 (`Website`→`websiteurl`, `Revenue`→`revenue` mapped automatically), reported as `inputFormat: csv`.
- Test 4: single-record inline create returns the contact GUID reused as lookup target by Tests 5–6.
- Test 5: polymorphic lookup `primarycontactid@contact` resolves per record; explicit `max_parallelism: 1` sets `usedDefaultParallelism: false` and drops the default-parallelism warning.
- Test 6: activity parties work in both shapes — single-object `from`/`to` auto-wrapped and a systemuser sender plus 2-recipient `to` array in the same batch.
- Test 7: a 160+ char name fails only its own record — 2/3 committed, `status: partial`; the `[Detail]` line carries the per-item outcomes (failed item has `id: ""` plus the verbatim Dataverse validation error).
- Test 8: a 2-party `from` array is rejected by Dataverse ("Communication activity cannot have more than one Sender party") — 0/1 created, `status: failed`, per-item error in `[Detail]`.
- Test 9: `from` on task fails per-record with the not-found field message in `[Detail]`; field existence is checked per record, not pre-flight.
- Test 10: unknown entity returns a 3-part not-found error with a get_tables hint.
- Test 11: ambiguous Display Name `Product` returns the first-line error only, with the three candidates in `[Detail]` `entityMatches`.
- Test 12-15: four validation errors (non-array input, missing file, empty array, missing entity_name) each return a single-line `[Error]` with a hint where applicable.
