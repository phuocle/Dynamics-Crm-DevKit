Kết luận chính: Phần scaffolding (tạo project/item) đã ngang hàng 100% — cả hai cùng dùng một single source of truth DynamicsCrm.DevKit.Shared/Templates/TemplateCatalog.cs (13 project + 17 item, Id trùng tên wizard class của VSIX). Các luồng deploy runtime (plugin, webresource, report, datasource, solution, modelbuilder) thực tế đều chạy bằng CLI — VSIX sinh sẵn file *.bat gọi CLI hoặc có menu tương đương. VSIX nhiều hơn ở phần UX tương tác trong VS; CLI nhiều hơn ở phần headless / batch / CI.
Về ví dụ anh nêu — CrmPluginRegistration: đoán của anh đúng một nửa. CLI không thiếu hoàn toàn: devkit new-item --type Plugin tự sinh attribute [CrmPluginRegistration] trong class, và devkit server đọc attribute đó trong dll rồi đăng ký ngược lên Dataverse (code → CRM). Thiếu đúng một chiều: CRM → code — menu VSIX "Add/Update Crm Plugin Registration" quét sdkmessageprocessingstep trên CRM rồi tự viết/补 attribute vào file .cs đang mở. CLI hiện chưa có lệnh nào làm việc này → đây là gap thật sự.

5. Tính năng chỉ VSIX có (CLI chưa có)

5.1 Add/Update Crm Plugin Registration — chiều CRM → code

  • Menu chuột phải trong code window, hiện khi cursor đang trong class IPlugin/CodeActivity; ẩn khi mọi attribute đã có Id.
  • Quét CRM: sdkmessageprocessingstep join sdkmessage/plugintype/sdkmessagefilter/secure config + step images; workflow quét plugintype (isworkflowactivity=1).
  • Viết attribute qua FileCodeModel: thêm mới [CrmPluginRegistration(...)] đủ tham số (Stage, Execution, Isolation, Id, UnSecure/SecureConfiguration, RunAs, Image1–4…), hoặc inject Id vào attribute sẵn có.
  • Khi chưa đăng ký bước nào → sinh attribute placeholder "???", "???", StageEnum.PostOperation….
  • Tác dụng phụ tiện lợi: tự sinh deploy.debug.bat / deploy.debug.only.bat và thêm using namespace Shared.
  • Nếu máy chưa cài CLI → copy lệnh dotnet tool install -g DynamicsCrm.DevKit.Cli vào clipboard.
  • Evidence: DynamicsCrm.DevKit.Vsix\Commands\CommandAddCrmPluginRegistration.cs (fetch 323–480, add attribute 91–141, inject Id 143–189, visibility 204–240); Lib\VsixHelper.cs:289–320

5.2 Wizard dialogs & visual pickers (11 dialog)

  • FormProject — connection + tên project, ràng buộc loại connection theo project (Console chặn DeviceCode/FromPac, UiTest bắt OAuth…).
  • FormItem — picker entity nạp toàn bộ metadata của org (LateBound, Js/Ts Form/WebApi, Dialog, Report).
  • FormPlugin — 1 dialog dùng chung 9 item: Class, Entity, Message (lọc theo entity), Stage, Execution, Data Source (DataProvider), ngôn ngữ (ResourceString), chọn file (BatFile), dropdown plugin để sinh Test.
  • FormConnection — quản lý nhiều connection mã hóa AES, default, test connection, checkbox "Use project .env" ghi DEVKIT_* vào .env solution.
  • FormWebResource — pick webresource sẵn có hoặc tạo mới (chọn solution + prefix + tên).
  • FormReportMapping — map .rdl ↔ report CRM có sẵn / tạo mới.
  • FormReportDatasets — editor dataset FetchXML trong .rdl ("Validate & Refresh Fields", "Format XML").
  • FormCustom / FormInput / FormReview — quản lý T4 template; FormBuildOutput — cửa sổ streaming khi npm build.
  • Evidence: DynamicsCrm.DevKit.Vsix\Lib\Forms\*.xaml.cs; CLI tương đương chỉ là interactive prompt (ConnectionPrompter.cs, TaskNewShared.cs:18–33) — không có visual picker

5.3 Build TypeScript trước khi deploy

  • Menu Deploy TypeScript (Debug/Release) chạy npm run debug|release {file} tại package.json gần nhất, stream output vào FormBuildOutput, rồi mới deploy + publish. CLI upload file hiện có, không build.
  • Evidence: Commands\CommandTypeScriptRelease.cs, CommandNewTypeScriptRelease.cs; Lib\TypeScriptBuildHelper.cs:28–100

5.4 Quản lý custom T4 template bằng UI

  • FormCustom: Set Default / Save / SaveAs / Delete / Rename / Review preview; lưu trong DynamicsCrm.DevKit.Config.json. CLI chỉ nhận tên template đặt sẵn (--template) hoặc đường dẫn file .tt (--t4).
  • Evidence: Lib\Forms\FormCustom.xaml.cs; Lib\VsixHelper.cs:651–705

5.5 Regenerate idempotent khi re-add item

  • Re-add một item (vd LateBound, JsForm) trong VSIX = cập nhật lại phần generated (.generated.cs, .form.js) và chỉ ghi file khi nội dung đổi (ShouldAddProjectItemAsync, WriteTargetFileIfChangedAsync). CLI new-item dùng --force để ghi đè, không có khái niệm "chỉ regen phần generated".
  • Evidence: Wizard\ItemTemplates\ItemTemplateBase.cs:44–103

5.6 UX trong trình soạn thảo

  • Context menu "DynamicsCrm.DevKit" trên item node của Solution Explorer (7 lệnh deploy), menu trong code window, CSS editor và HTML editor (Deploy WebResource); tự save file đang chọn trước khi deploy; status bar animation; cache ServiceClient 60 phút.
  • Sau khi tạo .rdl, VSIX mở ngay Report Designer để chỉnh tiếp.
  • Evidence: DevKitPackageVsct.vsct:108–178; VsixHelper.SaveSelectedItemAsync:507; Lib\CacheHelper.cs:21–129; Wizard\ItemTemplates\ReportItemWizard.cs:40–82

6. Tính năng chỉ CLI có (VSIX không có)

6.1 devkit generator — sinh code hàng loạt theo json profile

  • Types: jsform | tsform | jswebapi | tswebapi | csharp (trong json generators section).
  • Chọn entity: */all (toàn bộ org), để trống = suy ra từ các file *{suffix} sẵn có trong folder, hoặc danh sách cụ thể — VSIX chỉ làm được 1 item/lần.
  • Evidence: Tasks\TaskGenerator.cs:56–143; Shared\Enum.cs:29–37

6.2 Headless / CI / cross-platform

  • --plain / DEVKIT_NO_COLOR trong .env → output plain-text cho AI agent/CI; exit code rõ ràng (0 Success / 1 ValidationError…).
  • Chạy được trên .NET 10 (Windows và Linux), không cần Visual Studio; new-project list / new-item list in bảng catalog (cột Ready cho biết type nào scaffold được).
  • Update checker: check NuGet DynamicsCrm.DevKit.Cli mới hơn (cache 7 ngày, panel "UPDATE AVAILABLE").
  • Evidence: Program.cs:25–75, 163–202; Services\UpdateChecker.cs:17–78; Tasks\TaskNewShared.cs:36–92

6.3 Deprecated shims + legacy arg converter

  • 9 lệnh giữ lại chỉ để bat cũ sinh bởi VSIX/tiện ích trước đây tiếp tục chạy: plugin, workflow, dataprovider, datasource, proxytype, legacy-solution, downloadreport, uploadreport, downloadwebresource — tự redirect sang lệnh mới.
  • Converter legacy /type:generators, /arg:value → cú pháp mới.
  • Evidence: Program.cs:91–134; Services\LegacyArgConverter.cs:17–106

6.4 Fast deploy bằng GUID và pre-flight validator

  • webresource upload --webresourceid|-wid: đẩy file thẳng tới webresource theo GUID, bỏ qua mapping/tên; report upload nhận --report dạng name/filename/GUID.
  • DeploymentValidator pre-flight kiểm tra config server/webresource trước khi deploy.
  • Evidence: Commands\WebResourceCommand.cs:109–167; Services\DeploymentValidator.cs:24–76
