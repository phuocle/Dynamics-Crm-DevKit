## What Was Found (Inventory)

Audit confirmed against v4 production source (`D:\github\Dynamics-Crm-DevKit\v4\DynamicsCrm.DevKit.Cli`):

| Issue | Location | Root Cause |
|---|---|---|
| `--secret` in help text | SpectreLog.cs lines 88, 106, 154, 172 | Parser uses `--clientsecret`, help never updated |
| `--user` / `--pass` in launch profiles | launchSettings.json lines 158, 163 | Parser uses `--username` / `--password`, profiles never updated |
| `--sdk-login` in help + LegacyArgConverter but not in parser | SpectreLog.cs + LegacyArgConverter.cs | Option was documented and converted but `[CommandOption]` was missing |
| MCP tool count `32` in help text | SpectreLog.cs lines 117, 183 | Stale count; current count is 36 |

**Not a finding:** `/secret:`, `/user:`, `/pass:` were never part of v4 legacy CLI — v4 only had `/conn:`, `/json:`, `/type:`, `/profile:`, `/version:`, `/command:`, `/sdklogin:`, `/url:`, `/onlyupdateassembly:`. No extra LegacyArgConverter mappings needed.

## Decision

- `--sdk-login`: add as real `[CommandOption]` (legacy need confirmed; v4 had `/sdklogin:yes` → `--sdk-login`)
- All other stale options: update docs/profiles to canonical names (Option B — strict canonical)
- LegacyArgConverter: no changes (existing `sdklogin` mapping is correct and complete for v4 legacy)
