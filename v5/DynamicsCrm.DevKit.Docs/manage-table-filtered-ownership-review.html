manage_table có cần cập nhật?

Đánh giá khả năng hỗ trợ Filtered record ownership (preview) của Dataverse dựa trên ba tài liệu Microsoft Learn và implementation hiện tại trong repository.

Kết luận

Có — cần cập nhật nếu mục tiêu là để MCP tạo được filtered-ownership table.

Hiện manage_table chỉ nhận User hoặc Organization. Tài liệu SDK yêu cầu tạo bảng với OwnershipTypes.Filtered. Bổ sung Filtered vào lựa chọn ownership và mô tả tham số là thay đổi tối thiểu.

Phạm vi kết luận: hỗ trợ tạo bảng. Tạo filter, gắn filter với bảng và cấp quyền trong security role là các bước cấu hình riêng, không được thực hiện chỉ bằng ownership_type.

Microsoft đang mô tả điều gì?

  • Filtered ownership là row-level security dựa trên điều kiện cột. Record filter chứa FetchXML; entity record filter gắn filter với table; security role cấp các quyền Create, Read, Write, Delete, Append và Append to tương ứng.
  • Bảng không có record owner. Không thể share hoặc assign từng row cho user. Quyền truy cập là hợp của các filter người dùng nhận từ security roles và teams. System Administrator được cấp filter “All records”.
  • Đây là preview. Tài liệu maker ghi rõ tính năng preview; không nên ngầm quảng bá đây là ownership thông thường đã sẵn sàng cho production.
  • Ownership không đổi được sau khi tạo. Cần chọn chính xác lúc CREATE; UPDATE hiện tại vẫn nên giữ tính immutable.
  • Filter cũng áp dụng được cho một số bảng ownership hiện hữu. SDK doc nói filter có thể dùng trên bảng user/team và organization hiện có; đó là khả năng của hệ thống filter, không có nghĩa đổi ownership_type của bảng cũ.

Kiểm tra SDK cần làm trước khi implement: CLI đang tham chiếu Microsoft.PowerPlatform.Dataverse.Client 1.2.27. Microsoft Learn yêu cầu enum OwnershipTypes.Filtered (giá trị 32). Khuyến nghị thay đổi theo thứ tự

  1. Kiểm tra SDK 1.2.27 có OwnershipTypes.Filtered; xác nhận giá trị metadata 32 và hỗ trợ ở Dataverse environment đích.
  2. Thêm lựa chọn Filtered vào ownership_type và map trực tiếp tới enum của SDK. Giữ mặc định User để không phá hành vi hiện có.
  3. Ràng buộc Filtered không dùng chung với is_activity=true (lỗi rõ ràng thay vì silently ép về User). Với activity, giữ quy tắc User hiện tại.
  4. Cập nhật MCP tool description, SchemaToolsGuide, tài liệu testcall/35.manage_table.md, Wiki, và test ownership hợp lệ/không hợp lệ + activity interaction.
  5. Build CLI và chạy test tập trung của ManageTable. Kiểm tra metadata trả về là Filtered trên Dataverse có bật preview trước khi tuyên bố end-to-end.

Điều gì nằm ngoài thay đổi tối thiểu?

manage_table chỉ tạo metadata của table. Để hoàn tất cấu hình bảo mật, cần có workflow quản lý recordfilter/entityrecordfilter và gán filter privilege cho security role. Tài liệu hướng dẫn cũng mô tả tạo filter từ FetchXML trong maker UI.

Có thể dùng Web API/Dataverse SDK tổng quát để thao tác các entity cấu hình này, nhưng hiện repo chưa được khảo sát đầy đủ để khẳng định có sẵn MCP workflow chuyên dụng. Nếu muốn MCP hỗ trợ end-to-end, nên đánh giá thành yêu cầu riêng: công cụ CRUD filter, gắn filter với table, quản lý privilege/role, kiểm soát quyền admin, và test bằng user không phải administrator.

Đừng mô tả filtered table như “Organization-owned”: không có owner, và security semantics khác cả UserOwned lẫn OrganizationOwned.

Các giới hạn cần phản ánh cho người dùng

  • Preview, có thể thay đổi và có thể hạn chế.
  • Không share/assign row vì không có owner.
  • Hiệu năng: filter được áp vào mọi query; thiết kế filter cần hiệu quả.
  • Dataverse Search với filter có link-entity chỉ trả kết quả từ primary table theo giới hạn tài liệu.
  • Không áp dụng hiện tại cho external virtual tables.
  • Không thể đổi ownership type sau khi table được tạo.
