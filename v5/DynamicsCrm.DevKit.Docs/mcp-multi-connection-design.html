DevKit MCP Multi-Connection — 1 server, nhiều env, policy per-connection, alias theo tên

Ngày: 2026-11-14 · rev 3 — env setup luôn là SỐ, thêm ALIAS (DEVKIT_1_ALIAS=prod) theo ruling anh Phước · rev 2 — dry-run / impersonation per-connection, phân tích lại dry-run vs readonly · Trạng thái: PROPOSAL — chờ anh Phước review · File spec để AI code: DynamicsCrm.DevKit.Docs/Cli/mcp-multi-connection.md · Feature nền (đã ship): Cli/mcp-env.md

TL;DR — Khuyến nghị: Giữ 1 MCP server duy nhất trong client config, thêm 1 param tùy chọn env vào mọi tool + 1 tool mới connection_list. Server tự khai phá các nhóm DEVKIT_1_*, DEVKIT_2_*… trong .env và connect lười (lazy) khi lần đầu được gọi tới.

Policy theo connection: key DEVKIT_1_DRY_RUN=true biến nhóm 1 thành PROD đọc-chỉ-an-toàn (mutation bị chặn tại boundary, đọc thoải mái), nhóm không có key thì ghi tự do → đúng kịch bản "prod để dry-run cho an toàn, dev tự do, nhờ AI compare data / compare schema… đủ thứ".

Alias theo tên (rev 3): .env vẫn đặt bằng số, mỗi nhóm có thể đặt thêm bí danh — DEVKIT_1_ALIAS=prod, DEVKIT_2_ALIAS=uat. AI truyền env: "prod" hoặc env: "1" — cùng một nhóm. Prompt "hãy dùng mcp uat…" → env:"uat"; prompt không mention → default. Numeric là canonical, alias chỉ là địa chỉ thêm.

Chi phí schema: ~40K → ~42K tokens thay vì ~80K khi chạy 2 server (tiết kiệm ~48%). Behavior mặc định không đổi.

Hậu quả: 80 tool schema → ~80K tokens mỗi session, 2 process, 2 lần whoami để xác minh. Và điểm mù về an toàn: --dry-run là toàn cục — muốn prod an toàn thì dev cũng bị kèm dry-run (hoặc phải chạy 2 process với 2 flag khác nhau).

1.2 Điều đã có sẵn

Feature --env <id> (ship 2026-11-12, Cli/mcp-env.md) đã dựng xong nền móng — không cần đổi format .env, chỉ thêm key ALIAS + key policy:

  • Nhóm mặc định DEVKIT_* + các nhóm đánh số DEVKIT_1_*, DEVKIT_2_*, … không cần liên tiếp, không giới hạn số lượng.
  • ProjectEnvironment (Shared): Read(), HasGroup(), GetValue(values, key, groupId) (đã có overload theo nhóm), IsValidGroupId(), GetGroupKey() — giữ nguyên 100%, alias là key không-phải-connection-field (tiền tố DEVKIT_NO_COLOR đã mở đường).
  • Rules đã phê: args thắng per-field, không bao giờ trộn nhóm, không đọc OS env var.
  • File .env ở workspace hiện tại đã có sẵn nhóm mặc định + nhóm 1 (đã xác minh tên key, không đọc giá trị).

2. Mục tiêu & ràng buộc

#Mục tiêu
G11 server entry trong MCP client config — 1× token schema (~40K), 1 process.
G2AI gọi được cả hai (hoặc N) connection khai trong .env — chọn từng lệnh gọi, không cần restart.
G3Behavior mặc định (không truyền env, không có key mới) byte-identical với hôm nay.
G4AI tự khám phá được danh sách env (id + alias + trạng thái bảo vệ) mà không cần hỏi lại người dùng.
G5An toàn per-connection: env PROD đặt dry-run → mutation bị chặn ngay trên env đó; env DEV ghi tự do. AI compare data/schema chéo 2 env một cách an toàn.
G6Ngôn ngữ prompt = ngôn ngữ .env: nhóm có alias (prod, uat) thì prompt "dùng mcp uat" khớp trực tiếp; không mention gì → default. .env vẫn đặt bằng số (ruling rev 3).
G7Không lộ secret; không tạo state ẩn AI có thể quên (an toàn khi mutation).
#Ràng buộc
C1Scope chỉ devkit mcp — không đụng generator/server/VSIX (ruling của mcp-env.md).
C2Giữ nguyên mọi error text / output shape / JSON key hiện có, trừ những chỗ task này explicitly đổi.
C3Startup fail-fast giữ nguyên: chỉ connection default được connect lúc startup (hỏng → exit 2 như cũ); thêm: validate giá trị key mới (ALIAS, DRY_RUN) lúc startup.
C4--dry-run / --as-user giữ nguyên ngữ nghĩa khi không có key policy trong .env (cascade — xem mục 5.2). --category giữ nguyên per-server.
C5Không đọc lại .env khi server đang chạy — đổi .env phải restart server.
C6Nhóm trong .env luôn định danh bằng số (DEVKIT_1_*); alias chỉ là tên gọi thêm, không bao giờ thay thế id trong cấu hình.

C — Nhân tool theo env (whoami_1…) Clone tool set per env trong 1 process. ~80K KHÔNG CÓ (per clone) LOẠI — token bằng đúng 2 server, mất hết ý nghĩa
D — Giữ nguyên 2 server Status quo — cách hiện nay đạt "prod dry-run / dev tự do": 2 process, 2 flag khác nhau. ~80K KHÔNG CÓ (mỗi process 1 flag) Baseline — an toàn được nhưng đắt gấp đôi token
Vì sao loại B dù rẻ nhất? Thiết kế hiện tại của DevKit cố tình đặt policy (McpExecutionContext, dry-run, CallerId) ngoài tầm với của AI — server-side, fail-closed. Connection "active" AI-controlled là state ẩn ngược hẳn triết lý đó: quên switch = mutation nhầm org, và nếu policy cũng đi theo "active connection" thì một lần quên switch là prod mất áo giáp. Lưu AsyncLocal không cứu được vì AsyncLocal set trong 1 request không chảy sang request khác.
Vì sao alias thay vì nhóm đặt tên tự do (DEVKIT_PROD_URL)? Parser hiện tại đọc DEVKIT_<FIELD> cho nhóm default — không có cách phân biệt chắc chắn DEVKIT_AUTH_TYPE (field default) với DEVKIT_AUTH_TYPE_URL (nhóm "AUTH_TYPE", field "URL") mà không sinh ra parser two-pass dễ lỗi và rủi ro phá file .env cũ. Alias (DEVKIT_1_ALIAS=prod) giữ numeric làm xương sống — đúng ruling "env setup luôn là số" — với 0 thay đổi parser.

4.6 whoami — thay đổi

  • Thêm param env (như mọi tool).
  • Structured output thêm 2 field ở top-level (D2 — luôn có, kể cả default):
    • "env": "default" hoặc giá trị AI truyền vào (id hoặc alias) — khớp ngôn ngữ prompt để đối chiếu.
    • "dryRun": true/false — policy effective của connection vừa dùng.
  • Summary line khi dùng nhóm ≠ default: thêm (env <giá trị truyền>) — VD [Success] Connected to PROD (…) as # DEVKIT. Dataverse 9.2.…. 1 security role(s). (env prod). Khi default → không thêm gì, output giữ nguyên byte cũ (kể cả khi truyền alias của default).

4.7 Tag env trên các tool còn lại

Để mặc định byte-identical (G3): các tool khác chỉ thêm tag khi env ≠ default — hậu tố | env <giá trị truyền> ở cuối dòng summary (echo đúng giá trị AI truyền: | env 1 hoặc | env prod). Call không truyền env → output giữ nguyên 100%. Áp dụng cả text [DryRun]: [DryRun] Mutation blocked: Create account | env prod. (Decision point #3)

4.9 Thread-safety & vòng đời

  • ConcurrentDictionary<string, Lazy<ConnectionBundle>> — connect đúng 1 lần/nhóm dù gọi song song; alias lookup là thuần map → không thêm state.
  • Policy per-bundle dựng 1 lúc connect nhóm (từ McpExecutionPolicy) — immutable suốt process: AI không thể "tắt dry-run prod" lúc chạy (giữ triết lý policy-ngoài-tầm-với).
  • Mutation executors (DataverseMutationExecutor, DataverseWebApiMutationExecutor) đã nhận context qua argument → context bundle chảy vào boundary tự nhiên, không đổi chữ ký.
  • ServiceClient an toàn gọi đồng thời; token refresh SDK tự quản. Failed lazy connect KHÔNG cache — lần sau thử lại.
  • Không reload .env lúc chạy (C5).

5. Safety model — dry-run per-connection vs --category readonly

Hai cơ chế không phải một thứ, không thay thế nhau, và nằm ở hai tầng khác nhau:

5.1 Ba lớp phòng thủ

LớpCơ chếPhạm viChặn cái gìAi thực thi
L1 — Catalog --category readonly Per-server (cả process) Ẩn hẳn 22 mutation tool khỏi tools/list — AI không nhìn thấy tool để gọi. DevKit (schema filter)
L2 — Execution DEVKIT_<id>_DRY_RUN=true / --dry-run Per-connection (mỗi bundle 1 policy) Mutation tool vẫn hiện; lệnh mutation vào env đó bị chặn tại boundary → [DryRun] + preview. DevKit (AssertMutationAllowed)
L3 — Identity Security role của service account (VD role chỉ có Read) Per-connection (theo credential) Chặn tại Dataverse — kể cả ai đó gọi API ngoài DevKit. Dataverse (mạnh nhất)
Vì sao --category readonly KHÔNG thể per-connection? Catalog tool là thứ của process: một tools/list duy nhất, tool không biết trước caller sẽ truyền env nào. Param env được chọn tại mỗi call, trong khi ẩn/hiện tool xảy ra trước session. Muốn "ẩn mutation tool chỉ khi env=prod" là mâu thuẫn bản chất — L2 giải quyết đúng cái đó bằng cách hiện tool nhưng chặn execution theo env.

5.2 Cascade DryRun — quy tắc hiệu lực (theo id số; alias chỉ là địa chỉ)

Thứ tựNguồnÁp dụng cho
1 (cao nhất)DEVKIT_<id>_DRY_RUN trong nhóm đánh sốNhóm đó
2Flag --dry-run lúc startupNhóm default (và kế thừa xuống nhóm đánh số không có key riêng)
3DEVKIT_DRY_RUN (nhóm default trong .env)Nhóm default (chỉ khi flag không truyền)
4 (sàn)falseMọi nhóm không khớp nguồn trên
Ví dụ kiểm chứng cascade:
(A) không flag, không key            → mọi nhóm false    = hôm nay, byte-identical
(B) --dry-run, không key             → mọi nhóm true     = hôm nay, byte-identical
(C) --dry-run + DEVKIT_1_DRY_RUN=false → default=true, nhóm 1=false  (prod=default, dev=1)
(D) không flag + DEVKIT_1_DRY_RUN=true → default=false, nhóm 1=true   (dev=default, prod=1) ← kịch bản chính
(E) DEVKIT_DRY_RUN=true, nhóm 1 không key → default=true, nhóm 1=true (kế thừa)

Giá trị chỉ nhận true/false (case-insensitive, strict) — sai giá trị báo lỗi tại startup (fail-fast, C3), không chờ tới lần gọi đầu tiên.

5.3 Kịch bản prod/dev — "an toàn mà vẫn nhờ AI làm đủ thứ"

.env:   default = DEV, alias "dev"   |   nhóm 1 = PROD, alias "prod", DEVKIT_1_DRY_RUN=true
server: devkit mcp devkit-zcode     (KHÔNG cần --dry-run)

Anh Phước nói                       AI làm                    → Kết quả
──────────────────────────────────────────────────────────────────────────────────
"compare schema account giữa        2 call get_tables          → prod chỉ đọc, an toàn

                                    không env)
"đếm account trên prod"             execute_fetchxml           → đọc PROD OK (readonly KHÔNG

Kết quả: AI có toàn quyền đọc trên cả 2 env (so sánh, đối chiếu schema, đếm dữ liệu…), ghi thoải mái trên DEV, và PROD được chặn mutation ngay tại lệnh gọi — không cần AI "hứa là cẩn thận", không cần 2 process. Muốn chắc hơn nữa: ghép L3 — service account của nhóm PROD dùng role chỉ-đọc, khi đó dry-run chỉ còn là lớp dự phòng.

5.4 Impersonation per-connection (D8)

Cùng cơ chế cascade với DEVKIT_<id>_AS_USER (nhóm số) và DEVKIT_AS_USER (nhóm default, khi flag --as-user không truyền): key nhóm thắng flag; nhóm không có key thì kế thừa giá trị effective của nhóm default. Resolve + check System Administrator chạy per connection lúc connect nhóm đó (lazy), giữ nguyên semantics "không resolve được thì IGNORE + warning". Nếu aP không cần → bỏ phần này, dry-run vẫn hoạt động độc lập.

6. AI dùng "mcp uat" như thế nào? (trả lời câu hỏi 3)

Với người dùng, cách chỉ định env khi ra lệnh giống hệt ngày thường. AI định hướng nhờ ServerInstructions liệt kê nhóm theo id + alias ngay đầu session — prompt khớp tên là chạm đúng nhóm:

Anh Phước nóiAI hiểu & làm
"Hãy dùng mcp uat: tạo record Test Mcp Final" Thấy 2 (uat) trong instructions → mọi call trong task này đều truyền env: "uat" (≡ env: "2"). Output tag | env uat xác nhận.
"Hãy dùng mcp: tạo record Test Mcp Final" — không mention gì Không truyền env → default (nhóm DEVKIT_* — đúng hành vi hôm nay).
"Trên prod, đếm số account" execute_fetchxml với { "fetchxml": "…", "env": "prod" } — đọc OK dù prod đang dry-run.
"So sánh schema account giữa prod và dev" 2 call get_tables song song (env:"prod" + env:"dev" hoặc không env) — stateless nên song song an toàn.
"Cập nhật record đó lên prod" manage_record với env:"prod" → [DryRun] blocked + preview. AI báo lại "prod đang dry-run, chỉ xem trước được" — đúng ý đồ an toàn.
"Env nào đang được bảo vệ?" / "có những env nào?" connection_list → id + alias + dryRun. whoami {env:"uat"} → "env": "uat", "dryRun": false xác minh từng env.
"Dùng env 9…" (không tồn tại) [Error] Unknown connection group + [Detail] danh sách khả dụng → AI báo lại, không đoán mò.

Vì sao AI không quên truyền env? 3 lớp nhắc:

  1. ServerInstructions liệt kê nhóm + alias + trạng thái dry-run ngay đầu session (chỉ khi có >1 nhóm — ai dùng 1 env không bị nhiễu).
  2. Description của param env hiện trên 40/40 tool schema.
  3. Kết quả output có tag env khi ≠ default + [DryRun] tag khi bị chặn → AI tự đối chiếu được với yêu cầu.
