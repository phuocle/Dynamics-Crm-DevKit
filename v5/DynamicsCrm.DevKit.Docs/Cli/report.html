1. Tổng quan

"Manage Datasets..." là lệnh menu chuột-phải của VSIX trên một file .rdl (SSRS report). Nó mở dialog WPF để quản lý các FetchXML dataset bên trong RDL: list dataset, tạo mới, sửa/sửa-tên, validate FetchXML chống metadata org (sinh Fields từ metadata thật), bật/tắt pre-filter từng entity, lưu RDL với backup + atomic write. Toàn bộ logic là pure logic không phụ thuộc WPF/VS — chỉ cần ServiceClient + System.Xml — nên port sang CLI là move, không viết lại.

Ngoài dataset, report feature trong VSIX còn có: New Report (menu 0x1007 → CLI đã có new-item --type Report, I.18) và deploy upload/download (CLI đã có uploadreport/downloadreport). Quyết định 2026-11-07 của APhước: gộp các thao tác report thành một family devkit report --type dataset|upload|download và deprecate 2 lệnh cũ.

devkit report --type dataset← MỚI (port từ VSIX) devkit report --type upload← move từ uploadreport devkit report --type download← move từ downloadreport

2.1 UX flow của dialog (chuẩn tham chiếu cho CLI)

  1. Mở file → Reload(): detect encoding/BOM, parse XDocument, root <Report>, contract FetchXML (mọi dataset có CommandText = <fetch> đúng 1 root <entity>).
  2. List → mỗi dataset: Name, DataSource, CommandText, Fields, Parameters, FetchEntities, References.
  3. New → tên gợi ý Dataset{N} nhỏ nhất chưa dùng.
  4. Edit / rename → service tự rename mọi reference trong RDL.
  5. Validate & Refresh Fields → syntax → connect → metadata → rebuild Fields/Parameters/Prefilter grid.
  6. Apply → update có field bị xóa → MessageBox Yes/No → Add()/Update().
  7. Save RDL → SaveAsync(solutionFolder) (backup + atomic) → đóng.

4. Validation pipeline — 6 giai đoạn

Phần quan trọng nhất của feature (Validate(), cs:292-341):

  1. Syntax + entity graph — root <fetch>; đúng 1 root <entity>; mọi entity/link-entity có name, link-entity có alias, alias duy nhất — lỗi kèm số dòng.
  2. Metadata per entity — RetrieveEntityRequest { LogicalName, EntityFilters.Attributes } (cache).
  3. Sinh Fields — explicit attribute / all-attributes (lọc IsValidForRead + bỏ AttributeOf ảo) / aggregate-groupby (bắt buộc alias; count/countcolumn + dategrouping ép Integer). Tên: root → logical; link → alias.logical; normalize [^A-Za-z0-9_]→_; trùng tên sinh ra → lỗi gợi ý alias. Companion: lookup/customer/owner → XValue (Guid) + XEntityName (String). Reject: MultiSelectPicklist, File, Image + ngoài whitelist.
  4. Validate referenced attributes — link from/to, order, condition, valueof (cross-alias) phải tồn tại trên metadata đúng entity.
  5. DiscoverParameters — token @xxx trong condition value / <value> / attributes page, count, paging-cookie. MultiValue khi operator in/not-in/between/not-between hoặc >1 value. Update tái sử dụng mapping QueryParameter→ReportParameter hiện có.
  6. Server probe — BuildProbe: bỏ mọi filter + paging + prefilter attrs, top="1" (trừ aggregate); có parameter → probe không kèm filter (BuildExecutionCandidate giữ filter) + warning. RetrieveMultiple(FetchExpression) — lỗi server → fail.

Ngoài ra page/count trong fetch → tự thêm field hệ thống PagingCookie + MoreRecords.

Phần VSIX service đầy đủ hơn implementation MCP hiện tại (MCP chỉ làm root entity) (ApplyPrefilterAndParameters, cs:613-691):

Tắt pre-filter (update): gỡ attrs khỏi fetch + prune QueryParameter; report-level artifacts (lớp 3-5) giữ lại thận trọng + warning — đúng hành vi "conservatively retained" của dialog. Parameter user (@token) cũng vậy: QueryParameter gỡ, ReportParameter giữ + warning.

6. Save mechanics

  • Conflict detection — SHA-256 tại thời điểm mở; khác → IOException "The RDL changed outside this dialog. Reload it before saving.".
  • Backup — <backup-root>/.devkit/manage_report/backups/<file>_yyyyMMddHHmmssfff.rdl; backup-root = solutionFolder nếu có, ngược lại thư mục chứa file (CLI truyền null → backup cạnh .rdl).
  • Atomic write — temp .devkit.{guid}.tmp rồi File.Replace; lỗi → khôi phục từ backup.
  • Giữ nguyên format — encoding (UTF8/16/32/BE + declaration), BOM, newline, xml declaration; serialize DisableFormatting trên cây PreserveWhitespace → layout ngoài phần sửa giữ nguyên.
  • Verify sau ghi — re-parse; cập nhật hash.

8.2 Lệnh devkit report — shape

              [--name] [--new-name] [--fetchxml|--fetchxml-file] [--prefilter "a=on,b=off"] [--force]

Một lệnh + --type discriminator (shape APhước chỉ định 2026-11-07). Vì các type có bộ option khác nhau (anti-pattern devkit new — ruling 2026-10-28), command bắt buộc strict per-type validation: option không thuộc type → exit 1 tường minh (chống Spectre relaxed parsing âm thầm drop). Json sections uploadreports/downloadreports giữ nguyên key. Exit codes chuẩn: 0 ok / 1 validation / 2 connection.

11. Rủi ro & gotchas

Chú ý
  • Strict per-type validation bắt buộc — Spectre relaxed parsing âm thầm drop option lạ (report --type upload --name X phải lỗi, không được im lặng).
  • Bats/sh 1 nguồn thật (Shared Resources) — placeholder `12.ReportProjectTemplate` KHÔNG đụng; giữ byte shape (`.bat` CRLF/không trailing newline, `.sh` LF/có trailing, không BOM) vì wizard vs CLI COMPARE là byte-identical và fixtures compare sẽ bóc.
  • projitems không globbing (P.1); VSIX csproj explicit (:85-90) phải xóa entry (CS0101).
  • SaveAsync(null) — backup cạnh .rdl; tên backup có DateTime.Now → không byte-compare.
  • Removed-fields / delete-references là logic dialog-side — task CLI tự so Fields cũ/mới + FindReferences trước khi mutate; service không tự chặn.
  • RDL không phải FetchXML report → constructor ném InvalidDataException ngay từ gate — map thành exit 1 với message gốc.
  • Encoding/BOM/newline đã có trong service — CLI không tự đọc/ghi file.
  • --type trùng tên với new-item --type (khác scope) — chấp nhận theo shape aP chỉ định.
  • Shims giữ behavior cũ 100% — chỉ thêm notice; quên keeping old Args class → tests probe vỡ.
