DynamicsCrm.DevKit · Webhook Support Analysis · Addendum 2

Webhook URL giữa DEV, UAT, PROD và ALM

Phân tích tiếp theo trên cơ sở báo cáo Webhook-Support-Analysis.html: URL nằm trong registration metadata hay attribute/config; vai trò của solution; và cách triển khai URL khác nhau theo môi trường.

Kết luận nhanh

Nếu giữ thiết kế trong báo cáo gốc và gán URL literal vào WebhookUrl trên attribute, URL sẽ theo binary/config được build. Build một lần rồi dùng cùng assembly cho DEV, UAT, PROD sẽ không tự đổi endpoint. Build riêng từng môi trường có thể làm được nhưng dễ nhầm, khó kiểm soát, và buộc rebuild code cho config.

ServiceEndpoint/Webhook registration có thể là solution component và được đưa qua solution. Tuy nhiên, đưa component qua solution không tự chọn endpoint URL đúng cho từng đích. Cần target-specific override trong deployment pipeline sau import hoặc registration logic đọc cấu hình của môi trường đích.

Khuyến nghị: tách định nghĩa webhook/step (tên ổn định, message, table, stage, mode, filters) khỏi cấu hình endpoint theo môi trường. Dùng một source package và cấp URL riêng qua deployment settings/config cho DEV, UAT, PROD; deployment job tạo/cập nhật ServiceEndpoint.url trong chính môi trường đích. Không để URL hoặc auth secret của môi trường trong attribute assembly hay JSON được commit.

1. Báo cáo gốc đang đặt URL ở đâu?

Trong ví dụ attribute-driven ở báo cáo gốc, WebhookUrl được gán literal, ví dụ https://myfunc.azurewebsites.net/api/ContactUpdate. Báo cáo cũng nêu JSON endpoint config như approach thay thế, có profile DEV và url.

Đây mới là đề xuất kiến trúc; repo hiện tại chưa triển khai webhook registration. Code hiện tại không có PluginType.Webhook, WebhookUrl, hoặc CRUD đăng ký ServiceEndpoint trong TaskServer. Vì vậy hiện chưa có flow để tự chuyển URL DEV sang UAT/PROD.

Lưu ý: JSON có profile chỉ hữu ích khi deployment chọn đúng profile theo target environment rồi dùng giá trị đó để tạo/cập nhật endpoint. Khai báo profile tự nó không đổi URL.

2. ServiceEndpoint có đưa vào solution được không?

Có. Microsoft liệt kê Service endpoint là solution component. Webhook registration được lưu trong ServiceEndpoint với contract=8; SDK step tham chiếu endpoint đó.

Điều này cho phép vận chuyển phần registration/step qua solution ALM. Nhưng solution không tự suy ra mapping DEV → dev URL, UAT → uat URL, PROD → prod URL. Không nên giả định import solution thuần sẽ tự thay URL theo tên môi trường.

Trả lời: đưa component registration vào solution được; muốn URL theo môi trường, cần target-specific deployment setting/post-import step cập nhật serviceendpoint.url.

3. ALM có làm được không?

Có, nếu pipeline có bước cấu hình endpoint theo môi trường. Tài liệu Microsoft cho ALM Accelerator (được đánh dấu deprecated) có deployment setting webhookurl.webookname để cập nhật URL webhook trong deployment environment. Đây là bằng chứng cụ thể cho mô hình “import solution, rồi pipeline thay URL”. Đây là capability được tài liệu của ALM Accelerator mô tả, không phải bảo đảm mọi pipeline hoặc lần import solution chuẩn đều tự làm.

Với pipeline khác, có thể làm tương tự bằng script/tool sau import: tra ServiceEndpoint ổn định theo tên hoặc key, rồi PATCH URL target. Cần đảm bảo đúng endpoint và step liên kết trong chính môi trường đích.

5. Luồng ALM đề xuất

1
DEV authoring: định nghĩa endpoint key/name và webhook step trong solution. Dùng URL dev để test; không lưu production secret trong mã nguồn.
2
Export/build: đóng gói solution và mapping endpoint key. Nếu URL nguồn được export, coi đó là giá trị dev và bắt buộc override ở target.
3
Import vào UAT/PROD: dùng cùng solution artifact để giữ registration/step nhất quán.
4
Post-import configure: pipeline lấy URL từ protected deployment variable/secret store rồi cập nhật serviceendpoint.url ở môi trường hiện tại.
5
Verify: đọc lại tên/URL, xác nhận step trỏ đúng endpoint và chạy smoke test. AuthValue không thể đọc lại; secret cần quản lý riêng và không log.
Auth secret: Microsoft ghi AuthValue không thể retrieve sau khi set. Không thể đọc-back để so sánh secret cũ; pipeline phải quản lý rõ thao tác update và tránh log secret.

6. Hướng hỗ trợ nên thiết kế cho DevKit

  • Định nghĩa registration không chứa môi trường: endpoint key/name, message, table, stage, mode, filter, image.
  • URL là deployment input riêng: ví dụ deployment.DEV.json / deployment.UAT.json / deployment.PROD.json; không commit secret.
  • Upsert ServiceEndpoint bằng key/name ổn định, không dựa GUID khác nhau giữa môi trường; bind step tới endpoint của target.
  • Đưa endpoint và step vào solution nguồn để transport; deployer xử lý URL override sau import.
  • Fail fast nếu thiếu profile target hoặc endpoint UAT/PROD vẫn trỏ về DEV.

Cùng assembly/solution artifact có thể đi qua các stage; chỉ deployment settings thay theo môi trường. Không cần build lại plugin chỉ để đổi URL.

Nguồn

  1. Register a webhook — ServiceEndpoint, URL/auth và step.
  2. ServiceEndpoint table reference — operations/properties gồm create, retrieve, update, URL, AuthValue.
  3. Solution component dependency tracking — liệt kê Service endpoint là solution component.
  4. ALM Accelerator deployment settings — setting cập nhật webhook URL trong deployment environment; tài liệu đánh dấu accelerator deprecated.
  5. Environment variables in solutions — tách cấu hình theo environment; cần component tiêu thụ giá trị và cập nhật endpoint.
