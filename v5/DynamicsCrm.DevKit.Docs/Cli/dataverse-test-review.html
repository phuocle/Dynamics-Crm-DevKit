Thêm bộ test Dataverse vào solution hiện có

Đề xuất thêm DataverseTest vào cả new-project và new-item. Một project MSTest dùng DataverseFakes.Community có thể chạy cạnh bộ FakeXrmEasy hiện tại. aP duyệt đầu ra CLI và kết quả test trước khi mở phần VSIX.

Từ một plugin đến một file test

Ví dụ sau mô tả CLI sau khi triển khai. Solution mẫu đã có Contoso.Shared, Contoso.ProxyTypes, Contoso.Server và plugin PreAccountUpdate.

Tạo project trong solutiondevkit new-project --type DataverseTest --name Contoso.DataverseTests --solution Contoso.slnx
Chọn class cần test theo tên đầy đủdevkit new-item --type DataverseTest --project Contoso.DataverseTests --test-target Contoso.Server.Account.PreAccountUpdate
Chạy project vừa sinhdotnet test .\Contoso.DataverseTests\Contoso.DataverseTests.csproj

Project sinh ra có gì?

Một csproj net462, thư mục Framework/ và README. Project tham chiếu trực tiếp Server để tìm và chạy plugin, tham chiếu ProxyTypes cho early-bound, import Shared để dùng các wrapper nội bộ.

Người viết test thấy gì?

PreAccountUpdateTest.cs kế thừa PluginTestBase. Test chuẩn kiểm bốn guard. Test nghiệp vụ gọi Seed, RunPlugin<T> và kiểm thay đổi trên Target hoặc dữ liệu. Chỉ facade làm việc với engine.

Lệnh tạo dùng kết nối Dataverse theo quy tắc CLI hiện tại. Hai lệnh list và bộ test in-memory sau restore không cần kết nối.

Xem một assertion nghiệp vụ trong suite đã chạy

Test PreCreateSynchronousTest_01_SetsNameFromMonthAndYear chuẩn bị một khoản đoàn phí tháng 3 năm 2026. Đoạn dưới là phần thực thi và kiểm tra tên trong test đó.

RunPlugin<TargetPlugin>().WithTarget(target).Execute();
Assert.AreEqual("03-2026", target.ab_name);

Template cung cấp cách đưa Target vào plugin. Giá trị kỳ vọng 03-2026 do người viết test lấy từ quy tắc của ứng dụng.

Item sinh test gì cho từng loại server?

CLI dùng metadata và kiểu cơ sở để chọn mẫu. Khi chưa biết kết quả nghiệp vụ, item để lại khung Arrange–Act–Assert có trạng thái Inconclusive. Mỗi loại bên dưới cần ít nhất một fixture thực thi với kết quả quan sát được.

Loại serverVí dụ để aP nghiệm thu
PluginPlugin Update có pre-image đúng alias, thay đổi Target; sai một trong bốn guard sinh đúng exception. Có đường chạy cho Delete bằng EntityReference.
WorkflowChạy CodeActivity trên .NET Framework, truyền input và đọc giá trị output thực.
Custom ActionChạy message bound/unbound với SDK parameters; kiểm output hoặc tác động lên dữ liệu.
Custom APIĐọc đúng registration overload của API, chuẩn bị output key được khai báo và đọc giá trị API ghi lại.
Data ProviderChạy từng thao tác Create, Retrieve, Update, Delete, RetrieveMultiple với data source giả. Kiểm kiểu Target/Query và output đặc thù của từng thao tác.

Các lựa chọn đề nghị aP duyệt

Tên hiển thị và tên project

Dùng DataverseTest cho cả hai danh mục. CLI ở chế độ tương tác và dialog VSIX gợi ý <Solution>.DataverseTests. Truyền --name để đặt tên khác từ CLI. Khi solution có nhiều Server, dùng --server-project để chọn project cần test từ CLI.

Đặt facade trong project test

Mỗi project mới sở hữu Framework/ của mình và import production Shared. Cách này cho phép thêm một project là chạy; nếu solution có nhiều project test mới, mỗi project có một bản facade riêng.

Phiên bản engine

Dùng 1.3.2 cho đợt đầu, đúng bản đã chạy trên Union. Khi nâng version, chạy lại fixture net462 và các phép thử runtime. Không cần thay cơ chế cập nhật NuGet của template đang phát hành.

Bảo vệ project hiện tại

Giữ ID SharedTest, Test, payload và T4 hiện hành. Project mới có marker riêng; thêm item mới nhầm vào project legacy sẽ báo rõ project đích. Tạo lại project trùng tên phải dừng trước khi ghi.

Khi nào mới làm VSIX?

  1. Thấy và gọi được cả hai template. Kiểm tra catalog, picker, lệnh không tương tác, trường hợp trỏ nhầm project và chạy lại.
  2. Sinh đúng trong solution thật. CLI vừa build tạo project và item trong cả .sln và .slnx, chọn đúng Server, resolve được facade và cả hai project test cùng build.
  3. Test mới có thể bắt lỗi. Chạy net462 với fixture năm loại server, seed, image, trace JSON/nén, mock và pipeline; cố ý đổi kết quả kỳ vọng trong fixture để thấy test đỏ. TRX phải có test đã thực thi.
  4. Legacy qua hồi quy. So byte đầu ra cũ với baseline cố định, chạy test CLI đầy đủ và kiểm output từ public command. Ghi số pass/fail/skip, version engine và mọi gate còn mở.
