📋 Proposal: execute_sql MCP Tool & Standardized AI Design

Author: DynamicsCrm.DevKit Team  |  Date: 2026-08-26  |  Status: PROPOSAL (format-template.md Compliant)   ReadOnly   Wiki Standard

Microsoft provides a SQL query endpoint for the Dataverse Web API via the ?sql= query option. This document details the complete design of the execute_sql MCP tool, strictly adhering to the DynamicsCrm.DevKit MCP Refactoring Standards defined in Docs/testcall/format-template.md.

🎯 Core Refactoring & Quality Goals (format-template.md)

  • Standardized Tool Description: Exactly 3 sections in order: Plain text → WHEN TO USE: → RELATED TOOLS: with unicode arrows (→). No extra headers.
  • Mandatory [Hint] on Every Error: Every validation or runtime failure MUST emit a dedicated [Hint] line telling the calling AI exactly how to recover.
  • Standard MCP Tool Tags Only: Strict adherence to [Success], [Error], [Hint], [Detail]. No redundant inline category tags (e.g. no [SqlError], [EntityNotFound]).
  • 2-Step Inspect & Query AI Workflow: Instructs callers to discover custom tables/columns with get_tables before querying.
  • Dedicated AI Knowledge Resource: docs://instructions_for_sql providing full conversion matrices for Dataverse SQL limitations.

1. Tool Specification (Verbatim Description & Parameters)

The tool description follows the exact 3-section template standard used across all 36 MCP tools:

C# Tool Method Definition

[McpServerTool(
    Name = "execute_sql", 
    Title = "Run a SQL SELECT query",
    Idempotent = true, 
    Destructive = false, 
    ReadOnly = true,
    UseStructuredContent = true, 
    OutputSchemaType = typeof(SqlQueryResult)),
Description(
    "Run a SQL SELECT query against Dataverse in single-page or auto-paging mode.\n\n" +
    "WHEN TO USE:\n" +
    "- Query Dataverse records with standard SQL SELECT syntax (JOINs, aggregates, WHERE, ORDER BY)\n" +
    "- Read-only analytical queries, multi-table joins, or summaries after validating logical names\n\n" +
    "RELATED TOOLS:\n" +
    "- get_tables → discover entity and attribute logical names before querying\n" +
    "- execute_fetchxml → alternative for FetchXML-specific conditions or deep hierarchies\n" +
    "- docs://instructions_for_sql → Dataverse SQL syntax rules and conversion cheat sheet")]
public CallToolResult execute_sql(
    [Description("SQL SELECT query. Lowercase logical names. No SELECT *.")] string sql = "",
    [Description("1-50000. Default 5000. Use 10-100 for samples.")] int max_records = 5000,
    [Description("true = auto-page until max_records. false = first page only.")] bool get_all = false)

Parameters Specification (Wiki Aligned)

sql         : string : SQL SELECT query. Lowercase logical names. No SELECT *.
max_records : int    : 1-50000. Default 5000. Use 10-100 for samples.
get_all     : bool   : true = auto-page until max_records. false = first page only. Default false.

2. Standard Error & Hint Architecture (Rule 2 & 3 Compliant)

Per format-template.md Rule 2, EVERY error MUST carry a [Hint] line. No inline redundant tags may exist.

Trigger Condition[Error] Output LineMandatory [Hint] Output Line
Empty or whitespace sql [Error] sql is required. [Hint] Provide a SQL SELECT query. Read docs://instructions_for_sql for syntax examples.
Query starts with DML/DDL [Error] Only SELECT statements are supported. [Hint] Dataverse SQL is read-only. Use manage_record for create, update, or delete operations.
Query uses SELECT * [Error] SELECT * is not supported. [Hint] Call get_tables(name='...', include_columns=true) to view column names, then name required columns explicitly.
Query uses HAVING [Error] HAVING clause is not supported. [Hint] Filter rows using the WHERE clause before aggregating, or process thresholds in client code.
Query uses subquery in WHERE [Error] Subqueries in WHERE clause are not supported. [Hint] Rewrite the subquery using an INNER JOIN or LEFT JOIN with the related table.
Invalid Table in FROM [Error] Table '{table}' was not found. [Hint] Call get_tables to find the exact entity logical name.
Invalid Column in Dataverse response [Error] Invalid column '{col}' on table '{table}'. [Hint] Call get_tables(name='{table}', include_columns=true) to inspect available column logical names.
Aggregate > 50,000 records (8004E023) [Error] Aggregate query exceeded the 50,000 record evaluation limit. [Hint] Add indexed WHERE filters (e.g. statecode or createdon date range) to reduce evaluated records below 50,000.

3. Smart Auto-Corrections (Fail-Safe AI Features)

To reduce unnecessary roundtrips for benign AI habits without violating SQL syntax rules:

  • ✅ Auto-Strip Trailing Semicolon: SELECT a.name FROM account AS a; → stripped cleanly before Web API submission.
  • ✅ Auto-Handle TOP n: If AI passes SELECT TOP 10 name FROM account, the tool extracts 10, sets max_records = 10, removes TOP 10 from SQL, and executes seamlessly.
  • ✅ Auto Entity Set Resolution: Maps singular logical names (account) in FROM to plural entity set names (accounts) required by Web API endpoint URLs.

4. Dedicated AI Resource: docs://instructions_for_sql

Resource Registration

[McpServerResource(
    MimeType = "text/markdown",
    Name = "sql_instructions",
    Title = "Instructions for Dataverse SQL queries",
    UriTemplate = "docs://instructions_for_sql"),
Description(
    "Rules, supported operators, and T-SQL conversion cheat sheet for execute_sql. " +
    "Read this before writing complex SQL SELECT queries against Dataverse.")]
public static string SqlInstructions() => @"
# Dataverse SQL Query Rules

## CRITICAL: Inspect Table Schema Before Composing SQL
- Never guess column names or publisher prefixes on custom tables (e.g. `new_`, `hs_`, `crm_`).
- ALWAYS call `get_tables(name='...', include_columns=true)` FIRST if you do not know the exact column logical names.
- `SELECT *` is STRICTLY UNSUPPORTED. You must explicitly specify every column you need.
- Primary Key is ALWAYS `{entity_logical_name}id` (e.g. `accountid`, `contactid`, `hs_bank_transactionid`).

## Column Type Specifics
1. **Choice / OptionSet / StateCode / StatusCode**:
   - Compare with integer values, NOT strings (e.g. `WHERE a.statecode = 0`, NOT `WHERE a.statecode = 'Active'`).
   - Results provide integer values and formatted display labels via `FormattedValues`.
2. **Lookup Columns & JOINs**:
   - N (child) table uses lookup attribute (`parentcustomerid`, `hs_accountid`).
   - 1 (parent) table uses primary key (`accountid`).
   - Example: `INNER JOIN account AS a ON c.parentcustomerid = a.accountid`
3. **Dates**:
   - Stored in UTC. Use ISO date literals `'2026-01-15'`.
   - Only `DATEADD(day/month/year, -N, GETUTCDATE())` or `DATEADD(..., 'literal')` are allowed in WHERE/ON.

## Conversion Cheat Sheet (Standard SQL -> Dataverse SQL)

| What you want to do (Standard SQL) | Dataverse SQL Equivalent | Why / Rule |
|-----------------------------------|--------------------------|------------|
| `SELECT * FROM account` | `SELECT a.name, a.telephone1 FROM account AS a` | `SELECT *` not supported. Name all columns explicitly. |
| `SELECT TOP 10 name FROM account` | Omit `TOP`, pass `max_records: 10` parameter | `TOP` / `OFFSET...FETCH` not supported in SQL syntax. |
| `SELECT name FROM account WHERE id IN (SELECT accountid FROM contact)` | `SELECT DISTINCT a.name FROM account AS a INNER JOIN contact AS c ON a.accountid = c.parentcustomerid` | Subqueries in `WHERE` are unsupported. Use `JOIN`. |
| `WHERE a.modifiedon > a.createdon` | Filter client-side or use `execute_fetchxml` | Column-to-column comparison unsupported. |
| `SELECT COUNT(*) ... HAVING COUNT(*) > 5` | Filter with `WHERE` prior to aggregation, or aggregate in client | `HAVING` clause is unsupported. |
| `SELECT YEAR(createdon), COUNT(*)` | Group by entity attribute only; process date parts in client | Functions in `SELECT` / `GROUP BY` are unsupported. |
| `WHERE createdon >= GETDATE() - 7` | `WHERE createdon >= DATEADD(day, -7, GETUTCDATE())` | Only `DATEADD` and `GETUTCDATE()` supported in WHERE. |
| `SELECT 'Total', COUNT(*)` | `SELECT COUNT(*) AS total_count` | Literal values in `SELECT` list unsupported. |
| `WHERE 1=1` | Omit dummy condition | Literal-to-literal comparisons unsupported. |
";
