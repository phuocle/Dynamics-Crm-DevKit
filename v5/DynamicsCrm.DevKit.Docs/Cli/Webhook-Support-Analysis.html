1. Webhook trong Dataverse – Tổng quan

Webhook là cơ chế cho phép Dataverse gửi HTTP POST request chứa execution context (JSON) đến một endpoint bên ngoài khi một event xảy ra (Create, Update, Delete, …). Khác với Azure Service Bus (queue-based), Webhook gửi trực tiếp, đơn giản hơn, nhưng giới hạn bởi throughput của endpoint nhận.

So sánh Webhook vs Azure Service Bus vs Plugin

Tiêu chí Plugin Webhook Azure Service Bus
Chạy ở đâu Sandbox trong Dataverse External HTTP endpoint Azure Service Bus queue/topic
Execution mode Sync & Async Sync & Async Chỉ Async
Ngôn ngữ C# (.NET) Bất kỳ (HTTP endpoint) Bất kỳ (consumer)
Payload IPluginExecutionContext RemoteExecutionContext (JSON) RemoteExecutionContext (JSON)
Auth N/A (internal) HttpHeader / WebhookKey / HttpQueryString SAS token
Timeout 2 phút 60 giây N/A (queue)
Retry Không (fail = rollback sync) 1 lần retry (nếu 502/503/504) Queue-based retry
Đăng ký qua pluginassembly + plugintype + step serviceendpoint + step serviceendpoint + step

Ba loại Authentication cho Webhook

Type Giá trị authtype Mô tả Ví dụ
HttpHeader 4 Key-Value pairs trong HTTP header Authorization: Bearer xxx
WebhookKey 5 Query string với key code (dùng cho Azure Functions) ?code=abc123
HttpQueryString 6 Custom key-value pairs trong query string ?key1=val1&key2=val2

Dữ liệu Dataverse gửi đến Webhook

  • Headers: x-ms-dynamics-organization, x-ms-dynamics-entity-name, x-ms-dynamics-request-name, x-ms-correlation-request-id, x-ms-dynamics-msg-size-exceeded (khi payload > 256KB)
  • Body: JSON serialization của RemoteExecutionContext – chứa InputParameters, OutputParameters, PreEntityImages, PostEntityImages, MessageName, PrimaryEntityName, v.v.
  • Query String: Chỉ chứa auth values (nếu dùng WebhookKey hoặc HttpQueryString)
⚠️ Giới hạn quan trọng
  • Webhook chỉ hỗ trợ port 80 (HTTP) và 443 (HTTPS).
  • Khi payload > 256KB, ParentContext, InputParameters, PreEntityImages, PostEntityImages bị loại bỏ.
  • Timeout 60 giây. Nếu không response hoặc status code ngoài 2xx → fail. Retry chỉ với 502/503/504.

5. Đề xuất mở rộng CLI: Kiến trúc tổng thể

Hai approach khả thi

🅰️ Approach A: Attribute-Driven (Khuyến nghị)

Giống cách plugin hiện tại: Developer khai báo [CrmPluginRegistration] trên class, TaskServer đọc attribute từ assembly và tự động register webhook + step.

  • ✅ Nhất quán với mô hình hiện tại
  • ✅ Webhook config nằm trong code → version controlled
  • ✅ Tái sử dụng ~80% luồng xử lý của TaskServer
  • ⚠️ Cần "dummy class" chỉ mang attribute (không có logic)

🅱️ Approach B: JSON-Driven (Config only)

Webhook config nằm trong JSON file: Không cần assembly, khai báo endpoint + steps trực tiếp trong DynamicsCrm.DevKit.Cli.json.

  • ✅ Không cần compile assembly
  • ✅ Phù hợp với team không dùng C#
  • ⚠️ Khác biệt kiến trúc so với plugin/server flow
  • ⚠️ Cần command hoàn toàn mới (e.g., devkit webhook)
✅ Khuyến nghị: Kết hợp cả hai

Approach A (primary): Mở rộng TaskServer + CrmPluginRegistrationAttribute để developer khai báo webhook trên class – giữ nguyên trải nghiệm devkit server.

Approach B (secondary): Thêm JSON section "webhooks" cho trường hợp chỉ cần register webhook endpoint mà không cần assembly. Xử lý trước khi deploy .dll/.nupkg trong RunAsync().

8.3 Pseudo-code cho DeployServiceEndpointAsync

private async Task<Guid?> DeployServiceEndpointAsync(
    CrmPluginRegistrationAttribute attribute)
{
    // 1. Tìm existing endpoint bằng name
    var existing = _ServiceEndpointsCache
        .FirstOrDefault(x => x.Key == attribute.WebhookName);

    var endpoint = new Entity("serviceendpoint")
    {
        ["name"]       = attribute.WebhookName,
        ["url"]        = attribute.WebhookUrl,
        ["contract"]   = new OptionSetValue(8),  // Webhook
        ["authtype"]   = new OptionSetValue(
            (int)attribute.WebhookAuthType),
        ["authvalue"]  = attribute.WebhookAuthValue,
    };

    if (existing.Value == null)
    {
        // CREATE
        var request = new CreateRequest { Target = endpoint };
        request.Parameters.Add("SolutionUniqueName", Json.solution);
        var response = await OrgServiceAsync.ExecuteAsync(request);
        return ((CreateResponse)response).id;
    }
    else
    {
        // UPDATE (url hoặc authtype thay đổi)
        endpoint["serviceendpointid"] = existing.Value.Id;
        var request = new UpdateRequest { Target = endpoint };
        request.Parameters.Add("SolutionUniqueName", Json.solution);
        await OrgServiceAsync.ExecuteAsync(request);
        return existing.Value.Id;
    }
}

8.4 Pseudo-code cho DeployWebhookStepAsync

private async Task<Guid?> DeployWebhookStepAsync(
    Guid serviceEndpointId,
    CrmPluginRegistrationAttribute attribute)
{
    var sdkMessageFilterId = GetSdkMessageFilterId(
        attribute.EntityLogicalName, attribute.Message);
    var sdkMessageId = GetSdkMessageId(
        attribute.EntityLogicalName, attribute.Message);

    var step = new Entity("sdkmessageprocessingstep")
    {
        ["name"] = attribute.Name,
        ["mode"] = new OptionSetValue(
            attribute.ExecutionMode ==
                ExecutionModeEnum.Asynchronous ? 1 : 0),
        ["rank"] = attribute.ExecutionOrder,
        ["stage"] = new OptionSetValue((int)attribute.Stage),
        ["asyncautodelete"] = attribute.DeleteAsyncOperation,
        ["sdkmessagefilterid"] = sdkMessageFilterId,
        ["sdkmessageid"] = sdkMessageId,
        ["filteringattributes"] =
            attribute.FilteringAttributes?.Replace(" ", ""),
        ["description"] = attribute.Description,
        // ⭐ KHÁC BIỆT: dùng eventhandler thay vì plugintypeid
        ["eventhandler"] = new EntityReference(
            "serviceendpoint", serviceEndpointId),
    };
    // Không set plugintypeid!
    // Không set configuration (webhook không hỗ trợ)
    // ... Create/Update logic tương tự DeployPluginStepAsync
}

11. So sánh Plugin vs Webhook Registration Flow

🔌 Plugin Registration (Hiện tại)

  1. pluginassembly → Upload DLL content
  2. plugintype → Register class name
  3. sdkmessageprocessingstep
    → plugintypeid trỏ tới plugintype
  4. sdkmessageprocessingstepimage → Pre/Post images

Cần assembly: ✅ Bắt buộc

Endpoint ngoài: ❌ Không

🔗 Webhook Registration (Đề xuất)

  1. serviceendpoint → Register URL + auth
    (contract=8)
  2. Không cần pluginassembly/plugintype
  3. sdkmessageprocessingstep
    → eventhandler trỏ tới serviceendpoint
  4. sdkmessageprocessingstepimage → Pre/Post images

Cần assembly: ❌ Không bắt buộc

Endpoint ngoài: ✅ HTTP endpoint

12. Rủi ro và lưu ý

⚠️ Bảo mật AuthValue

authvalue là write-only – sau khi set không thể retrieve lại từ Dataverse. Cần:

  • Không log giá trị authvalue ra console
  • Cân nhắc đọc từ biến môi trường hoặc .env thay vì hardcode trong attribute
  • Khi cập nhật endpoint, luôn gửi lại authvalue (không thể kiểm tra giá trị cũ)
⚠️ Change Detection cho ServiceEndpoint

Không thể so sánh authvalue cũ vs mới (vì không đọc được giá trị cũ). Chiến lược:

  • So sánh url và authtype để quyết định update
  • Luôn gửi authvalue trong mọi update request (force update)
  • Hoặc: chỉ update khi user explicitly request (flag --force-auth-update)
💡 Webhook class "rỗng"

Với Approach A (attribute-driven), class Webhook chỉ mang metadata – không cần kế thừa IPlugin hay CodeActivity. Cần đảm bảo:

  • GetTypes() vẫn tìm được class này (đã OK vì chỉ check CrmPluginRegistrationAttribute.Name)
  • DeployPluginTypeAsync() KHÔNG được gọi cho Webhook type (không cần plugintype record)
  • DeployAssemblyAsync() cũng KHÔNG bắt buộc – nhưng nếu webhook class nằm chung DLL với plugin thì vẫn deploy assembly bình thường
🔴 Không hỗ trợ Unsecure/Secure Configuration

Webhook steps không hỗ trợ configuration (unsecure) hay sdkmessageprocessingstepsecureconfigid. Nếu developer set các giá trị này trên Webhook attribute, CLI nên bỏ qua và cảnh báo.
