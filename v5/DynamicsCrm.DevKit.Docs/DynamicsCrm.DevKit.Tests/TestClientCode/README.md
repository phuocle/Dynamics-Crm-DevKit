# TestClientCode

This directory contains 6 isolated project environments used for testing, validation, and verification of the DynamicsCrm.DevKit templates and generators. They simulate different user scenarios (JS vs TS, Unit Testing vs AI Code vs VSIX Templates).

## Folder Structure

### 01.DevKitJs-UnitTest
*   **Purpose**: Validates JavaScript unit testing capabilities.
*   **Tech Stack**: JavaScript, Jest, xrm-mock.
*   **Key Scripts**: `npm run test` (runs tests), `npm run coverage` (generates coverage).
*   **Key Files**: `test/` folder contains sync logic (`sync-devkit.js`) to ensure tests run against the latest devkit resources.

### 02.DevKitTs-UnitTest
*   **Purpose**: Validates TypeScript unit testing capabilities.
*   **Tech Stack**: TypeScript, Jest, ts-jest, xrm-mock.
*   **Key Scripts**: `npm run devkit-test` (runs tests with coverage), `npm run check` (compiles TS).
*   **Configuration**: Uses `tsconfig.json` for compilation settings.

### 03.DevKitJs-AICode
*   **Purpose**: Sandbox for testing code generated by AI assistants (Copilot/Gemini) in a JavaScript environment.
*   **Use Case**: Verifying that AI-generated snippets interact correctly with the `devkit.d.ts` definitions and runtime.

### 04.DevKitTs-AICode
*   **Purpose**: Sandbox for testing code generated by AI assistants in a TypeScript environment.
*   **Use Case**: ensuring type safety and correct compilation of AI-suggested TypeScript code.

### 05.DevKitJs-Vsix
*   **Purpose**: Represents the output structure of a fresh JavaScript project created via the VSIX template.
*   **Use Case**: Verifying the scaffolding, file structure, and default configurations provided to users.

### 06.DevKitTs-Vsix
*   **Purpose**: Represents the output structure of a fresh TypeScript project created via the VSIX template.
*   **Use Case**: Verifying the TS scaffolding, `tsconfig` settings, and build scripts (`build.js`) provided to users.
